# ADR-004：Provider Adapter 与能力降级

- 状态：Accepted
- 日期：2026-08-13

## 背景

Claude、Codex、OpenCode、OpenClaw 的协议、恢复能力、权限模型和 skill 入口不同，移动端又需要稳定统一的交互。

## 决策

Daemon 定义统一 Adapter SPI：

```text
Detect
Capabilities
Start
Resume
Send
Abort
RespondPermission
SetMode
PlanAction
GoalAction
SkillCatalog
InvokeSkill
Dispose
```

事件统一为 turn、message、tool、permission、question、plan、goal、skill、usage 和 file change。每个能力声明为：

- `native`：Provider 原生支持并通过契约测试。
- `emulated`：Daemon 或产品层提供有限模拟。
- `unsupported`：明确禁用并显示原因。

四类 Provider 并行实现原生协议；PTY 只作为标记清晰的兼容降级，不作为基础事件协议。

## 后果

客户端只消费 capability schema，不根据 Agent 名称硬编码按钮。每个 Provider 都必须维护受测版本矩阵、fixture/golden trace 和真实上游 gate；真实 gate 缺少凭据时标记 blocked，不得伪造通过。
