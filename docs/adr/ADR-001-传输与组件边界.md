# ADR-001：Relay、Daemon 与三类传输通道

- 状态：Accepted
- 日期：2026-08-13

## 背景

系统需要把多个 PC 本地工作区安全地暴露给 Android 和 Web，同时支持断线恢复、事件流和异步控制。服务器不能访问工作区，也不能读取端到端加密正文。

## 决策

采用三层边界：

1. Relay Server 只负责认证、路由、密文持久化、事件重放、presence、租约和命令状态。
2. PC Daemon 是唯一访问工作区和 Provider 进程的组件。
3. Android/Web/Admin 是客户端；Android 是唯一写控制端，Web/Admin 只读。

传输职责如下：

- REST：认证、配对、快照、历史分页、附件和异步命令提交。
- SSE：账号级可恢复增量读取，支持 `Last-Event-ID`。
- WebSocket：Terminal 与 Android 的双向命令、流式事件、心跳和 RPC。

采用 PostgreSQL 作为权威存储，Redis 只保存可重建的 presence、短租约和广播状态；事件写入使用 transactional outbox。

## 取舍

- 相比只用 WebSocket，REST/SSE 更容易实现快照、分页和断线恢复。
- 相比 gRPC，JSON 协议更适合 Flutter、Vue 和跨平台调试。
- Redis 不保存业务真相，故 Redis 故障只会造成短暂 presence 丢失，不会丢会话历史。

## 后果

协议必须包含版本、游标、幂等键和异步命令状态。三种通道需要分别测试，但客户端不会直接连接 Provider。
