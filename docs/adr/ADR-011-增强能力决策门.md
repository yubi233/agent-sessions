# ADR-011：增强能力决策门（更新/Artifacts/分享/fork/i18n）

- 状态：Accepted（决策门定义）；P6 各项保持 `decision_gated`，未通过各自前置决策前不实现 UI 或服务端
- 日期：2026-08-16

## 背景

v0.4 计划第 5.2/6 节把更新/changelog、加密 Artifacts、公开分享、fork/duplicate/rewind 与 i18n 列为「决策门范围」：每项都必须先通过安全、数据与发布模型 ADR，才能进入核心完成条件。它们都有各自的前置决策（D5/D6 与新增 D7-D9），在没有契约前用 fixture UI 标成完成会破坏「fixture 不等于真实」的证据口径。

## 决策

1. **更新/changelog（D5）**：需要签名清单的签名者、发布源（仓库/对象存储/CDN）、版本比较规则、平台包来源、回滚与离线行为全部确定后才实施。当前无真实发布源与签名密钥，`MOBILE-21`、`DEPLOY-05` 保持 `decision_gated`；客户端不显示伪造的「有新版本」提示。
2. **加密 Artifacts（D6）**：需要所有权、E2EE 密钥封装、MIME/大小上限、配额、保留期、删除与审计模型。当前无存储配额与保留策略，`MOBILE-24` 保持 `decision_gated`；不建立 Artifact 表或假链路。
3. **公开分享**：需要目标受众、访问认证、密钥封装、到期、撤销、下载/复制控制与泄漏响应。当前分享入口在 Android `MOBILE-19` 与会话 info 页明确显示 unavailable（见 P3-A），`MOBILE-23` 保持 `decision_gated`。
4. **fork/duplicate/rewind**：需要逐 Provider 声明原生语义、降级路径与数据模型；Happy 的对标行为按固定提交的实际情况声明，不强行伪造等价能力。当前快捷菜单中 fork/duplicate/archive 保持 disabled 并显示「Provider 未声明」原因。
5. **i18n**：需要 locale 选择、资源提取、回退、伪本地化与长文本回归。当前外观页保留 locale 入口但没有完整资源与回归，不显示空设置。

## 实施顺序与后果

- 各项的前置 ADR 通过并具备真实数据源后，才能把对应 `MOBILE-21/23/24` 从 `decision_gated` 改为可实施；未通过前 UI 只允许显示明确的 unavailable/disabled 原因。
- 视觉场景（`VISUAL-MOBILE-29+`）在没有 runner、截图契约与录屏 allowlist 同步前不得登记为「已存在」。
- 本 ADR 不改变既有只读边界：Relay 不读取 Workspace、不执行 Agent；Web/Admin 无写入口；Android 是唯一写控制端。
