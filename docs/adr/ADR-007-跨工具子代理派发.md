# ADR-007：跨工具子代理派发

- 状态：Accepted
- 日期：2026-08-14

## 背景

Happy 移动端对 Provider 原生 sub-agent 的展示很弱：子任务埋在同一会话流里，难以切换、复盘和跨工具使用。本项目已有多 Session、多 Terminal 和四类 Adapter。需要用产品层会话图补齐“主会话派发子代理”，而不是复制某个 Provider 的嵌套 sub-agent 协议。

## 决策

子代理是**一等 Session**，不是父会话里的嵌套 turn。

```text
Parent Session
  └── Delegation
        └── Child Session  (独立 Session / SessionInstance / ProviderThread)
```

- `Delegation` 是产品层任务：加密任务书、目标 Provider、状态、结果摘要、父子 Session 引用。
- 子会话可使用与父会话不同的 Provider（Claude → Codex / OpenCode / OpenClaw），也可以同 Provider。
- 首版默认同一 Terminal、同一已确认 Workspace；跨 Workspace 或跨 Terminal 必须单独确认，不自动越界。
- 派发由 Daemon 产品层执行：创建子 Session、启动对应 Adapter。父 Adapter 不需要原生 sub-agent。
- 若某 Provider 有原生 sub-agent，只可标记 `delegate_native=native` 且仅限同 Provider；跨工具一律 `delegate_cross_provider=emulated`。
- Android 仍是唯一写端。派发、批准、取消是父会话写命令；进入子会话后，写命令打到子会话自己的 lease epoch。
- 父会话只收 `DelegationChanged` 与加密摘要，不把子会话全文复制进父事件流。用户要看细节就打开子 Session。
- Web/Admin 只读可见父子关系与状态，不能派发或向子会话发 prompt。

状态机：

```text
proposed -> approved -> running -> completed
                    \-> rejected
           running -> failed | cancelled
```

`proposed` 仅当父 Agent 请求派发、需 Android 确认时出现。用户直接派发则从 `approved` 开始。

## 不做

- 不兼容 Happy / Claude / Codex 的原生 sub-agent wire protocol。
- 不让 Relay 调度或执行子代理。
- 不把子会话明文回流到父会话或服务器搜索。
- 不让子代理自动获得父会话未授权的 Workspace、设备或更高权限。
- 不把 PTY 或页面抓取当作跨工具桥。

## 后果

- 协议增加 `Delegation` 资源、命令和事件；能力枚举增加 `delegate_session`、`delegate_cross_provider`。
- Relay 只存密文任务书、父子 ID、状态和哈希；Daemon 创建并监督子 Session。
- Android 必须提供派发卡、子会话入口和确认流；列表按图而不是只按时间线展示。
- 每个真实 Provider 继续只证明自己的 Session 能力；跨工具派发的 contract 由 Adapter 平台与 mock 拥有。
