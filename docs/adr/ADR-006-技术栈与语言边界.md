# ADR-006：技术栈与语言边界

- 状态：Accepted（框架方向已确认；精确依赖版本在 P0 锁定）
- 日期：2026-08-13

## 背景

项目同时包含 Vue3 管理台/Web App、Flutter Android、Go Relay 和 Go PC Daemon。若每个端自由选择 UI、状态、网络和数据库技术，会导致协议 DTO 重复、状态语义漂移和客户端行为不一致。

## 决策

- Vue3 Web/Admin 全量使用 TypeScript strict，Vite + pnpm workspace。
- Admin/Web 统一使用 Element Plus 的基础控件和项目 design token；聊天时间线、Plan/Goal、Skill、权限和 DiffView 自行实现。
- Flutter 保留为 Android 技术栈，全部 UI/业务使用 Dart；Material 3 + Riverpod + go_router + Dio + Drift + Freezed。
- 如果未来要求 Android 也必须使用 TypeScript，必须把 Flutter 替换为 React Native；不尝试在 Flutter 中混入 TypeScript。
- Go HTTP 使用 Gin 生态：`github.com/gin-gonic/gin` 基于标准 `net/http` 提供 REST 路由、参数绑定和中间件；WebSocket 使用 `coder/websocket`，SSE 使用 Gin handler 配合标准响应流；数据层使用 pgx/sqlc、Goose、go-redis，日志使用 slog，观测使用 OpenTelemetry/Prometheus。
- Gin 只停留在 transport/handler 层，`*gin.Context` 不进入 domain/application；长连接的 cursor、背压、心跳和重连状态由协议层显式实现。
- Relay 和 Daemon 共用一个根 Go module；客户端通过 OpenAPI/JSON Schema 生成 DTO，而不是共享语言代码。
- Provider 协议客户端优先使用标准库和 adapter-local typed client，不引入统一 Agent SDK。

## 取舍

- Element Plus 提供成熟的表格、表单和弹层，减少管理台基础控件成本；领域 UI 仍保持独立视觉和数据模型。
- Flutter/Dart 保留原生性能、生命周期和 Android 能力；代价是 Android 不能满足“源码全 TypeScript”。
- Gin + 标准库 + 小型专用依赖降低 HTTP 样板代码，同时保留流式协议的显式控制；代价是需要项目自行维护错误映射、SSE 背压和 WebSocket 生命周期。
- sqlc 和显式迁移比 ORM 更冗长，但能让权限、幂等、outbox 和并发事务可审查。

## 后果

- P0 必须锁定 pnpm、Go、Flutter、JDK 和所有依赖版本，并提交 lockfile。
- 三端必须维护跨语言 schema/golden vector 测试。
- 不得在实现阶段临时引入第二套 UI 框架、状态管理或网络客户端来绕过既有边界。
