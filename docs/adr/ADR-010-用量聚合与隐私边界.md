# ADR-010：用量聚合与隐私边界

- 状态：Accepted，P3 实施前置契约；当前尚未实现
- 日期：2026-08-16

## 背景

v0.4 需要展示 today、7 天和 30 天用量，但现有系统没有可审计的跨端用量聚合链路。直接把 Provider 返回、prompt、会话正文或精确工作区信息写入 Relay，会破坏端到端加密与最小披露原则；只靠移动端 fixture 又不能证明真实统计。

## 决策

1. 唯一来源是 Daemon 从 Provider canonical usage event 提取的白名单数值。Provider 未返回可靠 usage 时，UI 显示“无可用统计”，不得估算或补零。
2. Relay 只接收 `usage_id`、账户/终端归属、Provider kind、UTC 日桶、整数 `input_tokens`、`output_tokens`、可选 cache token 计数和 schema 版本。禁止上传 prompt、回复、工具参数、文件路径、主机名、模型原始响应、费用、精确事件时间或 Provider 原始会话 ID。
3. Daemon 为每个来源事件生成稳定的 usage key；Relay 以 `(account_id, usage_key_hash)` 建立唯一约束。断线 outbox 的重复上传返回同一 canonical receipt，不重复累加。
4. 聚合使用 UTC 日桶，客户端必须标明 UTC。读取端只获得 account-scoped 的 today/7d/30d 聚合，不获得其它账号、单条 Provider 事件或会话正文。
5. 原始去重账本只保留最少字段 35 天；账号日聚合默认保留 400 天，账号删除时级联清除。保留期、导出和更改时区若有产品需求，必须另开 ADR 和迁移方案。
6. 所有数值必须是非负安全整数并有每条与每批上限。无效时间桶、未知 Provider、重复 ID 或超限值返回稳定错误，不能污染报表。

## 实施顺序与后果

- P3 在 ADR-009 的 Daemon event/upload 基础上为 usage 增加 OpenAPI/JSON Schema、SQLite additive migration、聚合查询与 Android 只读图表。未完成前 `MOBILE-20` 保持 `decision_gated`。
- `USAGE-01` 必须验证去重、UTC 分桶、拒绝错误数据、最小字段、保留清理与跨端读取授权；任何纯 UI fixture 只可验证图表状态，不能标记真实用量完成。
- 用量不是计费系统，也不用于 Provider 费用结算。真实 Provider gate 需要用户另行授权凭据、调用次数与额度，且报告只记录脱敏用量摘要。
