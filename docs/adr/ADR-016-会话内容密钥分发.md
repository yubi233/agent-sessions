# ADR-016：会话内容密钥（DEK）分发契约

- 状态：Accepted（v0.8.5 图片 opaque ref 链路 §3.2 的 P0 冻结契约；实现与本文不符时以修订本文为准）
- 关联：[迭代计划 v0.8.5](../zh/迭代计划/迭代计划v0.8.5.md) §3.2、[ADR-002](ADR-002-设备身份与端到端加密.md)（设备 E2EE 基座）、[ADR-014](ADR-014-DSH-ACP扩展与能力收口.md) §3.3（Daemon 附件读取端点）
- 事实锚点：packages/crypto/box.go（X25519 ECDH wrap/unwrap、RandomDEK、DeriveContentKey）、internal/domain/pairing.go（WrapDEKForDevice 预留）、internal/store/migrate.go（device_key_wraps 表）、internal/domain/attachment.go（附件密文分块上传）、internal/relay/attachment_read_contract_test.go（§3.3 读取端点证据）

## 1. 决策

v0.8.5 图片链路（G1）需要「移动端选图 → DEK 密封分块上传 → opaque ref → Daemon 授权读取/解密 → ACP image block」全程贯通，其中缺失的是会话内容密钥分发。ADR-002 §15 已确立原则——每个 Session 生成独立 DEK、用 X25519 包装给授权设备；本 ADR 冻结其会话级实例化：

1. **生成方 = Daemon**：会话创建/启动时 Daemon 生成 32 字节随机 DEK（crypto.RandomDEK），明文只保留在 Daemon 本机状态（与事件 DEK 同类边界，不写 Relay、日志或报告）；Daemon 持有明文 DEK 才能完成 §3.3 拉取后的附件解密。
2. **wrap 算法与版本**：crypto.WrapDEK（X25519 ECDH + HKDF-SHA256 派生，与 AlgorithmVersion=v1-aes256gcm-hkdfsha256 同族），收件人公钥 = 会话 owner 设备（android_owner）的 encryption_public_key；wrap 产物含版本字段，未来轮换双读。
3. **Relay 存储**：复用既有 device_key_wraps 表（dek_id + recipient_device_id 主键）；sessions 行加 content_dek_id（additive 迁移）关联。wrapped blob 对 Relay 不透明。
4. **owner 读取**：owner/write 设备经 GET /v1/sessions/:id/content-dek 读取本会话 wrapped DEK（按 recipient_device_id 过滤、只回自己的 wrap），用设备私钥 unwrap 后密封附件。读取端点不做面向终端用户的下载（与 §3.3 同口径）。
5. **降级边界（fail-closed）**：无 DEK/无 wrap/owner 不在线/撤销设备一律不发放——附件保持禁选并显示「等待会话附件密钥」（既有 sessionContentKeyAvailable 语义）；任何失败路径不把明文 DEK 或可解密元数据落日志。
6. **轮换与撤销**：会话级 DEK 生命周期随会话（不按时间轮换）；设备撤销后不再接受新 wrap（WrapDEKForDevice 的 active 校验已冻结，SEC-02/PAIR-03），已存在 wrap 由撤销语义自然失效（移动端只读自己的 wrap 且设备已 revoked 时读取被拒）。

## 2. 数据流

```text
会话创建/启动（Daemon）
  → DEK = RandomDEK()（明文仅 Daemon 本机）
  → wrapped = WrapDEK(owner 设备 encryption_public_key, DEK)
  → PUT /v1/daemon/sessions/:id/content-dek（Terminal 上行：dek_id + wrapped）
  → Relay：sessions.content_dek_id = dek_id；device_key_wraps 落账（recipient=owner）

移动端上传附件前
  → GET /v1/sessions/:id/content-dek（owner 鉴权）→ wrapped（本设备）
  → DEK = UnwrapDEK(设备私钥, wrapped)（私钥在 Android Keystore，不出设备）
  → 用 DEK 派生附件密钥 Seal 分块上传（既有 attachments/chunks 契约）

Daemon 发送 refs 时
  → GET /v1/daemon/attachments/:id（§3.3，归属校验）
  → 本机 DEK Open → 哈希复算 → ContentBlock image → SendContent
```

## 3. 端点契约（冻结）

### 3.1 PUT /v1/daemon/sessions/:id/content-dek（Terminal 上行）

请求：{ protocol_version, dek_id, wrapped_dek, recipient_device_id }

- 幂等：同 dek_id + recipient_device_id 重放返回既有记录（不回显 wrapped 以外字段）；
- 归属：目标会话的 workspace home Terminal 才可写；recipient 必须是同账号 active owner 设备；
- 会话已存在 content_dek_id 时：同 id 幂等放行，异 id 拒绝（防降级覆盖）。

### 3.2 GET /v1/sessions/:id/content-dek（owner/write 读取）

响应：{ dek_id, recipient_device_id, wrapped_dek }

- 只返回当前设备自己的 wrap（按 bearer 设备过滤），不枚举其它收件人；
- 无 DEK（未生成/未上行）返回 404 语义（fail-closed，客户端维持「等待会话附件密钥」）；
- 设备已撤销/非 owner → 403；响应不回显明文、不落日志。

## 4. 测试矩阵（冻结）

| 用例 | 层级 | 验收 |
| --- | --- | --- |
| DEK 生成 + wrap + 上行落账 | Go relay/daemon 契约 | 会话创建后 dek_id 落 sessions 行；wrapped 与明文不可互推（bytes 不回显） |
| owner 读取本设备 wrap | Go relay 契约 | 只回自己的 wrap；非 owner 403；无 DEK 404 |
| 幂等与冲突 | Go relay 契约 | 同 id 幂等；异 id 拒绝 |
| 撤销设备不获新 wrap | Go pairing 契约 | revoked 后 Put 拒绝（复用 WrapDEKForDevice 校验） |
| fixture 附件密封全链 | Flutter fixture | contentKeysReady 语义不变：无密钥禁选 + 「等待会话附件密钥」 |
| 真实设备 unwrap | Android 实机（授权 gate） | Keystore 私钥 unwrap → 密封上传（实机约束外，如实标注） |

## 5. 边界（如实）

- 多 owner 设备：wrap 按设备逐一发放（每设备一份 wrapped）；无私钥设备（如 web）天然不能解附件，属设计降级而非缺陷；
- Daemon 本机明文 DEK 丢失（本机状态清理）后：既有 wrap 不可再解（无法重新 wrap 同一 DEK 给新设备）——会话附件进入不可恢复 fail-closed，如实标注为会话级数据不可迁移；
- 移动端真实密封/unwrap 依赖设备私钥（Android Keystore），本期（v0.8.5）本地环境不执行实机 gate；Go/Relay 侧契约与 fixture 全链先行冻结并测试。
