本说明对应一轮“产品演示”，不是 Android 或发布验收。演示包含两个独立视频：第一段展示移动端控制主流程，第二段展示一次真实 OpenCode Provider/模型对话。两段不会伪装成同一条链路。

`testbox/` 是会话绑定的本地项目根目录，真实 Agent 仅以它作为 `--dir`。它不存放事件流、录屏、截图或测试报告；这些测试产物分别写入已忽略的 `e2e-verify/reports/` 和 `e2e-verify/screencasts/`。

## 怎么使用移动端主流程

视频中的顺序就是日常使用顺序：

1. 打开 Happy 风格移动端，应用通过 `bootstrapDevice()` 完成免登录设备初始化，不填写账号、邮箱或密码。
2. 创建会话并选择工作区、Provider；只有拿到有效 lease 且当前设备有写权限时，写入口才会启用。
3. 点击启动本机进程，随后在 composer 中发送任务。界面会显示用户消息、Assistant 流式消息和工具活动。
4. 出现权限请求时，在页面上明确允许或拒绝；问题卡需要先回答，Agent 才会继续。
5. 需要暂停时使用停止/abort；要结束本机进程时打开结束入口并完成二次确认。失败只显示错误，不伪造 stopped 成功状态。
6. 重新进入会话时执行恢复读取；恢复只读取 snapshot，不自动重放原来的 start、send 或 kill。

这一段的对话文字来自 deterministic Flutter fixture，用来解释控制面和状态变化，不代表真实模型回复。

## 怎么观看真实 Agent 对话

真实对话视频由本机 OpenCode Go 的 `deepseek-v4-flash` 生成，用户提示是“请说明移动端如何创建会话、发送任务、处理权限请求并结束会话”。视频中的 Assistant 文本来自真实 JSON 事件流，经过路径、凭据和系统信息脱敏后渲染。

复现时让 OpenCode 只能使用专用工作区：

```bash
mkdir -p testbox e2e-verify/reports/REAL e2e-verify/screencasts/REAL
opencode run --pure \
  --dir "$PWD/testbox" \
  --format json \
  --model opencode-go/deepseek-v4-flash \
  "请用中文说明一次真实的移动端 Agent 主流程：创建会话、发送任务、处理权限请求、结束会话。只输出给用户看的简短自然语言。" \
  > e2e-verify/reports/REAL/real-agent-events.jsonl
node e2e-verify/real/render-dialog-video.mjs \
  e2e-verify/reports/REAL/real-agent-events.jsonl \
  e2e-verify/screencasts/REAL
```

不要把仓库根目录作为 `--dir`，也不要在 `testbox` 下写入视频、截图、报告或事件流。这样 Agent 读取的是绑定项目本身，不会把测试产物误当成项目文件。

## Flutter 录屏复现

录屏脚本仍要求先有已通过的可见 macOS Flutter gate，但录屏产物固定写入 `e2e-verify/screencasts`：

```bash
node e2e-verify/mobile/record-macos.mjs \
  --gate-report e2e-verify/reports/<timestamp>/MOBILE/mobile-01-macos.json
```

脚本使用 5fps 可见窗口采集，输出 manifest、帧和 MP4；它不是 Android 真机验收，也不执行 Push、真实 Provider 或后台恢复 gate。

## 边界

- 移动端视频证明 UI 控制流程、lease/权限门控和状态展示。
- 真实对话视频证明本机 OpenCode CLI、Provider 和模型能够返回事件流。
- 当前移动端真实 Relay 内容密钥通道尚未把真实模型正文安全投影到 Flutter，因此不能把两段视频拼成“移动端已经展示真实模型对话”。
- `testbox` 是会话绑定项目目录，不能混入测试产物。
- 视频和临时事件文件都位于已忽略的 `e2e-verify` 测试产物目录，不写入 Git，也不作为长期测试报告保存。
