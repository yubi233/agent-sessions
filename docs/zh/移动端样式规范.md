# 移动端样式规范

适用范围：`apps/mobile` 全部 Flutter UI 代码。生效基线：v0.8.9 之后的样式一致性专项。

核心原则只有一条：**业务代码只消费语义 token 与主题档位，不写死样式字面量。** token 的唯一定义点在 `apps/mobile/lib/ui/app_theme.dart`（未来如拆分 `AppTypography`，同样只允许一处定义）。

规范分两个执法级别：

- **P0（机器执法）**：色彩、圆角、字号。违规会在守卫测试中直接失败。
- **P1（迁移期评审执法）**：间距、图标尺寸、透明度修饰与组件约定。规范给出档位与迁移映射，靠 code review 与分批迁移收敛；间距和图标在存量迁移完成后升级为机器执法（见 §8）。

## 1. 色彩（P0）

### 1.1 色彩角色表

所有颜色经 `ThemeData.colorScheme` 与 `AppSemanticColors`（`context.appColors`）两个入口消费，亮暗色值只定义在 `AppTheme._build` 一处：

| 角色 | 入口 | 用途 |
| --- | --- | --- |
| 页面底 | `colorScheme.surface`（scaffold 兜底 canvas） | Scaffold 背景 |
| 内容面 | `colorScheme.surface` / `surfaceContainerHigh` | 卡片、输入框、浮层面 |
| 浮起面 | `appColors.surfaceRaised` | SnackBar、tooltip、悬浮面板 |
| 描边 | `appColors.border`（= `colorScheme.outline`） | 分隔线、描边 |
| 主文本 / 次文本 | `colorScheme.onSurface` / `appColors.textSecondary` | 文字两级 |
| 成功 / 警告 / 信息 / 中性 | `appColors.success` / `warning` / `info` / `neutral` | 状态语义色 |
| diff 增 / 删 | `appColors.diffAddition` / `diffDeletion` | 代码差异底色 |
| 遮罩基色 | `colorScheme.scrim` | 相机占位黑场、模态压暗遮罩的基色 |

### 1.2 规则

- 禁止 `Color(0x…)` 字面量出现在 `app_theme.dart` 之外。
- 禁止裸 `Colors.white` / `Colors.black` / `Colors.grey…` 等 Material 色（`Colors.transparent` 允许）。
- 压暗遮罩使用 `colorScheme.scrim.withValues(alpha: AppOpacity.scrim)`；需要不透明黑场（例如相机尚未出帧）时直接使用 `colorScheme.scrim`。禁止把二者都归入同一个带透明度颜色 token。
- 新增颜色角色先使用 `ColorScheme` 已有字段；只有 Material 角色表不存在该语义时才扩展 `AppSemanticColors`，并同步亮/暗两组色值与本文档 §1.1。
- `withValues(alpha:)` 是颜色角色的修饰，不与裸色同等处理。除 §7 已冻结的 scrim 外，存量透明度先按具体用途分类；只有两个场景语义相同且走查确认后才共用命名 token，禁止按相近数值批量归并。

## 2. 间距与边距（P1）

### 2.1 档位表

基准 4pt 网格，外加一档 2pt 微调。`AppSpacing` 在现有六档基础上补 `micro`：

| token | 值 | 用途 |
| --- | --- | --- |
| `AppSpacing.micro` | 2 | 发丝间距：图标与文字微调、紧凑徽标内衬 |
| `AppSpacing.xs` | 4 | 行内间距：icon-label 间隙、chip 竖向内衬 |
| `AppSpacing.sm` | 8 | 默认元素间距：列表项之间、`SizedBox` gap 默认档 |
| `AppSpacing.md` | 12 | 卡片内边距、相关分组之间 |
| `AppSpacing.lg` | 16 | **屏幕左右安全边距（统一档）**、区块之间 |
| `AppSpacing.xl` | 20 | 大区块分隔 |
| `AppSpacing.xxl` | 24 | 页头/页脚呼吸感、弹层内边距 |

### 2.2 规则

- 标准元素间距中的 `EdgeInsets` / `SizedBox` / `Padding` 必须引用 §2.1 token，禁止继续写 3/5/6/7/9/10/14 等数字字面量；零间距使用 `EdgeInsets.zero`、省略零参数或 `SizedBox.shrink()`，不新增 `AppSpacing.zero`。
- `EdgeInsets.only` 允许用于布局定位，但每个方向的值仍取档位。
- 屏幕级左右边距一律 `AppSpacing.lg`，不允许各页面自定 12/14/20。
- `SizedBox` 承载的控件高度不归间距管：按钮 52/48 继续由主题控制，头像 34/38/42、状态点 7 使用 `AppSizes`，其余输入坞或固定控件使用对应主题或具名组件常量。`EdgeInsets` 始终是 inset：现有 56px 空态留白、120px 键盘 `scrollPadding` 等超出通用间距表的布局约束，迁移时必须改为有业务语义的具名布局常量；只有框架调用无法引用常量时才允许逐行理由豁免，禁止把它们伪装成 `AppSizes` 或压缩为不等价的通用间距。

### 2.3 存量迁移映射

| 现值 | 出现量级 | 映射 |
| --- | --- | --- |
| 6 | ~38 处 | 视觉走查后归 4 或 8（chip 内衬归 4，元素间距归 8） |
| 10 | ~33 处 | 紧凑 padding 归 8，分组间距归 12 |
| 14 | ~16 处 | 归 16 |
| 3/5/7/9 | 零星 | 就近偶数档 |
| 28 | 2 处标准 gap；另有固定宽度 | 标准 gap 归 24；固定宽度进入 `AppSizes` 或逐行裁决 |
| 56/120 | 空态留白/键盘滚动预留等特例 | 改为具名布局常量；无法常量化时才审批逐行豁免 |

迁移按屏幕分批（session chat / composer / settings / 其余），每批做一次亮暗双主题走查；不做全仓一次性替换。

## 3. 圆角（P0）

### 3.1 档位表

`AppRadius` 在现有三档基础上补两档与全圆语义：

| token | 值 | 用途 |
| --- | --- | --- |
| `AppRadius.micro` | 4 | 发丝徽标、贴边小元素 |
| `AppRadius.small` | 6 | chip、tooltip、ripple |
| `AppRadius.card` | 8 | 卡片、输入框、按钮、浮层默认（主题 `shape`） |
| `AppRadius.large` | 12 | sheet、大浮层、独立面板 |
| `AppRadius.pill` | 22 | composer 输入坞胶囊 |
| 全圆 | `StadiumBorder` / `CircleBorder` | 圆形按钮、头像裁剪；用形状而非 `999` 数值 |

### 3.2 规则

- 业务代码禁止 `BorderRadius.circular(<数字>)` / `Radius.circular(<数字>)`，只允许 `BorderRadius.circular(AppRadius.*)` 或主题 `shape`。
- `app_theme.dart` 内部允许字面量（token 定义点）。
- 存量映射：`4→micro`、`6→small`、`8→card`（62 处机械替换）、`10/12→large` 或 `card`（走查）、`2/1→micro`、`999→全圆形状`。

## 4. 字阶（P0）

### 4.1 档位表

字阶唯一定义点为 `AppTheme` 的 `textTheme`，业务代码经 `Theme.of(context).textTheme.*` 消费：

| 档位 | 规格 | 用途 |
| --- | --- | --- |
| `headlineSmall` | 26/w600 | 页面大标题 |
| `titleLarge` | 20/w600 | 页面标题（AppBar 主标题） |
| `titleMedium` | 17/w600 | 区块/卡片标题 |
| `titleSmall` | 16/w600 | 列表行标题 |
| `bodyLarge` | 17 | 大正文（会话气泡正文） |
| `bodyMedium` | 14 | 正文、辅助说明 |
| `bodySmall` | 12 | 次要说明 |
| `labelLarge` | 15/w600 | 按钮文字 |
| `labelMedium` | 12/w600 | chip、徽标 |
| `labelSmall` | 12/w500 | 时间戳、元信息 |
| `AppTypography.mono`（新增） | 13/monospace | 代码、diff、路径、终端输出 |

### 4.2 规则

- 业务代码禁止 `fontSize:` 字面量；字阶之外的需求先扩 `textTheme`/`AppTypography` 并同步本文档。
- 强调（加粗/变色）用 `style.copyWith(...)`，不得另立字号。
- 存量 5 处 `fontSize:` 字面量归阶：12→`labelSmall`/`bodySmall`（`session_info_screens.dart` 1 处、`git_diff_screens.dart` 2 处）、13（mono）→`AppTypography.mono`（`session_markdown_text.dart`、`session_question_panel.dart` 各 1 处）。

## 5. 图标与固定尺寸（P1）

`AppSizes` 现有 `statusDot=7`、头像三档 34/38/42，补图标四档（2pt 步进）：

| token | 值 | 用途 |
| --- | --- | --- |
| `AppSizes.iconSm` | 16 | 行内图标、按钮内图标 |
| `AppSizes.iconMd` | 18 | 默认操作/列表图标（现状主流） |
| `AppSizes.iconLg` | 20 | 工具栏、导航图标 |
| `AppSizes.iconXl` | 24 | 空态、强调位 |

规则：`Icon(size:)` 与 `IconButton(iconSize:)` 一律取 token；存量 14 归 16，17/19/15 就近归档。头像尺寸沿用现有三档；32/36 等空态图标先按 V090 B6 核实是否统一进入新语义档，不得为了通过守卫悄悄放入数字 allowlist。新增尺寸先扩 `AppSizes` 并登记用途。

## 6. 组件级约定（P1）

同类组件只允许一种画法，新增入口先查本节：

- **状态徽标/chip**：`labelMedium` + `AppRadius.small` + 横向 `AppSpacing.xs` 内衬；语义色取 `appColors`，禁止自定底色透明度组合。
- **卡片**：走 `CardTheme`（surface + radius 8 + elevation 0），不再手写 `BoxDecoration` 复刻。
- **浮层/菜单/overlay 面板**：`appColors.surfaceRaised` 背景 + `appColors.border` 描边 + `AppRadius.large`；overlay 内边距 `AppSpacing.md`。
- **操作反馈**：行内 `labelSmall` 文本（现状 `_feedback` 模式）或 `SnackBar`（`snackBarTheme` 已定义 surfaceRaised + radius 8）；禁止自绘居中大 toast。截图（2026-09-06）中「已添加到剪贴板」浮层的渲染来源不在当前代码中，需排查是否为旧构建或系统层产物。
- **按钮**：Filled 52 / Outlined 48 高度已由主题定义，业务代码不覆写高度。
- **分隔**：`DividerTheme`（1px border 色），禁止手写 `Container` 横线。
- **阴影**：仅 `AppShadows` token；新投影需求先扩 token。

## 7. token 扩充清单（随首批迁移落地）

| token | 定义 | 理由 |
| --- | --- | --- |
| `AppSpacing.micro` | 2 | 发丝间距档，存量 2pt 值收口 |
| `AppRadius.micro` / `large` | 4 / 12 | 存量 4 与 10/12 归档 |
| `AppTypography.mono` | 13/monospace | 代码/diff/路径共用等宽档 |
| `AppSizes.iconSm/Md/Lg/Xl` | 16/18/20/24 | 图标尺寸收口 |
| `AppOpacity.scrim` | 0.24 | 模态压暗强度；基色始终来自 `colorScheme.scrim` |

## 8. 守卫（机器执法）

新增 `apps/mobile/test/style_guard_test.dart`，用 Dart analyzer AST 扫描 `apps/mobile/lib/**/*.dart`（`analyzer` 必须作为显式 dev dependency 锁定；生成代码目录 `protocol/` 豁免）。禁止用正则或手写字符串剥离来判断语法节点，避免注释、字符串、嵌套表达式和格式变化造成误报/漏报：

- **Wave 1（规范落地即生效）**：
  - 禁 `Color(0x`，豁免：`app_theme.dart`；
  - 禁裸 `Colors.*`（`Colors.transparent` 除外），豁免清单随 §7 scrim token 落地清空；
  - 禁 `fontSize:`，豁免：`app_theme.dart` 及未来 `AppTypography` 定义文件；
  - 禁带数字参数的 `BorderRadius.circular(` / `Radius.circular(`，豁免：`app_theme.dart`。
- **Wave 2（间距与图标迁移均完成后启用）**：
  - `SizedBox(height/width:)` 的标准 gap 与 `EdgeInsets.*` 的通用间距必须引用 `AppSpacing.*`；`EdgeInsets.zero`、省略零参数和 `SizedBox.shrink()` 明确允许；固定控件尺寸引用 `AppSizes.*`、主题或具名组件常量，超大空态 inset、键盘滚动预留等引用具名布局常量。只有无法常量化的框架约束才能进入逐条理由 allowlist，不能用“数值在网格内”绕过 token；
  - `Icon(size:)` 与 `IconButton(iconSize:)` 必须引用 `AppSizes.*`；头像、状态点等引用各自已有尺寸 token；
  - 守卫自身必须有正向/负向 fixture，证明能拦截数字字面量、允许 token，并由 AST 自然排除注释、字符串及 `protocol/` 生成代码。

豁免统一登记在守卫测试的 allowlist 常量中，每条附理由注释；删除豁免与删除违规同属一个提交。

## 9. 治理

- token 定义与本文档同步变更，禁止只改代码不改文档（反之亦然）。
- 新档位必须登记来源（哪个存量值、多少处）与用途，先扩文档再迁码。
- 迁移批次验收口径：`flutter analyze` 零告警 + 全量 Flutter 测试 + 守卫测试 + 亮暗双主题走查该屏截图留档。
- 版本收口必须运行 headed Flutter 可见门禁：360x800、430x932、1280x800 三个代表性视口，并为至少一个受影响密集页面运行 200% 文本缩放；溢出、遮挡、不可达控件或 Semantics 丢失均阻塞交付。MP4 可选，结构化报告与截图必需。
