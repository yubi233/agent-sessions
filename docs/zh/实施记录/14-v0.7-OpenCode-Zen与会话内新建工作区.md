### P2 实施与验证

- Daemon 通过 `ResolveWorkspaceRoot` 在启动时 fail-closed 校验授权根；`WorkspaceManager.Create` 只接受共享名称规则，在授权根直接子级 mkdir/复用，新增目录执行 `git init --quiet`，并将 opaque workspace ID 与 canonical root 写入本机确认表。已存在的非目录、非 Git 根、符号链接逃逸和控制字符均拒绝；不会删除或覆盖用户已有目录。
- Relay `WorkspaceService` 以账号+规范化名称生成稳定 workspace/project ID 和幂等 scope，要求 Android owner/write 身份、在线 Terminal 以及 `workspace_create` capability。命令使用 `lease_epoch=0`，普通 session result 不接收；`/v1/daemon/commands/:id/workspace-result` 收到成功回执后才在同一事务登记 Workspace。客户端 create/status 响应和 workspace 列表只投影白名单字段，不包含 `canonical_root`。
- Flutter `SessionController.createWorkspaceWithName` 只向真实 Relay 提交名称，pending 时有限轮询并保持单飞；`NewSessionScreen` 对名称做 Form 校验、展示“正在创建工作区…”状态，成功后自动填充 workspace ID。真实 HTTP 模式不暴露 Host 目录选择，fixture 目录 flow 仅保留历史本地回归兼容。
