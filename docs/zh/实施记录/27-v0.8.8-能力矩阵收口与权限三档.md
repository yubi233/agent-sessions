## 2. 真实栈首曝缺陷与修复（全部有回归锚点）

1. **会话控制 kind 的 capability 门缺口**（V088-14/15 首曝）：`capabilityForCommand` 缺 `mode.set/question.answer/plan.action/goal.action/skill.invoke/permission.approve|reject/session.fork` 映射 + hello 未声明 → relay 门一律 `CAPABILITY_UNSUPPORTED`。v0.8.3 起的潜在缺陷（V085-08 仅 runner/fixture 层验证）。修复 + 双层回归（`TestCapabilityForCommandSessionControlKinds` + `TestDaemonCapabilitiesAdvertiseSessionControlKinds`）。
2. **executionMu 审批死锁**（V088-15b 首曝）：send 回合等审批期间持有 `executionMu`（`h.request` 阻塞在 session/prompt），approve 走同一把锁永远排队（SIGQUIT goroutine dump 实证 `runner.go:252` 阻塞）。修复：approve/reject 与 abort 同为抢占类（不取 executionMu，复用 `respondPermission` one-shot 校验）。回归 `TestV088PermissionApprovePreemptsInFlightSend`。
3. **localdev 审批卡投影缺失**：localdev encoder 未投影 `EventPermissionRequest`（v0.8.2 审批卡只在生产 E2EE 侧可见）。补 `permission_request` 投影（permission 对象与 question 同构，与生产同白名单口径）。
4. **pageBuilds 只声明不递增**（V087-12 遗留）：`SessionDetailScreen.pageBuilds` 无自增，localdev 导航落地判定恒假（navigate-timeout 误报）。build 内自增 + 已在目标页时以路由为等效落地信号。
5. **深链被恢复导航覆盖**（V087-12 帧遗留，V088-13）：`_openSessionWhenReady` 冷启动窗口 4s→60s + 落地后 10s 再断言循环（路由/选中会话被覆盖即重新拉回，恢复语义不改）。回归 `v088_deep_link_priority_test.dart`。

## 3. ask 审批语义（插件源码实证，纠正用例设计）

`approval=ask` 只在「模型对沙箱拒绝的操作带 `sandbox_permissions` 参数升级重试」时触发：`approval/request` → ACP `session/request_permission` → App 审批卡。workspace-write 档内普通工作区写由沙箱直接放行（codex 语义，正确行为）；`/tmp` 属 `writableRoots`（平台 temp 区）直接放行。审批卡用例必须用「沙箱真会拒」的越界路径（如 `~/` 下非工作区、非 temp 路径）诱导升级。放行闭环实证：沙箱拒 → 升级重试 → `permission_request`（含 request_id）→ `permission.approve` → 回合从 waiting_permission 推进 completed → `notes/v088-approval-probe.txt` 落盘。
