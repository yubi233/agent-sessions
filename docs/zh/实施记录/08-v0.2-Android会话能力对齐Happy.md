## 目标、范围与验证口径

本迭代把 Android 会话页补成 Happy 移动端同一套编码会话工作流：快捷操作、Resume、文件浏览、composer 控制面，以及真实 OpenCode transport。v0.1 的列表/时间线/Diff/Delegation/生命周期保持，不重做。

- 不做语音、社交、付费、Git 写、远程 shell、Happy wire protocol。
- 契约默认 `local_test=true`、`fixture_data=true`。
- 浏览器验收必须 headed Chrome：`real_browser=true`、`headless=false`。
- Flutter 验收仍是 MacBook 可见窗口：`visible_desktop_app=true`、`headless=false`。
- 真实 OpenCode 已授权；报告只留哈希、事件类型、usage。CLI smoke 不能替代 Adapter transport。

### P1 关键发现

- opencode 1.17 服务端校验 `part.id`：空字符串会被拒绝（400），缺省字段可省略。Part 序列化必须 `omitempty`。
- `/event` SSE 流按 `sessionID` 分发事件；`server.connected`/heartbeat 不进公共协议。
- 本机同时运行桌面端/happy 时 `opencode serve` 启动明显变慢，健康探测窗口放宽到 60s。
- Resume 三态：GET /session/{id} 200 且有消息 -> `resumed`；200 但无消息（上下文丢失）-> `restarted_with_context`；404/网络失败 -> `unsupported`。

### P5 追加缺陷修复：模型选择透传（全流程复测发现）

- 问题：`Adapter.Start`/`Send` 未把 `StartRequest.Model` 透传给 opencode `prompt_async`，live gate 落在服务端默认模型（第三方代理）上，事件流收不到 delta/usage 而超时。
- 修复：`Client.PromptAsync` 支持 `model` 参数并把 `provider/model` 拆为 `{providerID, modelID}` 对象（服务端契约）；`handle` 记住创建时模型，Send 保持透传；fixture 契约断言 Start/Send 均透传。
- 验证：fixture contract 通过；授权 live gate 复跑通过（`2026-08-15T12-24-05-583Z`，5.7s，事件类型 delta/completed/turn_started/usage，total_tokens=11954）。
- 复测说明：本轮全流程复跑中 macOS full gate 出现两次偶发 `environment_or_startup_failure`（失败点分别为 VISUAL-MOBILE-01 与 VISUAL-PAIR-01，窗口启动时序抖动），第三次全量 17 场景通过（`2026-08-15T12-35-50-018Z`）。

### P5 残余风险

- Android AVD/真机、Android Keystore/Drift、UnifiedPush 系统推送仍属后续原生硬化，不因 MacBook gate 通过而免除。
- Claude/Codex/OpenClaw 真实凭据仍缺失（blocked）；OpenCode live 只覆盖单实例，断线重连/多会话并发由 fixture 契约覆盖。
- Daemon 的 Relay WS 投递未接线：`SessionRunner` 消费的是本地 outbox，Relay->Daemon 实时投递仍待后续阶段。
- fork/archive 按 capability fail-closed（当前 unsupported），不属于本轮交付。
