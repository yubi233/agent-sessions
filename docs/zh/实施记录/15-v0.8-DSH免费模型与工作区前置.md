# v0.8 前置：DSH 接入 OpenCode Zen 免费模型迭代测试

> 状态：`implemented / partial-evidence`
> 关联计划：[迭代计划v0.8](../迭代计划/迭代计划v0.8.md)
> 日期：2026-08-30
> 范围：先完成本地 DSH 对 OpenCode 免费模型的配置与真实冒烟；工作区同步、Resume、DSH 模式 UI 按 v0.8 后续阶段继续。

## 1. 目标

让本地 DSH 支持以下 OpenCode Zen 免费模型，并做真实链路冒烟：

- `deepseek-v4-flash`（经 `opencode-go` 免费路由）
- `mimo-v2.5-free`（经 `opencode-zen` 免费路由）
- `big-pickle`、`ling-3.0-flash-fin-free`（经 `opencode-zen` 免费路由；与 `mimo-v2.5-free` 组成 v0.8 DSH 三模型测试池）

## 2. 已实现改动

### 2.1 `cordis.yml`

- `opencode-go` 保留 `https://opencode.ai/zen/go/v1`，模型继续使用 `deepseek-v4-flash`。
- 新增 `opencode-zen` provider：
  - `baseURL: https://opencode.ai/zen/v1`
  - 模型池：`mimo-v2.5-free`、`big-pickle`、`ling-3.0-flash-fin-free`
- `acp-agent.modelProviders` 增加：
  - `mimo-v2.5-free: opencode-zen`
  - `big-pickle: opencode-zen`
  - `ling-3.0-flash-fin-free: opencode-zen`

这样 DSH 的 ACP 模型选择器里可以同时看到 `deepseek-v4-flash` 与 Zen 三模型测试池，并通过 `session/set_config_option` 路由到正确的上游。

### 2.2 本机 DSH Web profile

本机 Web profile 的 provider 配置实际由 `$DSH_HOME/settings.yaml` 的 `llm-pi-ai.providers` 动态加载，profile 根 `cordis.yml` 只是 bundle/patch 的空组合入口。已在该 settings 的 `opencode-zen` route 配置：

- `baseURL: https://opencode.ai/zen/v1`
- `apiKeyEnv: OPENCODE_GO_API_KEY`（复用既有凭据引用，不读取或改写凭据）
- 模型池：`mimo-v2.5-free`、`big-pickle`、`ling-3.0-flash-fin-free`
- `retryPolicy.mode=normal`、`maxRetries=5`，即初始请求失败后最多额外重试 5 次

2026-08-31 已用已安装 DSH CLI 的 Web profile 在随机本地端口完成无模型启动验证并立即停止。该验证不发 prompt、不读取历史正文、不消耗模型额度。

### 2.3 `internal/adapter/dsh/adapter.go`

`dshKnownModels` 扩展为：

"deepseek-v4-flash-free",

### 2.4 `e2e-verify/real/dsh-live-prompt.mjs`

- 支持 `--model` / `--config` / `--provider` 参数。
- 支持 `AGENT_SESSIONS_DSH_MODEL` / `AGENT_SESSIONS_DSH_CONFIG` / `AGENT_SESSIONS_DSH_PROVIDER` 环境变量。
- `session/new` 后通过 `session/set_config_option` 切换到指定模型。
- 透传 `OPENCODE_GO_API_KEY`。
- 报告中的 `model` / `provider` / `command` 动态生成。

## 3. 测试结果

### 3.1 `deepseek-v4-flash` — passed

命令：

```bash
node e2e-verify/real/dsh-live-prompt.mjs \
  --model deepseek-v4-flash \
  --provider opencode-go \
  --config /Users/yubi/code/agentProject/agent-sessions/cordis.yml
```

报告：

```text
e2e-verify/reports/ADAPTER-DSH/p4-dsh-live-prompt-2026-08-30T18-08-13-490Z.json
```

结论：

- `real_model=true`、`real_upstream=true`
- 回复长度 2，`stopReason=end_turn`
- `status=passed`

### 3.2 `mimo-v2.5-free` — passed（额度命中按 v0.8 DSH 测试约定接受）

命令：

```bash
node e2e-verify/real/dsh-live-prompt.mjs \
  --model mimo-v2.5-free \
  --provider opencode-zen \
  --config /Users/yubi/code/agentProject/agent-sessions/cordis.yml
```

报告：

```text
e2e-verify/reports/ADAPTER-DSH/p4-dsh-live-prompt-2026-08-30T18-15-27-671Z.json
```

结论：

- 模型已被 DSH 正确识别并路由到 `opencode-zen`；
- 上游返回 `429 FreeUsageLimitError: Rate limit exceeded. Please try again later.`
- 不是“模型不存在/不支持”，而是免费额度/限流；
- 原始运行报告按当时脚本逻辑记录为 `failed` / `model_contract_failure`；在用户已授权的 v0.8 DSH 测试口径下，这个可识别的额度响应改按 `passed`（`pass_reason=zen_quota_accepted`）接受。
- 该通过只证明 DSH 的模型选择与 Zen 路由成立，不证明模型回复、历史回放或恢复后 `send`；后续 runner 必须把这三项残余风险写入报告。

## 4. 结论与下一步

- DSH 配置层面已经支持 OpenCode Go 与 Zen 三模型测试池；
- `deepseek-v4-flash` 已完成真实链路验证；
- `mimo-v2.5-free` 已被识别并正确路由；可识别的免费限流按 v0.8 DSH 测试约定接受，但仍不代表已完成回复、Resume 或工作区同步；
- 后续：
  1. 继续 v0.8 的工作区同步、Resume、DSH 模式 UI；
  2. 在 P4 runner 中固化 `opencode-zen` 三模型池、每模型最多额外重试 5 次与 `zen_quota_accepted` 报告字段。
