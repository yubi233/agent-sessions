### 2.3 埋点 schema v1（冻结，门禁 2 基石）

落点 `apps/mobile/lib/diagnostics/streaming_telemetry.dart`（P1 实现）。事件与字段：

- `stream_first_delta`：`{ts, seq, kind, message_id, latency_ms}`（send 受理 → 首条流式文本帧）；
- `stream_delta`：`{ts, seq, kind, message_id, delta_chars, cumulative_chars, since_last_ms, batch_events}`；
- `stream_completed_reconcile`：`{ts, seq, final_chars, last_stream_chars, consistent}`；
- `stream_poll`（采样）：`{ts, attempt, new_events, fetch_ms}`。

sink：内存 ring buffer **2000** 条上限；导出 `{"schema_version":1, "exported_at", "events":[...]}`。**审计红线：任何字段不得含消息正文/工具原文/内部路径**；V087-03 以注入正文子串零命中断言。

## 3. P1：埋点先行（2026-09-05 交付）

**交付物**（V087-02/03/10 全部 passed）：

1. **埋点 sink** `apps/mobile/lib/diagnostics/streaming_telemetry.dart`：4 类事件（`stream_first_delta`/`stream_delta`/`stream_completed_reconcile`/`stream_poll`）、ring buffer 2000、`export()` 输出 schema v1。语义要点：
   - **基线外帧忽略**：`sendAcceptedAt == null` 时（历史加载、非本端受理路径）帧不进埋点、不建帧状态，但 seq 高水位照常推进——防止回合内全量快照重解析把历史帧当新 delta；
   - **高水位去重**：会话级 seq 单调高水位，重复投递/全量重解析零重复埋点；
   - **回合边界**：`observeSendAccepted` 清上一回合帧状态（防跨回合长度串账）；
   - **审计红线**：字段白名单（seq/kind/message_id/长度/时间差），V087-03 以逐型键集精确匹配 + 注入正文子串零命中双重锁定。
2. **controller 三处挂点**（`apps/mobile/lib/state/session_controller.dart`）：send 受理基线（`_submitCommand` 内 `submitSessionCommand` 返回后）；逐帧观察（`_mergeSnapshot` incoming 列表，assistant/thought 白名单）；轮询批次采样（`timedPollFetch` 闭包覆盖初始拉取与前台循环，后台循环以 121 起续号采样）。
3. **daemon 回合流式摘要** `internal/daemon/turn_stream_summary.go`：在 `recordEventResult` 事件泵单点内累计 `message_delta`/`message_thought_delta`（rune 计数），`turn_completed`/`session_aborted` 终态输出至多一条 Info（delta_events/delta_chars/stream_span_ms/terminal）；`fwdCtx` 回收路径静默丢弃半途计数；`turn_started` 回合边界重置；开关 `AGENT_SESSIONS_TURN_STREAM_SUMMARY=0` 关闭。

3. **打字机平滑释放动画**：
   - 新组件 `apps/mobile/lib/ui/session/chat/typewriter_reveal_text.dart`：只释放「已到达文本」的前缀（fail-closed 不超前于数据），16ms tick 按 `落后 ~/ 24 + 1` 自适应追赶；completed（`streaming=false`）立即整段显示（对账收敛）；数据回退按当前数据截断；`typewriterRevealEnabled` 全局回滚开关置关即整段渲染现状形态；
   - assistant 气泡接线（`session_chat_node_seat.dart`）：builder 注入既有 `_DisplaySafeMarkdown`，显示层契约不变；
   - **投影层稳定 key**（`session_projection_controller.dart`）：assistant/reasoning 节点优先用上游 `messageId` 作 key 基座——流式期间节点每批整体替换（sequence 变化），稳定 key 让释放动画的元素状态跨帧存活；tool/command 等 key 消费方维持 sequence（既有测试引用不回归）。

**裁决偏差留档**：P0 裁决曾建议「thought 通道同动画」；实测 thought 在 UI 是折叠摘要面板（`_ReasoningRow`，只展示安全摘要、无逐帧生长文本面），动画不适用——本轮动画只作用于 assistant 回答气泡，偏差如实记录。

**测试**：`flutter test test/v087_typewriter_streaming_test.dart` 6/6 passed——

**实施笔记**：步进时钟 relay（每次快照 +30ms）是时间释放测试的关键模式——到达节奏由「拉取次数 × 步长」决定，与真实时序完全解耦；命令回执路径存在一次额外快照（时钟多推一步），初始批含用户消息属预期。

**回归修复（test_harness_defect）**：收紧档落地后 `session_controller_test` 两条乐观回显用例失败——`_DelayedEchoRelay` 的「流式阶段」此前只过滤 permission/question，fixture 默认回合的 canonical 用户消息照常进入合并窗口；且 `_mergeSnapshot` 的 replace 路径（首次拉取）在清账块之前提前返回，清账只发生在 append 路径（第二次拉取起）。旧 500ms 节奏下第二次拉取落在 300ms 断言窗口之外，掩盖了该耦合；250ms 收紧档后清账提前触发。修复：流式阶段不暴露任何 canonical 事件（阶段到达只由 `echoAfterCalls` 控制，与轮询节奏解耦），断言语义不变、时序耦合消除。
