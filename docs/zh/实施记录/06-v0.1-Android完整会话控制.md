## 目标、范围与验证口径

本迭代交付 Android 唯一写控制端的完整 fixture/local 链路，并补齐其依赖的 Relay 契约：配对和密文缓存、会话控制、能力面板、附件、Git DiffView、跨工具子代理、生命周期恢复和通知降级。

- 不做 Git 写操作、远程 shell、语音、社交、付费、Happy wire protocol、Relay Provider 调度或服务器端正文搜索。
- 本地回归默认使用隔离 SQLite 与 deterministic fixture，报告标记 `local_test=true`、`fixture_data=true`。
- 浏览器验收使用 headed Chrome，`real_browser=true`、`headless=false`；Android AVD/真机验收不冒充浏览器结果。
- 本轮 Flutter 验收使用 MacBook 本地的可见 macOS 桌面窗口：报告必须为 `real_browser=false`、`visible_desktop_app=true`、`headless=false`、`host_platform=macos`。浏览器验收仍由 `task test:e2e` 启动 headed Chrome。Android AVD、Android Keystore/Drift 原生集成与外接真机测试明确留到后续原生硬化阶段，不作为本轮 gate。
- Claude、Codex、OpenCode、OpenClaw 的真实 Provider/模型 smoke 需要专属凭据和授权；当前没有可用凭据时必须为 `blocked`，不以 UI 或 mock 代替。

## 证据记录规则

每一个 smoke、diagnostic、full gate 或 recording 都写入 `e2e-verify/reports/<timestamp>/<plan_id>/`，并包含验证口径、命令、测试 ID、fixture revision、失败分类和残余风险。录屏只在对应 full gate 通过后执行；不得记录 token、密钥、会话正文、diff 正文或解密附件。
