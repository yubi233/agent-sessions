## 1. 交付范围与关键事实

### 1.1 A 组：回合收敛（V086-11/12/13）

用户实测事故（foshan-loupan-tracker 会话 `sess_1788547318981_d1f3f9e4cdea4fc5`，debug 留档于主计划 §1.7）：发送后事件流在 seq 224（turn_phase）后完全终止，8 小时无终态、无错误、状态行恒"空闲"、同文本消息渲染两条气泡。

根因与修复：

1. **执行端静默失联无兜底**：新增 daemon 回合看门狗（`internal/daemon/turn_watchdog.go`）——send/SendContent 受理后布防，沉默窗口（`AGENT_SESSIONS_TURN_WATCHDOG_MS`，默认 120s，0=关闭）内无任何 handle 事件即补发脱敏 `session_error` + `turn_completed(stop_reason=watchdog_timeout)`；每个事件续命（慢回合/桥侧重试不误报）、终态/abort/removeHandle 撤防。契约测试 4 项（`turn_watchdog_test.go`）。
2. **上游瞬时失败无自愈**（2026-09-05 用户裁决：重试责任在 dsh 桥）：deepseek-harness 新增 `turn-retry.ts` 纯策略 + `session/prompt` 入口 `runPromptSessionWithRetry` 有界自动重试（瞬时集合 {408,429,500,502,503,504}；`DSH_TURN_RETRY_MAX`/`DSH_TURN_RETRY_BACKOFF_MS` 可配，默认 2 次/2s 指数退避）；每次重试先发可见 assistant 文本通知（"上游失败，第 N 次重试"，同时为看门狗续命）。vitest 10 项。
3. **客户端轮询无人续驱**：`session_controller.dart` 轮询窗口参数化（`foregroundPollAttempts`/`backgroundPollAttempts`/`pollInterval`，生产默认 120×500ms×2）；前台耗尽必转后台；后台耗尽显式超时收敛（`_turnInFlight=false` + 清账 + `isTurnTimedOut` 标记）；`session_chat_view.dart` 超时横幅（key `session-turn-timeout-row`）替代无限"处理中"。
4. **消息双气泡**：canonical 轨迹只有一条 user_message（Relay 幂等去重吞掉第二次重发的事件），第二次重置的乐观回显永远等不到清账。修复 = 重发防抖（`_turnInFlight` 时同文本拦截，提示"相同消息仍在处理中"）+ 超时收敛时兜底清账；`_mergeSnapshot` 既有同文本清账保持。
5. **状态行矛盾**：header 状态条（`_SessionStatusStrip`）消费 `turnInFlight`，回合在途显示"执行中"（idle+在途窗口期不再显示"空闲"）；merge 收到终态事实时按事件校正清除本地超时标记。

关联事实：V085-25（commit 14e57b3）已确认并修复"事件类型白名单缺口 → 流式回合事件 400 死信"——这是 A① 事故的另一半真实成因（事件已产出但上行被永久拒绝）。看门狗 + 死信救回入口（`daemon run --requeue-failed-events`）+ 白名单补齐三层合围。

### 1.2 B 组：权限目录全会话可达（V086-01/03/04/05）

1. **mode 目录变化即时回传**（§3.1）：dsh handle 在 `current_mode_update` 改变选中项时推内部 `modes_changed` 标记（同值去重），事件泵置顶消费后调 `syncModeInfo` 重上行 Relay；标记不进时间线/事件出口（`fakescenarios_test.go` 既有断言更新为新契约）。历史会话目录为空的根治仍是"start/resume 一次"（目录事实在桥，无 live handle 不伪造）。
2. **start/resume 回执后立即刷新 controls**：目录秒级到达，不等回合结束或重进页面。
3. **禁用原因可见**：`permissionDirectoryHint`（capability 支持但目录未同步 → "权限目录未同步——启动会话后自动获取"）接入权限下拉 helperText；无解释空壳消失。
4. **停止会话预检**：mode.set 对 stopped 会话直接提示"会话未运行，启动后可切换权限模式"，不再把 `local_state_missing` 当第一现场。
5. **会话信息页**：新增"权限模式能力"行（availability label + reason + 目录快照），非 dsh provider 的"不支持"如实可见。

### 1.3 C 组：主页终端卡片化（V086-14）

主页改为终端卡片流（`_TerminalGroup`/`_TerminalWorkspaceCard`）：每卡一台终端（hostname/平台/在线态）+ 卡内"同步"按钮直调 `syncDSHWorkspaces(terminalId:)`——全局同步按钮与选择抽屉（`_DSHWorkspaceSyncSheet`）移除。工作区按 `MobileWorkspace.terminalId` 分组；离线/无能力/未归属卡灰态带原因（fail-closed，不渲染可点却必败的按钮）；串行单槽（同步在途时其余卡禁用提示"同步进行中"）；零工作区但有可同步终端时出空卡保证首次使用的同步入口；首页打开即刷新终端状态（postFrame，收口遗留 2026-09-02 #3 的主页部分）。

### 1.4 D/E 组：消息渲染（V086-15/16）

- **Markdown（G10）**：引入 `markdown ^7.2.2`（Dart 官方解析器，GFM 扩展集）+ 新公共渲染器 `SessionMarkdownText`（`session_markdown_text.dart`）：多级标题/GFM 表格/有序无序嵌套列表/引用/行内粗斜体代码删除线链接/围栏代码块；display-safe fail-closed——原始 HTML（UnparsedContent/危险标签/整段 `<...>` 启发式）丢弃、图片只显 alt 不加载、链接纯文本不导航；流式 partial 天然降级（未闭合语法按普通文本）。`_DisplaySafeMarkdown` 改为薄包装。
- **复制全覆盖（G11）**：`_canCopy` 从"按节点类型 + completedTurn"改为"有可复制文本即出"——流式中/未终态 assistant（A① 事故中已产出文本不可复制是核心痛点）、tool、reasoning、notice、error 全覆盖；64K 字符截断口径（`…（内容过长，已截断）`）。pendingSteering 乐观回显仍仅 user 可复制。
