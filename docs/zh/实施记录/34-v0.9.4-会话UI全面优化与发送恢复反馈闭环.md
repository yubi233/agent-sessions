## 2. 阶段 P1：发送、配置与同步状态闭环（2026-09-19 收口）

### 2.1 消息发送事务（计划 §2.2/§2.4，UI-05/06/07，V094-19/23）

- 新增 `apps/mobile/lib/state/session_send_transaction.dart`：`SessionSendTransaction`
  （submissionId / clientMessageId / draftRevision / 阶段 / 错误分类 / 重试计数 / 取消标记）
  与结构化恢复阶段 `SessionRecoveryStep`（resume→start→resend，上限 1/1）。
- `SessionController.sendMessage` 拆分提交与观察：
  - 提交锁（全局 busy）只覆盖「验证 + 202 受理 + 首批快照」；30s 回执窗口与
    回合轮询转入后台事务观察器 `_observeSendTransaction`（`awaitTurnCompletion=true`
    的直调方保持内联观察，V093 语义不变）；
  - `_submitCommand` 新增 `deferSendObservation` / `onCommandAccepted` / `onTerminal`；
  - 失败回执优先于代际处理（V093-04b 不回退）；LOCAL_STATE_MISSING 触发
    结构化恢复链并换 `#recovered` 幂等键重发（clientMessageId 复用）；
  - 窗口耗尽：有可信进展（流式投影）→ processing；否则 verifying（结果待确认），
    绝不假报成败；
  - 失败事务保留在消息待处理项（正文在内），提供 `retryFailedSend`（新 attempt
    独立幂等键、先核验后补发）与 `consumeFailedSendForEdit`（新草稿非空时拒绝覆盖）；
  - 草稿结算按事务身份：仅当草稿仍是本次提交正文时才清空，观察期新草稿不受
    迟到结算影响；取消（`cancelAutoRecovery`）只阻止尚未提交的自动步骤。
