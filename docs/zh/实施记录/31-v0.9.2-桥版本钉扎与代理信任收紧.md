# 实施记录 31：安全加固——DSH 桥版本钉扎与 Relay 代理信任收紧

> 状态：`delivered`（2026-09-15；独立安全修复，不挂迭代计划）
> 背景：QVD-2026-57410（DeepSeek Harness Web 服务 `/api` 未授权 RCE，CVSS 9.8，Host 头伪造）安全复盘
> 关联：[ADR-013 §2](../../adr/ADR-013-DeepSeek-Harness-Provider接入.md)（本修复兑现其版本门承诺）；ADR-014/015 不受影响
> 测试套件：`docs/test/16-Adapter-Dsh.json`（新增 ADPT-DSH-14）

## 1. 暴露面结论（复盘事实）

本项目对 DSH 的唯一集成面是 ACP JSON-RPC over **stdio**（`internal/adapter/dsh/bridge.go`，per-session `dsh-acp-demo` 子进程，`exec.Command(node, bin, "-c", config)`）。逐项核验后确认 QVD-2026-57410 的漏洞面在本项目栈中**从未实例化**：

- 桥进程无任何 HTTP 监听（acp-demo 源码仅 stdio JSON-RPC）；
- 运行配置不挂 `dsh-host-webserver` 插件（仓库根 `cordis.yml` 与 DSH checkout `examples/acp-agent/cordis.yml` 均核验）；
- 云端部署仅 Relay + Caddy（`deploy/ecs/`，8787 只绑宿主机回环，公网入口唯一为 443 自签 TLS + 指纹放行）；
- 仓库根 `.dsh-vision-router/` 为 DSH vision-router 示例插件的 workspace 截图 artifact（无状态文件写入，非网络服务），已加入 `.gitignore`。

结论：**ACP 路径不受该漏洞影响**。复盘同时暴露两处工程缺口，按本轮修复：

1. ADR-013 §2 承诺的桥版本门未落地——实现只校验 `protocolVersion==1`，`agentInfo.name/version` 仅记录不校验，换桥/升级/指错 bin 均被静默接受。
2. Relay 的 ClientIP 信任面沿用 Gin 默认（信任所有代理），直连可达场景下 X-Forwarded-For 可伪造审计 IP。

## 2. DSH 桥版本门（ADR-013 §2 兑现）

- **新增 `internal/adapter/dsh/version_gate.go`**：`verifiedBridgeName="deepseek-harness-acp"`、默认白名单 `0.0.1`（与桥实现 `deepseek-harness packages/acp/acp/src/index.ts` 的静态 agentInfo、全部假桥 fixture、P0 冒烟报告一致）；`AGENT_SESSIONS_DSH_ALLOWED_VERSIONS` 逗号分隔覆盖（未设置→默认；显式置空→报错 fail-loud；空白项过滤），语义对齐 `binConfig`/`configuredPersistenceCompression` 既有风格。
- **接入四点**（均在既有 `protocolVersion` 判定之后）：`Detect`（fail-closed 矩阵、中文原因含实际版本、Version 留空，registry 自然 available=false）；`storeHandshakeLocked`（不覆盖 last-good 快照）；`Start`/`resumeStreaming`（拒绝建立/恢复会话并回收子进程，无 session/new 出站帧）。
- **测试**：`internal/adapter/dsh/version_gate_test.go`（版本越界/桥名不匹配/last-good 保持/Start 拒绝/Resume 拒绝/env 放行 0.2.0/白名单解析语义）；登记为 ADPT-DSH-14。
- **已知限制（如实登记）**：`agentInfo.version` 是桥侧静态值（不随 DSH checkout 包版本变化），本门保证"未登记的桥名/版本必须显式复验登记后才能接入"，**不提供 checkout 内容级校验**；如需 bin/checkout 内容哈希钉扎，须另立 ADR 修订。

## 3. Relay 代理信任收紧

- **`internal/relay/server.go`**（全仓唯一 gin 引擎装配点）：`gin.New()` 后显式 `SetTrustedProxies`。默认网段 = loopback + 私网 + 链路本地（`127.0.0.0/8`、`::1/128`、`10/8`、`172.16/12`、`192.168/16`、`fc00::/7`、`fe80::/10`、`169.254/16`），同时覆盖本地开发（127.0.0.1 直连）与云端拓扑（Caddy 容器经 compose 私网反代）。`AGENT_SESSIONS_TRUSTED_PROXIES` 可覆盖：`none`=全不信任；CIDR/裸 IP 逗号列表；非法条目 warn 后回落默认（保守方向，不阻断起服）。
- **效果**：公网直连 peer 不受信任，其 XFF 一律忽略（ClientIP=套接字对端，伪造关闭）；经 Caddy 的请求解析其追加后的真实客户端 IP（Caddy 恒追加真实套接字 IP 到 XFF 最右，远程伪造不可能）。
- **`internal/httpapi/handlers.go` `reqIP`**：改为直接透传 `c.ClientIP()`——ClientIP 天然不含端口，原 `strings.Split(ip, ":")[0]` 会把 IPv6（如 `::1`）截成空串；该函数当前无调用点，保持"仅审计"契约。
- **测试**：`internal/relay/trusted_proxies_test.go`（公网 peer XFF 忽略/私网代理链取最右非信任/`none` 全忽略/自定义 CIDR 生效/非法条目回落/解析语义/healthz smoke，经 `/__probe_ip` 探针路由断言引擎级 ClientIP 行为）；`internal/httpapi/req_ip_test.go`（IPv6 完整保留、IPv4 透传）。
- **文档**：`deploy/ecs/docker-compose.yml` relay `environment` 增加注释（默认已覆盖 Caddy；需收敛或禁用时放开注释行）。 acceptance.env.example 不收录该变量（其模式为 ACC_* 验收入口，Relay 运行时 env 的事实源是 compose）。
