## 冻结的 wire 事实（桥侧 dsh-acp，已核对源码与设计笔记）

- `session/set_config_option`，参数 `{sessionId, configId: "model", value}`；`value` 为普通模型 id（桥保留该模型已记住/默认档位）或 `model@effort` 变体。
- 模型解析：`modelProviders[model] ?? config.provider` 路由 provider，且该 model 必须出现在路由 provider 的 `listModels` 目录；否则 invalidParams 拒绝。
- 会话目录 = 默认 provider + `modelProviders` 全部路由 provider 的目录合并；`session/new`/`load`/`resume` 响应携带 `configOptions`（本实现不消费，目录由 Go 能力矩阵承载）。
- preset 围栏：仅当配置 `minimalModel` 时存在「preset 在首个 turn 后固定」拒绝；移除 `minimalModel` 后所有模型同属默认组合，会话中途切换不再触发围栏。

## Daemon/客户端既有链路（零改动验证）

- 终端能力门：`daemonCapabilities` 已声明 `model_select`（`apps/daemon/main.go`），`session.model_select` 命令可路由到本机。
- `SessionRunner.selectModel` 持久化 `model:<sessionID>`；`sendMessage` 按「send 密文随行 > 持久化选择 > handle 现值」顺序调用 `SetModel` 后再 `Send`。
- `GET /v1/sessions/:id/controls` 从能力矩阵 `model_select.Options` 提取 `models`/`default_model`；移动端 composer 的模型 sheet、lease+幂等命令与 send 随行模型均为既有实现（opencode 同链路）。能力矩阵放开后 DSH 自动获得相同入口。
- usage 事件经 `bindUsageContext` 从 send 随行模型回填 `ctx.Model`，会话发送后「等待模型事件」处将显示当前模型。
