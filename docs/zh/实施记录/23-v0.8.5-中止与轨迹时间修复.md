## 1. 本次接管范围

用户反馈是：发送“你好”后点击中止没有及时生效，中止没有进入轨迹，每条轨迹没有发送时间，中止后客户端过早刷新可能漏掉 Relay 新事件。本次内容追加到既有 v0.8.5，不创建新版本计划。

冻结口径如下：

- `session.send` 必须异步执行，RelayLoop 在 Provider 长时间发送期间仍能接收 `session.abort`。
- Provider `Abort` 成功后只生成一条 canonical `session.aborted`；失败只写脱敏错误，不伪造成功。Provider 后续 `cancelled` 终态只负责状态收口。
- 时间是 canonical event 生成时间，字段为 `created_at_unix_ms`，按设备本地时区显示 `HH:mm:ss`；历史或不可解密事件无可靠时间时显示“时间未知”。
- 轨迹统一保留普通事件、`turn_phase`、系统通知和加密占位事件的时间。
- `stopStreaming()` 先等待明确的 Abort 命令终态，再以有界增量快照轮询确认 `session.aborted` 或 `stopped`；超时保留后台恢复，不把失败显示成成功。
- 本轮 Flutter 只使用本地 macOS/桌面环境，不执行 Android 实机或 AVD；真实模型和付费上游不在未经授权的本地回归中调用。

## 6. 风险、回滚与残余项

- 异步发送的 durable `started` 行必须和进程内 in-flight 登记配合；重启后不能再次调用 Provider，按 `DAEMON_RESTART_RECOVERY` fail-closed。回滚时可关闭 async send，恢复串行执行，但必须保留 Abort 专用路径。
- `session.aborted` 只有 Provider Abort 成功才允许写入；任何网络/Provider 错误都只能显示脱敏错误。不能用客户端点击时间或 Relay 接收时间填充事件时间。
- 旧数据库的 `created_at_unix_ms=0` 是合法历史状态；迁移不得回填当前时间。旧客户端忽略 additive 字段，客户端遇到缺失时间显示“时间未知”。
- 当前仍需审查 `session.aborted` 在 Relay 终态投影中的 stopped 状态、handle 生命周期锁和异步任务在重连时的命令回执收口。
- 本记录不把 fixture、headless、macOS Flutter 窗口或局部 Go 测试写成 Android 实机、真实模型或完整发布 gate 证据。
