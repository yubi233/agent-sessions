| 故障链 | P0 诊断证据（`internal/daemon/v089_p0_diagnostic_test.go`） |
| --- | --- |
| ① Relay DB 世代与 Daemon durable state 脱钩 | 650ms 窗口 resolve 404 重试 3 轮、stream_hits=0、命令停留 started 无终态 |
| ② SSE reader 被同步业务执行阻塞 | send 等审批持有 executionMu → mode.set 阻塞 scanner → approve 1200ms bounded 窗口不可达；gate 释放后依序消费（队头阻塞而非丢命令） |

## 2. P1 Relay generation 与 Daemon state 隔离（commit 5b26307）

- **Relay 侧**：`relay_instance_meta` 表 + `ensureRelayGeneration`（crypto/rand 24B，`relgen_` 前缀 48hex，INSERT OR IGNORE 幂等）；`Repository.RelayGeneration`；V089-01 四测（同库重开稳定/删除重建必变/备份随文件走/独立建库互异）。
- **协议**：`DaemonHelloResponse`/`DaemonHeartbeatResponse` additive `relay_generation`（openapi.yaml + 三语言生成物零漂移）；domain/HTTP view/Daemon `RelayHello`/`RelayHeartbeat` 同步。
- **Daemon 侧**：`adoptRelayGeneration`（hello 权威；首次接触只记录不隔离——升级期 `generation=''` 行属于当前 Relay；变化→`IsolateStaleRelayState` 单事务收口；legacy 告警一次不强制）；`detectRuntimeGenerationChange`（heartbeat 发现→收口→`ErrRelayGenerationChanged` 终态退出，RunWithRetry 不退避）；`GenerationEnforcementDisabled` 回滚开关（`AGENT_SESSIONS_RELAY_GENERATION_ENFORCEMENT=0`）。
- **本地存储**：三表 `relay_generation` 关联列（additive）；写路径事务内打标；`IsolateStaleRelayState` 单事务完成「命令收口/outbox quarantine/cursor 清零/Terminal 绑定清除/reason 落档」，`command_outbox`（用户动作）不误删。

## 3. P2 Reset 编排与 stale 404 止血（commit 295b54b）

- **restart.sh 生命周期锁**：`reset_default_local_relay_db` 严格顺序「stop daemon → stop_orphan_daemons（fail-closed）→ stop relay → rm → start relay」；`restart-flutter` 置 `RELAY_DB_RESET_ALLOWED=false`，需要 reset 时返回可操作错误（提示执行完整 `./restart.sh restart`），不触碰 Flutter 进程与 DB。`AGENT_SESSIONS_RESTART_LIB_ONLY=1` 支持 tools/restart_test.sh 函数级行为回归。
- **stale 404 收口**：`staleGeneration404` 世代证据矩阵（enforcement 关闭→传播；legacy 无世代→收口 `legacy_no_generation`；行世代≠当前→收口 `generation_mismatch`；世代一致→传播不吞 API 漂移），覆盖 resolveAndPersist/Ack started/ackReceived（重复投递）/replayRejected/三个专用 result 共 6 位点；`closeStaleGenerationCommand` 本地终态 + 脱敏日志。
- **retry 分类**：401/403/409/426 + 签名错误码即时退出（保持）；`ErrRelayGenerationChanged` 终态退出；enforcement 关闭时 404 不清理（P3 后由 sweeper 心跳节拍重驱动，SSE 不再被阻塞）。

## 4. P3 SSE reader 与命令执行解耦（commit 8b0911b）

- `handleDelivery` 瘦身：只落盘（RecordRelayCommand，cursor 同事务推进）+ received ack + 入队；不执行 Provider/Resolve/事件上传。
- `processPending` 拆分：`dispatchPendingCommands`（扫描/入队，processMu 只保护扫描与去重标记）+ `processOneCommand`（逐命令 received→starting→started→终态状态机，worker 调用，网络与 Provider 执行在 processMu 外）。
- `relay_scheduler.go`：普通/控制双 worker 独立队列（控制优先队列：approve/reject/abort/question.answer + rejecting 重放）；**每队列独立唤醒通道**（实施中发现并修复共享令牌丢失唤醒竞态——控制 worker 抢走令牌后普通命令滞留队列）；session.send 仍 `executeSendAsync` 绑定 commandCtx；worker 生命周期绑定 RunWithRetry（defer cancel）。
- 修复 dispatch 路径缺陷：内存副本 Status 空串会绕过状态机直接执行——落定为 `received`。
- 未启动调度器的测试路径保留 `drainQueuesInline` 同步语义（既有测试零改动）。
- `RelaySchedulerStats` 脱敏指标（队列深度/处理计数/last_control_wait_ms/reader_last_read_unix_ms）+ heartbeat tick Debug 输出 + sweeper 重驱动。

## 5. P4 Outbox 世代隔离与可靠性回归（commit d879248）

- `relayGenerationFilterSQL` 查询层防线：PendingRelayEvents/PendingRelayUsages/RequeueFailedRelayEvents/RequeueTransientFailedRelayEvents 只返回当前世代（或升级期空世代）行——与 P1 事务隔离形成双防线；人工恢复入口默认不恢复旧世代。
- `RelayOutboxGenerationProjection` 只读投影（generation×状态×行数，UNION 三表，不含 envelope/正文/路径/密钥）。
- `TestV089OutboxRetryClassificationMatrix`：400→毒丸 failed、429→pending+退避、5xx→pending+记账、网络断开→RELAY_NETWORK、超时→RELAY_TIMEOUT；瞬态有界退避（30s→15min、上限 8 次）保持。

## 8. 残余风险与移交

- 同世代 404（Relay 同代内丢命令的异常）保持原错误传播 + 有界退避——按 §3.3 属"不吞真实 API 漂移"的有意设计，不自动清理。
- legacy Relay（不报告 generation）下 enforcement 开启时 404 一次收口——依赖"命令不存在则 resolve 永不可成功"的协议事实，若未来 Relay 出现可恢复的暂时性 404 语义需重新评估。
- 审批等待中 daemon 重启 → 桥实例丢失 → pending 审批 fail-closed cancelled（模型收到 rejected）为 at-least-once 既有语义，不在本期范围。
