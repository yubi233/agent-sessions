## 1. 阶段 P0：全局会话可续聊（commit `feat(dsh): P0 全局会话可续聊`）

### 1.1 根因链（比计划预期更深，逐层实测定位）

| 层 | 缺陷 | 证据 |
| --- | --- | --- |
| daemon 映射 | `providerThread` 只存 provider/instance/workspace，resume 无法定位 artifact 真实存储 | runner.go / dsh_workspace.go 代码核查 |
| 桥存储绑定 | resume 一律绑定 `<workspace>/.dsh-sessions` + 环境变量缺省编码；全局存储（zstd）来源会话根错/编码错 | 上游 `checkRootEncoding`「root already belongs to the other physical encoding」 |
| 桥配置 | `cordis.yml` 的 `persistenceCompression` 只看 `DSH_SNAPSHOT` 有无（record→none），显式 `DSH_SNAPSHOT_COMPRESSION=zstd` 被无视 | 真桥 stderr：`uses .jsonl.zstd, but this backend is configured for compression "none"` |
| 桥组合 | demo 组合未挂载 `agent-presets` 服务；实测 508 个真实 artifact 的 header **全部**携带 `agentPreset`（standard/minimal/code）→ session/load 一律 fail-closed | 只读扫描 `~/.dsh/sessions`（508 文件，header_with_preset=508） |

### 1.2 修齐

- daemon：`providerThread` 增加 `persistence_root`/`compression`（additive JSON）；导入记录 artifact 来源根与编码；旧映射首次 resume 按 id 两源定位并回写（一次性自升级）。
- adapter：`ResumeRequest.PersistenceRoot/Compression`（内部提示）；`newBinTransportForSource` 显式根路径（校验根、按编码注入 `DSH_SNAPSHOT_COMPRESSION`，跳过迁移，绝不创建/清理用户存储）；`minimalEnvWithCompression` 每调用编码覆盖。
- 桥侧（deepseek-harness 检出，**未随本仓库提交**，见 §5）：`persistenceCompression` 尊重显式覆盖；挂载 `agent-presets` 服务（roots 指向检出内 shipped presets）；examples 工作区补 presets 及其插件依赖（persona 等 3 包）。
- 客户端：导入确认弹窗文案与实际行为对齐（真实标题+最近十几条上下文，替代过时的「仅元数据」表述）。

## 2. 阶段 P1：持续同步 + 预览/回放合一（commit `feat(dsh,app): P1 持续同步`）

- `ReadSessionEventsAfter(path, afterSeq, limit)`：增量只取 watermark 之后的 user/assistant 正文；limit 截断保留最早新消息、水位停在最后一条已导入消息（不产生空洞）；标题仅在 watermark 之后出现新 `session/title` 行时返回最新值（DSH 侧重写标题可感知）。

- 标题更新：`ResolveDSHImport` 对已存在会话在标题非空且变化时更新 `display_name`（store 新增 `SetSessionDisplayName`）。

### 4.2 真实模型旅程：通过（2026-09-25，恰耗授权 2 次调用）

第一轮尝试（credentials-local 挂载后）仍被拦：demo 桥唯一路由 deepseek-official 缺 `DEEPSEEK_API_KEY`（env 与 `~/.dsh/.credentials.yaml` 均无）。二轮修齐：

1. **路由面缺失**：用户真实路由来自 `~/.dsh/settings.yaml` 的 `llm-pi-ai:` 段，基座组合模式是「`llm-pi-ai` 休眠挂载 + settings-file 发布 provider 档案」。demo 组合补 `settings-file` 与 `llm-pi-ai` 两行后目录仍退化——**settings 热发布有 debounce**（~100ms+文档读取），桥 spawn 后立即握手抢在路由注册之前；握手前等待 1.5s 后目录完整（21 个模型，覆盖用户全部真实路由）。
2. **真实调用**：桥①新建会话记住暗号「芝麻开门」→ 回复「好的」；桥②按导入映射路径（来源根+编码）回放同一 artifact、沿用冻结路由续问暗号 → 正确答出。`LIVE_SUMMARY provider=dsh protocol=1 source_bound=global,zstd real_model=2 context_inherited=1`。「导入的全局会话可在原上下文继续」在真桥+真实模型+真实数据副本上闭环。
3. **上游边界（如实登记）**：opencode-zen 全部 `*-free` 模型对非 OpenCode 客户端 403（`FreeTierError`）；`deepseek-v4-flash-free` 400 unavailable（均不产生 token 消耗）；回放后的会话 preset/路由首回合后冻结（`set_config_option` 切模型被上游拒绝）；含图片附件会话的回放需桥组合挂载 attachment store（demo 组合未挂载，"cannot deliver assistant image"）。
