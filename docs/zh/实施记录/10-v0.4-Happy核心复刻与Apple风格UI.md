## 范围与口径

v0.4 对齐 Happy Coder 的远程 Agent 核心用户旅程，并升级 Flutter、Web 和 Admin 的视觉与交互。它是行为复刻，不复制 Happy/Apple 的品牌、源码或资产；Provider 能力按 `native`、`emulated`、`unsupported` 独立声明。

本记录只把已实现、已运行并将随阶段独立提交的代码与证据写为完成。P0 是文档、架构决策和可执行测试基线；P1 只完成既有页面的设计系统与可访问性基础；P2 只完成受限本地 Relay-Daemon fixture 切片，不代表真实 E2EE、真实 Provider、AVD/真机或后续产品面已经完成。

## P0 事实结论

| 主题 | 已核实事实 | 后续动作 |
| --- | --- | --- |
| Relay 传输 | `internal/httpapi/handlers.go` 注册 REST 与 `/v1/events` SSE，没有 WebSocket handler。 | P2 按 ADR-009 新增 Daemon 专用流与 REST 回执。 |
| OpenAPI | `packages/protocol/schema/openapi.yaml` 没有 Daemon RPC、远程 Git RPC、`/v1/version` 或 WebSocket。 | 先扩 schema/generator，再接 handler 和客户端。 |
| Daemon | `run` 是 mock 心跳；`runner` 只消费本地 SQLite outbox。 | 不把本地成功写成 Relay-Daemon 成功。 |
| 存储 | Relay 权威库是 SQLite；presence/限流是可重建进程内状态。 | 所有迁移、备份和恢复按 SQLite 设计。 |
| Web/Admin | Web 只有 `/` 与 `/capabilities`；Admin 是单页只读。 | P4 后才可称为完整只读客户端。 |
| 可见验收 | Flutter macOS fixture、AVD、物理 Android、headed Chrome 和真实 Provider 是不同证据层。 | 每项在报告中保留真实口径，不相互替代。 |

## P2 事实结论

| 主题 | 已实现事实 | 尚未完成的边界 |
| --- | --- | --- |
| Daemon 传输 | `POST /v1/daemon/hello`、heartbeat、专用 `/v1/daemon/commands/stream`、ack/result 和 event upload 已注册；只有 active Terminal bearer 可访问。 | 没有 WebSocket；没有 Android/浏览器直接订阅 Terminal command stream。 |
| 授权与投递 | Relay 从 Session 重新推导 Workspace 与目标 Terminal；SSE 不传 `canonical_root`；started/result 重新校验 lease/instance。 | 多 Terminal 和完整并发 owner/instance 压力矩阵未完成。 |
| Daemon 恢复 | 本机 SQLite 持久化 relay command、cursor 和 event outbox；重复 delivery 去重；已 started 命令重启后报告 `DAEMON_RESTART_RECOVERY`。 | 真实 Provider 子进程生命周期与清理未验证。 |
| 只读 Workspace | `workspace-confirm` 绑定 opaque ID 与本机 Git 根；dispatcher 支持 file/code/Git 的 6 个只读 kind。 | 生产 E2EE encoder 缺失；端到端仅验证 `file.read`，没有 Android/Web 可见消费者。 |
| 加密与报告 | fixture encoder 仅上传结构哈希，Relay/account SSE 不含本机文件正文、相对路径或绝对根。 | fixture envelope 不是生产密钥流程；不得把此证据称为真实 E2EE。 |
