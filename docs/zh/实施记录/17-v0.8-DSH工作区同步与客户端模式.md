## 2. P2：DSH 工作区同步与会话按需导入

### 已完成

- 新增 Daemon 本地 `DSH Workspace Scanner`：只扫描授权根内“有 `.dsh-sessions` 有效证据 + Git 根”的项目；不创建目录、不初始化 Git、不跟随符号链接；深度上限 4、候选上限 1000，达到上限有可见失败状态。
- 新增 `ConfirmExistingDSHWorkspace`：对已存在项目做幂等本机确认，不修改文件。
- 新增 `workspace.sync_dsh` 命令链路：
  - owner/write + 在线 Terminal + `dsh_workspace_sync` capability 才能发起；
  - Daemon 扫描后通过专用 `/dsh-workspace-result` 回传 canonical roots；
  - Relay 按 `account + terminal + canonical root` 生成稳定 Workspace/Project ID 并登记；
  - 响应只返回 opaque workspace IDs，不泄露路径。
- 新增 `session.import_dsh` 命令链路：
  - 仅 home Terminal 可对已确认 Workspace 发起；
  - Daemon 通过专用 `/dsh-import-result` 回传 opaque Relay session IDs；
  - Relay 在同一事务内创建 `provider=dsh` 的 Session，并补充活动时间避免立即被休眠归档。
- 新增测试：
  - `internal/daemon/dsh_workspace_scanner_test.go`
  - `internal/relay/dsh_workspace_contract_test.go`
  - `internal/daemon/dsh_import_test.go`（补充构造符合 DSH 布局的 `session.jsonl`，验证 `ImportDSHSessions` 生成 relay session 映射和 `replay_state=pending`）
- Scanner 的 DSH 证据识别修正为：`session-query.db` 仍为标记，但 `session.jsonl` 必须符合 DSH 两级目录布局且可解析首行 header，避免把任意同名文件误认为有效工作区。
