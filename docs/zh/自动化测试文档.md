# 自动化测试文档

## 1. 范围与权威来源

本文是 Agent Sessions 的可运行测试地图。功能和当前实现状态以[项目文档](项目文档.md)为准；v0.1 Android 完整会话控制以[v0.1 迭代计划](迭代计划/迭代计划v0.1.md)和[v0.1 实施记录](实施记录/06-v0.1-Android完整会话控制.md)为准；v0.2 会话能力对齐以[v0.2 迭代计划](迭代计划/迭代计划v0.2.md)和[v0.2 实施记录](实施记录/08-v0.2-Android会话能力对齐Happy.md)为准。稳定测试 ID 的唯一归属由[测试套件索引](../test/测试套件索引.json)管理；结构化验收用例只放在`docs/test/`。

仓库已具备 Go、TypeScript 和 Flutter 的本地测试入口，Relay 使用隔离 SQLite，Web/Admin 的 Playwright 回归默认启动可见 Chrome；Web 录屏使用 CDP screencast，Flutter 录屏使用可见 macOS 窗口的 5fps fixture 帧。P0-P6 本地完成情况见实施记录；不能把 fixture 结果延伸为 Android 原生、真实 Provider 或真实上游通过结论。

## 2. 验证口径与授权

每个 smoke、targeted diagnostic、full gate 和 recording 报告必须记录下列字段：`local_test`、`fixture_data`、`real_browser`、`headless`、`real_upstream`、`real_model`、命令、测试 ID、fixture revision、失败分类、证据路径和残余风险。

- `real_browser=true` 仅表示可见 Chrome 执行用户可见流程；它不代表 Android 或真实 Provider。
- v0.1 当前 Flutter full gate 固定在 MacBook 本地的可见 Flutter macOS 桌面窗口：报告必须标记 `real_browser=false`、`visible_desktop_app=true`、`headless=false`、`host_platform=macos`。浏览器验收仍由 `task test:e2e` 启动 headed Chrome。Android AVD、Android Keystore/Drift 原生集成与外接真机留待后续原生硬化阶段，不能把 macOS 结果表述为 Android 原生或实机验收。
- `fixture_data=true`、`local_test=true` 的 mock/隔离 SQLite 不能描述为真实上游通过。
- `headless=true` 只用于 CI 或快速回归，不能替代本地 headed 验收。
- 真实 Provider/模型 gate 必须先说明提供方、预计请求次数、凭据来源类别、额度风险与停止点。无专属凭据或授权时记录 `credential_or_quota_blocker` 和 `blocked`。
- 截图、DOM、trace、视频和报告是证据，不是替代断言的测试。

## 5. 回归与录屏顺序

1. 先更新`docs/test/`中的稳定用例和测试索引，再新增根因层测试。
2. 运行聚焦单元、widget、Relay/Daemon/contract 测试并解决第一个因果失败。
3. 运行对应 Flutter macOS integration 和 headed Chrome 场景；Android 原生 integration 留待后续阶段。失败必须归类为 product、harness、selector/DOM、provider、凭据或环境问题之一。
4. 只有 P0/P1 full gate 都通过后，才执行录屏。录屏的 manifest 必须列出事先定义的用例、命令、浏览器/设备、验证口径、脱敏约束和 artifact。
5. 完成后在项目文档、实施记录和本矩阵回填结果；对照需求到测试到证据，不能以截图或 headless 单独标绿。

`task test:flutter:local` 先运行 Node 编排回归和`flutter build macos --debug --no-pub`，再运行长期 Flutter unit/widget 断言。断言通过后，runner 直接启动固定 debug 可执行文件，在每个登记场景稳定后使用 CoreGraphics 定位本轮窗口，并以 `screencapture -x -l <window-id>`按 5fps 连续 1 秒保存 PNG。若系统拒绝 Screen Recording，debug App 只写自身沙盒临时目录的`RepaintBoundary`帧；runner 必须校验每一张 PNG 的尺寸和 SHA-256 后才能复制到证据目录，并在 manifest 标记`flutter-render-boundary-fallback`。截图及 `manifest.json` 写入 `e2e-verify/screenshots/<timestamp>/MOBILE/`，报告通过 `artifacts`字段关联它们。P1/P2/P3 截图场景均先登记在实施记录：`VISUAL-MOBILE-01..08`和`VISUAL-PAIR-01`；按本轮用户确认，本地截图可以保留 deterministic fixture 的 QR、请求标识和附件演示名称，但不得启动真实账号、密码、恢复码、token、会话正文、真实附件或 diff。截图是视觉证据，不取代 Flutter 断言。

## 6. 当前已知缺口
