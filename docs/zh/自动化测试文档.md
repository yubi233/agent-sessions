# 自动化测试文档

## 1. 范围与权威来源

本文是 Agent Sessions 的当前测试地图。功能事实以[项目文档](项目文档.md)为准，阶段和退出条件以对应迭代计划为准，稳定 ID 的唯一 owner 以[测试套件索引](../test/测试套件索引.json)为准。v0.8 的结构化用例位于 [`docs/test/18-DSH本地工作区同步.json`](../test/18-DSH本地工作区同步.json)，覆盖 DSH 持久化、迁移、Resume/回放、工作区同步、Terminal 归属和客户端投影。`docs/test/` 只保存结构化、可执行的验收用例；不得把截图、一次性日志或临时脚本放入其中代替回归。

P0 已完成测试契约和文档基线；P1 已完成当前既有页面的设计系统回归；P2 已完成 Relay-Daemon 的受限本地 fixture 切片、生产 Daemon event envelope 的本地密码学边界，以及 owned-process Supervisor/`session.kill` 的根因回归；本轮又完成 Flutter 本地会话控制闭环（免登录 bootstrap、start/send/abort/kill 与 UI 门控），并补齐 v0.5 的真实 Relay feedback/fork HTTP/SQLite 契约、Daemon→Relay usage outbox 的 provider/model/timing 投影，以及 Flutter HTTP Repository / controller / Chat UI 的对应回归。v0.6 P5 新增 OpenCode idle/error 终态映射、回合级去重和 Relay stale-running 历史对账回归。P3/P4 已交付的只读产品面仍为 partial，其中 P4 已补齐账号 SSE cursor 的恢复和可见浏览器断网重连。历史报告、fixture、HTTP 200 或旧实施记录不能替代真实上游验证；本轮主 gate 明确改为本地 Flutter + 本地 Relay/Daemon，Android 实机、AVD、Push、后台恢复和经授权消耗 token 的真实 Provider full gate 继续作为后续独立 gate。

## 2. 验证口径

每个 smoke、targeted diagnostic、full gate 和 recording 报告必须记录：`report_kind`、测试 ID、命令、fixture revision、`real_browser`、`real_model`、`real_upstream`、`fixture_data`、`local_test`、`headless`、失败分类、证据路径和残余风险。报告不得包含 token、私钥、会话正文、diff、附件或原始 Provider 输出。

Flutter macOS 可见窗口是本轮唯一允许的 Flutter 本地开发/诊断环境；报告必须标记 `visible_desktop_app=true`、`real_device=false`。本轮不执行 Android 实机或 AVD，Push、后台恢复、网络切换和厂商后台仍是后续独立 gate。macOS full gate 若因 Screen Recording 或严格 5fps 环境失败，必须保留 `environment_or_startup_failure`，不能用 targeted diagnostic 代替 full gate。

| 证据类型 | 可以证明 | 不能证明 |
| --- | --- | --- |
| Go/Dart/TypeScript 单元、组件、集成 | 本地规则、持久化、契约和 fixture 行为 | 可见浏览器、真实 Android、真实 Provider |
| `task test:e2e` headed Chrome | Web/Admin 的用户可见流程 | Flutter、Android 原生、真实 Provider |
| `task test:flutter:local` | 历史/开发诊断的 macOS Flutter fixture 流程 | 当前移动端闭环主证据、Android 原生能力 |
| `task test:android:e2e` | AVD 诊断流程 | 当前移动端闭环主证据、物理设备/厂商后台 |
| `task test:android:device` | 移动端闭环主 gate：物理 Android 上的 Flutter fixture integration | 真实 Provider、Push、后台恢复、真实网络切换 |
| `task test:real` | 经授权的单项 Provider/模型调用 | Relay-Daemon-Mobile 完整闭环 |
| `task test:v08:preflight` | DSH 历史 artifact 只读清单、header/压缩格式/冲突检查；默认只跑本地预检 fixture，设置 `AGENT_SESSIONS_DSH_V08_WORKSPACE_ROOTS` 或 `AGENT_SESSIONS_DSH_V08_LEGACY_ROOTS` 才读取对应授权根 | 不迁移、不删除、不调用模型；报告只含计数、哈希和脱敏错误 |

| `AGENT_SESSIONS_DSH_REAL=1 task test:v08:real` | v0.8 真实恢复门 | runner 已接入 `e2e-verify/real/dsh-v08-resume.mjs`；未授权时 blocked 不启动模型；Zen 四模型各允许最多 5 次额外重试 |
| 录屏、截图、DOM 快照 | 辅助诊断和演示 | 业务 oracle 或完整功能通过 |

## 2.1 本地会话 full gate（本轮）

验收顺序：

```text
cd apps/mobile
flutter analyze
flutter build macos --debug --no-pub
flutter test --machine --concurrency=1
cd ../..
task test:e2e:relay
task test:v04:p2
task docs:verify
task check
git diff --check
```

Flutter 长期回归位于 `apps/mobile/test/`：`session_controller_test.dart`、`session_screens_test.dart`、`session_info_screens_test.dart`、`capability_controller_test.dart`、`http_relay_repository_test.dart`、`local_visual_fixture_test.dart` 与 `daemon_observation_test.dart` 覆盖 owner bootstrap、`start/send/resume/abort/kill`、lease/幂等/fail-closed、二次确认、wire 脱敏和只读观察。`apps/mobile/test/support/fixture_owner.dart` 与 `MobileAppHarness.bootstrapLocalOwner()` 是统一 fixture 入口。

Go 长期回归由 `task test:e2e:relay` 与 `task test:v04:p2` 驱动，证据覆盖 Relay/Daemon ack、result、canonical event、lease、幂等、响应丢失、SQLite/Relay 重启恢复和多 Terminal 隔离。该 gate 的固定口径为 `local_test=true`、`fixture_data=true`、`real_model=false`、`real_upstream=false`。本轮不执行 `task test:android:device`、`task test:android:e2e`、`task test:real` 或 `task test:flutter:local`。

P1 的最新证据分层：Flutter unit/widget 为 `local_test=true`；Flutter macOS 可见窗口为 `visible_desktop_app=true`、`fixture_data=true`；Web/Admin `p1-design-system` 为 `real_browser=true`、`headless=false`，但仍为隔离 Relay fixture，`real_upstream=false`、`real_model=false`。

## 2.2 restart.sh 本地生命周期回归

`restart.sh` 是本地完整入口：默认拓扑为 Relay → Daemon → Flutter macOS，Web/Admin 仅由 `--with-web`、`--with-admin` 显式启用。Relay 委托 `tools/relayctl.sh`，Daemon 委托真实 `go run ./apps/daemon run`，Flutter 委托 `flutter run -d <target> --no-pub`。Daemon token 缺失、Flutter 目标不存在、device 无唯一 online 物理 Android、子进程提前退出或启动超时都会在启动前/启动中 fail-closed，并清理本轮已启动组件。`--flutter-mode mac|device`、`--flutter-device <id>`、`AGENT_SESSIONS_FLUTTER_DEVICE` 选择 Flutter 目标；device 模式必须配置 `AGENT_SESSIONS_FLUTTER_RELAY_BASE`，不启动 AVD。状态目录和日志默认位于 `.task/restart/`，也可通过 `--state-dir`、`--log-dir` 或对应环境变量隔离。`stop` 只停止 PID 文件存在且命令签名匹配的 Daemon/Flutter/Web/Admin，并按 ownership 停止 Relay；`testbox/` 永远不是测试产物目录。

```text
task test:restart
```

该回归在临时状态和端口上执行 `bash -n`、帮助输出、缺少 Daemon token/无效端口 fail-closed、Flutter mac/device stub 启动、目标转发、重复启动、`status`、`stop`、启动失败回收和外部监听占用后的 Web 端口清理。其证据口径为 `local_test=true`、`fixture_data=true`（仅脚本 stub）、`real_browser=false`、`real_model=false`、`real_upstream=false`、`headless=false`；它不证明 Android、真实 Provider 或真实模型。

## 9. 运行顺序与失败处理

每个功能切片先运行最接近根因的测试，再运行受影响的跨层测试。建议顺序：`task check` -> 相关 Go/Dart/Vue suite -> `task test` -> `task test:android` -> `task test:deploy` -> `task test:e2e:harness` -> `task test:e2e` -> `task test:android:device -- --device-id <serial>` -> 授权真实 Provider/Push gate -> recording。macOS/AVD 仅作为诊断补充。

从第一个因果失败开始分类为 `product_defect`、`test_harness_defect`、`selector_or_dom_contract_defect`、`provider_http_error`、`provider_timeout`、`model_contract_failure`、`model_flakiness`、`credential_or_quota_blocker` 或 `environment_or_startup_failure`。不得通过跳过、弱化断言或把 fixture 说成真实链路来获得绿色结果。

任何新增或修复的 P0/P1 行为，都必须有根因层长期回归；用户可见跨层行为还必须有对应 headed/物理 Android 实机或授权 Provider gate，AVD 只能作为诊断补充。每个阶段完成后，把实际命令、退出码、报告路径、证据口径和剩余风险回填到实施记录。

## 12. v0.8 开工准备：DSH 存储预检

v0.8 计划与结构化用例分别见 [`docs/zh/迭代计划/迭代计划v0.8.md`](迭代计划/迭代计划v0.8.md) 和 [`docs/test/18-DSH本地工作区同步.json`](../test/18-DSH本地工作区同步.json)。本阶段只冻结契约并建立无破坏预检，不修改 DSH 上游、不迁移文件、不调用模型。

固定命令：

```text
task test:v08:preflight
AGENT_SESSIONS_DSH_V08_WORKSPACE_ROOTS=/absolute/authorized/root AGENT_SESSIONS_DSH_V08_LEGACY_ROOTS=/absolute/legacy/root task test:v08:preflight

```

`dsh-v08-preflight.mjs` 只读取显式授权根内的 `session.jsonl` / `session.jsonl.zstd` 首行 header 与 SHA-256 摘要。报告保存于 `e2e-verify/reports/<timestamp>/V08-PREFLIGHT/`，根路径、DSH session id、cwd、消息正文和凭据均不会写入报告；仅保留计数、压缩类型、错误类别和不可逆哈希。`session-query.db`、WAL/SHM 不作为事实迁移。`migration_ready=false`、重复 ID 冲突、双编码、未知压缩、header 不完整或源文件在读取期间变化时，报告 `status=blocked`，命令退出码为 2，P0 迁移必须停止。命令入口用 `AGENT_SESSIONS_DSH_V08_WORKSPACE_ROOTS=/absolute/root[,/absolute/root]` 和 `AGENT_SESSIONS_DSH_V08_LEGACY_ROOTS=/absolute/root[,/absolute/root]` 分开声明两类根；参数既可传项目根，也可直接传 `.dsh-sessions` 持久化根，避免把旧根误当成当前工作区。

生产工作区的持久化编码由 `AGENT_SESSIONS_DSH_PERSIST_COMPRESSION=none|zstd` 选择；Daemon 会把它透传为 `DSH_SNAPSHOT_COMPRESSION`，并在迁移时把旧 plain/zstd artifact 转为同一目标后缀。生产 `Start`/`Resume` 先规约 workspace realpath，再用于 session cwd、持久化根和 header，避免 macOS 符号链接别名导致 cwd mismatch。

- `relay_generation`：Relay 首建 SQLite 生成随机持久值；同库重启稳定、删除重建必变、备份随文件走；hello/heartbeat additive 返回；不进 event envelope、不替代 lease epoch、不改 Terminal ID/delivery seq/command ID 语义。
