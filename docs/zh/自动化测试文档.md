# 自动化测试文档

## 1. 范围与权威来源

本文是 Agent Sessions 的可运行测试地图。功能和当前实现状态以[项目文档](项目文档.md)为准；本轮 Android 完整会话控制以[v0.1 迭代计划](迭代计划/迭代计划v0.1.md)和[v0.1 实施记录](实施记录/06-v0.1-Android完整会话控制.md)为准。稳定测试 ID 的唯一归属由[测试套件索引](../test/测试套件索引.json)管理；结构化验收用例只放在`docs/test/`。

仓库已具备 Go、TypeScript 和 Flutter 的本地测试入口，Relay 使用隔离 SQLite，Web/Admin 的 Playwright 回归默认启动可见 Chrome，录屏使用 CDP screencast。P0-P5 历史完成情况见实施记录；不能把历史 fixture 结果延伸为本轮 v0.1 的通过结论。

## 2. 验证口径与授权

每个 smoke、targeted diagnostic、full gate 和 recording 报告必须记录下列字段：`local_test`、`fixture_data`、`real_browser`、`headless`、`real_upstream`、`real_model`、命令、测试 ID、fixture revision、失败分类、证据路径和残余风险。

- `real_browser=true` 仅表示可见 Chrome 执行用户可见流程；它不代表 Android 或真实 Provider。
- v0.1 当前 Flutter full gate 固定在 MacBook 本地的可见 Flutter macOS 桌面窗口：报告必须标记 `real_browser=false`、`visible_desktop_app=true`、`headless=false`、`host_platform=macos`。浏览器验收仍由 `task test:e2e` 启动 headed Chrome。Android AVD、Android Keystore/Drift 原生集成与外接真机留待后续原生硬化阶段，不能把 macOS 结果表述为 Android 原生或实机验收。
- `fixture_data=true`、`local_test=true` 的 mock/隔离 SQLite 不能描述为真实上游通过。
- `headless=true` 只用于 CI 或快速回归，不能替代本地 headed 验收。
- 真实 Provider/模型 gate 必须先说明提供方、预计请求次数、凭据来源类别、额度风险与停止点。无专属凭据或授权时记录 `credential_or_quota_blocker` 和 `blocked`。
- 截图、DOM、trace、视频和报告是证据，不是替代断言的测试。

## 3. 测试架构与统一入口

```text
packages/protocol/                 OpenAPI、JSON Schema、错误码、跨端序列化
packages/crypto/                   Go 加密、篡改和 AAD golden vectors
packages/crypto-ts/                TypeScript 互解与单元回归
apps/relay + internal/{domain,httpapi,relay,store}/  Relay/API/SQLite 集成回归
apps/daemon + internal/{daemon,gitread,adapter}/     Daemon、Git、Adapter contract 回归
apps/mobile/test/                  Dart unit 与 Flutter widget 回归
apps/mobile/integration_test/      可重复 Flutter integration 流程；Android 原生用例后续执行
e2e-verify/suites/                 headed Playwright Web/Admin 用户旅程
e2e-verify/mobile/                 MacBook Flutter macOS visible gate、后续 AVD 诊断与录屏入口
e2e-verify/reports/                脱敏 JSON gate 证据和覆盖审计
e2e-verify/screenshots/            fixture macOS 可见窗口 PNG、SHA-256 与截图 manifest
e2e-verify/screencasts/            可见浏览器/Android 演示帧、manifest、mp4
docs/test/                         结构化、稳定 ID 验收契约
问题排查/<date>-<test-id>/          可复用故障诊断、脱敏日志和结论
```

根目录`Taskfile.yml`是唯一长期命令入口；`e2e-verify/`是 headed 浏览器、Android full gate、报告和录屏脚本的唯一归档位置。业务回归不得只存在于一次性命令或截图里。

| 命令 | 层级与用途 | 当前口径 |
| --- | --- | --- |
| `task check` | 格式、文档、生成物和 TypeScript 类型 | local_test |
| `task test:protocol` / `task test:crypto` | 协议/加密根因 | local_test + fixture_data |
| `task test:relay` / `task test:daemon` / `task test:contract` | Relay、Daemon、Git、Adapter 根因 | local_test + fixture_data |
| `task test:android` | Flutter analyze、unit 与 widget | local_test + fixture_data |
| `task test:flutter:local` | MacBook 可见 Flutter macOS integration full gate，并保存 fixture PNG 截图/manifest | `real_browser=false`、`visible_desktop_app=true`、`headless=false`、`fixture_data=true` |
| `task test:android:e2e` | 后续 Android AVD integration diagnostic | 不属于本轮 v0.1 gate |
| `task test:e2e` | headed Web/Admin Playwright 回归 | real_browser=true, headless=false |
| `task test:record` | full gate 后的 Web/Android 录屏 | recording；不可替代断言 |
| `task test:real` | 经授权的 Provider live smoke | 默认 blocked |
| `task docs:verify` | 结构化用例、注册表和文档链接 | local_test |

## 5. 回归与录屏顺序

1. 先更新`docs/test/`中的稳定用例和测试索引，再新增根因层测试。
2. 运行聚焦单元、widget、Relay/Daemon/contract 测试并解决第一个因果失败。
3. 运行对应 Flutter macOS integration 和 headed Chrome 场景；Android 原生 integration 留待后续阶段。失败必须归类为 product、harness、selector/DOM、provider、凭据或环境问题之一。
4. 只有 P0/P1 full gate 都通过后，才执行录屏。录屏的 manifest 必须列出事先定义的用例、命令、浏览器/设备、验证口径、脱敏约束和 artifact。
5. 完成后在项目文档、实施记录和本矩阵回填结果；对照需求到测试到证据，不能以截图或 headless 单独标绿。

### Flutter 截图证据

`task test:flutter:local` 先运行 Node 编排回归和`flutter build macos --debug --no-pub`，再运行长期 Flutter unit/widget 断言。断言通过后，runner 直接启动固定 debug 可执行文件，在每个登记场景稳定后使用 CoreGraphics 定位本轮窗口，并以 `screencapture -x -l <window-id>`按 5fps 连续 1 秒保存 PNG。截图及 `manifest.json` 写入 `e2e-verify/screenshots/<timestamp>/MOBILE/`，报告通过 `artifacts` 字段关联它们。P1 截图内容先登记在实施记录的 `VISUAL-MOBILE-01..`；按本轮用户确认，本地截图可以保留 deterministic fixture 的 QR 和请求标识，但不得启动真实账号、密码、恢复码、token、会话正文、附件或 diff。截图是视觉证据，不取代 Flutter 断言。

P1 最近一次通过证据为 `e2e-verify/reports/2026-08-14T17-49-05-300Z/MOBILE/mobile-01-macos.json`：预构建 debug App 成功后，长期 Flutter unit/widget 套件通过；真实可见 macOS 窗口帧为 `480×992`（`480×960` 内容区加标题栏）。截图 manifest 位于同时间戳的 `e2e-verify/screenshots/` 目录，已覆盖 `VISUAL-MOBILE-01`、`VISUAL-MOBILE-02` 和 `VISUAL-PAIR-01`，每个场景 5 帧，共 15 张 PNG，帧尺寸为 `1096×2120`，包含 SHA-256、帧偏移和窗口元数据。当前 MacBook 工具链上的`flutter test -d macos` native integration 仍因 open/VM 握手回归延后，不能把该结果写成 Android 原生验证。

## 6. 当前已知缺口

- Flutter P1 安全应用壳、认证/配对和密文缓存已完成本地回归与 MacBook 可见窗口验收；P2 的会话实时链路、附件、DiffView、Delegation、通知和 Android 原生验收仍待后续阶段。
- Relay 现有 API 未覆盖 v0.1 的附件、Git diff、delegation、会话快照和删除契约；实现时必须同时补根因层 API 回归。
- `flutter test -d macos`的 native integration 在 macOS 26/Xcode 26/Flutter 3.47 组合下存在公开 open/VM 握手回归；本轮以预构建 debug App 的可见窗口 gate 替代，Android AVD/真机仍不属于通过条件。
- 真实 Claude/Codex/OpenCode/OpenClaw 凭据与授权尚不存在；所有 live smoke 保持 `blocked`。
