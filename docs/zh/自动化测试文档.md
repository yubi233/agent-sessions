# 自动化测试文档

## 1. 范围与状态

本文是 Agent Sessions 的测试地图，权威功能边界见[项目文档](项目文档.md)，实施顺序见[实施计划](实施计划.md)，执行级质量计划见[14-测试验证与质量门禁](实施计划/14-测试验证与质量门禁.md)，可执行验收契约见[基础验收用例](../test/基础验收用例.json)。唯一测试 ID 归属见[测试套件索引](../test/测试套件索引.json)。

当前仓库只有文档，没有 Go、Vue、Flutter 依赖、测试运行器、Compose 环境或 CI，因此所有用例状态均为 `planned`。现阶段仅能验证 JSON 和 Markdown 文档格式，不能声称任何 Relay、客户端、浏览器、Android 或 Provider 测试通过。

`docs/test/基础验收用例.json` 是跨项目关键用户旅程入口；它消费领域 suite 的 ID。新增或变更 ID 必须先更新 `docs/test/测试套件索引.json`，再更新用例和覆盖矩阵。没有对应 JSON suite 或可运行测试文件时，ID 仍只是 `planned`，不能当作已覆盖。

测试必须区分以下口径：

- `local_test`：本地进程、测试数据库、mock 或 fixture。
- `fixture_data`：种子数据、录制响应或离线协议样本。
- `real_browser`：headed 浏览器中的用户可见流程。
- `real_upstream`：真实 Agent、Gateway 或外部服务。
- `real_model`：真实模型调用；没有授权时不得伪造通过。
- `headless`：只作为快速回归或 CI，不替代 headed 验收。

## 2. 验证口径

每次 smoke、targeted diagnostic、full gate 或 recording 报告必须记录 `local_test`、`fixture_data`、`real_browser`、`headless`、`real_upstream` 和 `real_model`。真实 Provider 或模型 gate 执行前，报告预计请求数、凭据来源类别、token/额度风险和停止点；没有密钥、额度或授权时标记 `blocked`，不得用 fixture 冒充真实通过。

## 3. 测试架构和所有权

```text
packages/protocol/                 OpenAPI、JSON Schema、错误码、序列化和 golden vectors
packages/crypto/                   加密、篡改、AAD、密钥包装和跨端 vectors
apps/relay/tests/                  Gin HTTP、SSE、WS、PostgreSQL、Redis、outbox、租约
apps/daemon/tests/                 服务生命周期、路径安全、Git parser、监督和幂等
apps/daemon/adapters/*/fixtures/   四类 provider 事件和版本样本
apps/mobile/test/                  Dart 单元、Flutter widget、integration_test
apps/admin-web/tests/              Vue 组件、脱敏字段、权限和响应式布局
apps/web/tests/                    Vue 组件、只读状态、cursor 和 DiffView
e2e-verify/web/                    Web headed Playwright 用户旅程
e2e-verify/admin/                  Admin headed Playwright 用户旅程
e2e-verify/mobile/                 Android 模拟器/真机流程入口
e2e-verify/reports/                脱敏 JSON 报告、覆盖审计和 gate 结果
e2e-verify/traces/                 Playwright trace、失败截图和 DOM 证据
e2e-verify/screencasts/            headed 演示帧、manifest 和视频
tests/fixtures/                    协议、Git、Provider、数据库和确定性种子
docs/test/                         稳定结构化用例，不放一次性日志或截图
问题排查/<date>-<test-id>/          可复用失败诊断，需要时创建
```

最低可证明层级优先；跨层风险高的行为再增加集成或 headed E2E。一次性脚本、截图、DOM 快照和录屏只能作为证据，不能替代长期回归测试。

## 4. 测试分层

| 层级 | 证明内容 | 典型范围 |
| --- | --- | --- |
| 静态检查 | schema、格式、类型和构建完整性 | 全仓库 |
| 单元 | 纯规则和转换 | 加密、cursor、租约、Git parser |
| 组件 | UI 状态和交互 | 加载、空状态、错误、只读权限 |
| 集成 | API、鉴权、持久化和事件契约 | Relay、Daemon、SQLite、Postgres、Redis |
| Provider contract | Adapter 对统一 SPI 的遵守 | Claude/Codex/OpenCode/OpenClaw |
| 浏览器 E2E | 用户可见跨层流程 | Admin/Web P0 路径 |
| Android integration | 真机或模拟器流程 | 配对、会话、重连、diff、通知 |
| real upstream gate | 真实 Agent/Gateway 行为 | 仅在授权、凭据和额度满足时运行 |

## 6. 用例执行约束

- 所有命令测试使用固定 `request_id` 和 `idempotency_key`，验证重复请求不会重复执行。
- 所有事件测试验证 `event_seq` 单调、断线恢复和客户端去重。
- 所有 Git 测试使用临时仓库，并在测试结束清理；不得依赖开发者个人目录。
- 所有路径测试覆盖符号链接、`..`、非 Git 目录、特殊文件名和跨盘路径。
- 所有 provider 测试同时验证 native/emulated/unsupported 三种能力声明。
- 所有涉及真实 provider 的测试单独标注凭据来源、请求次数和失败分类。
- 失败证据可保存日志、截图、trace 和脱敏报告，但证据不能替代断言。

## 7. 计划中的命令入口

工程初始化后统一使用根目录 `Taskfile.yml`，不再维护另一套 `make` 命令：

```text
task check             静态检查、schema、生成文件和格式
task generate          运行 OpenAPI/JSON Schema 生成并检查无漂移
task test              单元、组件和集成测试
task test:protocol     协议、错误码和 golden vectors
task test:crypto       跨端加密、篡改和密钥包装 vectors
task test:contract     四类 Provider adapter contract tests
task test:e2e          headed Web/Admin E2E
task test:android      Flutter integration_test
task test:real         需要明确凭据和授权的真实上游 gate
task compose:up        隔离测试环境
task compose:down      清理本轮测试环境
task docs:verify       JSON、链接、引用和覆盖矩阵检查
```

在这些入口尚未实现前，不得在交付说明中声称测试已经通过。

## 8. 验收报告字段

每次 smoke、diagnostic、full gate 或 recording 至少记录：

```json
{
  "suite": "...",
  "status": "passed|failed|incomplete|blocked",
  "real_browser": false,
  "real_model": false,
  "real_upstream": false,
  "fixture_data": true,
  "local_test": true,
  "headless": true,
  "command": "...",
  "artifacts": [],
  "failure_class": null,
  "remaining_risk": "..."
}
```

## 9. 当前缺口

- 尚无 Go、Vue、Flutter 测试运行器。
- 尚无本地 Postgres/Redis 夹具和迁移。
- 尚无真实 Provider 凭据、版本矩阵和授权。
- 尚无 headed 浏览器或 Android 模拟器验收脚本。
- 尚无录屏、报告和诊断产物目录内容。

以上缺口属于当前仓库状态，不是被跳过的通过项。
