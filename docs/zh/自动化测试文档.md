# 自动化测试文档

## 1. 范围与权威来源

本文是 Agent Sessions 的当前测试地图。功能事实以[项目文档](项目文档.md)为准，v0.4 阶段和退出条件以[迭代计划 v0.4](迭代计划/迭代计划v0.4.md)为准，稳定 ID 的唯一 owner 以[测试套件索引](../test/测试套件索引.json)为准。`docs/test/` 只保存结构化、可执行的验收用例；不得把截图、一次性日志或临时脚本放入其中代替回归。

当前 P0 只完成测试契约和文档基线，尚未运行产品功能 gate。历史报告、fixture、HTTP 200 或旧实施记录不能替代本轮验证。

## 2. 验证口径

每个 smoke、targeted diagnostic、full gate 和 recording 报告必须记录：`report_kind`、测试 ID、命令、fixture revision、`real_browser`、`real_model`、`real_upstream`、`fixture_data`、`local_test`、`headless`、失败分类、证据路径和残余风险。报告不得包含 token、私钥、会话正文、diff、附件或原始 Provider 输出。

| 证据类型 | 可以证明 | 不能证明 |
| --- | --- | --- |
| Go/Dart/TypeScript 单元、组件、集成 | 本地规则、持久化、契约和 fixture 行为 | 可见浏览器、真实 Android、真实 Provider |
| `task test:e2e` headed Chrome | Web/Admin 的用户可见流程 | Flutter、Android 原生、真实 Provider |
| `task test:flutter:local` | 可见 macOS Flutter fixture 流程 | Android Keystore、通知、返回键、IME、物理设备 |
| `task test:android:e2e` | 可见 AVD 流程 | 物理设备、厂商后台限制、真实网络切换 |
| `task test:real` | 经授权的单项 Provider/模型调用 | Relay-Daemon-Mobile 完整闭环 |
| 录屏、截图、DOM 快照 | 辅助诊断和演示 | 业务 oracle 或完整功能通过 |

P0 的验证口径固定为：

```text
real_browser=false
real_model=false
real_upstream=false
fixture_data=false
local_test=true
headless=false
```

## 3. 测试架构与统一入口

```text
docs/test/                         结构化验收用例和唯一 ID 注册表
packages/protocol/, packages/crypto/ 协议、生成物和密码学根因回归
internal/, apps/daemon/, apps/relay/ Go 单元、集成与安全回归
apps/mobile/test/                  Flutter unit/widget 回归
apps/web/src/, apps/admin-web/src/ Vue 组件回归
e2e-verify/                        headed 浏览器、AVD、真实 Provider、报告和录屏入口
e2e-verify/reports/<timestamp>/    脱敏执行报告
e2e-verify/screenshots/            截图与 manifest
e2e-verify/screencasts/            录屏帧、MP4 与 manifest
Taskfile.yml                       唯一长期命令入口
```

| 命令 | 最低覆盖 | 默认口径 |
| --- | --- | --- |
| `task docs:verify` | ID owner、suite 双向登记、P0 必要 ADR/项目文档 | local static |
| `task check` | 格式、schema、生成物、TypeScript 和文档 | local static |
| `task test` | 协议、密码学、Relay、Daemon、Adapter、TS 回归 | local fixture/integration |
| `task test:android` | Flutter analyze/unit/widget | local fixture |
| `task test:e2e` | headed Web/Admin Chrome | `real_browser=true` |
| `task test:flutter:local` | 可见 macOS Flutter fixture | `visible_desktop_app=true`，不是浏览器/Android |
| `task test:android:e2e` | 可见 AVD 编排 | `simulated_device=true` |
| `task test:deploy` | SQLite 备份、恢复、完整性和明文扫描 | local integration |
| `task test:real` | 经授权的 Provider smoke | `real_model=true`、`real_upstream=true` |
| `task test:record` / `task test:flutter:record` | full gate 后录屏 | recording，不替代断言 |
| `task test:v04:p0` | P0 文档/生成物/格式 gate | local static |

真实模型或真实上游前必须先说明 Provider、模型、预计请求次数、凭据来源类别、token/额度风险和停止点。没有明确授权或凭据时，标记 `credential_or_quota_blocker`，不得伪造真实结果。

## 5. P0 回归沉淀

P0 已做的测试架构变更：

- 将 `MOBILE-15..26` 从“见计划”的占位描述升级为可执行用例；保留 ID 和标题语义。
- 将 `WS-01/WS-02` 标记为 `excluded`，因为当前没有 WebSocket；用 ADR-009 所定义的 REST + SSE 设计来驱动新 Daemon 测试。
- 新增协议、迁移、Daemon、Android、Web/Admin、可靠性和 usage 的稳定 ID，并在唯一注册表中为每个 ID 指定唯一 suite owner。
- 将 SQLite 与进程内可重建状态回填到 Relay、发布和基础验收用例；不再把 PostgreSQL、Redis 或虚构 Git/版本路由写成当前事实。

P0 gate 通过后才可把本段的“已登记”更新为实际“已运行”。当前没有浏览器、AVD、物理设备、真实 Provider 或录屏证据。

## 6. 运行顺序与失败处理

每个功能切片先运行最接近根因的测试，再运行受影响的跨层测试。建议顺序：`task check` -> 相关 Go/Dart/Vue suite -> `task test` -> `task test:android` -> `task test:deploy` -> `task test:e2e` -> `task test:flutter:local` -> AVD/真实 Provider/物理设备 gate -> recording。

从第一个因果失败开始分类为 `product_defect`、`test_harness_defect`、`selector_or_dom_contract_defect`、`provider_http_error`、`provider_timeout`、`model_contract_failure`、`model_flakiness`、`credential_or_quota_blocker` 或 `environment_or_startup_failure`。不得通过跳过、弱化断言或把 fixture 说成真实链路来获得绿色结果。

任何新增或修复的 P0/P1 行为，都必须有根因层长期回归；用户可见跨层行为还必须有对应 headed/AVD/真实设备或授权 Provider gate。每个阶段完成后，把实际命令、退出码、报告路径、证据口径和剩余风险回填到实施记录。
