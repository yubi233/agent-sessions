# Agent Sessions 迭代计划 v0.8.2：DSH 能力补全、工具活动与会话生命周期

> 状态：`planned`（2026-09-02 制定）
>
> 前序：[迭代计划 v0.8.1](迭代计划v0.8.1.md)。v0.8.1 后续已接入 `model_select`（`session/set_config_option`，configId=model）。本计划基于对 DSH ACP 桥（dsh-acp / dsh-acp-demo）wire 面、ACP SDK 0.25.1 和 DSH 策略包的核对，将所有确认存在可复用协议或核心语义的能力统一归入 B 类并要求在本期实现：工具事件、effort、权限决策回流、图像附件、`permission_mode`、会话生命周期（close/list/delete/fork）和 `additionalDirectories` 均按能力门控逐项交付；对确实没有安全语义归属的能力保持 fail-closed，且不改写 V08-12 的既有失败状态。
>
> 关联：`internal/adapter/dsh/{adapter,handle,mapper,bridge,persistence}.go`、`internal/adapter/spi.go`、`internal/daemon/{runner,readonly_dispatcher}.go`、`apps/daemon/main.go`、`apps/mobile/lib/state/session_controller.dart`、`examples/acp-agent/cordis.yml`，以及桥侧 `/Users/yubi/code/deepseek-harness/packages/acp/acp/src/index.ts`（setSessionConfigOption、sessionConfigOptions、session lifecycle 校验）、`content.ts`（supportsAcpImagePrompts）、`tools.ts`（acpToolCallFrameFor），DSH `/Users/yubi/code/deepseek-harness/packages/session/session-persistence/src/index.ts` 和 `session-persistence-jsonl/src/index.ts`（list/listSnapshots/持久化边界）。

本计划把“DSH ACP 直连”与“Agent Sessions 的 DSH adapter”分开记账：ACP 桥源码/SDK 证明的是 wire 能力，不能代替 Go adapter、Relay 和客户端已经接通。能力状态以 `internal/adapter/spi.go` 的矩阵为准；`packages/protocol/types.go` 和 Flutter fixture 里的并行清单必须在 P0 校对，当前已观察到它们与 SPI 的 `kill`/`permission_mode` 项存在漂移风险。

与前序计划的边界：本计划覆盖并更新 v0.8 §4.6 中“`session/list` 不依赖 ACP、用本地 JSONL 扫描替代”以及“model/effort、工具事件另立迭代”的暂定结论。v0.8/v0.8.1 已完成的 DSH 工作区同步、会话导入、`origin=dsh`、home Terminal 归属、持久化根和 Resume ready-handle 仍是本期前置基线；V08-12 的真实 `resume/send` 失败证据不因本期新增 B 类而改写。

## 1. 背景与问题

`model_select` 打通后，剩余缺口分为四类：

1. **数据已在 wire 上、被 Go 侧丢弃**（本期最高优先级）。`examples/acp-agent/tool-updates.cordis.yml` overlay 已设 `toolUpdates: true`，桥将 `tool/call`、`tool/result` 投影为 ACP `tool_call` / `tool_call_update` 帧（`tools.ts` `acpToolCallFrameFor` / `acpToolResultFrameFor`）：含 `toolCallId`、`status: in_progress|completed|failed`、kind 分类（bash→execute、edit→edit 等）、单行 `title`、≤16 KiB 的 `rawInput`、截断至 2000 字符的文本结果。而 `mapper.go` 白名单只放行 `agent_message_chunk` / `user_message_chunk` / `usage_update`，`tool_call`、`tool_call_update` 一律丢弃计数——移动端时间线完全看不到 DSH 的工具活动，只有最终文本回复。
2. **桥支持、Go 侧未接入**。桥的 `setSessionConfigOption` 对 `configId: thought_level` 有完整实现（按当前模型公布的档位校验、按模型记忆档位），`effort_select` 可复用 `model_select` 同款下发机制；另外模型池中 `gpt-5.5@xhigh`、`gpt-5.6-terra@max` 等条目说明部分模型已公布档位，但 Go 侧无法切换。
3. **客户端可表达、服务端链路待补齐**。移动端已有 `permission.approve` / `permission.reject` 命令类型与审批面板，但 daemon runner 的命令分发表没有对应 kind（`runner.go` 头注释明确列为未实现），返回 `ErrUnsupportedCommand`；本期补齐通用回流链路，并与 DSH ACP 的 pending permission 建立一一对应。
4. **协议和核心已有语义、桥尚未接入**。ACP SDK 定义了 `session/set_mode`、`SessionModeState`、`current_mode_update` 以及 close/list/delete/fork 类型和能力位；DSH 核心已有逐会话策略写入、持久化 list/snapshot 和可复用的 session 前缀语义，但当前 ACP 桥没有实现 mode、生命周期或非空 `additionalDirectories`。这些不是永久不兼容能力，而是本期必须补齐安全契约和全链路的 B 类。

## 2. DSH 能力缺口清单（20 项 SPI 能力与 ACP 扩展逐项核对）

对照 `internal/adapter/spi.go` 的 `adapter.CapabilityNames` 全量 20 项，记录的是当前实现基线：握手成功后 6 项为 native（`start`、`resume`、`abort`、`kill`、`model_select`、`usage`）、`permission` 为 emulated，其余 13 项为 unsupported。`tool_call`/`tool_call_update` 以及 ACP 的 session 生命周期、`additionalDirectories` 是协议扩展，不计入 20 项能力；本期 B 类实现后再由动态 gate 更新矩阵。核对依据为桥侧源码、ACP SDK 类型定义和 DSH 包实现，非文档推断。

**`permission_mode` 结论（特别确认）**

- **当前状态：不支持。** 当前 dsh-acp `initialize` 只广告 `loadSession`、`promptCapabilities` 和 `sessionCapabilities.resume`，session 响应不含 `modes`，源码也没有 `setSessionMode`；Agent Sessions 的 `GET /v1/capabilities` 因此必须继续返回 `unsupported`。移动端已有 `session.permission_mode` fixture/控件不构成 DSH provider 已切换的证据。
- **支持性：可以支持，并且本期按 B 类实现。** ACP SDK 0.25.1 已定义 `SetSessionModeRequest/Response`、`SessionModeState` 和 `current_mode_update`；DSH 核心已有可回放的 `sandbox/mode`（`read-only`、`workspace-write`、`danger-full-access`）、`approval/policy`（`ask`、`never`）以及 permission preset 写入路径。可是核心默认 preset 只覆盖 `workspace-write + ask` 与 `danger-full-access + never`，并没有现成的三模式 ACP 目录；现有 preset setter 也不是原子 bundle 写入。`examples/acp-agent/cordis.yml` 只把 `DSH_PERMISSION_MODE` 用作进程启动默认值（当前配置将 `danger-full-access` 配成 `never`，其他已知 mode 配成 `ask`），不是运行期 ACP 能力；当前 ACP `apply()` 没有实现 mode handler 或 mode 广告，也没有把默认组合中的策略服务作为 mode 目录暴露。本期必须补齐这些桥接并在完成条件满足后升为 native。
- **实现约束：** mode 目录必须来自可用策略服务或经其校验的显式桥配置，并明确每个 mode 对应的 sandbox/approval bundle；切换必须绑定单一 session、持久化并在恢复后重建，未知值/策略服务缺失/越权工作区一律拒绝。必须在追加前预检 mode fence，或由核心提供原子 bundle setter；策略写入失败不能留下只有 `permission/preset` 或只有单个 knob 的半套事件。有持久终端活动时遵守终端 backend 的 mode fence。默认在当前 turn 完成后生效，禁止切换造成正在执行的工具获得意外升权；若 ACP 客户端在生成中调用 `set_mode`，实现需定义并测试排队或明确拒绝的边界。
- **升格条件：** 只有当 `session/new`/`session/load` 返回可用 `modes` 和当前 mode、`session/set_mode` 写入并验证二者策略、`current_mode_update` 与 Agent Sessions canonical 状态一致，且 V082 模式测试全绿后，才能把 `permission_mode` 从 unsupported 改为 native。

- **会话生命周期与多根目录同样属于本期 B 类。** `session/close` 必须是可恢复记录的 graceful close，不能等同于 `abort` 或物理删除；`session/list` 只能读取授权范围内的脱敏元数据和 revision；`session/delete` 必须经过 close/冷状态检查、持久化确认、墓碑或审计记录后才返回成功；`session/fork` 只复制已提交事件前缀并建立新的 session 身份，明确父子关系、权限模式、cwd、附件引用和 fork 点；`additionalDirectories` 只能进入 session-scoped sandbox allowlist，恢复时重新校验，不能把 ACP 参数直接转成任意路径读写。上述操作均须幂等、可取消、跨账号/越权 fail-closed，并在 ACP、Go、Relay、mobile 四层使用同一 session 身份。

### DSH 既有接入基线（本期依赖，不改写历史结论）

v0.8.2 的新增 B 类能力必须运行在 v0.8/v0.8.1 已建立的 DSH 基线上；这些链路不在本期重新发明，但必须作为 P0 不变量、P1 前置和 P3 回归门明确验证：

| 基线 | 已有接入事实 | v0.8.2 约束 |
| --- | --- | --- |
| Workspace identity | `workspace.sync_dsh` 只允许 owner/write 发起，并绑定账号、home Terminal、canonical workspace root；`session.import_dsh` 只返回 Relay opaque session id；`provider=dsh` 建会话需 `origin=dsh`、home Terminal 在线且声明 `start` | close/list/delete/fork/additionalDirectories 均复用同一 Workspace/Terminal/账号 fence，不能从 ACP 参数重新推导或绕过 |
| 持久化与迁移 | DSH 工作区会话根固定为 `<workspaceRoot>/.dsh-sessions`；legacy artifact 只在显式授权根内做非破坏性预检/迁移，支持 JSONL/zstd 格式校验；Relay 不保存路径、DSH session id 或正文 | list/delete/fork 只能操作已验证 session id 和 persistence root；删除不得把迁移源、公共 Relay 行或未确认 artifact 当成可回收事实 |
| Start/Resume/Send/Abort/Kill | DSH adapter 是 per-session ACP stdio 子进程；Resume 通过 ready handle 先登记/订阅再发 `session/load`/`session/resume`，随后沿同一 handle `Send`；`Abort` 只取消当前 turn，`Kill` 仅对 adapter 明确拥有的进程组执行强制终止；唤醒结果保持六态 | 新的 mode、effort、附件、目录和生命周期控制不得破坏 ready-handle 时序、回放 checkpoint、cwd mismatch、Abort/Kill 语义和 `WakeTerminalOffline`/`WakeWorkspaceMoved` 等 fail-closed 结果 |
| 现有平台投影 | Flutter/Web 已有 DSH 工作区优先、只读历史列表、导入和文件/Git readonly-transport；`file_read`/`git_read` 不属于 ACP bridge B 类 | 本期只扩展 DSH ACP/Relay 写链路；不得把只读页面或 fixture 控件当作 provider native 证据 |
| 真实 gate | V08-12 真实 DSH `resume/send` 当前保留 `failed/model_contract_failure`；v0.8.1 工作区首页、同步/导入和 model_select 有独立 fixture/回归证据 | 本期不得改写 V08-12 状态；新增 B 类 fixture 通过不等于真实模型/真实 DSH gate 通过，P4 必须分别记录 |

| ACP/产品意图 | Agent Sessions 公共命令或接口 | 约束 |
| --- | --- | --- |
| `session/request_permission` 的 allow/reject | UI `permission.approve` / `permission.reject` → Relay/Daemon `permission.respond` | `permission.respond` 是协议枚举；request_id/session_id/tool_call_id 一一对应，响应只消费一次 |
| `session/set_mode` | UI `session.permission_mode` → Relay/Daemon `mode.set` | `mode.set` 的 payload 必须携带桥广告的 modeId；不能把 `DSH_PERMISSION_MODE` 直接当运行期事件 |
| ACP `session/close` | Relay/Daemon `session.stop` | `session.stop` 是本仓库承接 ACP close 的唯一公共命令；close 只停止/释放运行句柄，保留可恢复记录；不得复用 delete |
| ACP `session/list` | Relay `GET /v1/sessions` + DSH persistence `list/listSnapshots` | 只投影授权 metadata/revision，分页、排序和账号/workspace 过滤在服务端完成 |
| ACP `session/delete` | Relay/Daemon `session.delete` + DSH tombstone/reclaim | 先检查冷/已 close，再持久化确认；重试幂等，不直接无审计 unlink |
| ACP `session/fork` | Relay `POST /v1/sessions/:id/forks` 与 provider ACP fork 适配 | Relay lineage 与 provider transcript 前缀必须分别记录，不能把已有 subagent fork 或 metadata-only fork 冒充 ACP fork |
| ACP `additionalDirectories` | `session.start/resume/send` 的 opaque 目录引用 → DSH sandbox allowlist | 目录只在 session/workspace/Terminal 授权内生效，恢复和 readonly transport 复用同一 allowlist |

## 3. 目标与成功标准

### 3.1 目标

- G1：DSH 会话时间线呈现工具活动（tool.call / tool.result），对齐其他 provider 的体验；这是本期用户价值最大的一项。
- G2：`effort_select` 接入且目录真实：能切则切，切不了的档位绝不出现在目录中。
- G3：模型/档位/路由三元组的一致性由测试固化，配置漂移在 CI 层暴露。
- G4：能力矩阵和 ACP operation gate 对 B/C 两类缺口的表述与桥事实严格一致，SPI capability、session lifecycle 和事件能力不混为一层。
- G5：权限请求可从 ACP 经 daemon、Relay 回流到移动端，并将一次性决策准确送回原始 JSON-RPC 请求；任何失联或过期都 fail-closed。
- G6：图片附件可在 image-capable 部署中端到端发送、校验、渲染和失败回滚；text-only 部署继续明确拒绝，不误报为 native。
- G7：`permission_mode` 以 session 级 ACP mode/preset 方式可发现、可切换、可恢复；实现完成前保持 unsupported 和 fail-closed。
- G8：`session/close`、`session/list`、`session/delete`、`session/fork` 形成可审计、可恢复、幂等的会话生命周期闭环，不把 close 误作 delete，不把 provider fork 误作 subagent fork。
- G9：`additionalDirectories` 进入同一 session-scoped sandbox allowlist，创建、恢复、工具执行和 readonly transport 使用一致的多根目录授权，越权和路径漂移均拒绝。

### 3.2 成功标准

1. fixture 桥注入 `tool_call`（in_progress）→ `tool_call_update`（completed/failed）帧，canonical 事件流依次出现 `EventToolCall`、`EventToolResult`，载荷字段符合 §2 B 类白名单；畸形帧被丢弃并计数。
2. 移动端会话时间线对 DSH 会话渲染工具活动条目（复用既有 tool 事件 UI），不渲染 `rawInput` 之外的参数细节。
3. `session.effort_select` 命令链路（runner 持久化 → send 随行 → handle 下发 thought_level）全通；桥对不支持档位返回 invalidParams 时，命令失败被如实上报，UI 保留原档位。
4. `GET /v1/capabilities` 中 DSH 的 `effort_select.status == "native"` 且 `options` 与 `examples/acp-agent/cordis.yml`（或明确 overlay）声明的档位一致；`model_select` 目录一致性测试扩展为含档位。
5. 一致性守护测试能捕获三类漂移：roster 中出现 `examples/acp-agent/cordis.yml` 不可路由的模型、Default 模型不一致、档位目录与模型声明不一致。
6. ACP `session/request_permission` 生成 canonical `permission_request`，移动端一次性 `permission.approve/reject` 经 Relay/runner 回流后，原始请求收到 `allowed` 或 `rejected`；重复、未知、超时和断线均收到 `cancelled`，且 pending 不泄漏。
7. image-capable fixture 中，附件引用经授权读取/解密后转为 ACP image block，桥返回的 assistant image 可读回 canonical 事件；text-only 模型、缺失附件服务、坏 MIME/超限附件均被拒绝并产生可诊断错误。
8. `permission_mode` fixture 覆盖 `modes` 广播、合法/非法切换、session 恢复后的策略重建、in-flight 边界和 unknown-mode fail-closed；完成桥接后 capabilities 断言升为 native，任一 gate 未满足仍为 unsupported。
9. ACP 生命周期 fixture 覆盖 close 的 graceful 终态与重复幂等、list 的授权元数据/分页/revision、delete 的冷状态检查/墓碑/审计/重试，以及 fork 的已提交前缀、父子元数据和权限边界；所有失败不泄露路径、正文或凭据。
10. `additionalDirectories` fixture 覆盖规范化、重复/重叠目录、符号链接、工作区外路径、恢复后路径漂移、策略服务缺失和工具/readonly transport 共用 allowlist；非法输入不改变原策略。
11. `task check`、`test:daemon`、`test:relay`、V081 既有回归全绿；`git diff --check` 干净。

- V08-12（真实 DSH resume/send gate）重跑。
- Web/Admin 端任何写入口新增。

## 5. 迭代工作流与阶段门

遵循 v0.8.1 确立的顺序：先契约（P0），再 DSH/Go 实现（P1），再 Relay/移动端纵向链路（P2），最后真实能力门控、可见验收与文档收口（P3/P4）。P0 的工具、effort、权限、模式、图片、生命周期和多根目录契约未绿，不得进入 P1；P3 结束前本节全部 B 类都必须有实现和验收，任一动态前置条件未满足时只能保留条件式 unsupported，不能伪造 native 或移出本迭代。

## 8. 测试架构、验证与交付门

- 所有默认验证：`fixture_data=true`、`local_test=true`、`real_model=false`、`real_upstream=false`。
- P3 可见验收：headed Chrome（非 headless）、可见 macOS Flutter 窗口或 renderer fallback 标注。
- image/permission 的默认 gate 使用 fixture + image-capable/permission-ask overlay；生产 `examples/acp-agent/cordis.yml` 继续以 text-only 默认路由和 `approval.policy: never` 运行（模型目录可含 vision 条目），不能据此宣称端到端 native。
- permission_mode 的默认 gate 使用含 `dsh-permission-presets` 的 mode fixture；生产配置只提供启动默认 `DSH_PERMISSION_MODE`，在桥实现并广告前不得把它当作运行期能力，完成后也必须以真实 `modes`/current mode 为准。
- lifecycle 的默认 gate 使用独立 persistence fixture：覆盖 listSnapshots 并发刷新、close/load、delete tombstone 和 fork prefix；additionalDirectories 使用受控临时 workspace fixture，验证 sandbox policy 与 readonly transport 的同一 allowlist。生产部署未提供对应 handler、删除策略或多根目录 policy 时，能力保持 unsupported。
- 真实模型冒烟（可选）：须用户显式授权，独立 report；不与 fixture gate 混记。真实 vision/审批部署证据需脱敏归档。
- 一致性测试的 YAML 输入以仓库 `examples/acp-agent/cordis.yml` 及被选 overlay 为源，禁止在测试内复制第二份配置真相。

## 9. 风险、回滚与前置依赖

| 风险 | 处理 |
| --- | --- |
| Zen 免费池模型实际不公布 reasoningEfforts，effort 目录为空，`effort_select` native 名不副实 | P1 前置核查：仅当至少一个池内模型确认公布档位时才升 native；否则矩阵保持 unsupported 并将 Reason 改为"桥支持 thought_level，当前模型池无已公布档位"，工具事件部分独立交付，不阻塞 |
| rawInput 含敏感内容（如 bash 命令参数）进入客户端 | 载荷白名单保留 rawInput 但截断 16 KiB（与桥一致）；如验收发现泄露顾虑，可在矩阵/事件投影层降级为仅 kind+title，桥侧 16 KiB 上限不作为安全边界 |
| 工具事件导致既有时间线渲染回归 | V082-07 定向覆盖其他 provider 工具事件渲染不变 |
| 桥 `modelEffortVariants: true` 与 thought_level 通道交互误解 | 本计划已核对：variants 仅影响 configOptions 广播，set 通道对 thought_level 的处理不受影响；契约测试固化该理解 |
| 一致性测试因 YAML 解析引入生产依赖 | 解析仅限测试代码，生产路径零新依赖 |
| 当前生产默认路由为 text-only，图片能力被误报为 native | 能力矩阵按 ACP initialize/configOptions 动态 gate；image overlay 单独验证，缺 attachment service 或 image modality 时明确 unsupported |
| 权限请求悬挂导致客户端持续显示处理中 | pending registry 绑定 session/turn/request，prompt decode 失败、断线、超时、dispose 均补终态；watchdog 与 one-shot 清理防止泄漏 |
| 重复批准、越权附件引用或日志泄露 | request/attachment ref 校验、lease/idempotency、授权读取与脱敏日志；未知/过期/重复统一 fail-closed |
| mode 切换导致运行中工具意外升权或恢复后策略漂移 | 只允许 session-scoped 持久事件；定义 turn 边界，切换前后重新解析策略；未知 mode、策略服务缺失和不一致状态均拒绝并保持旧模式 |
| list/delete/fork 与持久化并发或崩溃恢复竞态 | list 只读 header/snapshot revision；delete 先写 tombstone/审计再回收，失败可重试且不伪造成功；fork 以稳定已提交前缀和新 id 原子发布，父会话不被修改 |
| `additionalDirectories` 绕过工作区或符号链接逃逸 | 规范化后逐项校验 realpath、账号/workspace 授权和 policy service allowlist；工具、fork、恢复、readonly transport 复用同一策略，任何漂移立即拒绝 |
| B 类实现扩散到 C 类桥不支持能力 | §3.3 明确 C 类不纳入；每项 B 类必须有动态能力 gate、契约、P1/P2 实现和 V082 用例，缺任一项只能保持 unsupported，不能静默降级成成功 |

## 10. 完成定义

`tool_call`/`tool_call_update`、`effort_select`、`permission` 决策回流、`attachments`、`permission_mode`、`session/close`、`session/list`、`session/delete`、`session/fork` 和 `additionalDirectories` 均通过 V082 契约、纵向与可见验收：权限请求能在原始 ACP 请求上收到一次性 allowed/rejected/cancelled 终态，图片在 image-capable overlay 中完成发送与 assistant 回读且 text-only 路由明确拒绝；模式目录来自桥真实广告，切换同时更新 DSH 的 sandbox/approval 策略并可在 session load/resume 后恢复；close/list/delete/fork 的状态、审计、父子边界和持久化结果一致，目录授权在创建、恢复、工具和 readonly transport 中一致。只有动态 gate 未满足的部署保留 unsupported，不能把未实现冒充 native；能力矩阵与桥事实一致并由动态 gate 和一致性测试守护，配置漂移可被 CI 捕获；B 类缺口按条件清零，C 类保持准确 unsupported；V081/V08 既有回归全绿，V08-12 状态未被改写；文档回填与 V082 结构化用例落盘完成。
