# Agent Sessions 迭代计划 v0.8.1：DSH 工作区主模式与工作区内会话创建

> 状态：`in_progress`
>
> 前序：[迭代计划 v0.8](迭代计划v0.8.md)。本计划只收口“已发现的 DSH 工作区如何进入客户端并作为唯一 DSH 建会话入口”；不把 v0.8 尚未通过的真实 `session.load/resume/send` gate 误记为已完成。
>
> 关联：`internal/domain/workspace.go`、`internal/domain/realtime.go`、`internal/httpapi/handlers.go`、`internal/daemon/dsh_workspace.go`、`apps/mobile/lib/{relay,state,ui}`、`apps/web/src/views/SessionsView.vue`、`docs/test/19-DSH工作区主模式.json`（本轮新建）、`Taskfile.yml`。

## 1. 背景与问题

v0.8 已实现 Daemon 的 DSH 工作区扫描，以及 Relay 的 `workspace.sync_dsh`、`session.import_dsh` 受控命令；但 Flutter/Web 只按 Relay 中**已经存在的 DSH 会话**分组。它们既不发起同步，也不显示“已同步但还没有会话”的工作区。

因此，主页面切到 DSH 模式后会显示“暂无 DSH 会话”，即使本机 DSH 已有大量项目。主页的全局“新建会话”入口还允许用户先建会话、后选工作区，与 DSH 的本地工作区归属模型相反。

本期将移动端截图所示的 Sessions 首页改为 DSH 工作区优先：先看到和刷新 DSH 工作区，只能在一个已同步、可操作的工作区中创建 DSH 会话。

## 2. 目标与成功标准

### 2.1 目标

- G1：DSH 成为 Flutter 首页默认且主要的会话组织方式；不再要求用户先切换模式才看见 DSH 工作区。
- G2：owner/write 端可显式选择在线 DSH Terminal，触发并观察本机 `workspace.sync_dsh`；同步结果刷新为可读、无路径泄露的工作区分组。
- G3：所有已同步 DSH 工作区均展示，即使尚未导入历史会话；每个工作区下展示其 DSH 会话或明确的空态。
- G4：移除 Sessions 首页全局“新建会话”按钮。DSH 新会话只能从选定 DSH Workspace 的详情页发起，并固定使用该工作区与 `provider=dsh`。
- G5：服务端同样约束 DSH 建会话，不能依赖客户端路由或按钮隐藏来绕过 workspace、home Terminal 和能力边界。
- G6：owner/write 端可按工作区显式导入历史 DSH 会话；Web 保持只读，不显示扫描、导入或建会话入口。
- G7：保留普通/历史会话的次级浏览入口，但不得重新成为首页默认或把非 DSH 会话混入 DSH 工作区列表。

### 2.2 成功标准

1. 登录 owner Flutter 后，Sessions 首页默认展示“DSH 工作区”；不再有顶栏全局“新建会话”图标，也不再以“暂无 DSH 会话”代替工作区列表。
2. owner/write 在选择在线、声明 `dsh_workspace_sync` 的 Terminal 后可点击“刷新 DSH 工作区”。页面可观察 `pending / succeeded / failed / unavailable`，成功后重新拉取 Workspace 投影。
3. Relay 返回的 DSH Workspace 投影包含稳定 opaque `id`、安全的单段 `display_name`、`origin=dsh`、`home_terminal_id`（或等价现有 `terminal_id`）、状态；绝不返回 canonical root、DSH session id、JSONL 路径或对话正文。
4. 同步出的每个 DSH 工作区均显示为工作区分组头；无历史会话时显示“尚无 DSH 会话”，而不是隐藏该项目。非 DSH 工作区与非 DSH 会话不得混入。
5. 只有 owner/write 且该 Workspace 的 home Terminal 在线并声明 DSH `start` 能力时，“新建 DSH 会话”可用。新会话创建后 `workspace_id` 固定为已选 Workspace 的 ID、`provider=dsh`，并路由到该 home Terminal；不提供可改写的工作区或 Terminal 选择器。
6. 任意客户端直接提交 `provider=dsh` 到非 DSH Workspace、非 home Terminal、离线 Terminal 或无相应 capability 时，Relay fail-closed，且不创建 Session/Daemon 命令。
7. owner/write 可在每个可操作的 DSH Workspace 显式发起“导入历史会话”；导入时有 pending/failed/succeeded 状态，完成后只刷新该 Workspace 的 DSH 会话元数据。Web 与只读设备没有这些写入口。
8. 工作区名仅由 Daemon 从 canonical root 的 basename 生成并经单段名称校验；用户可见名称不含 `/`、`\\`、驱动器前缀、父目录或完整路径。名称重复时以 opaque Workspace ID 区分，不能合并不同 canonical root。
9. 普通会话浏览仍可从“最近会话/全部会话”等次级入口使用；v0.8 既有非 DSH 流程不被删除或错误归入 DSH。
10. 新增 V081 结构化用例、长期回归、headed 浏览器/可见 Flutter 验收和文档回填；`task test:v081:local` 与 `task check` 通过。v0.8 的真实 DSH Resume gate 仍独立保留其失败/blocked 状态。

### 2.3 本期不纳入

- 修复或重跑 v0.8 的真实 `session.load/resume/send` 模型契约失败；它仍以原 V08-12/P4 单独追踪。
- 自动扫描、自动导入，或页面打开/下拉刷新时静默读取本机 `.dsh-sessions`。
- 上传 canonical root、DSH session id、JSONL、摘要、prompt、回复正文或任何凭据。
- 新建普通项目目录、`git init`、修改 DSH 上游、Android 实机/AVD、生产部署和跨机器迁移。
- 在 Web 只读端加入控制本机的同步、导入、创建、恢复或模型调用功能。

## 3. 冻结产品与安全决策

### 3.1 首屏信息架构：参考 DSH 的工作区分组栏

Flutter 的 `SessionHomeScreen` 固定为 DSH 工作区首页；移除顶部 `session-new-button` 和实验烧杯样式的 DSH 模式开关。DSH 不是筛选条件，而是本期产品的默认工作模型。原有普通/历史会话保留在“最近会话/全部会话”次级路由，不得重新抢占首页。

工作区 UI 参考用户提供的 DSH 侧栏：一个“工作区”工具栏，下面是文件夹样式的 Workspace 分组，每组下方是会话子项、选中态和相对时间。它不是把所有项目做成大卡片，也不是在首页铺开每个项目的操作按钮。

```text
宽屏：左侧工作区栏（约 320–360px）              右侧：选中会话/工作区详情
┌──────────────────────────────┐  ┌─────────────────────────────┐
│ 工作区                 [搜索][同步] │  │ 网游风格小说 / 可操作           │
│ 同步目标：MacBook Pro · 在线   │  │ 会话正文或工作区空态            │
│                                │  │                               │
│ ▾ 📁 网游风格小说              │  │ [新建 DSH 会话]                │
│    ◆ DSH 会话 · 2 分钟         │  │ […] 导入历史会话（仅元数据）    │
│      DSH 会话 · 34 分钟        │  │                               │
│ ▸ 📁 斗罗奶龙 · 尚无会话       │  └─────────────────────────────┘
│ ▾ 📁 agent-sessions            │
│    ◆ DSH 会话 · 17 分钟        │
└──────────────────────────────┘

窄屏：同一工作区栏作为全屏列表；点击工作区或会话后进入详情页，返回时恢复
      原有滚动位置、展开状态和搜索条件。
```

交互规则：

- 工作区行有两个独立点击目标：标题/文件夹区域负责选中并打开 Workspace detail，左侧展开箭头只负责展开或折叠。两者均有独立语义 label 和稳定 `Key`/`data-testid`；不得把整行同时绑定为两个互相冲突的手势。
- 选中工作区标题后，右侧/详情页呈现该工作区及其 home Terminal 状态；“新建 DSH 会话”只在这里可用并绑定该 workspace。空工作区可显示同一个、绑定该 workspace 的 primary action。
- 选中会话子项后，行有低对比度填充背景和小型强调标记；不能只靠颜色区分选中态。
- 工作区默认折叠，当前选中工作区和有待处理同步结果的工作区自动展开；用户展开/折叠状态只保存在本地 UI，不改变 Relay Workspace。
- 头部只保留本地搜索和“同步 DSH 工作区”两个主要工具动作，避免在 320–360px 的侧栏堆叠筛选、加号等图标。搜索仅过滤安全 `display_name` 和安全会话标签；不能搜索路径、正文或 DSH session id。首次版本不新增独立筛选器。
- 点击“同步 DSH 工作区”后，先在确认 sheet 内选择一个 online 且声明 `dsh_workspace_sync` 的 Terminal；若只有一个候选也必须显示其名称。栏内“同步目标”只说明当前默认/最近一次目标，不能代替本次确认。同步动作采用刷新/循环箭头加文字或清晰 tooltip，不能复用文件夹加号：后者会被理解为“新建本地项目”，而本期禁止新建目录和 `git init`。
- 工作区、会话和普通历史次级页都有稳定的路由状态。宽屏选中项在右侧替换详情；窄屏进入详情页。返回列表时恢复搜索词、滚动偏移和各分组展开状态，且不会触发同步、load 或 resume。

导入的历史 DSH 会话不允许显示由 prompt、文件路径或对话正文派生的标题。会话子项统一显示安全标签（如“DSH 历史会话”或用户在 Agent Sessions 内主动命名的标题）和 Relay 安全时间字段；不能照搬参考图里的 DSH 原始会话标题。

工作区栏顶部只保留搜索、同步和紧凑的同步目标/Terminal 状态条；“最近会话”与账户/设备为次级但清晰可达的入口。原截图中恢复码、二维码配对、设备管理等安全功能不再占据 Sessions 首屏；它们归入账户与设备页。点击 Terminal 状态条进入既有 Terminal 状态页，不改变当前 Workspace 选择。

### 3.2 用户状态与交互状态机

| 状态 | 首页呈现 | 可执行动作 | 禁止行为 |
| --- | --- | --- | --- |
| 首次、尚未同步 | 空态“尚未同步本机 DSH 项目”，说明仅读取授权根项目元数据 | owner/write 点击“同步本机 DSH 工作区”并确认目标 Terminal | 不用下拉刷新自动扫描；不显示“暂无会话”伪装为空项目 |
| 同步中 | 状态条、进度文案、禁用重复提交 | 查看目标 Terminal；停止本地轮询并返回当前投影 | 不显示伪造项目数；不把“停止等待”伪装成已取消 Daemon 命令；不开始导入或模型调用 |
| 同步成功、有项目 | 可折叠工作区分组栏与“已同步 N 个项目”短暂反馈 | 搜索、展开、打开工作区、再次刷新 | 不展示完整路径或 DSH session id |
| 同步成功、零项目 | 空态“授权根内未发现带 DSH 证据的 Git 项目” | 更换/检查 Terminal 后重试 | 不创建 Git 项目，不建议用户上传路径 |
| home Terminal 离线/非当前 Terminal | 工作区仍可读，显示不可用状态 | 查看 Terminal 状态 | 禁用新建、导入、恢复和发送；不路由到同名目录的其他机器 |
| 工作区无会话 | 分组下显示“尚无 DSH 会话”；详情保留工作区标题与空态 | “新建第一个 DSH 会话” | 不隐藏工作区或回退到全局新建 |
| 已导入历史会话 | 显示安全元数据与“需要 home Terminal 恢复”状态 | 打开只读详情；V08-12 通过后再开放恢复 | 在 V08-12 未通过时显示可用的恢复/继续发送入口 |
| 只读设备/Web | 可浏览工作区与会话 | 进入详情、切换次级视图 | 不渲染、也不请求同步/导入/新建/恢复 |

首次同步前需要一页轻量确认 sheet：显示所选 Terminal、仅扫描授权根中的 DSH 项目证据、不会上传路径或对话正文，并提供“同步”与“取消”。它不是权限绕过，也不把 `policy: never` 理解为自动批准。

### 3.3 可访问性与响应式规则

- 375px 宽度下工作区名单行截断、会话数与状态保持可读，列表不得横向滚动；长项目名用省略号，完整名可由语义 label 读取。搜索打开后占满单独一行，不能挤压同步和返回控件。
- 同步、新建、导入、更多、返回均为带文字或明确 `tooltip/semanticsLabel` 的语义控件，不依赖烧杯、加号或省略号图标单独表达核心含义。
- `pending / unavailable / failed` 同时用文字、颜色和图标表示；焦点可见、键盘/辅助功能可进入所有可执行控件。
- 展开箭头暴露 `expanded/collapsed` 状态；当前工作区和当前会话分别暴露选中语义。键盘焦点顺序为工具栏 → Terminal 状态 → 工作区组头/展开箭头 → 会话子项 → 详情操作，不能因桌面双栏而跳过列表。
- “新建 DSH 会话”在工作区详情中是唯一 primary button；“导入历史会话”放入更多菜单并有确认说明，避免误认为会导入聊天正文。
- 会话数为导入至 Relay 的安全元数据数量，不暗示本地 DSH 所有历史已被读取、恢复或可继续发送。

### 3.4 关键用户旅程

| 旅程 | 用户动作 | 系统反馈 | 终态 |
| --- | --- | --- | --- |
| 首次接入 | owner 打开“工作区”并点击同步 | 确认 sheet 显示 Terminal 和数据边界；随后显示同步中 | 成功展开工作区分组，或给出无候选/失败原因 |
| 浏览项目 | 搜索、展开一个工作区，点击组头或会话 | 组头与展开箭头各自响应；保留其他分组状态；选中行与详情联动 | 只读取安全投影，不触发扫描/load/model |
| 新建会话 | 选择工作区 → 详情页点击“新建 DSH 会话” | 创建中禁用重复点击；Workspace 与 provider 锁定 | 进入新会话详情，或显示 Terminal/capability 错误 |
| 导入历史 | 在工作区详情的更多菜单确认导入 | 明确“仅元数据”；显示 pending 和完成数 | 会话子项出现在该分组；恢复仍受 V08-12 限制 |
| Terminal 离线 | 用户在分组或详情页查看项目 | 灰化状态条和原因；仍能浏览安全元数据 | 不发起 create/import/resume/send |
| 只读设备 | 打开相同工作区栏 | 与 owner 相同的分组与会话投影 | 不显示写操作，也不请求写 API |

### 3.5 Workspace 安全投影

现有 `WorkspaceRow.ProjectID` 对 v0.8 DSH 工作区是 opaque hash，不能直接充当用户项目名，也不能通过 ID 前缀识别 DSH。新增明确、可迁移的 Workspace 元数据：

- `origin`：`managed | dsh`，用于服务端和客户端筛选；历史行回填为 `managed`。
- `display_name`：Daemon 只在扫描结果中从 canonical root 的 basename 派生，做单段名称校验和长度限制；Relay 可向同账号安全投影。
- 既有 `terminal_id` 继续作为不可变 `home_terminal_id` 语义；如果公共字段需要更清晰名称，只允许新增兼容别名，不能把真实根暴露到 API。

`account + home_terminal + canonical_root` 仍是 DSH Workspace 的幂等 identity。显示名相同绝不合并，刷新/重放不得改变 identity 或 home Terminal。

历史无 `origin` 的行不得根据 `ProjectID`、名称或路径猜测为 DSH；迁移一律保守回填为 `managed`。只有后续一次成功的、同 identity 的 `workspace.sync_dsh` result 才能把该行更新为 `dsh` 并填入安全显示名。因此升级后首个 DSH 首页空态必须明确引导用户**显式同步**，不能把旧的无标记行悄悄消失或误展示为 DSH 项目。

### 3.6 显式同步、结果轮询与导入

- `workspace.sync_dsh` 继续只能由 owner/write 在首次确认 sheet 或“刷新工作区”显式调用；下拉刷新只能刷新 Relay 投影，不能代替扫描命令。
- Flutter 新增 typed repository 方法及有限轮询：提交 `POST /v1/workspaces/sync-dsh`，仅轮询相应 `GET` 状态直到 `succeeded / failed`，随后刷新 workspaces 和 sessions。重复点击合并为同一 pending 操作，不无限轮询；用户离开页面或选择“停止等待”时只停止客户端轮询，命令结果仍由下次投影刷新收敛。
- 导入入口只存在于**工作区详情**的更多菜单。`session.import_dsh` 范围、幂等、Terminal fence 和元数据白名单均复用 v0.8 后端实现；客户端不枚举文件或解析 JSONL。导入确认文案明确“只导入会话元数据，不读取/上传消息正文”。
- 只读设备/Web 仅显示已有 DSH Workspace/Session 安全投影，不得调用写 API；隐藏按钮不能替代服务端鉴权。

### 3.7 工作区内建会话与历史会话边界

- 从 DSH **工作区详情**发起时，页面传递不可编辑的 `workspace_id`，并固定 `provider=dsh`；不再从主页或通用 picker 选择任意 Workspace。
- 复用现有 `POST /v1/sessions`，但在 `SessionService.CreateSession` 增加 DSH 专用服务端校验：Workspace 必须 `origin=dsh`、属于账号、绑定 home Terminal；该 Terminal 必须在线且声明 DSH 启动能力。校验失败不写 Session 或命令。
- 新会话详情显示所属工作区的安全 `display_name`。随后 `session.start` 仍复用 v0.8 home Terminal fence；离线或跨 Terminal 一律为 `unavailable` / `WakeTerminalOffline`。
- 通用 `NewSessionScreen` 可保留给次级非 DSH 流程，但 DSH 工作区入口使用锁定的参数化路由或独立 sheet，不能通过 UI 改成其他 provider/workspace。手动构造路由不能绕过 Relay 校验。
- 历史 DSH Session 的导入、显示和可见性不等于恢复成功。V08-12 未修复前，历史会话详情必须 truthful 地显示“恢复暂不可用”，不让用户点击会失败的恢复/继续发送操作；这不是把 V08-12 标记为完成。

### 3.8 Web 与次级会话视图

- Web 保持只读，默认以 DSH 工作区 → 会话的层级浏览；空工作区也保留，普通会话是显式次级切换。
- Flutter 的最近会话/全部会话保留现有普通会话用户旅程，但不在首页显示全局 DSH 新建入口，也不把普通会话混入 DSH workspace detail。
- 用户从普通历史页进入 DSH session 时，仍受 workspace 的 home Terminal 与 V08-12 恢复状态约束；只读浏览不得隐式 load/resume。

## 4. 受影响边界与契约

| 边界 | 变更 | 不变量 |
| --- | --- | --- |
| Daemon Scanner | 给 DSH candidate 附加受控 `display_name`，继续只读扫描 | 不创建目录、不跟随 symlink、不上传 root/JSONL 正文 |
| Store / Domain | Workspace 显式 `origin/display_name`；DSH session create 校验 Workspace + home Terminal + capability | identity 仍是 canonical root；不以名称或 ID 前缀判断 |
| Relay HTTP | 复用 sync/import API；`GET /workspaces` 扩展安全字段；`POST /sessions` 对 dsh 加强校验 | owner/write、账号、Terminal fence 与幂等保持 fail-closed |
| Flutter Relay Repository | typed sync/import state 和 workspace projection 解析 | HTTP body 不伪造 device/account/root |
| Flutter SessionController | 管理 DSH sync/import 的短生命周期状态、刷新和错误；以 Workspace 先于 Session 渲染 | 不在客户端扫描本机，也不缓存路径/正文 |
| Flutter UI | DSH 默认工作区分组栏、Workspace detail、新建/导入下沉到详情、移除全局加号 | Web/只读无写操作；普通历史入口仍可浏览 |
| Web | 默认只读 DSH Workspace 分组栏/会话视图，次级切换浏览普通会话 | 不添加 sync/import/create/resume/send |

## 5. 迭代工作流与阶段门

### 5.1 固定执行顺序

遵循“先契约，后细纵向链路，再扩展 UI，最后全量验收”的顺序；不要先堆 UI 或把 fixture 结果表述成真实 DSH 已通过：

1. **P0 合同门**：先迁移 Workspace 安全投影与 DSH create fence；Go 单元/Relay 契约必须先绿，才能让客户端开始消费新字段。
2. **P1 细纵向切片**：用受控授权根 fixture，完成“owner 同步 → Relay result → 一个空工作区分组可见”。这是本轮最小可交付链路；先做它，不能先实现搜索、筛选或历史导入。
3. **P2 工作区内操作**：在 detail 中完成 DSH create 与按需 import；每个写操作都先验证 Terminal、role 和 capability，再补根因层与 widget 回归。
4. **P3 可见交互验收**：对齐宽屏分组栏/窄屏详情导航与 Web 只读投影。先跑 fixture full gate，再以 headed Chrome 和可见 Flutter 窗口验证用户路径。
5. **P4 收口**：建立 V081 结构化用例、Task 聚合入口、覆盖缺口表和脱敏报告；在项目文档回填后再声明迭代完成。

每个阶段开始时先把该阶段的勾选项复制到实施记录；结束时必须记录运行命令、退出码、测试 ID、证据路径、验证口径和残余风险。不可因测试失败而跳过、弱化断言或把失败标为 flaky。

### 5.2 验证口径与权限门

| Gate | 目的 | 数据/权限 | 通过证据 |
| --- | --- | --- | --- |
| local smoke | Workspace projection、sync/import 状态机和 create fence | 临时目录、Relay fixture；`local_test=true` | Go/Flutter/Web 定向测试 |
| targeted diagnostic | 复现离线、跨 Terminal、同名、路径泄露或 selector 问题 | fixture；不扫描真实根 | 对应测试 ID 的失败分类与修复回归 |
| fixture full gate | 覆盖 V081 全部 P0/P1 用户旅程 | 隔离 Relay + DSH JSONL fixture；`fixture_data=true` | `task test:v081:local` 全绿 |
| visible UI gate | 验证实际可见布局、焦点、375px 和只读行为 | headed Chrome、可见 macOS Flutter fixture | browser/desktop report；不等同真实 DSH |
| authorized local smoke（可选） | 验证一次真实 Terminal 在用户授权根内发现项目 | 需用户明确同意读取项目元数据；不读正文、不调用模型 | 脱敏计数报告；`real_model=false`、`real_upstream=false` |

本期默认不请求模型、不读取历史正文、也不调用外部付费服务。因此 `real_model=false`、`real_upstream=false`。只有用户显式授权真实根后，才执行最后一行 local smoke；该动作会在测试账号/本机 Relay 中新增安全 Workspace 元数据，结束后按测试清理方案移除，不能冒充为纯 fixture。

### 5.3 失败处理与恢复

- `TERMINAL_OFFLINE`、`CAPABILITY_UNSUPPORTED`、`WORKSPACE_MOVED`、`SCOPE_DENIED` 均显示可理解状态，不自动换一台同路径 Terminal 重试。
- 浏览器 selector/等待失败归为 `selector_or_dom_contract_defect` 或 `test_harness_defect`；补稳定 `Key`/`data-testid` 和状态等待，不能以固定 sleep 掩盖。
- migration、投影或 direct API 断言失败归为 `product_defect`；从 P0 修复并补回归后再继续 UI 阶段。
- V08-12 的 `model_contract_failure` 继续在原 gate 保留；不得因 V081 的新建、导入或 fixture 成功而改写其状态。

## 9. 风险、回滚与前置依赖

| 风险 | 处理 |
| --- | --- |
| 仅在 UI 加按钮，后端仍接受任意 DSH workspace | P0 先加服务端 origin/home Terminal/capability fence，并有直调 API 回归 |
| 公开项目全路径或用 hash ID 代替项目名 | 仅传经校验的 basename display name；不在日志、API、测试报告写 canonical root |
| 同步默认自动扫描，超出授权 | 仅显式 owner/write 动作触发；下拉刷新只刷新 Relay metadata |
| 空项目被 UI 隐藏 | 先以 Workspace 渲染，再附着 Session；空态是分组内部状态 |
| 参考侧栏在手机上信息过密 | 宽屏用 master-detail；窄屏进入详情页；长名称截断、会话行按需展开，375px gate 覆盖 |
| workspace 列表过长 | `ListView`/等价懒渲染、局部搜索和折叠状态；禁止一次展开所有会话组 |
| 历史会话标题泄露 prompt/path | 仅允许安全固定标签、Agent Sessions 用户命名和白名单时间字段；不解析 DSH transcript 标题 |
| 工具栏 folder-plus 被误解为创建本地目录 | 同步动作使用明确刷新文案/语义，不新建目录、不 `git init` |
| 组头点击与展开手势冲突，误把用户带离列表 | 展开箭头与组头拆成独立控件；以 widget + headed E2E 固定语义、焦点和返回状态 |
| “停止等待”被理解为取消已投递同步 | UI 明确为停止客户端轮询；后端命令继续按既有幂等状态机收敛，重开页面后刷新投影 |
| 迁移影响既有 managed Workspace | migration 默认 `origin=managed`，仅 v0.8 scanner result 标为 `dsh`；可回滚 UI 默认视图并保留数据 |
| v0.8 Resume gate 失败被新 UI 测试掩盖 | V08-12 继续保持 failed；V081 不把 fixture 建会话表述为真实恢复或模型通过 |
