# Agent Sessions 迭代计划 v0.7：OpenCode Zen 免费模型全链路测试 + 会话内新建工作区

> 状态：`partial / 2026-08-29`
> P0-P5 已按阶段提交并完成本地/fixture 验证；Zen 真实模型 gate 因本机没有官方 Free provider 交集保持 `blocked`，因此不能把 v0.7 标记为真实模型全绿。各阶段证据见实施记录。
> 授权口径：本轮唯一授权的真实模型范围是 **OpenCode Zen 免费模型**（官方标注 Free 的条目，见 §4.1）。免费模型当前 input/output 均为 0 费用，但官方声明"limited time、可能轮换"，且 NVIDIA 系 trial 条款禁止提交个人/机密数据——测试问答必须使用无敏感内容的固定随机池。付费模型、真实付费上游、Android 实机均不在本轮范围。
> 流程遵循 `web-iterative-workflow` 技能：验证口径四分类（smoke → targeted diagnostic → full gate → recording）、失败分类表、证据报告 schema、每个已修复缺陷必须有根因层回归。

## 1. 背景与问题

1. **OpenCode Provider 当前不可用（截图已复现）。** 根因：近期本地栈重启均带 `--no-opencode`，OpenCode Server（`opencode serve`，127.0.0.1:4096）未运行，适配器 `GET /global/health` 探测失败后整体 fail-closed，App 显示「Provider 当前不可用」。这是启动编排回归，不是适配器缺陷；restart.sh 默认就是 `--with-opencode`。
2. **没有真实模型全链路证据。** 自动化测试文档明确记载"经授权消耗 token 的真实 Provider full gate 一直是后续独立 gate"。v0.7 用 Zen 免费模型补上这条链路，且零费用。
3. **新建会话只能挂到既有工作区。** 当前 `POST /v1/workspaces` 只登记元数据（`canonical_root` 由调用方给出，daemon 侧需要本机已确认的 root 才能 Start）。用户要求：创建会话时可直接**新建工作区 = 在 `/Users/yubi/code/`（授权根，可配置）内部新建文件夹**并绑定。
4. **回归脚本分散。** 现有门禁分散在 `Taskfile.yml`（test:relay/daemon/contract/e2e:relay/v06…）、`tools/restart_test.sh`、`e2e-verify/run.mjs` 各 suite、`apps/mobile`（flutter test / 集成 gate / 录屏）。需要统一入口与清单，避免"每次迭代重新找测试"。

## 2. 目标与成功标准

### 2.1 目标

- G1 修复 OpenCode Server 启动编排回归，App 新建会话不再出现「Provider 当前不可用」。
- G2 打通 Zen 免费模型真实链路：App（Flutter macOS）→ Relay → Daemon → OpenCode 适配器 → OpenCode Server → Zen 免费模型，回复流式返回并以 `turn.completed(idle)` 收口。
- G3 随机问答全链路测试：随机生成若干组问答（固定无敏感词池 + seed），经真实链路发送并断言回复、usage 投影与终态。
- G4 新建工作区：新建会话页支持「新建工作区」，在授权根（默认 `/Users/yubi/code/`）内部 mkdir `<name>`、登记 workspace（canonical_root 指向该目录）、daemon 本机确认后即可 Start。
- G5 回归测试统一管理：一份测试地图 + 一个聚合入口 + 结构化用例注册（`docs/test/10-v0.7全链路.json`）。

## 4. 关键设计

### 4.1 OpenCode Zen 免费模型接入

- Zen 是 OpenCode 官方托管模型网关；模型以 `opencode/<model-id>` 选用（如 `opencode/big-pickle`）。**当前免费清单**（2026-08-29 调研，按月轮换，实施时以当日 `/models` 为准）：`big-pickle`、`mimo-v2.5-free`、`hy3-free`、`ling-3.0-flash-fin-free`、`nemotron-3-ultra-free`、`nemotron-3.5-lightning-free`、`muse-spark-1.2-contributor-free`。
- 链路：用户在 opencode CLI 完成 Zen 认证 → `opencode serve`（4096）以用户默认模型/会话模型执行 → 我们的适配器按会话 model 传参。relay/daemon **不接触** Zen API key（key 只在 opencode 本机配置内），凭据边界不变。
- 模型选择链路：新建会话默认模型取 `AGENT_SESSIONS_OPENCODE_DEFAULT_MODEL`（新增，默认 `opencode/big-pickle`，非空才透传）；App 端 OpenCode 会话的 model select 读取 daemon 能力矩阵与该默认值，可切换到当日其它免费模型。禁止把付费模型 ID 硬编码进默认值。

### 4.2 新建工作区（授权根内新建文件夹）

- 授权根：`AGENT_SESSIONS_WORKSPACE_ROOT`（daemon 端新增，默认 `/Users/yubi/code/`，必须已存在；daemon 启动时校验并把绝对路径规约为 workspacesafe 根）。
- 新增 daemon 命令 `workspace.create`（走既有 terminal 命令信道，owner 设备发起）：
  1. 校验名称 `[a-zA-Z0-9._-]{1,64}`，拒绝 `..`、绝对路径、隐藏名；
  2. 在授权根内 `mkdir <root>/<name>`（已存在且为目录则复用，非目录则拒绝）；
  3. `workspacesafe` 校验新目录是干净 git 可初始化根（沿用既有安全规则，不放宽）；
  4. daemon 本机确认（ID+Root 落 daemon store）并回执 canonical_root；
  5. Relay 侧 `POST /v1/workspaces` 登记（`terminal_id` 绑定当前 daemon，project 自动创建）。
- Relay 端新增编排接口 `POST /v1/workspaces/create-with-folder`（owner 写设备专用）：串起 4.2 的命令流并幂等（同名已存在 → 返回既有 workspace）。App 新建会话页新增「新建工作区」入口：名称输入 → 调用 → 成功后选中新工作区。
- 安全边界：文件夹只能创建在授权根的**直接子级**；命令执行、路径逃逸、越权 terminal 全部沿用既有拒绝语义并新增契约回归。

### 4.3 随机问答生成与断言

- 生成器 `e2e-verify/real/qa_generator.mjs`：固定无敏感问题模板池（≥30 条，中英文各半，覆盖短/长/代码/数学/翻译类型）+ seed 随机抽样与措辞扰动；输出 `{question, minExpect}`（如"代码类回复必须包含代码块围栏"这类弱断言，不做全文 oracle）。
- 断言口径（对每组问答）：assistant 回复事件到达且非空 → `message.completed` 落库 → 会话终态 `turn.completed(idle)`；usage 投影 input/output > 0；连续失败归入 `model_contract_failure` / `model_flakiness`（重试上限 2 次，失败保留证据不标绿）。
- 与归档/休眠共存：长跑会话通过持续发送保持活动；测试结束主动归档清理或保留为证据数据（二选一，见 P4）。

### 4.4 回归测试统一管理

- **测试地图**：`docs/zh/自动化测试文档.md` 新增「v0.7 测试地图」小节，列出每类测试的目录 + 命令（结构化用例 / Go 单元与契约 / Flutter 定向与 gate / headed 浏览器 / 真实模型 / 录屏 / 诊断证据）。
- **聚合入口**：`Taskfile.yml` 新增
  - `test:v07:local`：本地全量（task check + relay/daemon/contract/e2e:relay + restart_test + Flutter 定向 3 文件）；
  - `test:v07:real`：真实模型全链路（显式 `AGENT_SESSIONS_ZEN_REAL=1` 才可执行，内部先 smoke 后 full gate， headed 浏览器步骤置 `HEADLESS=false`）；
  - `record:v07`：Flutter 录屏 + Web CDP 录屏入口。
- **结构化用例**：新增 `docs/test/10-v0.7全链路.json`（稳定 ID `V07-*`），注册进 `docs/test/测试套件索引.json`；真实模型用例单列 `real_model: true` 口径，fixture 用例不得混称。

## 7. 风险与回滚

| 风险 | 影响 | 对策 |
|---|---|---|
| Zen 免费清单轮换/限流 | full gate 模型名失效 | 用 `/models` 动态发现；模型名不进断言硬编码；模型目录变更即 checkpoint 失效（旧 checkpoint 改名 `.stale-<ts>` 保留） |
| 免费模型质量不稳（长文/代码问答） | 弱断言也失败 | 失败分类 `model_contract_failure`/`model_flakiness` 分离统计；重试上限 2；不静音不标绿 |
| `~/code/` 下误删/覆盖 | 数据损失 | 只创建不删除；已存在目录复用前校验为目录且为空或已是确认根；所有写操作限授权根直接子级 |
| opencode 端口冲突/启动慢 | P0 阻塞 | 复用 restart.sh 既有等待/清理；环境失败按 `environment_or_startup_failure` 处理后重跑 |
| macOS Screen Recording 权限或严格帧节拍 | 录屏场景无法全部使用原生窗口捕获 | 保留 `flutter-render-boundary-fallback` capture mode，逐场景校验完整 5fps 帧序列与 MP4；权限稳定后可补录 `macos-window` 证据 |
| 真实链路长跑触发自动归档/休眠 | 断言干扰 | runner 保持会话活动或结束后从归档视图断言；断言口径写入 V07-06 用例 |

## 8. 凭据与安全

- Zen API key 只存在于 opencode 本机认证配置；relay/daemon/报告/日志/录屏不得出现 key 或完整模型正文。
- 报告只记录 `credential_source: opencode-local-auth`、HTTP 状态、usage 计数与脱敏摘要。
- 随机问答池不含个人/机密数据（NVIDIA trial 模型条款）。
- 预计请求量：P3 smoke ≤6 次请求；P4 full gate ≈ 3 会话 × 4 问答 × 2 模型 ≈ 24 次 + 重试余量，全部落在免费条目；任一环节出现计费提示立即停止并标记 `credential_or_quota_blocker`。
