# 迭代计划 v0.10.0：Owner 多设备与配对加入

> 状态：`planned`（2026-09-29 立项；ADR-017 已落档）。用户裁决（2026-09-29「马上进行这个改造」）：现有手机保留为测试机**不被撤销**，新设备经「owner 配对」加入。前置：无（不依赖 v0.9.7 soak 收口，可并行）。

## 0. 背景与目标

单 active owner 模型下，新手机上线唯一路径是恢复码接管（互斥替换），无法实现「日常机 + 测试机并存」。本迭代新增 **owner 配对加入**：新设备生成配对请求 → 现役 owner 批准 → 新设备以第二个 active owner 上线，**既有设备零变化**。安全模型与不变量见 [ADR-017](../../adr/ADR-017-owner多设备与配对加入.md)。

非目标：终端配对语义不变；恢复码接管语义不变；不支持 owner 权限分级（首版所有 owner 等权）。

## 2. 阶段 P1：服务端契约（P0，2 天）

- [ ] 2.1 存储迁移（additive）：`pairing_requests` 补 `role` 列（默认 terminal）；owner 请求唯一 pending 约束（单账号 ≤1）。
- [ ] 2.2 域层：`CreatePairing` 接受 role=android_owner（校验公钥形状）；`ApprovePairing` 分支——owner 批准不撤销任何设备、创建 owner 设备行 + token pair + `device.paired` 审计；总开关 `AGENT_SESSIONS_OWNER_PAIRING`（默认 off，off 时创建端点返回稳定错误）。
- [ ] 2.3 HTTP：创建/轮询/批准三端点按 role 分支；未认证创建端点加防滥用（TTL 10min、过期清理）。
- [ ] 2.4 撤销语义：owner 可撤销其他 owner；撤销最后一个 active owner 后 bootstrap 重开放（等价首部署）。
- 测试 ID：OWN-01（未认证创建：TTL/单 pending/审计）、OWN-02（批准 → 新设备 active + 既有设备零变化）、OWN-05（撤销语义两分支）、OWN-07（开关关闭拒绝）。
- 验收：`go test ./internal/...` 全绿；契约测试钉住「不撤销」不变量。
