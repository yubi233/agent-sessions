## 1. 计划口径与完成定义

### 1.1 目标

v0.4 同时解决三个问题：

1. **核心闭环完整**：身份与配对、机器在线、Daemon 连接、会话启动与控制、事件同步、Provider 能力、文件与 Git 只读、设置、用量和通知形成真实链路。
2. **跨端职责一致**：Android 继续作为唯一写控制端；Web 只读查看会话与代码；Admin 只看运维白名单元数据；Relay 不读取工作区或执行 Agent；Daemon 不越过已授权 Workspace。
3. **全端体验统一**：借鉴 Apple 官网与 HIG 的克制层级、内容优先、响应式、语义色和可访问性，不复制 Apple 的营销布局、品牌、图片、字体文件或源码。

“全面复刻”在本文中指**对已核实核心用户旅程的行为对齐**，不是：

- 复制 Happy 源码、品牌、wire protocol、Socket.IO 房间或服务端内部实现；
- 把 Happy 的所有实验功能、社交功能和商业功能都搬入本项目；
- 用只有 UI 的 fixture 页面替代真实 API、权限、存储、加密和错误恢复；
- 要求四个 Provider 支持完全相同的能力。Provider 差异必须通过 `native / emulated / unsupported` 明示并 fail-closed。

Happy 的桌面/移动交接在本项目中映射为“PC Daemon 持有本地进程与 Workspace，owner Android 持有唯一远程写租约”。这是一项明确的安全适配，不引入桌面 Web、Admin 与 Android 多写端竞争；对外对标时必须声明该差异。

### 1.2 核心能力的完成判定

每项核心能力只有同时满足以下条件，才可标记 `completed`：

- 有真实用户入口，并覆盖 loading、empty、error、offline、forbidden、unsupported、stale、success 状态；
- 公开契约已进入 OpenAPI/JSON Schema 或所属领域唯一事实源，客户端生成物无漂移；
- 鉴权、scope、owner、lease epoch、幂等、路径边界和 E2EE/元数据边界已明确；
- 需要持久化时有 SQLite 迁移、升级兼容、备份恢复和回滚策略；
- 有根因层回归和跨层用户旅程，不依赖个人本地状态；
- 真实链路需要外部 Provider、Push 或 Android 原生能力时，已完成对应真实 gate，不能用 fixture 标绿；
- 用户可见界面完成多视口、键盘/读屏、200% 文本和 reduced motion 验收；
- 项目文档、结构化测试、自动化测试文档和实施记录已经回填为同一事实。

状态词统一为：

| 状态             | 含义                                                    |
| ---------------- | ------------------------------------------------------- |
| `real`           | 真实本地或真实上游链路存在，并有长期回归证据            |
| `partial`        | 只有部分层级、部分 Provider 或部分状态真实可用          |
| `fixture_only`   | 仅 deterministic fixture/mock，可用于开发但不计核心完成 |
| `planned`        | 已有范围与契约计划，尚未实施                            |
| `decision_gated` | 必须先完成 ADR、安全/数据决策，不能直接排 UI            |
| `excluded`       | 经产品决策排除，不计核心差距                            |
| `blocked`        | 实施后因凭据、真实设备、额度或外部授权无法完成真实 gate |

## 4. Happy 核心能力对照

### 4.1 固定基线中已核实的功能域

Happy 核心产品价值由以下行为组成：

- iOS、Android、Web 与 CLI/Daemon 共同提供远程 Claude Code/Codex 会话控制和设备交接；

## 5. v0.4 范围边界

### 5.1 核心退出范围

以下能力必须真实完成，才能宣称“v0.4 Happy 核心复刻完成”：

1. 现有认证、配对、设备撤销、恢复码和 E2EE 回归保持通过。
2. Relay 与 Daemon 有认证、heartbeat、命令下发、ack、事件回写、cursor/outbox 重放的完整链路。
3. Android 可从真实 Terminal 创建/启动会话，执行 send、abort/kill、恢复，并观察 canonical event 与断线恢复。
4. P2 基础闭环先由至少一个 Provider 完成真实 transport gate；最终若使用“Happy 核心全面复刻”表述，Claude 与 Codex 还必须分别完成最小 `start/send/abort/event` 真实 gate。OpenCode 是本项目扩展基线，不能单独替代 Happy 的 Claude/Codex 对标证据；OpenClaw 可按产品支持矩阵保持 unsupported。
5. 文件树、代码阅读和 Git 只读从真实临时 Workspace 贯通，路径逃逸、二进制、超大文件和 stale snapshot 安全降级。
6. 设置、机器状态、会话 info、recent、单消息/文本选择、用量和通知具有真实数据边界。
7. Web 完成核心只读旅程，Admin 完成运维白名单旅程，服务端拒绝两者所有写请求。
8. Flutter、Web、Admin 全部界面完成统一主题、响应式、可访问性和可见验收。
9. 可见 Android AVD 通过；涉及 Keystore、Push、厂商后台和物理设备性能的声明必须有物理 Android 证据。
10. 需求、测试、运行结果、证据、文档回填和残余风险形成闭环。

## 6. 目标架构与公开契约

### 6.1 端侧职责

```text
Flutter Android 写控制端
  |  REST 写入 + 账号级 SSE 读取
  v
Relay: 身份、元数据、密文事件、命令、租约、cursor、审计
  |  认证的 Terminal 命令流 + REST ack/event 回写
  v
PC Daemon: Workspace 安全、进程监督、Provider Adapter、离线 outbox
  |
  +-- Claude / Codex / OpenCode / OpenClaw capability matrix

Vue Web --------> Relay 只读 API/SSE，不注册写入口
Vue Admin ------> Relay 运维白名单 API，不接触正文/文件/diff
```

优先在现有 REST + SSE 架构上补 Daemon 下行命令流与上行 ack/event。只有 ADR 证明双向延迟、背压或代理兼容必须使用 WebSocket 时，才新增 WebSocket；不能因为 Happy 使用 Socket.IO 就直接复制。

### 6.2 P0 必须冻结的契约

实施前在 OpenAPI/JSON Schema 和 ADR 中冻结以下语义，端点名可按现有命名规范调整：

| 契约                     | 必须定义的字段/行为                                                                                  | 安全要求                                                  |
| ------------------------ | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| Terminal hello/heartbeat | protocol version、terminal/device ID、daemon version、platform、capability hash、last cursor、时间戳 | Terminal 凭据、重放窗口、撤销设备即时失效                 |
| Terminal command stream  | command ID、scope、kind、payload version、lease epoch、idempotency key、target instance、cursor      | 只允许目标 Terminal；未知 kind fail-closed；可恢复 cursor |
| Command ack/result       | accepted/running/succeeded/failed/cancelled、attempt、safe error code、event cursor                  | 不回传原始 prompt、密钥、绝对路径或日志正文               |
| Session event upload     | session/instance ID、sequence、event kind、ciphertext envelope、usage whitelist、idempotency key     | 单调 sequence、重复抑制、scope 与 instance 校验           |
| Presence                 | online/offline/stale、last seen、连接代次                                                            | 进程内可重建，不冒充持久事件                              |
| File/Git read RPC        | workspace ID、相对路径、snapshot ID、分页/大小限制                                                   | canonical root、symlink/路径逃逸拒绝、只读、审计          |
| Capability matrix        | Provider、version、available、reason、每能力三态                                                     | 未探测、过旧、异常一律 `unsupported`                      |
| Usage                    | metric version、Provider、session/event 去重键、时区、bucket、input/output/cache/context             | 只存白名单计数或账号级密文，不存正文                      |
| Push                     | device token reference、event category、deep-link reference、revocation                              | 通知正文最小化；撤销后不能继续发送                        |

稳定错误至少覆盖：`SCOPE_DENIED`、`LEASE_STALE`、`IDEMPOTENCY_CONFLICT`、`TERMINAL_OFFLINE`、`UNSUPPORTED_CAPABILITY`、`CURSOR_EXPIRED`、`WORKSPACE_PATH_DENIED`、`PROTOCOL_VERSION_UNSUPPORTED`。最终名称服从现有错误码注册表，禁止客户端解析自由文本。

### 6.3 版本与兼容

- Relay、Daemon、Flutter、Web 的协议声明携带明确版本，不以应用版本字符串代替 wire version。
- 先部署兼容旧客户端的 Relay，再更新 Daemon，最后发布客户端；至少支持 N/N-1 读取与明确的升级提示。
- 新字段默认可选且 fail-closed；删除或改义字段必须经过弃用周期。
- capability hash 变化触发客户端重新读取矩阵，旧缓存不能自动把能力升级为 `native`。
- 断线重连后按 cursor 恢复；cursor 过期必须回到受限 snapshot，而不是静默丢事件。

## 8. Apple HIG 启发的全端设计系统

### 8.1 设计原则

- **内容优先**：控制台保持紧凑、可扫描，不把运营工具改成营销落地页。
- **清晰层级**：页面标题只服务页面定位；卡片和侧栏内使用紧凑标题，不使用巨型 Hero 字号。
- **平台一致性**：Flutter 使用 Material 3 与平台语义；Web 使用语义 HTML；不强行把 Android 控件伪装成 iOS 控件。
- **克制表面**：页面 section 不做漂浮卡片；卡片只用于独立重复项、确认面板和工具结果，普通卡片圆角不超过 8px。
- **真实状态**：颜色、图标和文案共同表达在线、警告、错误和 capability，禁止只靠红黄绿。
- **可恢复交互**：破坏性操作二次确认，异步动作有 pending/result，网络恢复后不重复提交。

### 8.2 设计令牌

| 域   | 规则                                                                                                                                                 | 验收                                                                    |

### 8.4 体验与性能预算

- Web/Admin production build 在本地测试环境的 LCP 不高于 2.5s、CLS 低于 0.1；异步状态切换不产生不可解释的布局跳动；

- 不含 Provider 推理时间的本地 command enqueue-to-ack p95 目标不高于 500ms；event ingest-to-client p95、heartbeat age 和 reconnect 次数同时记录；
- 超大文件和 diff 沿用明确的大小上限、分页或受限摘要，不能为追求动画效果一次性渲染全部内容。

### P2：Relay-Daemon-Provider 最细真实纵向链路

**目标**：完成远程控制核心闭环，这是后续机器页、代码页和真实 Android 旅程的前置。

实施顺序：

1. 协议：Terminal hello/heartbeat、command stream、ack/result、event upload、错误码、版本协商。
2. 持久化：命令状态、cursor、审计和必要索引的 additive SQLite migration。
3. Relay：Terminal 认证、目标 scope、lease/idempotency、stream 恢复、事件入库和账号 SSE 投影。
4. Daemon：凭据读取、连接状态机、指数退避、有界重试、命令去重、ack、event/outbox 回写。
5. 进程：真实 Workspace 内启动一个 Adapter session，处理 send、abort、退出和清理。
6. 客户端：Android 从真实 Terminal 发起一次会话并观察事件，不依赖本地 fixture。
7. 回归：先 deterministic Adapter 证明协议，再经授权跑 OpenCode 真实 transport；两类证据分开报告。
8. 可观测性：记录脱敏的 heartbeat age、连接代次、命令队列深度、enqueue-to-ack 延迟、event lag、重连次数和 Provider 错误分类；指标标签不得包含正文、密钥或完整路径。

文件/Git 同阶段完成一条只读链路：真实临时 Git 仓库 -> Daemon 路径安全/Git 服务 -> Relay 密文/白名单契约 -> Android 文件/代码/Git UI。

## 10. 数据、迁移、发布与回滚

### 10.1 数据所有权

| 数据                     | 所有者/事实源     | Relay 可见性                    | 持久化策略                                           |
| ------------------------ | ----------------- | ------------------------------- | ---------------------------------------------------- |
| 外观/动效/密度偏好       | 单个客户端        | 不可见                          | Flutter 本机数据库；Web local preference，仅非敏感值 |
| Terminal presence        | Relay 进程内投影  | 白名单状态                      | 可重建；只持久化 last seen/版本摘要                  |
| 命令与状态               | Relay SQLite      | scope、kind、状态、密文 payload | 幂等、有限保留、审计，不存原始正文                   |
| Provider thread/本地日志 | Daemon 本机       | 不可见                          | 本地加密状态；日志脱敏与轮换                         |
| Session event            | Relay SQLite      | 密文 envelope + 最小索引        | 单调 seq、cursor、账户/Session scope                 |
| 文件/代码/diff           | Daemon Workspace  | Relay 只路由密文/受限摘要       | 不建立服务端明文副本；大小与生命周期受限             |
| Usage                    | 由 usage ADR 决定 | 仅白名单计数或账号级密文        | event 去重、bucket version、时区定义                 |
| Push token               | 设备/Push adapter | token reference 与类别          | 撤销、退出和设备删除时清理                           |
| Artifact/share           | 未决定            | 未决定                          | ADR 前不建表、不做假链路                             |

### 10.2 SQLite 迁移规则

- 迁移归 `internal/store/migrate.go` 及其测试，禁止另建无人消费的迁移体系。
- 优先 additive table/column/index；迁移有稳定版本、事务边界和幂等测试。
- 升级前执行备份与 integrity；迁移失败保持旧库可启动或明确停止，不能半迁移运行。
- 新 Relay 先兼容旧 Daemon/客户端；写入新格式前通过 feature flag/capability 协商。
- 破坏性清理至少延后一个发布周期，并保留统计证明旧格式不再使用。
- 迁移测试覆盖空库、现有数据、重复执行、磁盘/约束失败、重启和恢复备份。

### 10.3 分阶段发布

1. 发布兼容旧客户端的 Relay schema/读路径，功能默认关闭。
2. 发布 Daemon 协议与能力，验证 heartbeat/command/event，再开启小范围 feature flag。
3. 发布只读 Web/Admin，不改变权限。
4. 发布 Android 新路由与写能力，按 server capability 显示。
5. 观察错误、重连、队列和迁移指标后扩大范围。
6. 只有 N/N-1 使用率满足弃用条件后，才删除兼容分支。

### 10.4 回滚

- UI：语义 token 和新路由用 feature flag/导航隐藏回滚，旧数据与选择器保持兼容。
- Relay：关闭新 capability 与命令接受；保留 additive schema，不做未经验证的 down migration。
- Daemon：停止获取新 kind，旧版本看到未知命令必须拒绝并回报 `unsupported`。
- Android：服务端 capability 关闭后入口自动不可用，已发幂等命令仍可查询终态。
- Usage：停止新 bucket 写入，旧会话计数仍可显示；不得因回滚重复聚合。
- Push/更新/分享/Artifact：各自有 kill switch；撤销与删除路径必须在关闭创建后继续可用。

## 12. 验证命令与证据口径

实施后的本地 full gate 不能只执行 `task test`，因为它不包含 Flutter、headed E2E、部署、真实 Provider 或录屏。按实际影响显式运行：

```text
task docs:verify
task check
task test
task test:android
task test:deploy
task test:e2e
task test:flutter:local
task test:android:e2e
```

真实 Provider、物理 Android 和录屏独立运行：

- `task test:real -- ...`：仅在用户授权请求数、Provider/model、token/额度和凭据来源后执行；
- 物理 Android gate：P5 建立长期入口后执行，不能用 AVD 代替；
- `task test:record`、`task test:flutter:record -- --gate-report <passed-report>`：只在对应 full gate 通过后执行。

证据必须区分：

| Gate               | real_browser  | real_model | real_upstream | fixture_data | local_test | headless | 不能证明                               |
| ------------------ | ------------- | ---------- | ------------- | ------------ | ---------- | -------- | -------------------------------------- |
| Vue/Vitest         | false         | false      | false         | true/false   | true       | false    | 可见浏览器与视觉                       |
| headed Web/Admin   | true          | false      | false         | true         | true       | false    | Flutter/真实 Provider                  |
| Flutter macOS 可见 | false         | false      | false         | true         | true       | false    | Android 原生/真机                      |
| Android AVD        | false         | false      | false         | 可选         | true       | false    | 物理设备/厂商后台                      |
| 物理 Android       | false         | false      | 视数据源      | false        | true       | false    | 未调用的真实 Provider                  |
| Provider live      | false         | true       | true          | false        | false      | false    | Relay-Daemon-Mobile 闭环，除非专门串联 |
| recording          | 继承对应 gate | 继承       | 继承          | 继承         | 继承       | false    | 断言本身                               |

报告在现有 schema 外增加 `simulated_device`、`real_device` 和 `protocol_version` 时，必须保持向后兼容。HTTP 200、截图、DOM 快照、RepaintBoundary fallback、视频、mock success 都不能单独证明业务契约完成。

## 13. 风险、阻塞与决策门

| 风险/阻塞                          | 影响                                      | 处置与停止条件                                          |
| ---------------------------------- | ----------------------------------------- | ------------------------------------------------------- |
| 权威文档与代码冲突                 | 错误 API、测试和完成声明                  | P0 未对齐前不开始跨层实现                               |
| Daemon 无真实 Relay 闭环           | 机器、会话、文件、Push 上层均可能是假能力 | P2 作为首个核心纵向切片，不允许 UI 绕过                 |
| Happy 服务端源码目录缺失           | 无法验证内部实现                          | 只做行为参考，自建 ADR/契约/威胁模型                    |
| Provider 能力不对称                | UI 暴露无法兑现操作                       | 三态 capability + 真实 Provider 独立 gate               |
| Android 证据主要来自 macOS fixture | 原生权限、Keystore、通知和性能未知        | AVD + 物理设备分级，不混称                              |
| Push/真实模型需外部凭据与额度      | 无授权时无法完成真实 gate                 | 提前说明请求/费用；无授权标 `blocked`，不伪造           |
| usage 去重/时区/隐私未决           | 图表数字不可信或泄漏元数据                | usage ADR 前不实施统计页成功态                          |
| UI 大面积重构                      | 选择器、性能、信息密度回归                | 语义 token 小切片迁移，保留稳定选择器，逐屏 gate        |
| 更新/分享/Artifact 安全模型缺失    | 供应链或数据泄漏                          | ADR、撤销/回滚先于 UI；默认关闭                         |
| MIT/第三方/品牌边界                | 合规风险                                  | 行为重写、NOTICE 审计、独立品牌与资产                   |
| SQLite migration/旧客户端          | 启动失败或数据不兼容                      | additive migration、N/N-1、备份/integrity、feature flag |

实施前必须明确 owner 的决策：

- `D1` Daemon 下行使用 SSE 还是引入 WebSocket；默认选择现有 REST+SSE。
- `D2` usage 是设备本地、Relay 白名单聚合还是账号级密文聚合。
- `D3` v0.4 支持哪些 Provider 的哪些真实能力；未选项保持 unsupported。
- `D4` 物理 Android 与 UnifiedPush 环境、凭据和验收设备。
- `D5` 更新清单的签名者、发布源和回滚策略。
- `D6` Artifacts 是否进入 v0.4；分享默认不进入核心。

## 14. v0.4 最终退出条件

只有以下全部成立，才能将计划状态从 `not_started/in_progress` 改为 `completed`：

- 第 5.1 节十项核心退出范围全部为 `real`，或对外声明明确缩小且未把 blocked/fixture 说成完成；
- Relay-Daemon-Android 的真实本地跨层闭环通过；Claude 与 Codex 分别完成最小真实 gate，或计划保持 `blocked/incomplete` 且不使用“Happy 核心全面复刻完成”表述；
- Web/Admin headed 多视口旅程通过，服务端写权限反向测试通过；
- Flutter macOS fixture 通过开发 gate；可见 Android AVD 与物理设备的核心旅程分别通过，并按各自口径报告；
- 所有 P0/P1 结构化用例都有可执行前置、步骤、预期、清理和长期测试文件；
- 新增/修复的每个 P0/P1 行为均有根因层回归，用户可见跨层行为有 E2E；
- 主题、200% 文本、键盘/读屏、reduced motion、最小视口、浅深色和长内容检查通过；
- SQLite migration、备份/恢复、明文扫描和 N/N-1 兼容通过；
- full gate 通过后才生成录屏，报告不含密钥、正文、diff、附件或原始 Provider 回复；
- 覆盖审计逐项完成：需求 -> 测试 -> 结果 -> 证据 -> 文档回填 -> 残余风险；
- 项目文档、ADR、自动化测试文档、结构化 suite、实施记录和 Happy 对比记录反映同一当前事实。

以下表述禁止出现在交付结论中：

- “fixture 已通过，所以真实分享/Artifacts/Push 已完成”；
- “macOS Flutter 窗口证明 Android 真机通过”；
- “OpenCode CLI smoke 证明完整移动端远程控制通过”；
- “HTTP 200 或录屏证明业务 oracle 通过”；
- “视觉场景写进文档即等于 runner 已登记”。
