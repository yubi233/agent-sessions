# Agent Sessions 迭代计划 v0.5：按 DeepSeek Harness 会话模块重构移动端会话 UI

> 状态：`planned / design_only`
> 本文只规划，不实施代码改动。
> 交互基准：本机 `/Users/yubi/code/deepseek-harness` 的实际会话 UI 模块源码与 E2E 契约。

## 1. 目标

把当前 Flutter 会话详情页从“控制面板 + 简单时间线 + 本地 composer”重构为 `deepseek-harness` 会话模块的移动端等价实现：常驻会话壳、严格会话 header、Chat / Trajectory 同源视图、Conversation Node 投影、唯一滚动宿主、sticky composer seat、composer chain 接管、InputMachine 提交语义、QueueDock、Input Trigger、权限/模型 seat、ContextMeter 和 StatsLine 必须按参考项目的可观察行为对齐。

v0.4 已有的 `start / send / resume / abort / kill`、lease、权限、幂等键和 fail-closed 仍是底层事实来源。v0.5 只重构移动端 UI 逻辑与展示投影，不能用 UI 状态伪造 Relay / Daemon 成功结果，不能绕过 `SessionController` 的写入口。

## 3. 强制交互契约

以下是实现验收的硬约束，不是设计建议：

- **Resident Shell**：会话根壳、滚动宿主、composer seat 和 textarea identity 跨无会话/空白会话/活跃会话保持稳定；切换 tab 或会话不得销毁草稿、队列和滚动语义。
- **Workspace Hero**：无当前会话时仍渲染同一个 InputBar DOM，只读 textarea / 虚线卡片成为 Workspace picker 入口；选择 workspace 后复用或打开空白会话，不换平行树。
- **Hero Agent Preset**：无会话/空白会话 Hero 的 agent preset chip 与 Workspace picker 同级暂存，不绑定不存在的 session；选择 workspace 后把暂存 preset 应用于下一条会话链路，不销毁 resident InputBar。
- **Agent Preset Header Label**：已创建会话只在 header actions 中显示只读 preset label；只有会话 summary 记录 preset 时才加载 roster，未知 preset 回退显示 id，不允许在会话开始后提供切换入口；从设置页 staged preset 回到 Hero 时必须有一次性 introduce cue，播放完成后清除。
- **Workspace Picker 生命周期**：picker 必须覆盖 loading / ready / empty / error / workspace deleted / pending pick 状态；选择中的 workspace 可先显示 pending label，失败后回退；空白会话 replay 或 summary 未落定时进入 settling，不在 hero 与 docked composer 之间闪烁。
- **Workspace Picker 添加流程**：添加 workspace 只能通过 directory flow；有既有 workspace 时 add action 固定在菜单尾部，空列表且 add 是唯一动作时直接打开目录 flow；flow 打开、native/browse 待选或 adopt 中必须禁用其它菜单动作；directory-flow occupant 卸载时撤销 open flow；创建失败显示错误对话框，Choose again 仅在 flow 可用时启用。
- **Workspace 切换草稿交接**：从无会话/空白会话选择 workspace 后，resident InputBar 的 draft、结构化引用和草稿图片必须迁移到目标空白会话；若目标会话不能接收图片句柄或 workspace 选择失败，源草稿与图片不得被清空。
- **Header Breadcrumb**：subagent 会话 header 必须显示父子 ancestry breadcrumb；点击父级打开对应 session，当前项禁用；空白会话隐藏 header chrome 但不卸载 resident shell。
- **Subagent Catalog Action**：父会话 header action 必须提供 subagent catalog 树；支持打开/关闭 catalog、刷新 parent catalog、展开/收起子树、打开 child address、显示 running/inactive/diagnostic 状态、token/duration 摘要和 diagnostic 禁用原因；树项必须支持键盘移动、Escape/blur 关闭和焦点恢复。
- **Strict Session Slots**：header、active view、composer bar、composer dock、input dock、input overlay、input left/right 和 header actions/utilities 必须在 Flutter 中有清晰等价边界；功能控件不得继续散落在消息主体中。
- **Slot 所有权**：`input.dock` 只承载 Queue/Todo/Goal 等可换行 strip，`composer.dock` 只承载 StatsLine 类只读读数，`input.left/right` 只承载 composer card 内一行小控件，`input.plan/model/attachments` 是命名 seat；实现不得把这些交互混回父 widget 或消息流。
- **无障碍与焦点契约**：view tabs、breadcrumb、workspace picker、command/model/permission 菜单、question/approval/goal 面板、文件打开错误对话框、可滚动详情区必须有稳定 Semantics label、焦点顺序、可键盘触达的关闭/确认动作和焦点恢复点。
- **View Ring**：`对话` 与 `轨迹` 是同一 Session window 的两个 view entry；Chat 和 Trajectory 各自维护自己的滚动/选择状态，但不得互相改写快照。
- **View / Details Store 生命周期**：Chat 选择、Trajectory 选区、详情 inspector target 与草稿必须按 session 隔离；同一 session 的 conversation 与 details 读取同一个 view store 实例，列表投影刷新不得丢选择；会话销毁时必须清理选择、inspect target 和持久草稿。
- **Conversation Nodes**：不能再用 `event -> widget` 直连渲染。必须先投影为 user / steering / context injection / assistant-step / reasoning / tool / command / manual-compaction / compaction / model-retry / turn-error / turn-max-tokens / turn-tail / unknown 等节点，再由 keyed renderer 渲染。
- **唯一滚动宿主**：Chat 和 Trajectory 都挂在同一个 conversation scroll owner 下；sticky composer seat 的真实高度必须参与可见区域计算，不能用嵌套 `ListView + shrinkWrap` 近似。
- **Chat 历史加载**：Chat view 必须覆盖 history loading、open error、hasMore、loadingOlder 和 load older 行；加载更早历史前记录语义 anchor，prepend 后保持同一可见节点位置，失败或空页必须释放等待 anchor。
- **Chat Scroll 恢复**：Chat tab 切走切回、同会话 view 重挂载或详情页重新进入时，必须优先恢复已保存的 chat scroll 语义位置；只有没有保存位置且会话打开完成时才一次性跳到底部。用户离底后保存 anchor，回到底部或强制 follow 时清除保存位置。
- **Streaming Tail**：流式内容只更新当前尾部或 partial node，不得重建已结算节点；用户离开底部后暂停跟随，新用户消息或 steering 才强制回到底部。
- **Turn Status**：运行中的 turn 必须有 turn-level 状态行覆盖 first-token 等待、工具执行和 streaming 阶段；状态行不得按 step 闪烁，长时间运行才显示 elapsed clock。
- **Think 安全显示**：默认折叠，只展示上游明确允许的 display-safe reasoning summary / thinking summary；无安全摘要时显示运行元数据，不拼接或展示隐藏 CoT。
- **Assistant Markdown 尾部状态**：reasoning 位于 streaming 尾部时显示 running，已结算 reasoning 显示 ok；interrupted assistant partial 必须显示停止状态；未知 block 只能以安全 JSON fallback 展示；只有 tool-call head、无正文的 assistant shell 不应渲染空气泡。
- **Tool 行**：工具调用保持消息流位置，但展示为紧凑行并委托详情 renderer；collapsed row 点击 / Enter / Space 展开，路径链接点击或键盘激活不得同时触发展开；长 input/output/card body 在行内 scroll cap 内滚动；root call 与 subcall 通过同一 keyed dispatch 渲染，不得丢失嵌套 tool 树。
- **Tool Details / File Open**：工具行可选中进入详情/inspector；点击产物路径按会话 cwd 解析，Host/OS 拒绝时显示页面内错误对话框并可重试同一路径。
- **Tool 专用 presenter**：read/search/diff/terminal/code/ask-question 等工具行优先消费 Host 提供的 callView/resultView；running、ok、error、interrupted/stopped 状态必须反映在 leading slot；专用 card 不可用时才回退 JSON args / flattened output，不得把 malformed 或未知 card 当成功详情。
- **Details Panel 尾部状态**：详情面板选择已不在当前窗口、缺少 toolName 或调用头被截断时必须显示可理解 fallback；嵌套 subcall inspect 要解析到完整 frozen block、原始 args 和 output；running 工具详情不能用已结算输出占位。
- **File Open Race**：文件/目录打开请求必须有本地 request epoch；用户关闭错误对话框、重试或点击新路径后，旧请求的迟到拒绝不得重新打开旧对话框或覆盖新路径 busy/error 状态。
- **Inspect Handoff**：从 Chat 工具行进入 inspect 时，必须通过 view store 传递一次性 inspect target，切到 Trajectory 后应用并清空，不允许 Chat 与 Trajectory 共享临时 widget 状态。
- **Composer Chain**：Approval / Question / Plan Review 等 pending interaction 接管整个 composer seat；处理完成后恢复 InputBar 与原草稿。pending 不再作为 Chat 中的可操作卡片出现。
- **Question Flow**：普通 question 支持多题、上一题/下一题分页、单选/多选、推荐标签、freeform、无选项 textarea、skip、minimize、cancel、校验错误和提交失败重试；单选 custom 会替换选项，多选 custom 可与已选项并存；plan-review 是同一 chain entry 内的专用形态，不单独抢同一个 carrier。
- **Question Carrier 生命周期**：同 key baseline replay 必须保留已输入草稿和已选答案；新 rpc/key 替换时重置本地状态；collapse/minimize 只折叠面板不得触发 cancel；cancel / submit 的晚到失败不得污染下一个 question carrier。
- **Plan Review Flow**：plan-review takeover 必须提供 approve、decline（如存在）和 discuss/cancel 三种动作；按钮使用 question option 的真实 label 回传，长 plan markdown 独立滚动，提交失败在面板内 re-arm 并显示错误。
- **Takeover Scroll / Retry**：Question、Approval 和 PlanReview 的长正文或长命令必须在 composer cap 内独立滚动，操作按钮始终可触达；answer / cancel / allow / reject 失败后保留本地草稿、busy latch 复位并允许重试。
- **Question 优先级**：问题接管优先于 approval；问题解决后，如果 approval 仍 pending，composer chain 重新选中 approval。
- **InputMachine**：输入草稿、command claim、reference occurrence、undo/redo、paste 升级、adjudicating、submitting、settled、release 必须由单一状态机驱动；提交 attempt 必须有 seq / abort 边界，adjudicating / submitting 期间重复 Enter、按钮连点和图片删除均不得产生第二次提交或破坏当前快照。
- **Submit 回滚与晚到结果**：提交失败要保留 draft、结构化引用和草稿图片；若失败返回时 draft 未漂移，可恢复原 claim 并提示错误，若 draft 已变化只能提示错误，不得用旧 attempt 覆盖新草稿；组件释放或会话切换必须 abort Host-side preparation / serialization，晚到成功或失败 no-op。
- **Textarea 细交互**：软换行高度、输入框内部滚动、caret reveal、按钮按下后保焦、滚轮链式转交给 conversation scroll、Safari/IME 兼容都属于 InputBar 契约；不得用固定行高或重建 TextField 近似。
- **Overlay / Escape 分层**：Escape 先关闭 input overlay / menu，再交给输入状态机；已 claim command 不能仅靠 Escape 释放，必须由删除 token 或明确动作释放；长按 Enter 不得重复提交。
- **Reference Clipboard**：结构化引用的 Backspace/Delete 删除、copy/cut 普通文本投影、paste-begin / paste-upgrade、选区失效 paste attempt 必须保持原子事务和 undo/redo 语义。
- **Busy Enter**：运行中输入保持可编辑；键盘提交按 Queue / Steer 策略分流，发送按钮不替代键盘策略。空草稿 + Cmd/Ctrl+Enter 可显式 steer 全部队列；空草稿 + 普通 Enter 无操作。
- **Enter 设置**：busy Enter 偏好是用户级设置项，默认 Queue，可切换 Queue / Steer；Shift+Enter 永远换行，已寻址 subagent 只走其继续执行支持的 Queue。
- **QueueDock**：队列是会话级权威 transient inbox 投影。排队项必须支持编辑、删除、逐条 strict steer；多项默认折叠；任何队列提交都必须是显式动作。
- **QueueDock 展开与只读**：多项 queue 默认折叠，但编辑、busy 或操作中必须强制展开；单项 queue 不显示 count header；subagent 或不可变队列只展示预览，不渲染可误触的编辑/删除/steer actions。
- **Queue 操作失败面**：非文本 queue item 的编辑按钮禁用并说明原因；edit / delete / steer / steer all 失败必须以 composer notice/toast 呈现，不得静默丢失本地编辑态或误标为已处理。
- **Todo / Goal Dock**：Todo、Goal、Queue 同属 `conversation.input.dock` 上下文栈。Todo 只读显示 host 投影列表并支持折叠；Goal 只显示 active/paused/blocked，支持 edit/pause/resume/clear 单飞操作、inline 错误、Enter 保存、Escape 取消；Goal 创建只能通过 `/goal` command。
- **Steering Bubble**：Host 带 placement 的 queue 中，`queued` 进入 QueueDock，`steering` 在 Chat 尾部呈用户样式气泡；被持久 user/message 接管时不得闪烁或重复。
- **Pending Steering Actions**：pending steering 是 Host 权威的 pre-admission 投影，只提供 copy，不显示时间或 fork；被持久 user/message 接管后，copy/action 行随 durable node 重新判定，不复用 transient action 状态。
- **禁止自动 flush**：当前 `_SessionComposer.didUpdateWidget` 在 streaming 结束后自动发送 `_queuedMessages` 的行为必须移除；参考项目队列不会在用户未确认时隐式提交。
- **Input Trigger**：`/` 与 `@` 由 textarea selection + draft revision 定位；菜单挂在 `conversation.input.overlay` 等价层，保留焦点、键盘导航和候选分组。禁止继续按最后一个空格截 token。
- **Input Trigger 生命周期**：候选菜单必须覆盖 pending/loading、empty、source failed、source removed、outside dismiss 和 anchored max-height；source failed/source removed 按参考实现从菜单组静默移除并刷新 lexicon，不显示伪错误项；点击 composer card 内部不关闭菜单，点击外部关闭；Space 只能在 leading trigger 命中 source `matchSpace` 时消费。
- **Input Trigger Source / Generation**：trigger source 注册后要 warm 到所有 live controller；source dispose/HMR 移除必须同步关闭或剔除 live menu group；候选 settle/fail、pick、insert-text/reference 都必须带 generation / draftRev / session scope，过期或跨 session 结果必须 no-op。
- **Input Trigger 语法边界**：`/` 要避开 URL/路径中非触发位置，`@` 要避开 `user@host` 形态；quoted `@"..."` 文件引用、中间编辑、draftRev CAS 和选区失效必须阻止 stale pick 写入。
- **Command Launcher**：前置 `+` 是 `/` command launcher，不是附件入口。附件入口必须迁移到独立 attachment seat 或扩展位。
- **Command Adjudication**：菜单选择 execute-kind command（如 `/compact`）必须立即执行且不污染 draft phase；粘贴或手输的已知 slash command 可在 Enter 时一次性 adjudicate + submit；未知 `/xxx` 走默认文本发送；source warmup / adjudication 失败只发 notice 并保留草稿、claim 和图片。
- **Command Input Node**：耐久 `/goal` 等 slash command 输入必须投影为独立 command-input Chat Node，位于 generic command result 之前；该节点按用户气泡样式展示，但不提供 timestamp、copy 或 fork。
- **已发送引用展示**：已发送 user/steering 文本中的已验证 `/command`、`@session`、`@file`、`@"quoted path"` 可投影为只读 reference chip / reference summary；这是展示层投影，不重新 claim command，不凭文本猜测新文件，也不绕过 provider vocabulary。
- **Command Images**：带图片的 slash command 只有声明支持 images 时才能提交；不支持时必须拒绝整个提交并保留草稿和图片，不能只消费文字。
- **Model / Permission Seats**：模型与权限是 composer 内可替换控件；block 状态下模型 seat 仍可用，用于解除 provider/model 不可用；禁用必须展示原因。
- **Model Menu**：模型选择是两层菜单（模型/effort drill-in），catalog load 失败在菜单内 retry，selection 失败用 composer toast；已寻址 subagent 不显示模型 seat。
- **Model Store / Host Reconcile**：composer seat、popup 和 `/model` 入口共享同一个逐会话 model directory；本地未被 Host 消费的 selection 在 reconnect 后回退到 Host target；只有 Host 明确 route unservable 才 block composer，catalog 暂时缺项不能单独构成 block。
- **Model Menu 焦点与返回**：模型菜单每次打开都刷新 catalog；Escape 在二级 pane 先返回 root，再关闭并恢复 trigger 焦点；方向键在当前 pane 内移动焦点；选择当前模型/effort 是 no-op；空模型和空 effort 必须有菜单内空态。
- **Permission Risk**：普通权限 preset 立即提交 `/permission <preset>`；`danger-full-access` 必须先弹风险确认，勾选确认前不可提交，取消/遮罩/Escape 不提交；locked 或 projection 缺失时必须关闭菜单并清空确认态；`custom` preset 不作为可点菜单项渲染。
- **StatsLine / ContextMeter**：统计只来自上游投影或可声明的窗口回退；缺字段时省略或显示不可用，不填假数字。上下文占用率是近似投影，必须与 usage 区分；StatsLine 过长时只在真实截断后延迟显示完整 tooltip；ContextMeter 点击打开 breakdown dialog，trigger 再点、outside pointerdown 或 Escape 关闭，capacity 消失时关闭且恢复后不自动重开，0% 不画伪占用段，缺 breakdown 时退化为单段。
- **Attachments / Images**：图片粘贴、移动端选择和可支持的拖放入口共用 imageLimits 预检；整批超限整批拒收并 toast；错误优先级按 unsupported type -> count -> single size -> total size 判定；发送成功后释放草稿图片，切会话时释放历史图片 URL/句柄。
- **Prompt / Notice Toast**：promptError、image intake 拒绝、queue/model/permission 操作失败必须通过 composer notice/toast 呈现；重复的相同错误要重新启动短暂提示，不得因为 toast 展示清空 draft、结构化引用或草稿图片。
- **Message Actions**：用户消息提供复制/时间；已完成轮次尾部 assistant 才允许复制、时间和 fork，纯 Think、轮次中间消息和仍在运行的节点不提供分支；复制成功只显示短暂成功反馈，写剪贴板失败不得伪装成功。
- **Message Chrome 尾部状态**：复制按钮必须防重复点击、成功态短暂回退，平台剪贴板不可用时走安全降级或明确失败；同日/跨日时间格式稳定；已发送 reference chip 需支持紧贴中文、多词 session label、无扩展名文件和句尾标点分离。
- **Assistant Feedback Actions**：assistant actions slot 必须支持 like / dislike、当前 rating 的 aria-pressed、首次 hover/focus lazy ensure、点击同 rating retract、点击另一 rating replace；记录 rating 后才显示 note 入口，note popover 锚定按钮并可 Escape / outside pointer 关闭，失败区分 row failure 与 panel failure，version-conflict 用专门文案，stale save 不得覆盖新开的编辑草稿，关闭后恢复触发按钮焦点。
- **Produced Files / File Mentions**：assistant turn-tail 的产物文件 chips 来自工具 follow-along 位置，不从闭合 prose 猜测；最多显示可容纳前缀和剩余计数，Host 支持时显示打开目录；inline code 文件提及只在有 provider vocabulary 时可打开。
- **Produced Files Turn 数据**：产物文件必须按同一 turn 内 first-seen 去重，遇到 closing assistant seq 停止；只收成功的 mutation / deliverable 位置，忽略 read、失败、orphan、replacement 或缺少 location 的结果；历史 prepend 补齐 turn start 后要能重放 tail，live append 要增量扩展同一 turn 数据。
- **Subagent Composer**：已寻址 one-shot 或 parent offline subagent 由只读 composer 接管并说明原因；continuable child 普通输入只保留其支持的 Send/Queue，Stop 不绕过 parent ownership。
- **Trajectory Overlay**：Trajectory 是 full-height ledger view，composer 作为 overlay/sticky seat 预留高度；Trajectory 自身可以加载更早历史、虚拟化、搜索、折叠、选择记录和检查器。
- **Trajectory Toolbar / Search**：Trajectory toolbar 必须支持 duration/equal-width 切换、turn 全折叠、assistant tool-call 全折叠和搜索；搜索索引允许节流，但 streaming partial 必须纳入搜索与 timeline 结构。
- **Trajectory Mode 切换**：切换 duration/equal-width 或实际时间/压缩时间等 timeline mode 时，必须清空或重映射当前 range selection，避免旧时间轴选区套到新布局；该状态只属于 Trajectory，不回写 Chat。
- **Trajectory Timeline 交互**：Overview timeline 必须支持时间范围选择、拖拽/滚轮缩放或等价移动端手势、选中记录自动进入可见区域；新数据导致选区越界时清空或夹紧，不回写 Chat state。

## 5. 目标结构

Flutter 侧应拆成与参考模块同构的边界，而不是继续扩写单个 `session_screens.dart`：

```text

└── SessionConversationRoot（resident）
    ├── SessionHeader
    │   ├── Breadcrumb / title
    │   ├── Header actions
    │   ├── Header utilities
    │   └── View tabs
    └── SessionScrollBody（唯一滚动宿主）
        ├── SessionViewOutlet
        │   ├── ChatView
        │   │   ├── ConversationNodeList
        │   │   ├── StreamingTail
        │   │   ├── ReasoningRow
        │   │   ├── ToolStepRow
        │   │   ├── CompactionRow
        │   │   └── TurnTailRow
        │   └── TrajectoryView
        │       ├── TrajectoryToolbar
        │       ├── TrajectoryTimeline / Overview
        │       ├── TrajectoryTable / virtual rows
        │       └── RecordInspector
        └── ComposerSeat（sticky / takeover boundary）
            ├── InputDock（Todo / Goal / Queue）
            ├── ComposerChain
            │   ├── QuestionPanel
            │   ├── ApprovalPanel
            │   ├── PlanReviewPanel
            │   └── InputBar fallback
            └── ComposerDock（StatsLine）
```

Flutter 可以不实现 slot registry，但必须保留同等所有权边界：每个区域只能读取自己的 projection 和动作面，不能靠父 widget 直接拼装所有业务控制。

### P0：契约冻结与投影测试

替换 `_SessionTimelineList` 的 raw event 渲染；实现 keyed node list、ReasoningRow、ToolStepRow、ToolDetails 入口、ContextInjectionRow、ManualCompactionRow、CompactionRow、TurnTailRow、MessageActions、AssistantFeedbackActions、ProducedFilesRow、TurnStatusRow、StreamingTail、model-retry/turn-error/turn-max-tokens/unknown rows。滚动实现底部跟随、用户上滚暂停、append user/steering 强制到底部、history loading/open error/load older、prepend 历史保持 anchor，并补齐工具行 expand/collapse、路径链接手势隔离、subcall 递归渲染、文件路径打开失败对话框、inline code 文件提及打开能力、Chat -> Trajectory inspect handoff、assistant feedback note popover 与 user/steering 气泡交接。

### P3：Composer State Machine

用 `SessionComposerController` / `SessionInputMachine` 替换 `_SessionComposerState` 的局部 bool/list 状态。实现 `plain/claimed/adjudicating/submitting/blocked`、草稿镜像、提交快照、失败保留、成功清空、release abort、结构化引用 delete/copy/cut、paste-upgrade、caret reveal、输入框滚动链式转交和 undo/redo。删除 streaming 结束自动发送队列。补齐 Escape overlay 分层、按钮保焦、长按 Enter 防重复提交和 Queue / Steer 用户级 Enter 偏好入口。

### P4：Composer Chain 接管

把 `_PermissionRequestItem` / `_QuestionRequestItem` 从消息流和普通 composer 子块中移除，改为 `QuestionPanel`、`ApprovalPanel`、`PlanReviewPanel`、`SubagentReadOnlyPanel` 接管 composer seat。问题优先于 approval；普通问题覆盖多题、上一题/下一题、skip、minimize、freeform、无选项 textarea、单选 custom 替换、多选 custom 并存、validation 和失败重试；plan-review 覆盖 approve / decline / discuss。完成后恢复 InputBar、草稿、附件和焦点。长问题、plan markdown 与 approval 命令在 composer cap 内滚动，按钮常驻可达，提交失败时保留本地状态并 re-arm。

### P5：Input Trigger、QueueDock 与 Control Seats

实现 selection-based `/` / `@` 输入触发、Command launcher、候选 fetching lifecycle、source failed/source removed、outside dismiss、anchored max-height、候选分组、键盘导航和焦点保持。QueueDock 改为会话级投影，支持编辑、删除、逐条 strict steer、多项折叠、编辑/busy 强制展开、subagent 只读和显式 steer all；非文本 row 的编辑禁用原因、操作失败 notice/toast 和本地编辑态恢复必须可测。Todo、Goal、模型、权限、计划、附件迁入 composer seats / dock / overlay，不再堆在主体或表单控制条中；Goal creation 走 `/goal` command-input 节点，Goal dock 只处理 edit/pause/resume/clear。补齐 imageLimits 预检、command images 支持声明、permission risk confirmation、permission locked reset 和 model 两级菜单焦点/返回/空态/错误面。

### P6：Trajectory View

实现 Trajectory snapshot builder、turn/request grouping、Overview timeline、toolbar、duration/equal-width 切换、search、search index throttle、streaming partial layout、collapse、virtual rows、record inspector、load older。Overview timeline 支持时间范围选择、拖拽/滚轮缩放或等价移动端手势，选中记录自动进入可见区域，选区越界时清空或夹紧。Trajectory 不读取或改变 Chat projection；只消费同一 Session window、自身 target projection 和一次性 inspect target。

### P7：StatsLine、ContextMeter 与证据回填

接入真实 usage、token、cache、TTFT、decode throughput、turn/step count、context pressure；缺字段省略或显示不可用。更新测试文档、项目文档、实施记录和 macOS 可见录制脚本。

## 9. 验收标准

- 打开会话后进入 resident conversation shell；切换空白/活跃、Chat/Trajectory、会话路由时，composer seat 与草稿不被销毁。
- 无会话/空白会话 Hero 的 Workspace picker 和 agent preset 使用同一个 InputBar；只读 textarea / card 的 Enter 或 Space 可打开 picker；选 workspace 后不重建 composer，pending pick / deleted workspace / error retry / replay settling 不导致 hero 与 docked composer 闪烁；directory flow 添加 workspace 的 busy、error retry 和 flow unavailable 状态可见。
- 已创建会话的 agent preset 只读显示在 header actions，不能切换；subagent header breadcrumb 可打开父级，subagent catalog action 可打开/关闭、刷新、展开 child 树、显示 diagnostic 禁用原因并用键盘操作。
- 选择 workspace 时 draft、结构化引用和草稿图片按目标会话可接收性迁移；选择失败或目标拒绝图片时，本地输入和图片保持原状。
- `对话` / `轨迹` 切换不丢失会话、草稿、队列、Chat scroll anchor 或 Trajectory inspect state。
- Chat 不再直接渲染 permission/question 操作卡；pending wait 只通过 composer takeover 处理。
- Chat history loading / open error / load older 都有可见状态；加载更早历史后保留 reader anchor，失败或空页不污染后续滚动。
- 运行中的 turn 状态行覆盖 first-token、tool 和 streaming，长运行显示 elapsed clock，并且不随单个 step 重建闪烁。
- Question takeover 优先于 approval；answer / cancel / allow / reject 都是一次性动作，resolved 后恢复 InputBar。
- 运行中 textarea 仍可编辑；普通发送、Queue、Steer 和 Stop 的可用性与 blocked reason 分开呈现。
- QueueDock 不自动提交；编辑、删除、逐条 steer、全部 steer 均需显式用户动作；steering 气泡与持久 user/message 交接无重复无闪烁。
- QueueDock 的非文本 row 显示编辑不可用原因，edit/delete/steer/steer all 失败通过 notice/toast 报错并保留本地编辑态。
- QueueDock 多项默认折叠，编辑或 busy 时自动展开；单项不显示 count header；subagent / immutable queue 只读展示。
- Todo dock 只读展示投影列表并可折叠；Goal dock 的 edit/pause/resume/clear 单飞，错误 inline 展示，完成/清除/空值不占位，创建只通过 `/goal`。
- `/` / `@` 菜单基于 selection 和 draft revision；IME Enter 不发送；菜单打开时焦点留在输入上下文；URL、`user@host`、quoted file token、中间编辑和 stale draftRev pick 都有边界测试。
- `/` / `@` 菜单覆盖 loading / empty / source failed / source removed / outside dismiss，source failed/source removed 静默移除对应组并刷新 lexicon；菜单高度锚定 composer 上方，composer card 内点击不关闭，外部点击关闭。
- Escape 先关闭 overlay/menu，再进入输入状态机；已 claim command 不因 Escape 隐式释放；长按 Enter 不重复提交。
- reference occurrence 的 delete/copy/cut/paste-upgrade、undo/redo、caret reveal、输入框内部滚动与滚轮链式转交都有可重复测试。
- `+` 只打开 command launcher；附件入口不再占用 command launcher；不支持图片的 command 必须拒绝整次提交并保留图片。
- slash command input 以 command-input Chat Node 呈现；节点无时间、复制和 fork 行为，不伪装为普通 user/message。
- Model seat 在 composer block 下仍可用；无 provider/model/capability 时显示具体原因，不伪装成发送失败；已寻址 subagent 不显示模型选择。
- Model menu 打开刷新 catalog，二级 pane 的 Escape 先返回 root，再关闭并恢复 trigger 焦点；选择当前模型/effort 是 no-op，空模型/空 effort 有空态。
- Think 只显示 display-safe 摘要；无摘要时不显示推理正文。
- Tool、compaction、retry、turn-tail 都是紧凑语义行，工具详情由独立 renderer/inspector 承担；tool row 可点击/Enter/Space 展开，路径链接不触发行展开，subcall 递归保留 keyed 行，文件路径打开失败显示可关闭/可重试对话框。
- Trajectory 具备轮次分组、Overview、虚拟行、历史加载、搜索/折叠/检查器，且不改变 Chat projection。
- Trajectory toolbar 支持 duration/equal-width、turn 全折叠、assistant call 全折叠；搜索索引节流但必须包含 streaming partial；Chat inspect target 应用后清空。
- StatsLine 与 ContextMeter 只显示真实投影或明确窗口回退；缺失字段显示不可用或省略，不填 0。
- unsupported、只读、无 lease、provider unavailable、content key unavailable、image limit exceeded、subagent read-only 均 fail-closed，并显示可理解的禁用原因。
- 图片粘贴/选择/可支持拖放共用预检、错误优先级和资源释放语义；发送失败保留草稿和图片。
- 普通 question 支持多题、上一题/下一题、单选/多选、推荐标签、freeform、无选项 textarea、skip、minimize、cancel 和失败重试；plan-review 支持 approve/decline/discuss。
- Question / Approval / PlanReview 长内容在 takeover card 内滚动，按钮始终可触达，失败重试不丢草稿、附件或已选答案。
- `danger-full-access` 权限 preset 必须有风险确认；取消、遮罩和 Escape 不提交；locked / projection 缺失会关闭菜单并清空确认态，`custom` preset 不显示为可点项。
- 已完成 assistant turn tail 才允许 fork；user/steering 气泡不显示 fork。
- assistant feedback 的 like/dislike 首次交互懒加载、可撤销或替换 rating；note popover 锚定触发按钮，Escape/outside 关闭并恢复焦点，保存失败留在面板内，晚到结果不得覆盖新草稿。
- assistant turn-tail produced files row 按可用宽度折叠 chips 和剩余计数，Host 支持时可打开目录；inline code 文件提及没有 provider vocabulary 时保持惰性展示。
- `start -> send -> abort`、`start -> kill`、恢复、错误和 read-only 路径仍由真实 Relay/Daemon receipt 驱动。
- 核心交互具备 Semantics label、焦点顺序、键盘触达、关闭/确认动作和焦点恢复验收；视觉录制不能替代无障碍断言。
- 关键控件保留稳定 key 或新增等价 key：`session-tab-chat`、`session-tab-trajectory`、`session-composer`、`session-composer-input`、`session-workspace-picker`、`session-workspace-add`、`session-agent-preset`、`session-agent-preset-label`、`session-subagent-catalog`、`session-send-button`、`session-stop-button`、`session-command-launcher`、`session-todo-dock`、`session-goal-dock`、`session-queue-dock`、`session-question-panel`、`session-approval-panel`、`session-assistant-feedback`、`session-message-feedback-note`、`session-stats-line`、`session-context-meter`、`session-kill-button`、`session-kill-confirm`。

## 12. 风险与决策

- `session_screens.dart` 已经过大，v0.5 必须先拆边界再迁功能，避免继续扩大单文件状态耦合。
- 当前 fixture 事件字段不足以支撑完整 StatsLine / Trajectory 时，只能显示不可用或窗口回退，不能补假 usage。
- Queue/Steer 需要 Relay/Daemon 显式支持 placement 或等价投影；协议未就绪时 UI 只能沉淀本地 fixture 契约，不能声称真实 provider 已支持。
- Composer 与 Android IME、键盘顶起、安全区、滚轮/触摸链式滚动是高风险区，必须有 widget 测试和 macOS 可见录制；安卓实机 gate 后续单独执行。
- Model / Permission seat 的语义来自 capability DTO 和 controls/projection；禁止按 provider 名称硬编码。
- Flutter 没有 React slot registry，但必须用 controller/provider + widget 边界保留等价所有权，避免跨区域直接读写。
- 未组合真实投影单元时，移动端应明确标注回退范围；不能把可见窗口折算说成全会话统计。
