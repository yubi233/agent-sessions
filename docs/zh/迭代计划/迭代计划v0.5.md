## 3. 强制交互契约

以下是实现验收的硬约束，不是设计建议：

- **Resident Shell**：会话根壳、滚动宿主、composer seat 和 textarea identity 跨无会话/空白会话/活跃会话保持稳定；切换 tab 或会话不得销毁草稿、队列和滚动语义。
- **Workspace Hero**：无当前会话时仍渲染同一个 InputBar DOM，只读 textarea / 虚线卡片成为 Workspace picker 入口；选择 workspace 后复用或打开空白会话，不换平行树。
- **Hero Agent Preset**：无会话/空白会话 Hero 的 agent preset chip 与 Workspace picker 同级暂存，不绑定不存在的 session；选择 workspace 后把暂存 preset 应用于下一条会话链路，不销毁 resident InputBar。
- **Workspace Picker 生命周期**：picker 必须覆盖 loading / ready / empty / error / workspace deleted / pending pick 状态；选择中的 workspace 可先显示 pending label，失败后回退；空白会话 replay 或 summary 未落定时进入 settling，不在 hero 与 docked composer 之间闪烁。
- **Header Breadcrumb**：subagent 会话 header 必须显示父子 ancestry breadcrumb；点击父级打开对应 session，当前项禁用；空白会话隐藏 header chrome 但不卸载 resident shell。
- **Strict Session Slots**：header、active view、composer bar、composer dock、input dock、input overlay、input left/right 和 header actions/utilities 必须在 Flutter 中有清晰等价边界；功能控件不得继续散落在消息主体中。
- **无障碍与焦点契约**：view tabs、breadcrumb、workspace picker、command/model/permission 菜单、question/approval/goal 面板、文件打开错误对话框、可滚动详情区必须有稳定 Semantics label、焦点顺序、可键盘触达的关闭/确认动作和焦点恢复点。
- **View Ring**：`对话` 与 `轨迹` 是同一 Session window 的两个 view entry；Chat 和 Trajectory 各自维护自己的滚动/选择状态，但不得互相改写快照。
- **Conversation Nodes**：不能再用 `event -> widget` 直连渲染。必须先投影为 user / assistant / reasoning / tool / command / compaction / turn-tail / retry / error 等节点，再由 keyed renderer 渲染。
- **唯一滚动宿主**：Chat 和 Trajectory 都挂在同一个 conversation scroll owner 下；sticky composer seat 的真实高度必须参与可见区域计算，不能用嵌套 `ListView + shrinkWrap` 近似。
- **Streaming Tail**：流式内容只更新当前尾部或 partial node，不得重建已结算节点；用户离开底部后暂停跟随，新用户消息或 steering 才强制回到底部。
- **Think 安全显示**：默认折叠，只展示上游明确允许的 display-safe reasoning summary / thinking summary；无安全摘要时显示运行元数据，不拼接或展示隐藏 CoT。
- **Tool 行**：工具调用保持消息流位置，但展示为紧凑行并委托详情 renderer；不得继续用大型控制面板卡片承载工具状态。
- **Tool Details / File Open**：工具行可选中进入详情/inspector；点击产物路径按会话 cwd 解析，Host/OS 拒绝时显示页面内错误对话框并可重试同一路径。
- **Composer Chain**：Approval / Question / Plan Review 等 pending interaction 接管整个 composer seat；处理完成后恢复 InputBar 与原草稿。pending 不再作为 Chat 中的可操作卡片出现。
- **Question Flow**：普通 question 支持多题、单选/多选、推荐标签、freeform、skip、minimize、cancel、校验错误和提交失败重试；plan-review 是同一 chain entry 内的专用形态，不单独抢同一个 carrier。
- **Takeover Scroll / Retry**：Question、Approval 和 PlanReview 的长正文或长命令必须在 composer cap 内独立滚动，操作按钮始终可触达；answer / cancel / allow / reject 失败后保留本地草稿、busy latch 复位并允许重试。
- **Question 优先级**：问题接管优先于 approval；问题解决后，如果 approval 仍 pending，composer chain 重新选中 approval。
- **InputMachine**：输入草稿、command claim、reference occurrence、undo/redo、paste 升级、adjudicating、submitting、settled、release 必须由单一状态机驱动。
- **Textarea 细交互**：软换行高度、输入框内部滚动、caret reveal、按钮按下后保焦、滚轮链式转交给 conversation scroll、Safari/IME 兼容都属于 InputBar 契约；不得用固定行高或重建 TextField 近似。
- **Overlay / Escape 分层**：Escape 先关闭 input overlay / menu，再交给输入状态机；已 claim command 不能仅靠 Escape 释放，必须由删除 token 或明确动作释放；长按 Enter 不得重复提交。
- **Reference Clipboard**：结构化引用的 Backspace/Delete 删除、copy/cut 普通文本投影、paste-begin / paste-upgrade、选区失效 paste attempt 必须保持原子事务和 undo/redo 语义。
- **Busy Enter**：运行中输入保持可编辑；键盘提交按 Queue / Steer 策略分流，发送按钮不替代键盘策略。空草稿 + Cmd/Ctrl+Enter 可显式 steer 全部队列；空草稿 + 普通 Enter 无操作。
- **Enter 设置**：busy Enter 偏好是用户级设置项，默认 Queue，可切换 Queue / Steer；Shift+Enter 永远换行，已寻址 subagent 只走其继续执行支持的 Queue。
- **QueueDock**：队列是会话级权威 transient inbox 投影。排队项必须支持编辑、删除、逐条 strict steer；多项默认折叠；任何队列提交都必须是显式动作。
- **Queue 操作失败面**：非文本 queue item 的编辑按钮禁用并说明原因；edit / delete / steer / steer all 失败必须以 composer notice/toast 呈现，不得静默丢失本地编辑态或误标为已处理。
- **Todo / Goal Dock**：Todo、Goal、Queue 同属 `conversation.input.dock` 上下文栈。Todo 只读显示 host 投影列表并支持折叠；Goal 只显示 active/paused/blocked，支持 edit/pause/resume/clear 单飞操作、inline 错误、Enter 保存、Escape 取消；Goal 创建只能通过 `/goal` command。
- **Steering Bubble**：Host 带 placement 的 queue 中，`queued` 进入 QueueDock，`steering` 在 Chat 尾部呈用户样式气泡；被持久 user/message 接管时不得闪烁或重复。
- **禁止自动 flush**：当前 `_SessionComposer.didUpdateWidget` 在 streaming 结束后自动发送 `_queuedMessages` 的行为必须移除；参考项目队列不会在用户未确认时隐式提交。
- **Input Trigger**：`/` 与 `@` 由 textarea selection + draft revision 定位；菜单挂在 `conversation.input.overlay` 等价层，保留焦点、键盘导航和候选分组。禁止继续按最后一个空格截 token。
- **Command Launcher**：前置 `+` 是 `/` command launcher，不是附件入口。附件入口必须迁移到独立 attachment seat 或扩展位。
- **Command Input Node**：耐久 `/goal` 等 slash command 输入必须投影为独立 command-input Chat Node，位于 generic command result 之前；该节点按用户气泡样式展示，但不提供 timestamp、copy 或 fork。
- **Command Images**：带图片的 slash command 只有声明支持 images 时才能提交；不支持时必须拒绝整个提交并保留草稿和图片，不能只消费文字。
- **Model / Permission Seats**：模型与权限是 composer 内可替换控件；block 状态下模型 seat 仍可用，用于解除 provider/model 不可用；禁用必须展示原因。
- **Model Menu**：模型选择是两层菜单（模型/effort drill-in），catalog load 失败在菜单内 retry，selection 失败用 composer toast；已寻址 subagent 不显示模型 seat。
- **Permission Risk**：普通权限 preset 立即提交 `/permission <preset>`；`danger-full-access` 必须先弹风险确认，勾选确认前不可提交，取消/遮罩/Escape 不提交。
- **StatsLine / ContextMeter**：统计只来自上游投影或可声明的窗口回退；缺字段时省略或显示不可用，不填假数字。上下文占用率是近似投影，必须与 usage 区分。
- **Attachments / Images**：图片粘贴、移动端选择和可支持的拖放入口共用 imageLimits 预检；整批超限整批拒收并 toast；发送成功后释放草稿图片，切会话时释放历史图片 URL/句柄。
- **Message Actions**：用户消息提供复制/时间；已完成轮次尾部 assistant 才允许复制、时间和 fork，纯 Think、轮次中间消息和仍在运行的节点不提供分支。
- **Produced Files / File Mentions**：assistant turn-tail 的产物文件 chips 来自工具 follow-along 位置，不从闭合 prose 猜测；最多显示可容纳前缀和剩余计数，Host 支持时显示打开目录；inline code 文件提及只在有 provider vocabulary 时可打开。
- **Subagent Composer**：已寻址 one-shot 或 parent offline subagent 由只读 composer 接管并说明原因；continuable child 普通输入只保留其支持的 Send/Queue，Stop 不绕过 parent ownership。
- **Trajectory Overlay**：Trajectory 是 full-height ledger view，composer 作为 overlay/sticky seat 预留高度；Trajectory 自身可以加载更早历史、虚拟化、搜索、折叠、选择记录和检查器。
- **Trajectory Timeline 交互**：Overview timeline 必须支持时间范围选择、拖拽/滚轮缩放或等价移动端手势、选中记录自动进入可见区域；新数据导致选区越界时清空或夹紧，不回写 Chat state。

## 4. 当前 Flutter 现状

当前 `SessionDetailScreen` 已有浅层 tab 和底部 composer，但仍不满足参考模块契约：

```text
SessionDetailScreen
├── Scaffold / AppBar / QuickMenu
├── _SessionStatusStrip
├── _SessionViewTabs
├── Expanded
│   ├── _SessionChatView
│   │   ├── ListView
│   │   ├── _SessionTimelineList(scrollable: false)
│   │   ├── _SessionRecoveryStrip
│   │   └── InlineError
│   └── _SessionTrajectoryView
│       └── ListView.separated(raw events)
└── _SessionComposer
    ├── pending _PermissionRequestItem / _QuestionRequestItem
    ├── local _QueueDock
    ├── _CommandLauncherMenu
    ├── _AttachmentQueue
    ├── _ComposerSuggestions
    ├── TextField
    ├── Send / Stop
    └── _ComposerControlStrip
```

主要问题：

- `_SessionChatView` 虽过滤 permission/question，但 `_SessionTimelineList` 仍保留可操作 pending 卡片能力；pending 的唯一交互面尚未收敛为 composer chain。
- `_SessionTrajectoryView` 只是原始事件列表，不是按轮次、请求、工具、partial 与 usage 组装的 Trajectory ledger。
- `_SessionComposer` 自己维护 `_queuedMessages`、`_commandMenuOpen` 和 `_suggestions`，没有会话级 queue projection、InputMachine 或 selection CAS。
- streaming 结束后本地队列会自动发送，违反 QueueDock 显式提交契约。
- `/` / `@` 补全按末尾 token 和空格切分，不能覆盖中间编辑、选区、IME、reference occurrence 和 command claim。
- model / effort / permission 仍是普通表单控制条，没有作为 composer seats 参与 block、locked、projection、toast 与菜单交互。
- stats/usage 只来自 `SessionControlState` 的局部字段，没有 `StatsLine` 与 `ContextMeter` 的分层口径。
- 当前 header 仍偏 AppBar + QuickMenu；参考实现需要 session header actions / utilities / view tabs 的固定 chrome。
- 当前 header 未定义 subagent ancestry breadcrumb，也未把空白会话 header 隐藏与 resident shell 保活拆开验收。
- 当前无会话/空白会话 Hero 只解决入口展示，未定义 agent preset 暂存和 Workspace picker 与同一 InputBar 的联动。
- 当前 Workspace picker 未定义 loading / empty / error / deleted workspace / pending pick / replay settling 状态，可能在会话打开或 workspace 删除时出现 hero / docked composer 闪烁。
- 当前附件是手动按钮 + 本地 chips，没有 imageLimits 统一预检、paste/drop 入口、command images 支持声明、发送失败保留语义和资源释放验收。
- 当前 TextField 只承担普通文本输入，没有结构化引用 copy/cut/delete、paste-upgrade、caret reveal、输入框滚动与 conversation scroll 链式滚动契约。
- 当前 input overlay、命令 claim、长按 Enter、按钮保焦和 Escape 关闭层级未写成独立契约，容易在菜单、IME 和提交状态间互相抢事件。
- 当前 takeover 面板没有长内容滚动、按钮可达、提交失败重试、焦点恢复和 Semantics 验收。
- 当前 QueueDock 没有非文本编辑禁用原因和操作失败 notice/toast 验收。
- 当前 Todo / Goal 没有作为 `conversation.input.dock` 投影 strip 验收；Goal edit/pause/resume/clear、inline 错误、单飞和 `/goal` command-input 节点未定义。
- 当前工具行没有 details/inspector、产物路径打开、Host/OS 拒绝重试对话框。
- 当前消息动作没有按 turn-tail 约束复制/时间/fork，也没有 user/steering 气泡交接验收。
- 当前 turn-tail 产物文件和 inline code 文件提及没有独立行/打开能力/容量折叠验收。
- 当前未定义已寻址 subagent composer 接管、只读原因和模型 seat 隐藏规则。
- 当前权限 preset 缺少 `danger-full-access` 风险确认流程，模型选择也不是两级菜单和 load/select 分离错误面。

## 5. 目标结构

Flutter 侧应拆成与参考模块同构的边界，而不是继续扩写单个 `session_screens.dart`：

```text
SessionDetailScreen（路由适配器）
└── SessionConversationRoot（resident）
    ├── SessionHeader
    │   ├── Breadcrumb / title
    │   ├── Header actions
    │   ├── Header utilities
    │   └── View tabs
    └── SessionScrollBody（唯一滚动宿主）
        ├── SessionViewOutlet
        │   ├── ChatView
        │   │   ├── ConversationNodeList
        │   │   ├── StreamingTail
        │   │   ├── ReasoningRow
        │   │   ├── ToolStepRow
        │   │   ├── CompactionRow
        │   │   └── TurnTailRow
        │   └── TrajectoryView
        │       ├── TrajectoryToolbar
        │       ├── TrajectoryTimeline / Overview
        │       ├── TrajectoryTable / virtual rows
        │       └── RecordInspector
        └── ComposerSeat（sticky / takeover boundary）
            ├── InputDock（Todo / Goal / Queue）
            ├── ComposerChain
            │   ├── QuestionPanel
            │   ├── ApprovalPanel
            │   ├── PlanReviewPanel
            │   └── InputBar fallback
            └── ComposerDock（StatsLine）
```

Flutter 可以不实现 slot registry，但必须保留同等所有权边界：每个区域只能读取自己的 projection 和动作面，不能靠父 widget 直接拼装所有业务控制。

## 6. 改造边界

### 纳入

- Android 会话详情页 resident shell、header、scroll owner、Chat view、Trajectory view、sticky composer seat。
- 会话级 display-safe projection：Chat nodes、Trajectory snapshot、pending waits、queue、stats、context pressure。
- Composer input machine：draft、command claim、reference occurrences、submit phases、busy enter、Queue/Steer。
- Approval / Question / Plan Review composer takeover。
- `/` command launcher、`/` / `@` input trigger、模型 seat、权限 seat、ContextMeter、StatsLine。
- Workspace hero、hero agent preset、subagent breadcrumb 与只读 composer、图片附件 lifecycle、Todo/Goal dock、工具详情/文件打开失败、produced files、消息动作/fork、permission risk confirmation。
- 现有 Relay / Daemon fixture 与真实链路的分层测试证据。

### 不纳入

- 不复制 `deepseek-harness` React 源码、CSS、品牌、图标或资源。
- 不重写 Relay / Daemon 协议，不新增 Android 后台、Push、AVD 或真实 provider gate。
- 不展示隐藏 CoT，不从日志推断或拼接推理正文。
- 不发明 provider 未提供的 usage、context、trajectory 字段。
- 不把本地 fixture 录屏描述为真实模型或真实上游验收。

## 8. 分阶段实施

### P0：契约冻结与投影测试

把参考源码锚点固化到实施记录；新增 projection / composer machine 的纯测试。先证明当前 raw events 能被组装为 display-safe Chat nodes、pending waits、queue、stats/context 和 Trajectory snapshot。任何字段缺失必须显式落为 unavailable，不写 fallback 假值。

### P1：Resident Shell 与严格 Header

把 `SessionDetailScreen` 收敛为路由适配器；实现 `SessionConversationRoot`、`SessionHeader`、唯一 scroll owner 和 sticky composer seat。`_SessionStatusStrip`、QuickMenu、日志入口、view tabs 迁入 header actions/utilities；subagent ancestry breadcrumb 可点击打开父级；空白会话隐藏 header chrome 但不卸载 resident shell；空白会话与活跃会话复用同一个 composer seat，并保留 hero agent preset 暂存入口。补齐 Workspace picker 的 pending pick、deleted workspace、error retry、空态和 replay settling，避免会话加载过程中 hero / docked composer 闪烁。

### P2：Chat Nodes 与滚动契约

替换 `_SessionTimelineList` 的 raw event 渲染；实现 keyed node list、ReasoningRow、ToolStepRow、ToolDetails 入口、CompactionRow、TurnTailRow、MessageActions、ProducedFilesRow、StreamingTail、retry/error rows。滚动实现底部跟随、用户上滚暂停、append user/steering 强制到底部、prepend 历史保持 anchor，并补齐文件路径打开失败对话框、inline code 文件提及打开能力与 user/steering 气泡交接。

### P3：Composer State Machine

用 `SessionComposerController` / `SessionInputMachine` 替换 `_SessionComposerState` 的局部 bool/list 状态。实现 `plain/claimed/adjudicating/submitting/blocked`、草稿镜像、提交快照、失败保留、成功清空、release abort、结构化引用 delete/copy/cut、paste-upgrade、caret reveal、输入框滚动链式转交和 undo/redo。删除 streaming 结束自动发送队列。补齐 Escape overlay 分层、按钮保焦、长按 Enter 防重复提交和 Queue / Steer 用户级 Enter 偏好入口。

### P4：Composer Chain 接管

把 `_PermissionRequestItem` / `_QuestionRequestItem` 从消息流和普通 composer 子块中移除，改为 `QuestionPanel`、`ApprovalPanel`、`PlanReviewPanel`、`SubagentReadOnlyPanel` 接管 composer seat。问题优先于 approval；普通问题覆盖多题、skip、minimize、freeform、validation 和失败重试；完成后恢复 InputBar、草稿、附件和焦点。长问题、plan markdown 与 approval 命令在 composer cap 内滚动，按钮常驻可达，提交失败时保留本地状态并 re-arm。

### P5：Input Trigger、QueueDock 与 Control Seats

实现 selection-based `/` / `@` 输入触发、Command launcher、候选分组、键盘导航和焦点保持。QueueDock 改为会话级投影，支持编辑、删除、逐条 strict steer、多项折叠和显式 steer all；非文本 row 的编辑禁用原因、操作失败 notice/toast 和本地编辑态恢复必须可测。Todo、Goal、模型、权限、计划、附件迁入 composer seats / dock / overlay，不再堆在主体或表单控制条中；Goal creation 走 `/goal` command-input 节点，Goal dock 只处理 edit/pause/resume/clear。补齐 imageLimits 预检、command images 支持声明、permission risk confirmation 和 model 两级菜单错误面。

### P6：Trajectory View

实现 Trajectory snapshot builder、turn/request grouping、Overview timeline、toolbar、search、collapse、virtual rows、record inspector、load older。Overview timeline 支持时间范围选择、拖拽/滚轮缩放或等价移动端手势，选中记录自动进入可见区域，选区越界时清空或夹紧。Trajectory 不读取或改变 Chat projection；只消费同一 Session window 和自身 target projection。

### P7：StatsLine、ContextMeter 与证据回填

接入真实 usage、token、cache、TTFT、decode throughput、turn/step count、context pressure；缺字段省略或显示不可用。更新测试文档、项目文档、实施记录和 macOS 可见录制脚本。

## 9. 验收标准

- 打开会话后进入 resident conversation shell；切换空白/活跃、Chat/Trajectory、会话路由时，composer seat 与草稿不被销毁。
- 无会话/空白会话 Hero 的 Workspace picker 和 agent preset 使用同一个 InputBar；选 workspace 后不重建 composer，pending pick / deleted workspace / error retry / replay settling 不导致 hero 与 docked composer 闪烁；subagent header breadcrumb 可打开父级。
- `对话` / `轨迹` 切换不丢失会话、草稿、队列、Chat scroll anchor 或 Trajectory inspect state。
- Chat 不再直接渲染 permission/question 操作卡；pending wait 只通过 composer takeover 处理。
- Question takeover 优先于 approval；answer / cancel / allow / reject 都是一次性动作，resolved 后恢复 InputBar。
- 运行中 textarea 仍可编辑；普通发送、Queue、Steer 和 Stop 的可用性与 blocked reason 分开呈现。
- QueueDock 不自动提交；编辑、删除、逐条 steer、全部 steer 均需显式用户动作；steering 气泡与持久 user/message 交接无重复无闪烁。
- QueueDock 的非文本 row 显示编辑不可用原因，edit/delete/steer/steer all 失败通过 notice/toast 报错并保留本地编辑态。
- Todo dock 只读展示投影列表并可折叠；Goal dock 的 edit/pause/resume/clear 单飞，错误 inline 展示，完成/清除/空值不占位，创建只通过 `/goal`。
- `/` / `@` 菜单基于 selection 和 draft revision；IME Enter 不发送；菜单打开时焦点留在输入上下文。
- Escape 先关闭 overlay/menu，再进入输入状态机；已 claim command 不因 Escape 隐式释放；长按 Enter 不重复提交。
- reference occurrence 的 delete/copy/cut/paste-upgrade、undo/redo、caret reveal、输入框内部滚动与滚轮链式转交都有可重复测试。
- `+` 只打开 command launcher；附件入口不再占用 command launcher；不支持图片的 command 必须拒绝整次提交并保留图片。
- slash command input 以 command-input Chat Node 呈现；节点无时间、复制和 fork 行为，不伪装为普通 user/message。
- Model seat 在 composer block 下仍可用；无 provider/model/capability 时显示具体原因，不伪装成发送失败；已寻址 subagent 不显示模型选择。
- Think 只显示 display-safe 摘要；无摘要时不显示推理正文。
- Tool、compaction、retry、turn-tail 都是紧凑语义行，工具详情由独立 renderer/inspector 承担；文件路径打开失败显示可关闭/可重试对话框。
- Trajectory 具备轮次分组、Overview、虚拟行、历史加载、搜索/折叠/检查器，且不改变 Chat projection。
- StatsLine 与 ContextMeter 只显示真实投影或明确窗口回退；缺失字段显示不可用或省略，不填 0。
- unsupported、只读、无 lease、provider unavailable、content key unavailable、image limit exceeded、subagent read-only 均 fail-closed，并显示可理解的禁用原因。
- 图片粘贴/选择/可支持拖放共用预检和资源释放语义；发送失败保留草稿和图片。
- 普通 question 支持多题、单选/多选、推荐标签、freeform、skip、minimize、cancel 和失败重试。
- Question / Approval / PlanReview 长内容在 takeover card 内滚动，按钮始终可触达，失败重试不丢草稿、附件或已选答案。
- `danger-full-access` 权限 preset 必须有风险确认；取消、遮罩和 Escape 不提交。
- 已完成 assistant turn tail 才允许 fork；user/steering 气泡不显示 fork。
- assistant turn-tail produced files row 按可用宽度折叠 chips 和剩余计数，Host 支持时可打开目录；inline code 文件提及没有 provider vocabulary 时保持惰性展示。
- `start -> send -> abort`、`start -> kill`、恢复、错误和 read-only 路径仍由真实 Relay/Daemon receipt 驱动。
- 核心交互具备 Semantics label、焦点顺序、键盘触达、关闭/确认动作和焦点恢复验收；视觉录制不能替代无障碍断言。
- 关键控件保留稳定 key 或新增等价 key：`session-tab-chat`、`session-tab-trajectory`、`session-composer`、`session-composer-input`、`session-workspace-picker`、`session-agent-preset`、`session-send-button`、`session-stop-button`、`session-command-launcher`、`session-todo-dock`、`session-goal-dock`、`session-queue-dock`、`session-question-panel`、`session-approval-panel`、`session-stats-line`、`session-context-meter`、`session-kill-button`、`session-kill-confirm`。

## 12. 风险与决策

- `session_screens.dart` 已经过大，v0.5 必须先拆边界再迁功能，避免继续扩大单文件状态耦合。
- 当前 fixture 事件字段不足以支撑完整 StatsLine / Trajectory 时，只能显示不可用或窗口回退，不能补假 usage。
- Queue/Steer 需要 Relay/Daemon 显式支持 placement 或等价投影；协议未就绪时 UI 只能沉淀本地 fixture 契约，不能声称真实 provider 已支持。
- Composer 与 Android IME、键盘顶起、安全区、滚轮/触摸链式滚动是高风险区，必须有 widget 测试和 macOS 可见录制；安卓实机 gate 后续单独执行。
- Model / Permission seat 的语义来自 capability DTO 和 controls/projection；禁止按 provider 名称硬编码。
- Flutter 没有 React slot registry，但必须用 controller/provider + widget 边界保留等价所有权，避免跨区域直接读写。
- 未组合真实投影单元时，移动端应明确标注回退范围；不能把可见窗口折算说成全会话统计。
