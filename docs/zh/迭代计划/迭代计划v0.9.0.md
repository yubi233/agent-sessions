| 旧稿缺口 | 本版裁决 |

## 2. 目标、验收与非目标

### 2.1 目标

- **G1 超时与同步解耦（L1）**：send 受理 2 分钟后只切换 UX 表达；选中会话仍能收到迟到事件并以服务端终态自动翻正。
- **G2 用户出口与恢复（L2）**：超时横幅提供“查看结果”；后台/断网/重进恢复语义不回归。
- **G3 前台多会话对账（L3）**：用一个 quiet list reconcile 发现非当前 streaming 会话的进度或终态，按需拉快照；后台零新请求。
- **G4 会话级推模式（L4）**：为当前选中会话增加只读 SSE 失效通知，快照仍是内容和状态的唯一事实源；轮询是可随时启用的降级路径。
- **G5 样式一致性（B1-B7）**：色彩、字号、圆角、间距与图标由 token 和守卫约束；完成强制可见验收。
- **G6 可审计交付**：需求、测试 ID、长期测试文件、唯一聚合命令、可见证据和项目文档形成闭环。

### 2.2 必须可观察的结果

1. 事故 fixture 在 seq 48 停滞后无需用户操作，迟到终态到达时清除超时、展示完整结果。
2. 同一会话旧轮询响应即使晚于新回合、steer、中止、切换会话或认证切换返回，也不能改写当前回合状态。
3. SSE 断开期间轮询继续提供最终一致性；恢复后从已成功合并的 session cursor 重放，无丢失、无重复 UI 节点。
4. 非当前会话只有在快照确认真实终态后显示“有新完成结果”，打开后清除；失败或仅 `last_seq` 前进不伪装完成。
5. 后台、离线、注销、账号切换、设备撤销和 dispose 后无新 Timer/SSE 请求，也不接受迟到响应。
6. `task test:v090:local` 和 `task test:v090:flutter` 均通过；不能用截图、录屏或 `task check` 替代 Go/Flutter 行为断言。

### 2.3 明确非目标

不做 UnifiedPush、系统通知、Android foreground service、WebSocket、账号级多会话移动端 SSE、后台常驻连接、真实模型调用、生产数据迁移或 Android 实机 gate。现有账号级 `/v1/events` 和 Terminal 专用 `/v1/daemon/commands/stream` 不改变语义。

## 3. 冻结契约

### C1 回合状态与超时语义

- 将“服务端仍有活动回合”“前台等待已超时”“当前是否执行同步任务”拆成独立状态，禁止继续用 `_turnInFlight` 同时表达三者。
- 本机 send 只有在 `submitSessionCommand` 收到 Relay 202 后才算受理；必须在同一 command id/idempotency key 的首次即时受理分支内、等待 `_awaitCommandReceipt` 或任何快照之前，用单调时钟原子记录 `acceptedAt`、活动回合和 `uxDeadline=acceptedAt+2min`、`continuationDeadline=acceptedAt+60min`，随后通知 UI。相同幂等命令重试复用已有锚点，不得等 `_submitCommand` 整体返回后才起算或重复续期。
- 进程重启恢复、账号内其他设备发起回合，或本机缺失受理锚点时，先合并一次 canonical snapshot；若确认仍为活动态，以首次成功观察的单调时刻 `observedAt` 建立本 App 运行期的 2/60 分钟预算。单调锚点不跨进程持久化；同一进程内进入后台再恢复时 elapsed duration 继续累计且不重新起算。禁止用 attempts×interval 或不可信服务端时间推导等待时长。
- 到达 2 分钟 deadline 后置 `turnTimedOut`，横幅改为“等待结果已超时，仍在同步”，但活动回合事实保持；空草稿仍允许用户中止，有草稿时沿用既有 queue/steer 交互。
- UI 已区分 `SessionSubmitMode.send` 与 `SessionSubmitMode.steer`，但当前二者都调用同一 `sendMessage`。实现必须把本地提交意图显式传入 controller（例如 `TurnSubmissionIntent.newTurn|steer`，无需改变 Relay `session.send` wire kind），禁止靠文案、草稿或易漂移的 `_turnInFlight` 猜测。steer 不创建新业务回合、不清除超时、不重置续轮期限；但会推进技术同步代际，避免提交前发出的旧快照迟到后覆盖新状态。只有在前一回合已有 canonical 终态后受理的 `newTurn` 才重置业务回合起点与超时预算。
- 选中会话的降频轮询为 10 秒一拍（单会话最多 0.1 QPS），到 60 分钟 continuation deadline 停止；到期只停止该任务并保留超时提示。L3 的全局 25 秒 quiet reconcile、SSE 失效通知、生命周期恢复和“查看结果”仍可发现迟到事实。
- 任何路径都不得因为本地超时伪造 idle/completed，也不得清除服务端仍可能执行的回合事实。

### C2 异步隔离与单航班

- `authGeneration`：登录态或设备绑定变化、认证失效、注销及 dispose 时递增。旧代际的 Timer、SSE、REST 回包全部丢弃。
- `selectionGeneration`：沿用并扩展现有选择代际；它绑定“当前可见 session surface + 选中会话”。切换会话、离开会话页面或页面重新挂载时推进，旧选择的 UI 状态、controls、timeline、L1 和 SSE 不得写入当前页面。
- `syncGeneration[sessionId]`：在 send、steer、abort 等可能改变回合状态的命令实际提交前，以及 canonical 终态收口时推进。它是取消旧异步任务的技术代际，不等同于 Provider turn id；steer 推进该值但继承原业务回合起点、超时标记和 60 分钟期限。命令受理后必须在新代际下置一次 pending snapshot；L1、手动刷新和终态写入都携带该值。
- 每个异步任务在发请求前、每次 `await` 后、调用 `_mergeSnapshot` 前和修改 timedOut/active/controls 前校验适用代际。代际不匹配是正常取消，不显示错误。
- 每个会话最多一个 snapshot refresh in-flight；SSE 唤醒、L1、L3、手动刷新和 lifecycle recovery 进入同一个 coalescing scheduler。新唤醒只置 pending，当前请求结束后从已合并 cursor 再拉一轮。

### C3 L1/L2 快照同步

- 所有增量快照继续使用 session-local `afterSequence`，以 `_mergeSnapshot` 为唯一合并路径；终态事件和服务端非 streaming 状态均可翻正。
- “查看结果”触发一次强制快照同步，但仍服从单航班和代际守卫。成功只在真实状态/事件到达时清横幅，失败保留横幅并显示现有脱敏错误。
- 最后事件新鲜度使用客户端成功合并事件时的单调/墙钟组合记录，显示于超时横幅次级行；服务端时间只用于事件展示，不用于网络健康判断。
- 切换会话只取消该选择的 L1 任务；不会伪造远端回合终止。再次打开时从本地 session cursor 恢复。

### C4 L3 quiet reconcile 与完成角标

- 定时条件：认证有效、前台、网络非 offline，且本地至少有一个 `streaming`、`waitingPermission`、`waitingQuestion` 或其他已确认活动回合的会话。默认全局 25 秒一拍；这里的 0.04 QPS 只指 `listSessions()`，并与手动列表刷新共享 single-flight。
- 周期路径调用 quiet reconcile：不把 `SessionListPhase` 切为 loading/error、不覆盖已有可用列表；失败只记脱敏状态并等待下一拍。手动刷新仍有原有加载与错误反馈。
- 先比较本地与 `listSessions()` 的 `status`/`lastSequence`；只有 status 翻转或 `last_seq` 前进才把对应会话加入 L3 快照队列。每拍最多取 4 个、并发最多 2 个，状态翻转优先于仅序号前进，未处理项留到后续拍；正在被 L1 或 SSE 唤醒拉取的会话由单航班去重。该上限使 L3 后台流量最多为 0.04 list QPS + 0.16 snapshot QPS，不包含用户手动刷新。
- 后台停止新拍；前台恢复先走既有 cursor recovery，再立即执行一次 quiet reconcile，二者共享请求，不叠加首拍。
- 非当前可见会话的完成角标为认证运行期内存集合 `unseenCompletedSessionIds`，不持久化。只有该会话此前在本机被观察为活动，且增量快照成功确认 canonical `turn.completed` 的 idle 投影，或确认会话由活动态转为 idle 后才置位；`turn.completed` 的 stopped 投影不算“完成结果”。
- 打开并成功合并该会话快照、会话被移出列表或认证代际结束时清除角标。列表项提供稳定 Key 和 Semantics label“有新完成结果”；仅序号前进、拉取失败、stopped/errored 不显示“完成”。

### C5 L4 Relay 会话级 SSE

- 新增 additive 端点：`GET /v1/sessions/{id}/events`。必须先按当前账号授权目标 session；错误必须沿用现有 snapshot 的稳定 JSON 语义：不存在为 404/`INVALID_REQUEST`，跨账号为 403/`SCOPE_DENIED`，设备撤销为 403/`DEVICE_REVOKED`。客户端不得只按 HTTP 403 作全局退出判断。
- `Last-Event-ID` 优先于 query `after_seq`；二者都是该 session 的排他 `event_seq`，必须使用独立类型/命名 `SessionEventCursor`，绝不能传入 `/v1/events` 的 `AccountEventCursor`。
- 事件帧仅作失效通知：`id: <session event_seq>`、`event: invalidated`、`data: {}`。App 不解析 canonical envelope；收到通知后按已合并 session cursor 拉 snapshot。
- 服务端先订阅 Hub，再立即从 SQLite 回放并 flush 一个连接注释；响应包含 `text/event-stream`、`Cache-Control: no-cache` 和 `X-Accel-Buffering: no`。初始回放和每次 Hub 唤醒都按 last-sent cursor 从 SQLite 补齐缺口；每个 15 秒 heartbeat tick 必须先复核 token/设备，再从 SQLite 补缺口，最后发送注释心跳。所有回放严格按 `event_seq` 升序去重。Hub 只负责降延迟，即使 channel 丢唤醒也必须在下一 heartbeat 自愈；断开即释放订阅和 ticker。
- 每个心跳复核 access token 是否仍有效，以及绑定设备是否仍 active；查询失败 fail-closed。设备被撤销后最多一个心跳周期关闭旧连接。契约测试同时断言 `text/event-stream`、`no-cache`、单调 id 和断开资源释放。
- 现有账号级 `GET /v1/events` 的 account-global cursor、frame 和 Web 消费者保持不变；现有三项 `TestP4AccountSSE*` 必须作为 V090-08 回归运行。

### C6 L4 App 传输状态机

- 先成功合并一次目标会话快照，再用其 session cursor 建立 SSE，消除首次从 0 回放全部历史的风险。快照与建流之间的事件由服务端 replay 补齐。
- SSE frame id 只是 wake watermark。只有 snapshot 成功合并后才推进可恢复 cursor；快照失败时不得用已看见但未消费的 SSE id 重连，否则会跳过事件。
- 使用专用 streaming HTTP client：TCP 建连以及收到 SSE headers/首次 flush 的 handshake 各自最多 10 秒；建流后禁用普通 REST 的 12 秒 receive timeout；以“15 秒服务端心跳、40 秒无字节 watchdog”判定僵死并主动重连。
- 状态为 `connecting/live/backoff/pollFallback/resourceInvalid/authInvalid/stopped`。进入 backoff 或 pollFallback 时轮询立即托底；连接 flush 注释不清零退避，收到首个正式 heartbeat/事件后才算 live 并清零退避次数。`resourceInvalid` 只停止该会话同步，不清全局认证态。
- live 时由 SSE wake 驱动增量快照，不再同时运行 250/500ms 高频在途轮询；L3 的 25 秒安全对账仍保留。connecting/backoff/pollFallback 时，活动回合先使用既有有界在途轮询，进入 UX 超时后切到 L1 10 秒续轮。
- 临时错误：网络错误、EOF、watchdog、429、可恢复 5xx使用带 jitter 的 1 秒到 30 秒指数退避；前台期间持续重试，不永久降级。
- 401/`UNAUTHENTICATED`：复用 `HttpRelayRepository` 现有 single-flight refresh，一条失败链最多尝试一次，成功后重连；刷新失败进入 `authInvalid`。403 必须读取稳定 code：只有 `DEVICE_REVOKED` 进入 `authInvalid`；`SCOPE_DENIED` 进入 `resourceInvalid`、刷新列表并停止该会话请求，不得注销仍有效的账号。
- 404 不能直接等同“旧 Relay 不支持端点”：只做一次同 session snapshot 探测。snapshot 200 才判定旧 Relay 无此路由并在当前认证代际进入 `pollFallback`；snapshot 404/403 则按会话不存在/越权进入 `resourceInvalid`；探测遇到网络、429 或可恢复 5xx 时结论仍未知，保持 `backoff` 并由轮询托底。405、501/`CAPABILITY_UNSUPPORTED` 或显式 `poll_only` 可直接固定回落；Relay kill switch 必须返回 501/`CAPABILITY_UNSUPPORTED`，不得伪装资源 404。
- 400/非法 frame 先强制 `after_seq=0` 全量快照并重试一次，重复失败按协议错误固定回落并留下脱敏诊断。临时错误重试期间继续轮询；429 的合法 `Retry-After` 可采用，但等待仍上限 30 秒并加入 jitter。
- 客户端同一时刻只为“前台且 session surface 可见”的当前选中会话保留一条 SSE。离开会话页面、切换会话、后台、offline、注销和 dispose 必须取消 stream、watchdog、backoff delay、L1 和 pending wake；其他前台页面只由 L3 对账。

### C7 认证、销毁与回滚

- 增加 App 认证状态与 `SessionController` 的显式协调：认证建立后初始化会话运行期；注销/恢复换设备/账号切换前先 `resetForAuthBoundary()`，再清 token/cache。远端只有 refresh 最终失败或 typed `DEVICE_REVOKED` 才触发认证收口；`SCOPE_DENIED`、会话 404 等资源错误不得清账号 token。
- `SessionController.dispose()` 必须同步阻止新调度、递增 auth generation，并取消全部 Timer/stream。任何完成中的 Future 返回后不得 `notifyListeners()`。
- 本机绑定设备由其他 owner 撤销时，Relay 在心跳关闭 SSE；下次连接/REST 返回 403 后 App 退出认证态并清理会话运行期。撤销其他设备不影响本机连接。
- App 提供 `SESSION_EVENT_TRANSPORT=auto|poll_only` 构建开关（默认 `auto`）；Relay 提供 `AGENT_SESSIONS_SESSION_SSE_ENABLED=0|1` kill switch（默认 `1`，关闭时端点返回 501/`CAPABILITY_UNSUPPORTED`）。回滚只切换传输，不回滚数据库或事件 schema。

### C8 A/B 文件协调

A 线允许按本计划新增按钮、文案、Key 与 Semantics；B 线仍严格限制为视觉迁移。共同触达 `session_chat_view.dart` 时，先完成 A 线行为提交和测试，再在独立提交中迁移 B 线 token，并重新运行两线测试。禁止以“只改视觉”为由删除 A 线可访问性语义，也禁止在 B 线顺手改变交互。

### C9 不做全局后台心跳

移动端后台常驻需要 foreground service/系统推送，不符合本期成本与平台语义。场景按下表承载：

| 场景 | 承载层 | 用例 |
| --- | --- | --- |
| 前台且会话页面可见的选中会话 | session SSE；失败时 L1 | V090-01/02/03/09 |
| 前台其他页面或非当前会话 | L3 quiet reconcile | V090-06/07 |
| 桌面失焦/最小化 | 延续 V085-25：不误判移动端后台 | V090-05 |
| 移动端后台到前台 | 停流/停拍，恢复后 cursor + 首拍对账 | V090-05/07/09 |
| 进程重启 | 全量首快照后再建 SSE | V090-05/09 |
| 断网到在线 | 停流、轮询不发请求；在线后恢复 | V090-05/07/09 |

## 8. 风险、观测与回滚

| 风险 | 防护与回滚 |
| --- | --- |
| 多同步源重复请求/乱序 | per-session single-flight + pending wake + auth/selection/sync 三重代际；快照 cursor 是唯一 commit 点 |
| SSE 看见 id 后快照失败导致跳序 | SSE id 不提交 cursor；重连永远使用最近一次成功合并的 session cursor |
| Hub 非阻塞 channel 丢唤醒 | 初始、每次 wake 和每个 heartbeat tick 都从 SQLite cursor 补缺口；Hub 不承担可靠性 |
| REST 12 秒 timeout 杀死 15 秒心跳流 | streaming client 独立配置，receive timeout 禁用，40 秒无字节 watchdog 接管 |
| 临时网络错误形成永久降级 | 临时错误持续有界退避；轮询同时托底；只有不支持/重复协议错误才按认证代际固定回落 |
| 账号/设备切换串数据或资源 403 误注销 | auth generation + typed error code + resetForAuthBoundary + 服务端心跳复核；迟到回包与 `SCOPE_DENIED` 负向回归 |
| L3 请求放大或页面闪烁 | 全局 25 秒 list、每拍 4 个/并发 2 个 snapshot、仅活动集合存在时运行、quiet reconcile、single-flight；后台停拍 |
| Relay 长连接资源泄漏 | 当前 App 仅一条 session stream；handler context、ticker、Hub subscription 均有释放断言 |
| UI 大迁移掩盖行为回归 | A/B 独立提交；全量 Flutter + 强制 headed gate；B 线不改文案/Key/Semantics/回调 |
| 紧急回滚 | App `poll_only` + Relay kill switch；继续运行 L1/L3，无 schema/数据库回滚 |

只记录脱敏元数据：连接状态、重连次数、fallback 原因分类、snapshot coalesce 次数和耗时；不得记录 token、SSE data、正文、密文、session 标识或本机路径。
