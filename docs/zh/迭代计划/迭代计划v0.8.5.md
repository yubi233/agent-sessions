## 1. 诊断基线

### 1.1 会话发送图片：opaque attachment ref 链路（B-2）

ADR-014 §4 裁决：`Relay/移动端只持有 opaque attachment 引用（id、MIME、宽高、字节大小、哈希），不接触明文；Daemon 授权读取/解密后把图像转为 ACP image content block 发给桥`，拒绝矩阵 fail-closed，失败不落明文日志。未接通前 attachments 保持条件式 unsupported 并如实标注原因，不冒充可用。

**已就绪的部分**（不用重做）：

- 桥侧（deepseek-harness）100% 就绪：`packages/acp/acp/src/content.ts` 的 `admitAcpPrompt`（图像 admission、MIME 表、canonical base64 校验）、`@deepseek-ai/dsh-attachment-local` 挂载、`assistantBlockToAcp` 双向转换、`initialize` 如实广告 `promptCapabilities.image`；受控 overlay `e2e-verify/fixtures/dsh/cordis-v083-image.yml` 已存在。
- Go 侧通路就绪：`internal/adapter/dsh/extension_handle.go:279-306` `SendContent`（image → `{type:"image", data, mimeType}`，字节只经内存）；`internal/daemon/runner.go:427-470` 已按 `fixture_payload.images` 路由混合内容。
- 移动端上传半链路就绪：`apps/mobile/lib/attachments/attachment_picker.dart`（MIME 白名单 → 会话 DEK + AAD 密封 → 分块）；`session_controller.dart` 逐块上传 + complete 幂等续传；Relay `POST /v1/attachments/chunks|complete`（`internal/httpapi/handlers.go:78-79`）与 ATTACH-01 契约测试、SQLite attachment/chunk 行均已就位。
- 能力矩阵预留升格口径：`internal/adapter/dsh/adapter.go:461-469` 明确"Relay opaque attachment ref 接入后按 deployment 条件升格"。

**缺失的四环**：

1. **会话内容密钥交付通道**：`apps/mobile/lib/relay/http_relay_repository.dart:635` `sessionContentKeyAvailable` 恒返回 `false`（"真实 Relay 尚未部署端到端内容密钥交付通道；必须 fail-closed"），生产环境回形针按钮永远禁用。
2. **Daemon 授权读取通道**：附件只有上行 POST，没有任何供 Daemon 按引用拉取密文块的端点。
3. **发送密文仍是 inline base64**：`runner.go:1296-1301` 走 `fixture_payload.images`（base64 明文随命令信封过 Relay）。按 ADR-014 §4 必须改为 opaque ref（attachment id、MIME、宽高、字节大小、哈希），Daemon 校验引用授权后自行读块解密。
4. **能力升格与 UI 门控联动**：矩阵从 unsupported 按 deployment 条件升格；移动端模型设置弹窗 "⊘ attachments 不可用" chip（`session_model_seat.dart:817-852`）与 `attachmentPickBlockedReason`（`session_controller.dart:1632-1640`）随之联动。

本期范围只接 **图片**（png/jpeg/webp，对齐 ADR-014 B-2 图像契约与桥 admission）；文本附件（txt/md）上传链路虽已具备，发送保持 unsupported 并如实标注，不在本期放开。

### 1.2 权限选择器不可点击（图 1）

- 控件本体：`apps/mobile/lib/ui/session_screens.dart:4875-4950` `_ComposerControlStrip` 的 `DropdownButtonFormField`（key `composer-permission-mode-select`）。`onChanged` 需要同时满足 `permissionModeBlocked == null` 且 `controls.availablePermissionModes.isNotEmpty`；目录为空时 `items` 为 0 且 `onChanged: null`，控件整体禁用——这就是截图中"只有标签和箭头、点了没反应"的空壳。
- 显示条件由 provider 能力矩阵驱动：dsh 把 `permission_mode` 声明为 native（`internal/adapter/dsh/adapter.go:414-421`），所以控件显示；而目录来自 `GET /v1/sessions/:id/controls`，**`internal/httpapi/handlers.go:587-641` 只输出 model/usage/models/model_groups/default_model/efforts，从不输出 `permission_mode` / `available_permission_modes`** → 真实链路目录恒空 → 恒禁用。
- 会话级 mode 目录其实已在 Daemon 内存：桥在 `session/new|load|resume` 响应回带 `modes`，`internal/adapter/dsh/extension_handle.go:36-71` `storeModes` 已存入 handle，但**没有任何上行通道把它带到 Relay/客户端**。
- 第二处契约错位（即使能点也会失败）：移动端命令 kind 是 `session.permission_mode`、payload key 是 `permission_mode`（`apps/mobile/lib/domain/session_models.dart:625`、`session_controller.dart:1762`），而 Daemon 只接受 `mode.set` + `mode_id`（`internal/daemon/runner.go:199`、`:1279`）→ 现有 mobile kind 落 `ErrUnsupportedCommand`。
- fixture 仓库硬编码了目录（`fixture_relay_repository.dart:1963-1969`），所以 fixture 演示能点、测试没拦住真实链路——本期把 fixture 与真实契约对齐，禁止继续各自漂移。

### 1.3 副标题工作区名显示错误（图 2）

- 副标题组件 `_HappySessionHeaderTitle`（`session_screens.dart:5624-5674`）读取 `session.projectName`（JSON 字段 `project_name`），**全仓库只有 fixture 赋值过该字段**，Relay `sessionView`（`internal/httpapi/handlers.go:1649-1671`）从不下发 → 生产恒为 null → 恒落硬编码兜底 `'agent-sessions'`（`session_screens.dart:5665`）。与用户当前选了哪个工作区完全无关，不是"显示了别的工作区"，而是"永远显示写死的字符串"。
- `MobileSession` 上已有现成的 `workspaceName` 解析与 `workspaceLabel` getter（`session_models.dart:120,165-167`），但 Relay 不下发 `workspace_name`，组件也未使用。
- 同族缺陷（遗留问题 v0.8.1 #4）：空会话 hero 显示 `ws_v08_…` 原始 ID 而非工作区显示名（`session_screens.dart:2043-2053`），本期一并修复。

### 1.4 工作区列表 5 vs 3（图 3）

### 1.5 用量缺"首 token 平均 xx s · xxx tok/s"（图 4 模型设置弹窗）

- **ACP 标准不提供这两个指标**，dsh 桥的 `usage_update` 也不带（`deepseek-harness/packages/acp/acp/src/index.ts:918-937` 只带 token 计数与 contextWindow）。dsh 终端 CLI 的"首 token xx s · xx tok/s"是**前端由会话事件时间戳现场折算的**：`step/start` 事件时间 → 首 条 token 型 `assistant/chunk` 时间 → `assistant/message` 时间（`packages/client/runtime/src/client/sessions/assistant-timing.ts:36-49`、`turn-metrics.ts:40-97`）。
- 结论：**原始 timing 数据在桥的 `ctx.on('session/event')` 里全部可见，只是没有投影**。
- Agent Sessions 下游整条链路已铺好字段、零改动即可点亮：`internal/domain/usage.go` 已有 `ttft_ms`/`decode_throughput`（含上限校验）；`internal/daemon/relay.go:1362-1399` `ttftFromPayload`/`throughputFromPayload` 已能读 `ttft_ms`/`decode_throughput`，甚至支持从 `timing{stepStartTime, firstTokenTime, completedTime}` 子 map 推导（camelCase 与 dsh 事件字段一一对应）；Relay controls view 已下发；移动端 chips 已实现（`session_stats_line.dart:47-56`，key `session-stats-ttft`/`session-stats-throughput`），仅在 null 时隐藏。
- **唯一缺口：桥不投影、Go mapper 不透传**（`internal/adapter/dsh/mapper.go:28-33` `usageUpdate` 只有 4 个 token 计数）。

### 1.6 会话的 Agent 预设（确定口径）

- dsh 内部有完整会话级 agentPreset 生命周期：`SessionHeader.agentPreset` + `agent-preset/selected` 持久化事件 + roster（`standard`/`minimal` 两个 shipped preset）；**preset 由桥部署配置派生**（`config.minimalModel` 命中为 `minimal`，否则 `standard`），`session/set_config_option` 切模型联动换 preset，但**首 turn 后冻结**；load/resume 从最后一条 selected 事件重建；fork 继承。
- ACP 协议面**读写路径都不存在**：`session/new` 不收 preset 参数；`session/list` 只回 `sessionId/cwd/updatedAt`。
- Agent Sessions 链路全无该字段：Go/协议/Relay 均无；`MobileSession.agentPresetId` 解析 `agent_preset_id` 但恒 null；Flutter 只有 fixture 脚手架（`session_agent_preset.dart` 注释明确"真实 Relay 没有 roster 协议时不渲染"）。
- **本期裁决**：Agent 预设 = 桥部署配置派生的会话属性，Agent Sessions 做**只读投影**（如实显示 standard/minimal），**不支持客户端选择写入**（桥无写路径且首 turn 冻结，写入保持 unsupported 并如实标注）。桥补只读暴露（dsh/* extension，ADR-014 §7 规则）。

## 2. 目标与完成标准

### 2.1 目标

- G1（图片）：真实链路"移动端选图 → DEK 密封分块上传 → opaque ref 随命令发送 → Daemon 授权读取/解密 → ACP image block → 桥 admission → 模型回复"全程贯通；任一条件不满足（缺密钥、缺 attachment 服务、text-only 模型、MIME/超限/哈希不符、无引用授权）时保持 unsupported/准确拒绝，任何失败路径明文不落日志。
- G2（权限）：会话级权限 mode 目录经 controls 下发，移动端可选、可切换、有 pending 与失败浮出，`danger-full-access` 类高风险 mode 保留风险确认弹窗，`current_mode_update` 回流与 UI 状态一致。
- G3（工作区）：会话页副标题与空状态 hero 显示真实工作区显示名；dsh 工作区发现口径与终端对齐（非 Git 根可登记），安全边界（授权根、深度、符号链接、确认流）不放宽。
- G4（用量）：usage 投影携带首 token 时延与解码吞吐，移动端显示真实值；无数据时保持隐藏，不显示假值。
- G5（预设）：会话 Agent 预设真实链路只读可见；写入明确 unsupported 带脱敏中文原因。
- G6（回归）：OpenCode/Codex 与 V081–V084 全部回归绿；fixture 仓库与新契约对齐，不再硬编码漂移。

### 2.2 完成标准

1. opaque attachment ref 命令 envelope、会话内容密钥分发、Daemon 附件读取授权三份契约冻结并有 schema/生成物；Relay 侧任何视图、日志、回执不出现明文或可解密元数据。
2. 真实 Relay 链路上权限下拉框有目录、可点、可切换，命令以权威契约（`mode.set` + `mode_id`）到达 Daemon 并回写桥；目录缺失时控件禁用且显示原因，不再是无解释空壳。
3. 副标题/空状态显示工作区显示名；money 等 5 个 dsh 工作区经 sync + 确认流全部可登记、可见。
4. 模型设置弹窗用量区显示"首字 x.xs · xx.x tok/s"（真实桥数据）；旧桥/无 timing 时字段缺省。
5. 会话详情/模型设置显示 Agent 预设只读值；选择器不渲染于生产链路。
6. `task check`、Go/Flutter/Web 定向测试、deterministic overlay、headed Chrome、可见 Flutter gate 全部通过；真实模型 gate 另行授权记录。

### 3.1 opaque attachment ref 发送命令

```text
ciphertext.fixture_payload.attachments: [
  { attachment_id, mime, width?, height?, size_bytes, sha256 }
]
```

- 取代 `fixture_payload.images`（inline base64）在**生产链路**的使用；`images` 保留给 fixture/e2e overlay（deterministic 测试需要注入确定性字节），Daemon 两者都认但生产客户端只发 refs。
- Daemon 校验顺序（fail-closed，任一失败整批拒绝并回 `session_error` 脱敏原因）：引用归属（attachment 属于该 session/account）→ 状态 completed → 数量/总量上限 → 逐块读取 → 哈希复算（`sha256` 与登记值一致）→ 解密 → 构造 `ContentBlock{Type:"image"}` → `SendContent`。块顺序冻结为 image blocks 在前、text 在后（与桥 `admitAcpPrompt` 语义一致）。
- 字节只经内存；事件、回执、日志、审计均不得含 base64/明文。

### 3.2 会话内容密钥分发（新 ADR）

- 推荐：Daemon 在会话创建时生成会话内容 DEK，用已配对 owner 设备公钥 wrap 后随会话快照/controls 下发（wrapped blob 对 Relay 不透明）；移动端以设备私钥 unwrapped 后用于附件密封。备选（移动端生成并上传 wrapped DEK）在 P0 评审后定稿。
- 冻结内容：生成方、wrap 算法与版本字段、轮换与撤销、无 DEK 设备的降级边界（fail-closed 维持现行为）。新增 ADR-016（或 ADR-002 修订附录）承载，遵循"显式授权部署模式，不暗中改变默认边界"。
- `sessionContentKeyAvailable` 接通真实通道后，无密钥会话仍禁选附件并显示"等待会话附件密钥"。

### 3.3 Daemon 附件读取授权

- Relay 新增 **Daemon 鉴权**的只读端点（按 attachment_id 返回 `metadata_ciphertext` + 密文 chunks；响应不回显任何可识别元数据），复用既有 terminal/daemon 认证与 lease 语义；不做面向终端用户的下载端点（本期无此需求）。

### 3.4 controls / sessionView 扩展

- `GET /v1/sessions/:id/controls` 增加：`permission_mode`（当前生效）、`available_permission_modes`（会话级目录，来源 = Daemon 从 handle `Modes()` 上行）。目录为空时不输出字段，客户端维持禁用 + 原因。
- `sessionView` 增加：`workspace_name`（workspaceId → workspace 显示名的服务端解析）、`agent_preset_id`（只读，未协商时缺省）。usage 的 `ttft_ms`/`decode_throughput` 已在 view 中，无需改动。

### 3.5 权限命令契约统一

- 权威契约 = Daemon 既有 `mode.set` + `mode_id`。移动端 `SessionCommandKind.permissionModeSelect` 的 wire kind 由 `session.permission_mode` 改为 `mode.set`、payload key 改为 `mode_id`；`events.json`/OpenAPI/TS 生成物、fixture 仓库同步。旧 kind 不留别名（协议客户端仅本仓库两端，同步收口，避免双契约长期共存）。
- 切换清账双通道：`mode.set` 命令回执 + 桥 `current_mode_update` 事件投影，两者以前者为准、后者校正。

### 3.6 dsh 工作区发现口径（重裁决）

- P0 盘点 dsh 终端 5 工作区的注册证据后定稿，方向：
  1. `.dsh-sessions` 持久化证据（有效 `session-query.db`）即构成 dsh 候选，**Git 根不再是 dsh 来源的必要条件**（ADR-005 的 Git 门槛继续约束 Agent Sessions 自管项目与 gitread 功能面）；
  2. 若盘点确认存在"无本地证据却被 dsh 列出"的工作区（如网游风格小说），评估从 dsh 自身持久化（会话 DB 的 distinct cwd / 全局注册表）补充候选来源。
- 安全边界不放宽：授权根、深度上限、隐藏目录/`node_modules`/符号链接跳过、canonical path、sync → Daemon 本机确认 → 登记的确认流全部保留。
- 非 Git 根工作区：Git 只读功能（gitread）不可用并如实标注，不影响 dsh 会话；`display_name` 仍取 basename；移动端 `isDsh` 过滤不变。

### 3.7 usage timing 扩展（桥 + mapper）

- 桥在 `assistant/message` 触发的 `usage_update` 上附版本化 `_meta`（与既有 CHUNK_META_KEY 同模式，SDK 客户端剥除未知字段，无需扩展协商）：`{ turn, step, ttftMs, decodeThroughput, outputTokens }`，折算公式与 dsh 前端/`session-stats` fold 完全一致（`ttftMs = firstTokenTime - stepStartTime`；`decodeThroughput = outputTokens / ((completedTime - firstTokenTime)/1000)`）；无流式/replay 轮次不发 timing。
- `mapper.go` `usageUpdate` 增加对应字段，payload 产出 `ttft_ms`/`decode_throughput`（含 `output_tokens` 复核）；Daemon `ttftFromPayload`/`throughputFromPayload`、Relay view、移动端 chips 零改动。
- 缺失/畸形 timing 丢弃并计数，不阻塞 usage 主字段。

### 3.8 Agent 预设（只读投影）

- 桥读路径：`session/load`/`resume` 响应（及 `session/list` 行，若实现成本一致）按 ADR-014 §7 dsh/* extension 版本化回带 `agentPreset`；未协商扩展的客户端收不到该字段。
- Go `wire.go` 落 wire type → handle 会话元数据 → Daemon 会话状态上行 → Relay `agent_preset_id` → 移动端 `SessionAgentPresetLabel` 接真实数据；`SessionAgentPresetSeat`（选择器）生产链路维持不渲染，设置页如实标注"由 DSH 桥配置决定，客户端选择不可用"。

## 6. 验证与证据口径

- 默认验证：`fixture_data=true`、`local_test=true`、`real_model=false`、`real_upstream=false`；deterministic overlay 使用本地真实桥进程 + `cordis-v083-image.yml` 注入，不调用模型。
- 本轮验证按四类分开报告，不得混称：**smoke**（真实模型最小链路先通）→ **targeted diagnostic**（单个失败功能/契约定向复现）→ **full gate**（V085 套件全量 + 回归）→ **recording**（full gate 通过后的录屏演示）。任何 incomplete gate 不能称为完整通过。
- headed Chrome 与可见 Flutter gate 记录 `real_browser=true`/`headless=false`（移动端按既定口径走 Android 实机）；headless 只作快速回归；录屏只是通过后的展示证据。
- 真实模型/真实上游需用户显式授权，执行前说明预计请求次数、模型/提供方、用量与可停止点；先 smoke 再 full gate，429/超时按有上限重试并记录尝试次数，契约失败不得靠重试标绿。
- 每个 gate 报告沿用仓库既有报告 schema，至少包含：`suite/status/real_browser/real_model/real_upstream/fixture_data/local_test/headless/browser/model/provider/credential_source/command/request_ids/usage/artifacts/failure_class/remaining_risk`；凭据只记来源类别（如 `env:NAME`），不记值。
- 失败必须按标准分类归因：`product_defect`、`test_harness_defect`、`selector_or_dom_contract_defect`、`provider_http_error`、`provider_timeout`、`model_contract_failure`、`model_flakiness`、`credential_or_quota_blocker`（标记 blocked，不伪造真实验证）、`checkpoint_mismatch`、`environment_or_startup_failure`；不得为绿色结果静音、跳过、放宽断言或改写历史证据。
- 图片链路的通过标准必须逐层独立证明（上传→读取→解密→桥 admission→回复），不得以 fixture 演示替代真实 gate；任一层失败保持 `partial`/`blocked` 并如实标注能力状态。
- 长 gate/录屏命令必须有最终退出码或明确超时分类；结束清理本轮启动的子进程、端口与录屏进程，不动用户已有服务。
- 历史 failed/partial 证据不改写；本期修复以新 V085 ID 独立报告承接。

- 图片链路四环（密钥交付、引用发送、授权读取解密、桥 admission）在真实链路贯通，且拒绝矩阵与"不落明文"边界经审计证明；未满足 deployment 条件的实例保持 unsupported 且原因如实。
- 权限选择器在真实链路可用（目录下发、`mode.set` 贯通、回流一致），且目录缺失时行为可解释。
- 工作区显示与发现口径修复：副标题/空状态显示真实显示名，dsh 工作区实机 5/5 对齐，安全边界无放宽。
- 用量 timing 与 Agent 预设按冻结契约贯通，缺省路径不显示假值；预设写入保持 unsupported 如实标注。
- OpenCode/Codex 与 V081–V084 回归全绿；deterministic overlay、headed Chrome、可见 Flutter gate 与 V085 套件有可审计报告，失败项带标准 failure_class 分类。
- 关键回归沉淀完成：六个缺陷各有一个根因层回归与一个用户可见端到端回归（或书面说明既有覆盖足够）；覆盖缺口审计矩阵与自动化测试文档同步。
- 录屏演示完成（full gate 通过后 `task record:v085`），或用户明确跳过时记录跳过原因。
- 真实模型 gate 若未获授权或部署缺少图像能力，如实记 `blocked/partial`（failure_class=`credential_or_quota_blocker` 等），不阻塞其余项收口，也不升格能力矩阵。
