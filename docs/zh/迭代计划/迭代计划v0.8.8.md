## 1. 诊断基线（2026-09-05 真实栈盘点）

### 1.1 矩阵来源与升格规则（本轮不动协议，只动状态与证据）

- 矩阵唯一来源：`internal/adapter/dsh/adapter.go:390` `successMatrix`（spec §2 冻结口径，逐项硬编码 status/reason）；UI 只透传（`apps/mobile/lib/ui/settings_screens.dart:457`「能力状态来自 Relay 声明」、:551 三态文案）。
- 移动端入口门控：`controlBlockedReason('<capability>')`（`session_controller.dart`）按矩阵 status 屏蔽入口——`attachments` 已被门控（:1719/:1834），矩阵升格后入口自动解锁，无需改 UI 门控逻辑。
- 升格先例：v0.8.3 P5 将 permission_mode/fork 升为 native，流程 = 桥事实（`bridgeImplementedACP` 锚点）+ 全链路回归 + deterministic gate 证据 + 守护测试修订（`internal/adapter/dsh/consistency_guard_test.go:81-145`）。本轮沿用同流程。
- 守护测试现状：`consistency_guard_test.go:130-144` 把 attachments 钉死为 unsupported（reason 必含「opaque attachment ref」）；升格时该段必须与矩阵同步修订，否则守护测试红——这是「状态不得先于实现变更」的强制机关。

### 1.2 attachments：链路已建成约九成，缺最后一根接线

**已就绪面（本轮零改动或仅回归）**：

- 移动端全套：附件选择与密封（`apps/mobile/lib/attachments/attachment_picker.dart`，metadata + chunk 逐块 envelope Seal）；分块上传（`http_relay_repository.dart:777/:808` chunks/complete）；refs 进 `session.send`（`session_controller.dart:1138` `_completedAttachmentRefs`）；无密钥 fail-closed 语义（`sessionContentKeyAvailable`，「等待会话附件密钥」禁选）。
- Relay 全部路由在位：`internal/httpapi/handlers.go:55`（owner 读 content-dek）、:81-82（上传 chunks/complete）、:136（§3.3 Daemon 读附件）、:138（§3.1 DEK 上行）、:140（§3.1b owner-key）。
- Daemon DEK 编排在位：`internal/daemon/sessiondek.go`（首启生成 DEK 落 `local_state` 键 `session-dek:<sessionID>`，:44-52；临时 X25519 wrap 上行，:68-96）+ 接线（`relay.go:760` `SetDEKPublisher` → :768-774）。
- Daemon refs 发送路径在位：`internal/daemon/runner.go:549-602`（refs 与 inline images 互斥、sha256/尺寸复算、`SendContent` 同批、失败收口）；`SendContent` 通道（`extension_handle.go:309`）与桥 admission（v0.8.3 P3）已通。V085-04/05 已 passed。

**缺口（本轮全部收口）**：

1. **生产连接层从未注册附件拉取出口**：`SetAttachmentFetchSink`（`runner.go:207-213`）全仓库只有测试调用（`runner_test.go:1204/:1301`）。真实链路 send 携带 refs 时报「附件拉取出口未配置（attachments unsupported）」（`runner.go:558`）——这是 attachments 从「测试可通」到「产品可通」的唯一断点。
2. **矩阵钉死 unsupported**：`adapter.go:463-468`（reason「Relay opaque attachment ref 接入后按 deployment 条件升格」即预留的升格条件）+ 守护测试 :139-144。
3. **部署前置未盘点**：本机 DEK 生成依赖 owner 设备 `encryption_public_key`（§3.1b owner-key 端点）；localdev 环境有无 owner 设备、无 owner-key 时 404 fail-closed 形态、DEK 上行失败重试语义，P0 实测盘点。
4. **解密组合契约需冻结**：`FetchAttachment` 返回最小密文投影（`relay.go:370-380`，metadata_ciphertext + chunks + chunk_sha256），注释口径「按会话 DEK 解密」；mobile 侧实际是「DEK 派生附件密钥 + 逐块 envelope Seal」（`attachment_picker.dart:94-163`，`crypto.DeriveContentKey`）。daemon Open 的精确组合（metadata envelope + 逐块 envelope + 拼接 + sha256）以 P0 盘点冻结为准，杜绝两侧算法漂移。

### 1.3 file_read / git_read：daemon 执行器已在，缺「声明 + 真实消费者」

- **执行器完整**：`internal/daemon/readonly_dispatcher.go` 实现 `file.tree/file.read/code.read/git.status/git.changes/git.diff` 六个只读 kind（:63-89），沙箱边界严格（workspace 根只来自本机确认映射 :128、terminal 归属校验 :124-127、错误码脱敏 :34-49）；git 走 `internal/gitread`。
- **命令路由双通道**（`relay.go:1275-1292`）：web 密封请求走 `ExecuteWeb`（生产可用，`web_read_transport` 能力）；fixture_payload 命令走 `Execute`（移动端现状命令 envelope 即 fixture_payload 形状，遗留 2026-08-23 #1 统一后的事实）。
- **声明面缺口**：`apps/daemon/main.go:269-271` 仅 `useFixtureAdapter` 时向 hello 声明 `file_read`/`git_read`——真实 dsh 适配器（含 localdev 真实桥）不下发，客户端按 capability gate 隐藏入口。
- **消费面缺口**：
  - `git_read`：移动端 UI 已存在（`git_diff_screens.dart` + `git_diff_controller.dart` + 路由 `router.dart:80`），但只有 `FixtureGitDiffRepository`（`git_diff_repository.dart:13` 注释「不能复用 RelayRepository，以免 Git 明文进入会话传输契约」——该边界指**会话传输契约**，只读命令是独立 kind，不进会话时间线正文）——**无真实传输实现**。
  - `file_read`：**无任何移动端消费者**（仅 fixture repo 与 daemon 执行器存在），需要新建工作区文件树/文件查看入口（范围 P0 裁决，推荐做——见 §2 G3）。
- **矩阵 reason 语义拆正**：`adapter.go:469-474` 现行 reason「桥 fs/* 请求按 -32601 拒绝 / 桥未实现 git 读取能力」混淆了两件事——ADR-014 §9 排除的是**桥侧 fs 工具方向**（ACP `fs/*` Agent→Client，两套授权真相，维持不做）；而应用层只读命令通道（本轮升格路径）与桥无关。P0 冻结新 reason 措辞，区分「桥 ACP fs/*（不做）」与「应用层只读命令（已接通）」。

### 1.4 边界事实（如实，不纳入本轮）

- **真实 E2EE 口径**：移动端命令 envelope 现状为 `ciphertext.fixture_payload` 形状（遗留 2026-08-23 #1）；事件侧生产 E2EE 下移动端为密文占位（v0.8.7 §1.4 口径）。本轮三项能力的验收口径 = fixture + localdev 明文/fixture_payload 投影；只读命令结果经 `EventToolResult` 进 canonical 事件流，真实 E2EE 部署下移动端仍读不到正文——与现状一致，如实留档不阻塞。真实 E2EE 移动端解密与 Android Keystore unwrap 实机 gate 维持 V085 承接项（实施记录 24 §5）。
- **delegate_session / delegate_cross_provider 本轮不做**：桥侧仅 B-12 观察投影（`dsh/delegation/changed`，ADR-014 §8），未实现 child session 编排；ADR-014 §9 明确「观察类投影不得提升 delegation 能力」。升格需桥侧真实实现，另立专项。
- **effort_select 无需动作**：动态升格已内建——DSH ACP 模型目录公布 efforts 即自动 native（`adapter.go:453-462`），无桥侧改动不参与本轮。
- **桥 ACP `fs/*` 维持 -32601 fail-closed**：`handle.go:1039-1050` 的 `handleBridgeRequest` 本轮不新增 case（ADR-014 §9 理由不变）。

## 9. P0 裁决补记（2026-09-05，实施时冻结）

### 9.1 附件解密契约冻结（daemon Open 唯一契约，双侧实现只依赖此伪代码）

Seal 侧事实（mobile `attachment_picker.dart` + 双侧 `crypto` 包同构）：

- 载荷分块：明文按 `floor(512KiB × 0.68)` 字节切片；每块独立 envelope。
- envelope：`{alg:"v1-aes256gcm-hkdfsha256", key_id, nonce(b64 RawStd), ciphertext(b64 RawStd), aad_hash, payload_version:1}`，序列化为 UTF-8 JSON 字节后作为上传块。
- 密钥：`DeriveContentKey(dek, "content")`（HKDF-SHA256，salt="agent-sessions-v1"，32 字节）。
- AAD（逐字段 JSON 序列化后 sha256，字段顺序固定）：`{entity_id: sessionId, event_type: "attachment:chunk", protocol_version: 1, event_seq: 块序号(0 起), key_id: dekId}`；metadata 块 event_type=`attachment:metadata`、event_seq=0、明文仅 `{\"name_length\":N}`。
- nonce：由时间种子小端 12 字节（Open 侧从 envelope 读取，不依赖种子）。

daemon Open 伪代码（P1 实现，明文只经内存）：

```text
openAttachment(sessionID, proj AttachmentFetchProjection) ([]byte, error):
  dek = base64.RawStdEncoding.Decode(local_state["session-dek:"+sessionID])   # 32 字节；缺失 → fail-closed
  parts = []
  for i, chunkBytes := range proj.Chunks:
    env = json.Unmarshal(chunkBytes) → crypto.Envelope                        # 形状不符 → fail-closed
    aad = {EntityID: sessionID, EventType: "attachment:chunk", ProtocolVersion: 1, EventSeq: i, KeyID: env.KeyID}
    plain = crypto.Open(dek, env, aad)                                        # aad_hash/GCM 校验失败 → fail-closed
    sha256(plain) hex 与 proj.ChunkSHA256[i] 恒等比对（大小写不敏感）          # 不符 → fail-closed
    parts = append(parts, plain)
  plaintext = concat(parts)                                                   # 按存储顺序，无重叠无空隙
  # 总长度由 runner 侧 ref.SizeBytes/ref.SHA256 既有复算兜底（runner.go:572-580）
  return plaintext
```

metadata envelope daemon 不消费（仅含 name_length，daemon 不需要文件名；文件名不出 Relay 边界）。

### 9.2 localdev 部署前置盘点结论与修复决策（V088-09 的前置事实）

- **断点链（实测代码路径）**：restart.sh `ensure_local_owner_bootstrap` 以占位公钥 bootstrap owner（`"encryption_public_key":"local-dev-owner-encryption-public-key"`，restart.sh:924/935）→ daemon `publishWrappedDEK` 取 owner-key 后 `crypto.DecodePublic` 报「owner encryption public key 无效」（sessiondek.go:74-77），失败仅记日志（不阻断 start，本机 DEK 已落 `local_state`）→ Relay 无 wrap → 移动端 `sessionContentKeyAvailable=false`（http_relay_repository.dart:636-652）→ 附件入口恒禁用「等待会话附件密钥」。同时 App 侧 localdev 身份库为 `InMemoryDeviceIdentityStore`：`createOrRead()` 返回 fixture 占位公钥、`readEncryptionPrivateKeyB64()` 恒 null（secure_token_store.dart:333-341/:386）——即便有 wrap 也无法 unwrap。
- **修复决策（P1 实施，允许局部重构）**：localdev owner bootstrap 改用**真实 X25519 密钥对**——
  1. `apps/daemon` 新增 `encryption-keygen` 子命令（Go ecdh X25519，私钥为 32 字节种子，0600 落 state dir，幂等回放公钥；RFC 7748 clamp 与 Dart `newKeyPairFromSeed` 同构，双侧公钥可互推一致）；
  2. restart.sh：bootstrap 载荷换真实公钥；私钥经新 dart-define `LOCAL_DEV_ENCRYPTION_PRIVATE_KEY_B64` 注入 App（localdev 调试壳，生产 Android Keystore 路径零改动）；
  3. App：`InMemoryDeviceIdentityStore` 支持播种（createOrRead 从种子推导真实密钥对、readEncryptionPrivateKeyB64 返回种子），main.dart localdev 装配处接线。
  - 依据：staged-bootstrap 架构（curl bootstrap + dart-define 注入）是 localdev 既定形态；本修复只替换「占位 → 真实」，不引入第二套配对协议。私钥仅存在于本机 state dir（0600）与 localdev 调试进程内存，不进 Relay/日志/报告。
