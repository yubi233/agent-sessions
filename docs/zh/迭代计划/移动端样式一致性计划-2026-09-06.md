## 1. 目标与非目标

### 目标

1. 规范落为机器执法：Wave 1 守卫（色彩/圆角/字号，规范 §8）上线并全绿；Wave 2 在间距和图标迁移完成后同时强制两类 token。
2. P0 存量清零：圆角字面量约 79 处（含 62 处 `circular(8)`）、`fontSize:` 5 处、业务代码裸 `Colors.*` 2 处。
3. P1 存量分批收敛：间距半档 6/10/14 约 87 处、图标尺寸散布、组件级约定，以及已经存在但画法不一致的空状态。透明度按语义分类，不按相近数值机械归并。
4. 完成强制 headed Flutter 可见验收：亮/暗主题、三个代表性视口和 200% 文本；报告与截图必需，MP4 可选。

### 非目标

- 不改交互/Key/Semantics/用户可见文案（硬约束）。
- 不改色盘设计本身：暗色盘 VS Code 对齐已是独立改动（工作区 `app_theme.dart` 未提交部分），本计划只消费该基线。
- 不补建旧版 VISUAL-MOBILE-30/31/32 专属 fixture；v0.9.0 可见门禁若缺少代表状态，只增加满足本期验收的最小 fixture，不借机重构整个 harness。

## 3. 实施批次（每批一个 commit，可独立 revert）

### B1 Token 扩充（纯新增，零行为变化）

按规范 §7 清单扩充 `app_theme.dart`：`AppSpacing.micro=2`、`AppRadius.micro=4`/`large=12`、`AppTypography.mono`（13/monospace）、`AppSizes.iconSm/Md/Lg/Xl`（16/18/20/24）、`AppOpacity.scrim=0.24`；`app_theme_test.dart` 补档位及亮暗 `colorScheme.scrim` 断言。不得覆盖工作区中已有的深色盘改动。

门禁：`flutter analyze` 零告警 + 全量 `flutter test --machine --concurrency=1` 零 diff。

### B2 P0 存量清理

- 圆角全量归档：`circular(8)` → `AppRadius.card`（62 处机械替换）；4/6/2/10/12 按 §3.2 映射逐个走查归档；`999` → `StadiumBorder`/`CircleBorder` 全圆形状。
- `fontSize:` 5 处归阶：12 → `labelSmall`/`bodySmall`（session_info 1 处、git_diff 2 处，git_diff 两处同时核对其继承颜色是否达标——旧计划 H1 残余）；13 → `AppTypography.mono`（session_markdown_text、session_question_panel 各 1 处）。
- 裸色 2 处按不同语义处理：`pairing_scanner.dart:114` 是相机未出帧的黑场，直接用 `colorScheme.scrim`；`session_chat_view.dart:406` 是模态压暗，用 `colorScheme.scrim.withValues(alpha: AppOpacity.scrim)`。不得把不透明黑场错误归入带透明度的自定义 scrim 色。
- 其余 `withValues(alpha:)` 先登记“文件/组件/语义/现值”。只有语义相同且亮暗走查确认后才新增命名 opacity token；本批禁止“顺手按数值归并”。

门禁：B1 门禁 + 改动屏亮暗双主题走查截图留档。

### B3 Wave 1 守卫落地

在 `pubspec.yaml` 显式登记并锁定兼容版本的 `analyzer` dev dependency，新增 `apps/mobile/test/style_guard_test.dart`，基于 Dart analyzer AST 实现规范 §8 Wave 1：禁 `Color(0x`、裸 `Colors.*`（`Colors.transparent` 除外）、`fontSize:`、带数字参数的 `BorderRadius.circular(`/`Radius.circular(`；豁免仅 `app_theme.dart`（token 定义点），如有残余豁免必须附理由注释。禁止用正则或手写字符串清洗模拟语法解析。

门禁：守卫全绿；全量 flutter test 不回归。

### B4 间距分批迁移（P1，T1 已裁决）

批次顺序：session chat/composer（`SizedBox` gap 最高频区）→ 首页/工作区/设置 → 其余屏。按规范 §2.3 映射表执行（6→4 或 8、10→8 或 12、14→16、3/5/7/9 就近、标准 gap 28→24）；零间距改用 `EdgeInsets.zero`/省略参数/`SizedBox.shrink()`。现有 56px 空态 inset、120px 键盘 `scrollPadding` 以及固定宽高必须先分类，分别进入具名布局常量、`AppSizes` 或逐行理由豁免，不得冒充通用间距或机械压缩。屏幕左右安全边距统一 `AppSpacing.lg`，每批亮暗走查。

完成标准：`lib/ui` 内 §2.1 档位外间距数值清零。

### B5 图标收敛 + Wave 2 守卫

`Icon(size:)` 与 `IconButton(iconSize:)` 按 `AppSizes` 归档（14→16、17/19/15 按用途就近）；32/36 等空态大图标先核实是否需要新语义档。随后在同一 AST 守卫启用规范 §8 Wave 2：业务间距必须引用 `AppSpacing.*`，图标必须引用 `AppSizes.*`，固定控件尺寸或特殊 inset 必须引用对应具名常量；只有无法常量化的框架约束才能进入逐条理由 allowlist。守卫补正负 fixture，不能只做“允许若干数字”的弱检查。

门禁：同 B3。

### B6 组件约定与空状态

先完成 T3 核实，再按旧计划 B1 未竟项（H2-H6）、B2（错误横幅视觉归一、页面标题归一、capability chip 第三态补色、语义色映射、tab 文本角色）、B3（已有用户可见空状态的视觉归一）排期执行。必须保留原文案、Key、Semantics、回调和重试控件类型；不合并职责不同的同形组件。

`SizedBox.shrink` 必须先分为“条件隐藏/可选控件”“解析器忽略节点”“真实页面空状态”三类。前两类保持原行为，不纳入清零指标；第三类只有在原本已经存在可见空状态时才迁移画法。若需要新增文案、Semantics 或交互，移出 B 线单独立项。

### B7 headed 可见终验（必选；MP4 可选）

复用现有 macOS Flutter harness，覆盖亮/暗主题、360x800、430x932、1280x800，以及至少一个 200% 文本场景。结构化报告和代表帧截图必须留档；允许且仅允许计划内视觉差异，溢出、遮挡、不可达控件、Key/Semantics/交互变化均失败。若现有 fixture 不足，在本期补最小 v090 场景。MP4 before/after 可在全部 gate 通过后生成，但不是交付前提，也不能替代断言。

## 4. 门禁与回归口径

1. 每批：`flutter analyze` 零告警；`flutter test --machine --concurrency=1` 全绿且不改断言；`git diff --check` 干净。
2. 涉及 UI 的批次：改动屏亮暗双主题人工走查，截图按规范 §9 留档；紧凑布局同时跑 200% 文本 widget 回归。
3. 守卫测试（B3 起常驻 test 目录）纳入日常回归；版本收口执行全量 `flutter test`，不能只跑 mobile 相关子集。
4. B7 执行 `task test:v090:flutter` 的 headed 可见门禁；报告与截图是必需证据，MP4 仅为可选演示。
