# Agent Sessions 迭代计划 v0.8.3：DSH ACP 能力收口与交互扩展

> 状态：`planned`（2026-09-03 修订）
>
> 前序：[迭代计划 v0.8.2](迭代计划v0.8.2.md)。v0.8.2 已完成 Agent Sessions 仓库范围内的契约、工具事件、权限回流和 fixture gate，但依赖外部 DSH bridge 的 `permission_mode`、图像、生命周期和多根目录能力尚未闭环。本计划接管这些未完成的 B 类项，并与本次从 C 类提升的能力一起完成 DSH bridge、Go adapter、Daemon/Relay 和客户端的真实接入；不能再仅以条件式 `unsupported` 作为迭代完成结果。
>
> 本计划承接对 `/Users/yubi/code/deepseek-harness` ACP bridge、ACP SDK 0.25.1 以及 DSH `permissionPresets`、`userQuestions`、`planMode`、`goals`、`skills`、session persistence、attachments、workspace 和 subagent 服务的核对。目标是把 C 类中确实可以通过本地 DSH ACP bridge 较小范围改动接入的能力转为 B 类，并一次收口 v0.8.2 遗留的可接入 B 类；没有安全语义归属、需要改变执行域或缺少 DSH 等价语义的能力继续保持 C 类，不通过文本伪造成功。

## 1. 背景与问题

v0.8.2 的 C 类清单把几种不同情况混在了一起：有些能力已经存在于 DSH 核心，只是 bridge 没有投影；有些能力可以用 ACP 的 unstable elicitation 或 extension 通道承载；另一些能力则要求把本地文件、PTY、MCP 或跨 provider 运行时交给客户端，不能靠增加一个 ACP handler 安全完成。同时，v0.8.2 已判定可支持但尚未改完 DSH bridge 的 mode、session lifecycle 和多根目录不能继续作为外部前置悬置，必须纳入本期实施。

当前 DSH ACP bridge（`packages/acp/acp/src/index.ts`）已经具备：

- `initialize`、`session/new`、`session/load`、`session/resume`、`session/prompt`、`session/cancel` 和 `session/set_config_option`；
- `session/update` 的 assistant、usage、tool-call 投影，以及 approval → `session/request_permission` 的单次决策通道；
- DSH agent 上下文中的 `ctx.userQuestions`、`ctx.planMode`、`ctx.goals`、`ctx.skills` 和 subagent drain 生命周期。

DSH 核心还具备可复用的 `permissionPresets`、`sandbox/mode`、`approval/policy`、session persistence、attachment store 和 workspace/sandbox 服务；ACP SDK 已定义 `session/set_mode`、session lifecycle capability、image block 与 `additionalDirectories`。因此 `permission_mode` 等项的准确结论是“当前 bridge 不支持，但可以通过本地 DSH ACP 改造支持”，本期必须实现后再按证据升格。

但 bridge 当前没有将这些 DSH service 转为 ACP client 可消费的结构化能力。若直接把它们写入普通 assistant 文本，客户端无法区分状态、无法安全回写操作，也会丢失取消、版本、权限和重放语义。

本期采用两层协议：

1. 有 ACP 对应语义的能力优先使用 ACP 标准或 SDK 的可选/unstable 方法，例如 `plan_update`、`available_commands_update` 和 elicitation。
2. ACP 没有标准方法的能力使用版本化 `dsh/*` extension，并通过 `initialize` 的 namespaced `_meta` 协商；未协商、版本不兼容或客户端断线时保持 `unsupported`/`cancelled`，不降级为无结构文本。

## 2. 目标与成功标准

### 2.1 目标

- G1：收口 v0.8.2 尚未完成的 DSH bridge B 类：`permission_mode`、条件式图像、`session/close/list/delete/fork` 和 `additionalDirectories`，实现后按真实 gate 升格。
- G2：为 DSH ACP bridge 建立版本化、可发现、按 session 隔离的 `dsh/*` extension 契约。
- G3：接通 `question` 与 ACP elicitation，保留 DSH question 的多问题、多选、自由输入、intent/detail 和取消语义。
- G4：把 DSH plan mode projection 映射为状态扩展；在 `exit_plan_mode` 提供完整 markdown 时发送 ACP `plan_update`，补齐计划审核闭环。
- G5：把 DSH goal projection、CAS 变更和 round 状态投影为结构化 goal 事件，并提供受控的 goal 操作回流。
- G6：使用 ACP `available_commands_update` 发布 DSH command/skill 安全目录，并提供可校验的显式 skill invocation；不暴露本地路径、skill body 或任意代码执行入口。
- G7：将 DSH 本地 subagent 的 start/end 生命周期作为 tool/extension 状态投影接入；不把可观测性冒充为 `delegate_session`、ACP child session 或跨 provider session API。
- G8：Go adapter、Daemon、Relay、Flutter/Web 与 DSH bridge 使用同一 capability gate、request id、revision、lease 和取消终态。
- G9：所有 B 类能力均有 fixture、假桥、可见 UI 和真实 DSH bridge 的独立证据；修复 V08-12 暴露的真实 `resume → send` bridge 契约问题，保留历史失败记录并新增通过证据。

### 2.2 成功标准

1. `session/new/load/resume` 返回真实 `modes/currentMode`，`session/set_mode` 通过 DSH permission preset 服务原子切换并在恢复后重建；`permission_mode` 全链路验收通过后由 `unsupported` 升为 `native`。
2. `session/close/list/delete/fork` 与 `additionalDirectories` 在 bridge、持久化、workspace/sandbox、Go adapter、Relay/mobile 之间使用同一 session 与授权边界；图像在 attachment service 和模型同时支持时端到端可用，否则准确拒绝。
3. bridge 从 `InitializeRequest.clientCapabilities` 读取客户端的 elicitation、plan 与 namespaced extension 声明，并在 `InitializeResponse.agentCapabilities._meta` 准确报告自身 DSH extension 版本；不支持扩展的客户端不会看到可点击但必失败的入口。
4. DSH `ctx.userQuestions.ask()` 发起的请求能够到达 ACP client，回答按原 request/session/agent 归属回到 DSH；取消、超时、断线、重复回答和 delegated child 均 fail-closed。
5. 已提交的 DSH plan projection `{active,pending}` 能按序转成 `dsh/plan/changed`；`exit_plan_mode` 携带的完整 markdown 在提问前转成 ACP `plan_update(type=markdown)`，审核结束后发送 `plan_removed`。不从 markdown 猜造 plan entries。
6. goal 的创建、编辑、暂停、恢复、完成、清除和 stale revision 拒绝均能形成结构化事件；Relay 不看到 goal 正文以外的 DSH 私有 payload、凭据或路径。
7. `ctx.skills.snapshot()` 仅在 `complete=true` 时转成安全 skill 目录和内容摘要 revision；user-invocable skill 同 DSH commands 一并通过 `available_commands_update` 发布。调用只能使用已广播的 skill name，调用结果、失败和取消可关联到原始请求。
8. 本地 subagent 的 `subagent/start` 和配对 `subagent/end` 能映射为 running/completed/failed/cancelled 工具活动或 `dsh/delegation/changed`；不创建伪 ACP session，不开放 child 写控制，不将 SPI `delegate_session` 误报为已支持。
9. Agent Sessions 能力矩阵只在 bridge 标准能力/extension 和对应 handler、adapter、Relay/mobile gate 全部存在时升为 `emulated` 或 `native`；任何一层缺失都返回准确的 `unsupported` reason。
10. V083 fixture、headed Chrome、可见 Flutter gate、真实 DSH overlay 和 V081/V082 回归通过；v0.8.2 遗留 B 类不再以“后续 bridge 条件”留空，V08-12 的历史失败不改写但必须由新的 resume/send 修复用例给出通过证据。

## 3. 能力分类与范围冻结

### 3.1 本期 B 类：可通过 DSH ACP bridge 接入，全部实现

| # | 能力 | DSH 可复用基础 | ACP 承载方式 | 本期交付口径 |
| --- | --- | --- | --- | --- |
| B-1 | `permission_mode` | `permissionPresets`、`sandbox/mode`、`approval/policy`、session event 持久化 | ACP `session/set_mode`、`SessionModeState`、`current_mode_update` | bridge 广告真实 mode 目录；原子切换 sandbox/approval bundle，恢复重建并遵守 in-flight/Terminal fence；验收后升 `native` |
| B-2 | `attachments`（图像） | attachment store、ACP content admission、模型 `inputModalities` | ACP image content block + 动态 capability | 补可用 DSH overlay 与全链路验证；仅服务和模型都支持时开启，引用授权、MIME/大小/哈希和失败回滚完整 |
| B-3 | `session/close/list/delete/fork` | session persistence 的 list/snapshot/inspect、已提交事件前缀与 agent dispose | ACP session lifecycle 标准方法/能力位 | close 可恢复、list 脱敏分页、delete 冷状态且有墓碑/审计、fork 只复制已提交前缀；全链路幂等 |
| B-4 | `additionalDirectories` | workspace registry、sandbox/readonly allowlist、session meta | ACP `session/new`/恢复/fork 的 `additionalDirectories` | 规范化、授权、symlink/重叠校验并持久化；恢复时复验，不直接信任客户端路径 |
| B-5 | `question` | `ctx.userQuestions`、结构化 question/answer、intent/detail 校验、agent ownership | 优先 `unstable_createElicitation`；自有客户端使用 `dsh/question/*` fallback | 完整请求/回答/取消/超时/断线/child ownership；不支持的客户端保持 unsupported |
| B-6 | `elicitation` | DSH user-question provider 可作为表单后端 | ACP unstable elicitation capability gate | 只支持声明的 form schema 与有限字段类型；不把开放式工具授权混入 elicitation |
| B-7 | `plan` | `ctx.planMode`、`plan/mode` 事件、`{active,pending}` projection、`exit_plan_mode` 的 markdown detail | 状态使用 `dsh/plan/changed`；审核内容使用 ACP `plan_update(type=markdown)`/`plan_removed` | 不生成虚假 entries；plan mode 切换回写 DSH，审核必须经过 question/elicitation |
| B-8 | `goal` | `ctx.goals`、goal projection、change revision、round driver | `dsh/goal/*` extension 与 canonical `goal.changed` | 支持读取和显式 mutate；CAS、owner、取消、重放和脱敏完整可验证 |
| B-9 | `skill_catalog` | `ctx.skills.snapshot()`、durable skill-catalog source、`userInvocable` | ACP `available_commands_update`，必要时以 `dsh/skill/catalog` 补充内容摘要 revision | 只发布 name/description/whenToUse/invocation 等安全字段；不广播 path、resourceBase、locator、metadata 或 skill body |
| B-10 | `invoke_skill` | tool-skill 的 user-explicit invocation 与 session prompt slot | `dsh/skill/invoke` 严格入口；通用 ACP client 仍可发送已广告的 slash command | 只接受当前目录中 `userInvocable` 的 skill name；复用同一 prompt/cancel 生命周期，不把未知 skill 降级为普通文本 |
| B-11 | ACP `available_commands_update` | DSH commands registry、user-invocable skill catalog | ACP 标准 session update | 合并目录并定义重名规则；目录变化全量替换，不能把只读/禁用 skill 广告为可执行 |
| B-12 | subagent lifecycle 投影（事件能力） | `subagent/start`、`subagent/end`、runId、provider、local、stopReason、continuable drain | 普通 `tool_call`/`tool_call_update` + `dsh/delegation/changed` | 只投影 running 与终态；不是 SPI `delegate_session`，不开放外部 child session 控制 |

这些能力在 Agent Sessions 的 20 项能力清单中仍使用三态：`permission_mode` 与完整 ACP elicitation 在标准语义和全链路 gate 成立时可为 `native`；`question` 使用 `dsh/question` fallback，以及 `plan`、`goal`、`skill_catalog`、`invoke_skill` 依赖 DSH extension 时最多为 `emulated`。图像按 deployment/model 条件动态判定，生命周期与多根目录使用各自 ACP capability gate。B-11/B-12 是 ACP/事件层能力，不新增 SPI 能力名，其中 B-12 不改变 `delegate_session=unsupported`。`dsh/*` extension 不得对其他 ACP agent 宣称通用互操作。

### 3.2 本期继续 C 类：不以简单 bridge 修改接入

| 能力 | 保持 C 类的原因 |
| --- | --- |
| `file_read` / `git_read` | Agent Sessions 已有独立 readonly transport；DSH ACP bridge 的本地 `ctx.fs`/git 工具不是 agent-side ACP 方法，重复接入会产生两套路径授权真相 |
| ACP `fs/read_text_file`、`fs/write_text_file` | ACP 方向是 Agent 调 Client，需改变 DSH 本地 fs 执行域并重新处理 cwd、symlink、sandbox、版本和写审批，不是薄适配 |
| terminal | DSH PTY registry 与 ACP client terminal 是不同 owner/生命周期；委托会引入 cwd、kill/release、断线清理和 sandbox 跨域问题 |
| editor/NES | DSH edit/write 工具没有 ACP NES suggestion session 的位置、编辑历史和接受/拒绝语义 |
| MCP 管理 | 当前 bridge 只有拒绝或忽略 `mcpServers`，没有 session-scoped MCP client、工具注册和权限生命周期 |
| `delegate_session` / `delegate_cross_provider` | DSH lifecycle 投影只有观察语义，没有 Agent Sessions 的外部 create/resolve、独立 child lease、跨 provider routing 和权限契约；不能由 subagent tool update 冒充 |
| ACP-controlled child session delegation | DSH subagent fork 与外部可控 child session 的身份、持久化前缀、取消和恢复语义不同；本期只实现普通 session fork 与 subagent 观察投影，不开放 child 控制 |

### 3.3 v0.8.2 遗留 B 类收口原则

`permission_mode` 特别确认可支持：当前 bridge 尚未广告 `modes` 或实现 `session/set_mode`，所以基线仍是 `unsupported`；但 ACP SDK 与 DSH permission preset 服务已经提供足够语义，本期必须补齐 mode 目录、原子 preset 切换、session 持久化/恢复、`current_mode_update` 和 in-flight/Terminal fence，不使用 `dsh/*` 扩展绕过 ACP 标准 mode。图像、`session/close/list/delete/fork`、`additionalDirectories` 同样纳入 P0-P5 实施和验收；只有具体部署前置确实缺失时才在运行时保持带 reason 的条件式 `unsupported`，不能把代码链路未实现当作可接受的完成状态。

## 4. 协议与安全契约

### 4.1 命名、协商与版本

- 扩展命名空间固定为 `dsh/`，方法名使用 `dsh/<domain>/<verb>`，通知名使用 `dsh/<domain>/changed`；禁止复用未获 ACP 注册的标准方法名。
- 客户端在 `InitializeRequest.clientCapabilities._meta["com.deepseek.dsh/extensions"]` 声明可处理的扩展及版本，bridge 在 `InitializeResponse.agentCapabilities._meta` 的同名键报告自己的目录；elicitation 和 plan 分别以 ACP 的 `clientCapabilities.elicitation.form`、`clientCapabilities.plan` 为准。未声明的能力不得主动发送请求或通知。
- ACP 扩展参数使用 camelCase。每个 session 扩展至少带 `protocolVersion` 与 `sessionId`；长生命周期交互另带业务 `requestId`，状态修改另带 `expectedRevision`。JSON-RPC id 继续用于单次 method response，不被业务 id 替代。
- 版本只允许向后兼容的 minor 升级；未知字段由严格 schema 拒绝。major 不匹配、重复 request id、revision 倒退和跨 session 请求均 fail-closed。
- extension method 的 transport failure、client error、EOF 和 dispose 必须收敛为明确错误或 `cancelled`；不能把通知发出视为业务成功。

### 4.2 permission mode

- mode 目录来自 DSH `permissionPresets` 的可用且可校验 preset；至少明确 `workspace-write`、`danger-full-access`，若提供 `read-only` 必须先在核心注册显式 preset，不能由 bridge 临时拼出未命名组合。
- `session/new/load/resume` 返回 `modes.currentModeId` 和稳定的 id/name/description；`session/set_mode` 只接受当前会话已广告的 modeId，成功后发送 `current_mode_update`，未知、custom 或已失效 mode 一律拒绝。
- 切换必须通过 DSH 公开 preset setter；若现有 setter 不能原子持久化 `permission/preset`、`sandbox/mode`、`approval/policy`，先在 DSH 核心补原子 bundle API。任何失败不得留下半套事件。
- mode 修改绑定 session、live agent、lease 和 expected revision；生成中请求在 step 边界排队或明确拒绝，不得让当前工具获得意外升权。持久 Terminal 存在时必须通过其 mode fence。
- `DSH_PERMISSION_MODE` 只决定进程启动默认值，不作为运行期切换通道，也不构成 capability 证据。恢复后的当前 mode 必须从持久 session projection 重建。

### 4.3 图像、生命周期、多根目录与 resume

- 图像发送沿用 opaque attachment reference：Relay 只传 id、MIME、尺寸和哈希元数据，Daemon 授权读取/解密后转为 ACP image block；DSH attachment service 与模型 `inputModalities` 缺一即拒绝，不在普通日志、事件或 fixture 公共 payload 写明文。
- `session/close` 是可恢复的 graceful close，与 `session/cancel`、`session/delete` 分离；重复 close 幂等，关闭期间停止新 prompt 并使 in-flight turn、pending question/permission 和 subagent drain 收敛。
- `session/list` 只从 DSH persistence 返回授权范围内的脱敏元数据、状态、revision 和分页游标；`session/delete` 只接受冷/已关闭会话，先写墓碑/审计并确认持久化，再回收物理数据。
- `session/fork` 只复制指定 revision 前的已提交事件前缀，生成新的 session identity 和父子元数据；不复制凭据、未提交尾部、pending 交互或运行中升权状态。它是普通 session fork，不等于 DSH subagent delegation。
- `additionalDirectories` 在 new/fork/resume 时规范化并绑定 workspace/session allowlist；处理重复、重叠、symlink 和路径漂移，工具 sandbox 与 Agent Sessions readonly transport 使用同一授权真相，恢复时重新校验。
- 单列 V08-12 的真实 `load/resume → prompt` 修复：检查恢复后 agent/preset/model selection、event cursor、inbox/turn ownership 和 output settlement，不得用新建会话成功替代恢复会话验证。

### 4.4 question/elicitation

- DSH `AskUserQuestionItem` 转 ACP form 时使用 string、single-select 和 multi-select；带 Other 的问题用独立 custom string property 表达。无法表达的字段拒绝，不静默丢失 `intent` 或 `detail`。
- `plan-review` 必须同时传递被审核的 markdown detail 和 approve/keep-planning 自有选项；服务端再次验证 approve label 属于原问题选项。
- request 的 agent 必须是当前 Context 中的 live root；delegated child 触发 question 时按 DSH `DELEGATED_CALLER` 语义结束，不向客户端制造悬挂面板。
- 一个 request 只消费一次 answer；answer schema、选项 label、自由文本长度和多选数量由 Flutter/ACP client 预检，并由 Daemon/bridge 在解密或接收后重新校验。Relay 只校验密文 envelope、账号、session、lease 和幂等元数据，不能声称校验其看不到的 answer 正文。
- `unstable_createElicitation` 不可用时，只能在客户端明确声明 `dsh/question` 后使用私有扩展；没有 fallback 时返回 capability unsupported。

### 4.5 plan

- DSH committed plan projection 只有 `{active,pending}`，通过 `dsh/plan/changed` 发送；不得从这个 projection 或 assistant 文本合成 ACP entries。
- `exit_plan_mode` 调用 `ctx.userQuestions.ask()` 时，bridge 从 `intent=plan-review` 的 `detail` 取得已由 DSH 校验的完整 markdown：客户端声明 `clientCapabilities.plan` 时先发送 `plan_update(type=markdown)`，审核结束后发送同 id 的 `plan_removed`。plan update 与普通 assistant message 分开计数和渲染。
- 状态扩展和临时 markdown 均按 session event/request 顺序发送；回放、实时更新、重复 revision 和 out-of-order update 必须可去重。
- `dsh/plan/set_mode` 只能切换 session-scoped plan mode，不能修改 sandbox/approval；生效边界复用 DSH `agent/pre-step`，当前 turn 中的请求要么排队到边界，要么明确拒绝。
- `exit_plan_mode` 的审核结果必须通过 question/elicitation 回到 DSH tool result；客户端断线不代表批准，默认收敛为 cancelled。

### 4.6 goal

- `dsh/goal/get` 返回当前 projection、revision、phase、round counters 和安全时间字段；不返回 session event 原文、DSH 路径或内部 agent 对象。
- `dsh/goal/mutate` 只接受显式 operation（create/edit/pause/resume/complete/clear），携带 expected revision；冲突返回 stale revision，不覆盖他人变更。
- goal round driver 的自动状态变化只发送 changed notification，不把后台 continuation 当作客户端请求成功。
- 目标文本、blocked reason 和用户编辑长度受 schema/审计限制；失败、取消和重试必须保持事件幂等。

### 4.7 skill catalog/invoke

- `ctx.skills.snapshot()` 只公开 `skills` 与 `complete`，没有公共 revision 或参数 schema。bridge 仅在 `complete=true` 时，对排序后的安全 descriptor 计算内容摘要作为 `catalogRevision`；incomplete observation 保留 last-good 目录或保持 unavailable，不发布半套目录。
- descriptor 只包含 name、description、whenToUse 和 invocation policy；`path`、`resourceBase`、`locator`、provider metadata 与 skill body 不进目录。DSH 未提供 risk 元数据，因此移动端不得猜 normal/high，所有 DSH skill 显式调用统一经过确认。
- `available_commands_update` 合并 DSH command 与 `userInvocable` skill；同名冲突在 bridge 侧 fail-closed 或使用 P0 冻结的稳定命名规则，不能由客户端猜优先级。
- `dsh/skill/invoke` 必须引用当前 `catalogRevision` 和 skill name；bridge 复用或在 tool-skill 中提取公开的 user-invocation helper，进入既有 session prompt slot、pre-step injection 和 cancellation，不能靠拼接字符串绕过校验，也不能让未知 skill 回退成普通 prompt。
- skill 的加载和文件读取仍由 DSH SkillFileSystem/tool-skill 控制；客户端不提交参数、可执行脚本、任意路径、skill body 或 provider 凭据。调用状态映射到现有 turn/tool lifecycle。

### 4.8 delegation

- 仅允许把 DSH `subagent/start` 与配对的 `subagent/end` 投影为工具活动和 `dsh/delegation/changed`；start 只在 child 已发布后出现，不合成 proposed 状态，child 的创建仍由 DSH runtime 负责。
- 投影字段限于 runId、parent session、running/terminal 状态、provider、local、stopReason 和可选的受限结果摘要；不发送 task envelope、完整 child 正文、凭据或本地路径。
- parent dispose、permission mode 变化、workspace/Terminal fence 失效和 ACP 断线均触发 child-first drain；状态只能收敛为 completed/failed/cancelled。
- 禁止把该投影解释为 `delegate_session`、`session/fork`、`session/list` 或 `delegate_cross_provider`；客户端没有独立 child session 写入口，SPI 两项 delegation 能力继续 unsupported。

## 8. 验证与交付门

- 默认 fixture 不调用真实模型、真实上游或用户本机 DSH 根；所有扩展输入使用受控 schema 和隔离 session。
- 本地 deterministic 真实 DSH overlay 是必过门，必须显示 bridge commit/config、ACP SDK 版本、标准能力与 extension negotiation 结果和 capability gate；仅看到插件加载或 CLI 可用不能升格为 native。真实模型/上游冒烟另需用户显式授权。
- extension 事件必须经过 canonical mapper 和加密 Relay envelope；禁止在 `last_event`、日志、fixture 公共 payload 或移动端缓存写入 DSH session id、路径、凭据、task envelope 和 skill 私有文件。
- 每个交互请求必须有终态：`accepted/succeeded`、`rejected`、`cancelled` 或明确错误；断线和超时不能留下无限 pending。
- mode、session lifecycle、plan state、goal、skill catalog 和 subagent 终态尽量从 committed event 或稳定 snapshot 重建；plan-review markdown 仅在其 pending request 生命周期内存在，resolved 后必须移除，不伪造持久化 projection。
- Web 只读、非 owner/write 设备和未声明 extension 的 ACP client 不得产生 question、goal mutate、skill invoke 或 child control 命令。
- P1 bridge handler 与 P3 adapter/Relay 链路、P4 可见验收完成前，`permission_mode` 等能力仍按 V082 的 `unsupported` gate 处理；P5 收口时，deterministic overlay 中具备前置的能力必须达到计划状态。只有 attachment service、模型 modality 或受控部署配置确实缺失时，生产实例才允许条件式 `unsupported` 并返回具体 reason。

## 9. 风险、回滚与前置依赖

| 风险 | 处理 |
| --- | --- |
| mode 切换只写入部分 sandbox/approval 状态 | 使用 DSH 原子 permission bundle API；追加前校验 revision/in-flight/Terminal fence，失败不提交任何 knob event |
| close/delete/fork 混用导致数据丢失或孤儿会话 | 三套状态机和幂等键分离；delete 限冷状态且先墓碑，fork 仅 committed prefix，破坏性路径做故障注入 |
| additional directories 形成第二套授权真相 | workspace、sandbox、tool 与 readonly transport 共享规范化 allowlist；new/load/resume/fork 每次复验 symlink 与路径漂移 |
| 图像内容或本地路径泄露 | Relay 只持有 opaque ref/元数据，Daemon 授权解密；日志与 fixture 明文扫描，text-only 和缺服务默认拒绝 |
| ACP client 不支持 unstable elicitation 或 DSH extension | initialize 明确协商；缺失时保持 unsupported，不把问题转成普通文本或自动批准 |
| extension schema 与 DSH 插件类型漂移 | bridge 只依赖公开 service/type，版本化 schema、严格未知字段拒绝和 V083 contract test |
| question/plan-review 断线导致工具永久等待 | pending registry 绑定 session/agent/request，EOF、timeout、dispose、child ownership 统一收口 |
| plan 更新乱序或重复造成 UI 回退 | committed revision、session event 顺序、去重窗口和回放/实时同一 fold |
| goal 并发编辑覆盖他人状态 | expected revision/CAS；冲突只返回 stale，不写半套事件 |
| skill invoke 被用作任意代码/路径执行 | 只接受 complete catalog 中的 user-invocable skill name；SkillFileSystem、sandbox、approval 和现有工具权限继续是唯一执行边界，客户端不能提交脚本/path/body |
| subagent 投影被误认为 ACP child session | wire 文档与 UI 明确标注 observe-only；不提升 delegation capability，不开放 child session API、resume 或 cross-provider routing |
| 大型 skill/goal/question payload 泄露或拖垮 bridge | 字段白名单、大小上限、截断策略、背压和 cancellation；失败不落明文日志 |
| v0.8.2 bridge 改造再次只停留在条件 gate | 实施记录 20 遗留项逐项映射到 P0-P5 和 V083-01..08；代码或 deterministic gate 缺失时本迭代不得标 completed |
| 真实模型或恢复会话仍有契约失败 | 先用 deterministic bridge 修复 V083-07；经授权再跑 V083-26。旧 V08-12 报告不改写，新失败如实保留且迭代状态为 partial |

## 10. 完成定义

V083 的 B 类能力只有在标准 ACP/extension 协商、DSH bridge handler、Go adapter/runner、Relay schema、客户端 gate 和对应测试全部通过后才算接入：

- `permission_mode` 由 bridge 广告真实 mode 目录，`session/set_mode` 原子写入 preset/sandbox/approval，恢复和 current update 一致，并通过 in-flight/Terminal fence；满足全链路后升为 `native`；
- 图像在 attachment service 与 image-capable 模型条件满足时完成 opaque ref 到 ACP image block 的双向链路；text-only/缺服务准确拒绝且不泄露明文；
- `session/close/list/delete/fork` 分别满足 graceful/脱敏分页/墓碑审计/committed-prefix 契约，幂等、授权和恢复成立；
- `additionalDirectories` 在 new/load/resume/fork 全路径进入同一 workspace/sandbox/readonly allowlist，并通过 symlink、越权和路径漂移回归；
- V08-12 的 `resume → send` 根因在 bridge 修复，deterministic gate 必过；历史失败报告保留，真实模型复验另立证据；
- `question/elicitation` 能完成结构化请求、一次性回答、plan-review、取消和断线收口；
- `plan` 的 active/pending 能从 DSH projection 重建；plan-review markdown 只在审核期间通过 ACP update/remove 按序呈现，mode/审核不会伪装成普通消息；
- `goal` 的 projection、CAS 操作和 round 状态可回放；
- `skill_catalog/invoke_skill` 具备 complete snapshot、内容摘要 revision、scope、userInvocable 和确认校验，结果安全投影；
- subagent lifecycle 只作为 observe-only tool/extension 投影，start/end 配对、父子 drain 和脱敏成立，`delegate_session` 不因此升格；
- 能力矩阵使用既有 `native/emulated/unsupported` 三态并以 Reason 说明 extension/事件限制，客户端不根据 UI 或配置存在猜测能力；
- `file_read`/`git_read`、ACP `fs/*`、terminal、NES、MCP、`delegate_cross_provider` 和 ACP-controlled child delegation 仍准确保持 C 类；
- v0.8.2 已完成的工具事件、effort、permission one-shot 不回归，V081/V082 回归通过；V08-12 原有失败/blocked 证据保持不变但有 V083 新修复证据承接。
