>
> 需求（2026-09-05）：会话 LLM 回复实现**打字机式的流式传输**——回复文本随上游产出逐步到达、逐步渲染，用户能"看见"模型在写，而不是长时间"生成中..."后一次性出全文。
>
> 本计划两条硬门禁，未落地不得标记 `delivered`：
>
> 1. **截图门禁**：可见窗口连续帧证据中，同一 assistant 气泡的文本随时间逐步增长（打字机过程人眼可见），"整段一次性出现"不得通过（§6.1）；
> 2. **日志门禁（埋点先行）**：移动端先建流式埋点并独立交付（P1），再由埋点导出日志证明 delta 逐步到达（时间戳与累计长度单调、首字延迟与终态对账记录齐全）。**临时 print/脚本日志不作为证据**（§6.2）。

## 1. 诊断基线

### 1.1 wire 层 delta 链路已就绪（本轮不动的部分）

delta 事件的产生、上行、存储、拉取四段全部已通，本轮零协议改动：

- **产生**：dsh 桥 `agent_message_chunk`（`_meta kind=text-delta`）→ `EventMessageDelta`（`internal/adapter/dsh/mapper.go:143` 起 `mapSessionUpdate`，:191 一带；thought 增量 `mapThoughtChunk` 同文件）；codex（`internal/adapter/codex/mapper.go:168`）、opencode（`internal/adapter/opencode/events.go:108-133`）、mock（`internal/adapter/mock.go:82,115`）同产；claude/openclaw 无事件（fail-closed，`internal/adapter/claude/claude.go:77-80`）。
- **映射与白名单**：`internal/daemon/relay.go:1683-1726` wire 名映射（`message.delta`/`message.thought_delta`/`turn.phase`）；白名单 `internal/domain/daemon.go:1260-1277`（V085-25 已补齐，事故注释在档）；schema 单一真值 `packages/protocol/schema/events.json:16`。
- **上行**：outbox 逐条 POST（`internal/daemon/relay.go:1396-1463` 入队、:1472-1504 flush，毒丸/退避语义既有），**无任何节流/合并/批量**——delta 到达频率 = 桥产出频率。
- **存储与拉取**：Relay 双写 `session_events` + `account_event_log`（`internal/store/sqlite.go:753-771`）；移动端消费 `GET /v1/sessions/:id/snapshot?after_seq`（`internal/httpapi/handlers.go:776-813`，原样返回全部事件，含未完成回合的 delta/phase 中间态）。

### 1.2 移动端现状：有"生长节点"雏形，但粒度粗、覆盖窄、不可证明（v0.8.6 交付后复核）

- **打字机雏形**：`_coalesceStreaming`（`apps/mobile/lib/state/session_controller.dart:2440-2460`）把同类 streaming 帧坍缩为单一生长节点；气泡整段渲染 `node.text`（`apps/mobile/lib/ui/session/chat/session_chat_node_seat.dart:172`，经 `_DisplaySafeMarkdown` :247-255 薄包装转发 v0.8.6 D 组的 `SessionMarkdownText`——markdown ^7.2.2 GFM + display-safe，流式 partial 天然降级）；尾部"运行中"小标（`_AssistantTailStatus` :202-215）；状态行相位（`session_chat_view.dart:490-523`，v0.8.4 交付）与 v0.8.6 新增的超时横幅（`session-turn-timeout-row` :460）。
- **增量语义在服务端**：localdev 编码器把 `message_delta` 累积为"全量已收文本 + `streaming:true`"投影（`internal/daemon/localdev_encoder.go:80-98`；thought 同 :121-146），客户端按"每帧全量、整体替换"消费（`session_controller.dart:2444-2446` 注释即此契约）。
- **到达粒度 = 轮询粒度**：v0.8.6 已把轮询参数化——`foregroundPollAttempts=120` / `backgroundPollAttempts=120` / `pollInterval=500ms` 可注入（`session_controller.dart:92-96`）；发送后前台轮询（:2314-2344）耗尽**必转后台续轮**（:2344），后台耗尽显式超时收敛（:2375-2388：复位 `_turnInFlight`、清账乐观回显、`turnTimedOut` 标记驱动横幅，迟到事实按事件校正）。文本仍以 ~0.5s 步进跳变，无任何平滑。
- **覆盖面窄**：轮询仍只由本端 send 触发（v0.8.6 未加会话页常驻驱动）；回合由 dsh 终端等外部发起时，会话页没有持续轮询驱动流式渲染（是否补 watch 模式列 P0 裁决）。
- **fixture 一次性到达**：`apps/mobile/lib/relay/fixture_relay_repository.dart:1280-1348` 的 `'v084 stream'` 回合（:1284）在同一时刻 append 全部帧，下一次 `getSessionSnapshot`（:665-691）全量返回——**现有 fixture 演不出"逐步到达"**；跨轮询逐 delta 只有测试内 relay 子类模拟（`apps/mobile/test/session_controller_test.dart:1133` `_StreamingTurnRelay`）。
- **v0.8.6 交付的可复用面**：超时收敛/重发防抖/清账有回归锚点（`apps/mobile/test/v086_turn_convergence_test.dart`）；本计划不改终态判定与清账语义，只在其上叠频率、埋点与渲染。

### 1.3 证据面缺口：埋点不存在，截图校验不含内容增长

- **移动端无统一 logger**：lib 下无 debugPrint/Logger 封装（grep 零命中），设置页无调试日志/导出入口——门禁 2 无从谈起，埋点必须从零建且先行。
- **服务端只有失败与计数日志**：毒丸/恢复（`internal/daemon/relay.go:1484-1486`、:886）与 diagnostics 原子计数（`internal/httpapi/api.go:36-41`、owner-only `GET /v1/diagnostics` `handlers.go:471-489`）；**无 per-event-type 的 delta 产生量/间隔/延迟埋点**。
- **截图基建已有但缺流式断言**：macOS 可见窗口 100 帧证据 + 严格帧序列校验（`e2e-verify/mobile/macos-screenshot.mjs:18-23` 常量、:47 起 `validateStrictWindowFrameSeries` 强制 5fps、:170 起 `captureMacosWindowOrScreenFrameSeries` 主屏回退捕获）；场景注册表已用到 VISUAL-MOBILE-38（`run-macos.mjs:243-262`）；v0.8.6 新增 smoke 录屏链（`e2e-verify/mobile/record-smoke-v086.mjs`：预构建 macOS App + fixture 场景注入 + 逐帧捕获默认 10s/3fps + ffmpeg 合成）；Android 实机 gate（`run-android-device.mjs`，integration_test 无流式场景）。帧序列校验只验窗口/流程形状，**不含"文本增长"内容断言**——现有基建无法证明流式。V086-07 实机教训入档：TCC 屏幕录制授权、显示器休眠（`caffeinate -u` 唤醒 / `-dis` 防休眠）、宿主负载下严格 5fps 门序列受阻（smoke 口径留档）——门禁 1 的环境前提与缓解据此设计（§3.5/§6.1）。
- **参照物**：web 用账号级 SSE 做"失效唤醒 + snapshot 拉取"（`apps/web/src/session.ts:135-227`，只读 cursor 忽略 data、:166-169 触发重拉；`apps/web/src/chat.ts:160-169`），同样消费全量投影——两条客户端路线均以服务端累积投影为契约。

### 1.4 边界事实：真实 E2EE envelope 在移动端是占位

`SessionTimelineEvent.fromRelayEvent` 只消费 `fixture_payload` 明文（`apps/mobile/lib/domain/session_models.dart:864-873`），密文 envelope 落 `encryptedPlaceholder`。本轮验收口径为 localdev/fixture 明文投影（现有全部实机 visible gate 同口径）；真实 E2EE 移动端解密维持现状、不纳入本轮（§7 不做事项）。

## 2. 目标与完成标准

### 2.1 目标

- G1（打字机可见）：流式回合进行中，assistant（含 thought）气泡文本随上游产出逐步增长渲染，不再"长时间生成中...后一次性出全文"；数据层维持服务端全量投影契约，展示层在到达数据上做平滑释放。
- G2（埋点先行）：移动端建流式埋点与日志导出（结构化、只含元数据不含正文），独立阶段交付、先于一切门禁执行；门禁 2 证据必须出自该埋点。
- G3（截图门禁）：macOS 可见窗口新增流式场景，连续帧证据 + 帧级内容校验（气泡文本长度单调增长），帧 PNG 与机读序列双双入 evidence。
- G4（日志门禁）：同一回合导出的流式日志满足判定标准（§6.2）：≥N 条 delta 到达记录、时间戳严格递增、累计长度单调递增、首字延迟与终态对账字段齐全。
- G5（fixture 仿真）：fixture 支持逐 delta 按时间释放，供 widget 测试与可见 gate 复现"逐步到达"；与真实契约同 schema 门守护。
- G6（覆盖面，裁决项）：会话页打开且投影 `status==streaming` 时的驱动轮询（非本端发起回合也能看到流式），是否本轮实施由 P0 裁决。
- G7（不回归）：v081–v086 聚合回归、v0.8.4 流式投影/状态行既有测试、fixture 与真实契约 schema 门全绿。

### 2.2 完成标准

1. 流式回合内气泡文本渐进增长有连续帧截图证据（§6.1 判定通过），且帧 PNG 供人审可辨认文本变长过程。
2. 埋点作为独立交付物先行合入：埋点事件字段清单经 P0 冻结；controller 测试断言日志序列（到达时间戳单调、累计长度单调、对账字段）；导出文件不含消息正文（审计断言）。
3. 同一回合的截图 + 日志双证据可互相对照（同 seq 序列），一并登记 25 号套件 evidence。
4. fixture 逐 delta 时间释放在 controller/widget 测试与可见 gate 中各有一处消费；`after_seq` 与 `streaming` 语义不漂移。
5. 打字机释放与 v0.8.6 `SessionMarkdownText` 的 partial 降级兼容：半开代码块/表格等中间态渲染不崩不闪，completed 后终态一致（widget 测试）。

7. 完成标准 1-5 均不接受"临时脚本/print 日志、单帧截图、录屏"替代。

### 3.1 埋点契约（P0 冻结字段清单，门禁 2 基石）

埋点事件（建议命名，P0 定稿）：

- `stream_first_delta`：`{ts, seq, kind, message_id, latency_ms}`——`latency_ms` = send 受理 → 首条流式文本帧到达；
- `stream_delta`：`{ts, seq, kind, message_id, delta_chars, cumulative_chars, since_last_ms, batch_events}`——`delta_chars` 为本帧相对上一同身份帧的字符差，`batch_events` 为本批次同达帧数；
- `stream_completed_reconcile`：`{ts, seq, final_chars, last_stream_chars, consistent}`——completed 全文与最后流式帧的对账结果；
- `stream_poll`（采样）：`{ts, attempt, new_events, fetch_ms}`。

落点：`_mergeSnapshot`（合并时逐帧）、发送轮询循环（批次）、`_snapshotCompletesTurn` 翻终态处（对账）。sink 为内存 ring buffer（容量 P0 裁决，建议 ≥2000 条）+ 设置页开发者/诊断入口导出 JSON（含 `schema_version`）。**审计红线：任何埋点字段不得包含消息正文/工具输入输出原文**；导出测试断言此红线。

### 3.2 打字机渲染口径（P0 裁决）

- 推荐：**数据驱动为主 + 平滑释放为辅**。动画只是"已到达 buffer 的展示释放"：释放速率自适应落后量（如每 tick 释放 `max(1, buffer/30)` 字符），数据到齐即追平；**动画永不展示未到达的文本**（fail-closed），completed 全文到达后立即对账收敛，不允许动画尾滞。
- 裁决项：动画默认开/关、释放速率参数、thought 通道是否同动画（建议同）；"关"的回滚形态 = 直接整段渲染（现状行为）。

### 3.3 轮询策略（P0 裁决数值，与 v0.8.6 协调）

- 在途前台轮询收紧档（建议 `pollInterval` 500ms → 250-300ms），仅限"发送受理后在途回合 + 会话页可见"窗口；**实现走 v0.8.6 已交付的参数化入口**（`session_controller.dart:92-96` 可注入字段），不改窗口结构与超时收敛语义（看门狗在 daemon：`AGENT_SESSIONS_TURN_WATCHDOG_MS`，`internal/daemon/runner.go:152`；客户端显式收敛 `session_controller.dart:2375-2388`）。
- 常量参数化（可配置），后台轮询维持降频；G6 watch 模式（若裁决做）用独立低频档（建议 1s），不与本档互踩。
- Relay 压力评估：单会话单客户端在途窗口收紧一倍，QPS 增量有界；不引入服务端改动。

### 3.4 fixture 逐 delta 时间释放

- `FixtureRelayRepository` 增加时间释放流式模式：回合内 delta 按计划表（如每 300-500ms 一条、共 N 条后 completed）逐步可见于 `getSessionSnapshot`；测试档用注入时钟（既有先例 `FixtureRelayRepository(clock: () => _now)`，`apps/mobile/test/session_controller_test.dart:16`），可见 gate 档用真实时间。
- 释放计划表参数化（帧数/间隔/字符增量），可见 gate 场景按 §6.1 判定反推预算（回合时长 12-20s、截图 5fps 现有调度足密）。

### 3.5 截图门禁校验器（P0 冻结机制）

- 每帧截图时由驱动侧同步采样"当前渲染气泡文本长度"写入 manifest 帧元数据（widget 树读取，不 OCR）；校验器按帧序断言：长度序列单调不减且严格递增次数 ≥K（建议 K≥3），首帧即全文的形态判失败。
- 帧序列校验扩展落点 `e2e-verify/mobile/macos-screenshot.mjs`（`validateStrictWindowFrameSeries` :47 起同族）；场景注册表编号自 VISUAL-MOBILE-38 之后顺延（P0 冻结具体编号）。
- 环境前提沿用 V086-07 实机口径：TCC 屏幕录制授权前置检查、`caffeinate -u`/`-dis` 防休眠、预构建 App 复用 `record-smoke-v086.mjs` 口径；**机读判定（manifest 长度采样）与帧节拍解耦**——偶发掉帧不破坏单调性判定，帧 PNG 仍作人审证据。

### 3.6 daemon 回合级流式摘要日志（可选裁决）

- 回合终态处一条 info：delta 条数/总字符数/回合时长/session 标识（`internal/daemon/runner.go` `recordEventResult` :1274 起，v0.8.6 看门狗合入后的现位）；**不做逐 delta 日志**（噪声与体量不可控），不影响 outbox/白名单语义。裁决"做"时作为门禁 2 的服务端佐证，"不做"时门禁 2 以移动端埋点为唯一证据源。

## 6. 验证与证据口径

### 6.1 截图门禁判定

同一流式回合内：连续 ≥30 帧（沿用 100 帧证据口径的子序列）中，assistant 气泡渲染文本长度序列**单调不减且严格递增次数 ≥K（P0 冻结，建议 ≥3）**；"首帧即全文"或长度序列平台化（无增长）判失败。帧 PNG 供人审辨认文本变长；机读判定来自 manifest 帧级长度采样（§3.5）。场景使用 fixture 时间释放回合，回合时长预算 12-20s。帧采集环境按 V086-07 口径前置检查（TCC 屏幕录制授权、`caffeinate` 防休眠）；宿主负载导致帧节拍抖动时，机读判定以 manifest 长度采样为准（与 fps 解耦），帧数下限按实际捕获数判定；环境受阻按遗留流程如实留档并复跑，不静默降级为通过。

### 6.2 日志门禁判定（证据必须出自 P1 埋点）

同一回合导出日志：`stream_delta` 记录 ≥N 条（P0 冻结，与 fixture 计划表一致）；`ts` 严格递增；`cumulative_chars` 单调递增；`stream_first_delta.latency_ms` 在位；`stream_completed_reconcile` 存在且 `consistent=true`。日志文件原样入 evidence，不改写；缺埋点或以 print/临时日志替代判门禁失败。

### 6.3 通用口径

- 默认验证：`fixture_data=true`、`local_test=true`、`real_model=false`、`real_upstream=false`；可见 gate 为本地真实桥/fixture + 真实可见窗口，不调用模型。
- 四类分开报告：smoke → targeted diagnostic → full gate → recording；incomplete gate 不得称完整通过。
- 实机 gate 记录 `visible_desktop_app=true`/`headless=false`（macOS 口径，`docs/zh/自动化测试文档.md:13`）；真实模型/上游需用户显式授权（仅 V087-12 可选路径）。
- 报告 schema、failure_class 分类、证据不改写、结束清理沿用 v0.8.5 §6 / v0.8.6 §6，不另立标准。

## 7. 风险、回滚与不做事项

| 风险 | 处理与回滚 |
| --- | --- |
| 平滑动画伪造流式（"假打字机"：数据未到先演字） | 动画只释放已到达 buffer、速率自适应落后量；截图校验基于渲染长度序列、日志以数据到达为准；回滚 = 动画开关置关（整段渲染现状形态） |
| 与 v0.8.6 在飞改动冲突（同文件轮询/清账/状态行） | P0 承接确认 + rebase 盘点先行；本计划不改终态判定与清账语义，只叠频率/埋点/渲染 |
| 轮询收紧造成 Relay QPS/电量压力 | 仅在途 + 会话页可见窗口收紧；常量可配置；后台维持降频；watch 模式独立低频档 |
| fixture 时间释放引入测试 flake | 测试档注入时钟（不用真实 sleep）；可见 gate 用帧数下限 + 宽松时间预算，不绑固定时刻 |
| 埋点记录正文造成隐私/审计违规 | schema 红线只允许元数据与长度；导出测试断言无正文；导出入口置于开发者/诊断入口 |
| 判定阈值（N/K/帧数）拍脑袋导致门禁形同虚设或过苛 | P0 用实机盘点数据定阈值；判定标准写入 §6 后按证据不改写 |
| 帧采集环境受阻（TCC 屏幕录制授权、显示器休眠、宿主负载掉帧——V086-07 实测教训） | 前置检查 + `caffeinate -u`/`-dis` + 预构建 App（`record-smoke-v086.mjs` 口径）；机读判定与帧节拍解耦（manifest 长度采样）；受阻按遗留流程留档复跑，不静默降级为通过 |
| daemon 摘要日志噪声 | 只做回合级一条 info；裁决不做则零改动 |
| 真实 E2EE 部署形态下移动端仍为占位（本轮口径不覆盖） | 如实留档（§1.4），不阻塞本轮；真实解密另立项 |

本期明确不做：移动端接 SSE/WebSocket/长连接（维持快照轮询框架，理由与 web 参照口径留档 P0 裁决）；`events.json` wire schema 改动与新增事件类型；服务端 delta 合并/节流/批量上行改造；客户端增量拼接重构（全量投影契约维持）；真实 E2EE envelope 的移动端解密；claude/openclaw 的 delta 能力（无事件产生，fail-closed 维持）；逐字符音效/光标闪烁等装饰性动效；上游自动重试与轮询无上限延长（终态收敛归 v0.8.6 看门狗）。
