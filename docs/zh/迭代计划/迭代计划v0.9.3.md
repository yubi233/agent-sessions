## 0. 复核结论与版本边界

- v0.9.2 的 P0–P2 交付物是实的：能力事实源（执行侧为准 + 受控重探测）、会话生命周期（resume 而非 start）、Relay 按来源合并事实，均已在真机与单元/集成层通过。
- v0.9.2 的**收口缺口**只有一项：V092-10 判定为 `partial`——链路成立（`resume→start→send` 全 completed、回合 `turn_completed`、重启前历史保留），但三条断言未达成。
- 本计划**明确排除**：不重开 ACC-01..06 与 V092-01..09；不改桥版本门（记录 31）与代理信任设计；不做破坏性数据库迁移、不重置 SQLite；不为压测消耗真实模型额度（压测用 fixture 桥注入确定性 delta）。
- 本计划的完成会反过来解除 v0.9.2 的 `partial`：V093-05 负责把 V092-10 改判 `passed` 并回填状态口径。

## 1. 已复现故障链与分层归因（待阶段 0 实测钉死）

三项缺陷全部来自 2026-09-17 的云端真机验收，均有一手证据（daemon 日志、`daemon.db` 出箱计数、手机 UI dump），不是推测。

### 1.1 现象（R18 实测）

| 编号 | 现象 | 一手证据 |
| --- | --- | --- |
| F1 | 单回合产生 16779 个 delta 事件，出箱一度积压 13832 条 `pending`（delivered 3866），实测约 16 条/秒；大量事件 `attempts=0` | `relay_event_outbox` 按 status 聚合；积压最终全部投递（16982 delivered、pending 归零） |
| F2 | 回合 `turn_completed` 后手机 UI 仍长时间显示「生成中」，需一次视图切换才收敛到「已完成」 | daemon 日志 `terminal=turn_completed` vs 手机 dump 状态词 |
| F3 | resume 后时间线出现 `system-reminder`（skill catalog）被投影成「你」的消息，用户实际发送的正文不可见；该回合异常冗长（35282 字符、跨度 232 秒） | 手机 UI dump 的 `会话节点 你` 节点内容 |
| F4 | daemon 重启后**首条** `session.send` 以 `local_state_missing`（session instance 不存在）失败，需再次发送才触发 `resume→start→send` | daemon 日志 + `relay_commands` 的 `error_code=LOCAL_STATE_MISSING` |

### 1.2 候选根因层（代码可证；归属待实测）

- **L1 传输层（对应 F1/F2）**：`internal/daemon` 的事件上传循环——批量大小、串行 ack、节流/退避策略、以及「`attempts=0` 长期排队」的调度语义。F2 很可能是 F1 的直接后果（终态帧排在积压尾部），因此**先修 F1**。
- **L2 桥/投影层（对应 F3）**：resume 时桥注入的上下文（`system-reminder`）在事件流中缺少来源标记，客户端只能按「谁发的」二分投影，于是把系统注入内容当作 user 消息。
- **L3 客户端恢复层（对应 F4）**：客户端在收到 `LOCAL_STATE_MISSING` 后是否自动执行 start 回退 + send 重试。v0.9.2 的 R17 修复（commit `b61a8be`）覆盖的是「状态未翻转触发 start 回退」的本地形态，云端实测显示该自动路径在首条发送场景未生效。

### 1.3 已排除的误判（不进入实现方向）

- **不是模型/渠道问题**：同一回合的 403 `FreeTierError` 已由模型目录双源对齐解决（v0.9.2 §8.3），F1–F4 与 provider 无关。
- **不是事件丢失**：出箱最终全部 `delivered`，问题在**吞吐与排序**，不在可靠性语义。
- **不是云主机性能**：积压发生在 Daemon 侧出箱，未观察到 Relay 拒绝或 5xx。

## 2. 目标与验收标准

- **G1（吞吐）**：万级 delta 回合结束后，出箱积压在目标阈值内归零；手机 UI 无需任何人工操作（含视图切换）即收敛到终态。阈值在 V093-01 量化后冻结。
- **G2（投影）**：resume 后时间线只反映真实用户消息与助手回复；系统注入内容（`system-reminder` 等）不进入用户可见投影；回合长度回落到正常量级。
- **G3（恢复）**：daemon 重启后，手机对同一会话的**首条**发送即成功，全程零手工（T1 裁决）。
- **G4（收口）**：`task test:v092:local` 完整聚合门（含 headed 真实浏览器 12/12 与 `test:restart`）通过，V092-10 改判 `passed`，v0.9.2 状态满足其 §6 完成定义。

## 3. 影响面与冻结契约

### 3.1 影响模块

- `internal/daemon`（事件出箱上传循环、命令调度；F1/F2/F4）
- `internal/adapter/dsh`（resume 上下文注入与来源标记；F3）
- `apps/mobile`（消息投影与自动恢复；F2/F3/F4）
- `internal/relay`、`internal/httpapi`（仅在需要时确认批量接口的幂等与顺序语义）
- 文档与测试：`docs/test/32-v093-event-throughput-and-context.json`、本计划、实施记录 33

### 3.2 冻结契约（实施前必须先冻结）

- **投递顺序与幂等**：`event_seq` 的严格递增与重复投递幂等（Relay 侧按 `(session_id, event_seq)` 去重）不得因批量化而放松。
- **终态语义**：`turn.completed` / `message.completed` 的到达顺序与「终态后不再产生该回合 delta」的保证不变。
- **最小环境**：桥进程的最小环境派生（ADR-013 §5）不回退；Daemon 启动侧必须继承完整环境（v0.9.2 §20.3 的 PATH 回归教训）。
- **E2EE 边界**：事件 envelope 的加密与 AAD 绑定不变；本次优化只动传输节奏，不动密码学形状。
