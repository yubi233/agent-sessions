## 0. 结论与范围

本轮不是单纯换色和压缩间距，而是三个相互依赖的改造：

1. **状态和消息事务**：统一主状态；区分连接、设备写权限、租约、执行会话和单条消息；自动恢复、重发、失败、草稿不再各说各话。
2. **移动端会话骨架**：紧凑标题、可读消息流、不遮挡的状态槽、全宽文本输入、紧凑配置摘要与渐进展开设置。
3. **内容与可理解性**：消息动作、Markdown 表格/代码、图标、模型/权限名称、真实标题、主题和无障碍统一收口。

### 0.1 实施边界

- 主改动在 `apps/mobile` Flutter 会话页面；共享组件在 Android 与 macOS 上同步受益。Web只补会话详情的同步反馈/补拉缺口，不重设计页面；Web/Admin均不增加写操作。
- 发送状态不能靠 UI 猜测；影响面明确包含 `internal/httpapi`、`internal/domain`、`internal/store`、`internal/daemon` 和 `packages/protocol` 的必要兼容投影：复用已持久化命令关联，补齐权限目录安全名称/说明。保持HTTP+SSE架构，不为UI更换传输协议。
- 不清理真实用户state、不重置SQLite、不做破坏性迁移；优先复用现有事件receipt关联查询，若必须新增持久字段，仅允许冻结兼容契约后的增量迁移。桥版本门、代理信任、权限能力声明与模型默认路由不变。
- 当前聊天路径仍使用localdev/fixture payload；生产事件加密器存在，但移动端生产聊天解密渲染和命令加密发送未贯通（见§0.3）。本版本优化当前可运行链路并保护已有密码学边界，**不把生产聊天E2EE完整建设隐含纳入UI任务**，也不把明文测试链路包装成加密完成。
- 不新建AI标题生成调用；标题优先已有 `displayName`，其次客户端已可见的真实用户正文摘要，最后用已有 `session.title`。非可读加密事件只显示占位，不参与摘要；摘要不上传明文元数据。
- “所有都改”指全部 18 项纳入本版本的必交付范围；阶段先后不代表低优先级项可不做。任何未完成必选用例阻塞 `delivered`。

## 2. 冻结的体验与数据契约

### 2.1 单一展示状态，不伪造底层事实

拟新增纯展示投影 `SessionPresentationState`（名称为计划，当前文件不存在），由 controller 已有事实派生，header、状态槽、消息状态和 composer 同源消费。不要让 widget 自己再写一套恢复判断。

展示优先级：当前会话硬阻断（只读/服务不可用/断网，保留并附注在途状态）→ 需要回答/审批 → 自动恢复/重发 → 结果待确认/已知失败 → 执行中 → 可开始/待发送。底层事实仍分维度保存，不把权限或网络错误写成 session 的 canonical stopped。

- 连接层：使用网络/事件 transport 的真实状态；`provider.available` 只代表能力可用性，不代表 WebSocket、SSE 或 Provider 当前会话已经连接。
- 角色层：`canWrite` 只说明设备可控制；lease 按现有自动获取流程执行。无 lease 不增加“请手动获取后才能输入”的常规步骤。
- 会话层：canonical 状态为事实，恢复/命令处理中为本地事务态。stopped 不一定等于不可发送；可自动恢复时显示“发送时将恢复会话”，不错误禁用恢复入口。
- 操作层：区分“可编辑草稿”和“可提交消息”。恢复期间可写下一条草稿，但禁止同一事务被再次提交；执行中 queue/steer/abort 按既有契约判断。
- 恢复 cause 无确证时用“正在恢复会话”，不一律断言“检测到终端已重启”；首次启动用“正在启动会话”。

### 2.2 消息事务身份与送达语义（先于布局开发）

当前 pending 仅为 `Map<sessionId, String>`，canonical user event 还可能先于执行失败；现有字段不足以可靠解决消息级关联。本轮必须建立显式事务对象，而不是仅改气泡颜色。

建议事务字段：`sessionId`、本地 `submissionId`、草稿 revision、初次/重试 `commandId`、稳定 `clientMessageId`、消息快照/附件引用、起始 cursor、阶段、错误分类、自动重试次数、已核验结果。不得因新增关联把正文复制到遥测、关联索引或新增明文元数据；当前fixture链路并非生产保密证明。

明确实现选择：

1. 一次显式发送生成稳定 `clientMessageId`；同一自动恢复重发复用该 ID，但按既有 `#recovered` 规则更换失败命令的幂等键。两次用户主动发送相同文本必须获得不同 ID。本地事务账本保存逻辑消息与初次/重发命令的映射。
2. 优先复用Relay已存的event receipt → CommandID关系，在授权后的snapshot白名单DTO中兼容增加可选 `command_id`，不透出正文或跨会话关联；历史无receipt事件允许为空。关联缺失时不按文本猜测。
3. `ConversationNode` 扩展独立的关联/投递展示字段，**不把 clientMessageId 塞进现有 messageId**，避免错误开启 fork/feedback；Provider messageId 的行为保持不变。
4. 对同一事务的重发用户节点做投影合并；原始事件/轨迹不删除。错误仅在关联明确时合并为该消息的恢复记录。无关联的历史错误仍完整保留。
5. 旧事件无关联 ID 时保守降级：显示“状态未确认”，不对全历史做文本相等去重、不猜属于最近一条消息。本地命令账本可关联当次发送；不能可靠匹配时宁可保留记录，不删除真实历史。
6. P0冻结receipt查询、outbox CommandID和客户端解析的兼容契约，并同步OpenAPI/生成物；一并补齐实际Command响应已有的 `error_code` schema。只有外层command关联不足以满足重发分组时，才补可选逻辑ID透传；必须验证Runner/localdev路径及生产事件编码器的隔离往返兼容，不修改AAD/envelope，不将编码器测试等同生产聊天端到端验收。当前命令仍走fixture_payload，非fixture聊天事件保持占位与fail-closed，不借本次改造新增明文降级。

| 展示状态 | 判定证据 | 可用动作 |
| --- | --- | --- |
| 正在提交 | 本地已创建事务，尚无服务受理回执 | 禁止重复提交同事务，可编辑下一条草稿 |
| 已受理，等待执行 | Relay 202；不能据此称 Provider 已收到 | 查看状态；按实际支持提供中止 |
| 恢复中 / 正在重发 1/1 | 明确可恢复错误或发送前恢复，事务尚未终结 | 查看阶段；取消尚未提交的自动后续步骤 |
| 结果待确认 | 回执超时/查询失败，且没有权威执行结果 | 核验结果；不新建发送命令 |
| 已开始处理 / 已完成 | 关联执行事件或明确成功终态，按其保证范围展示 | 保留既有中断/后续发送语义 |
| 未送达 / 执行失败 | 关联失败回执；前者仅用于确定未交给执行端的错误 | 显式重试或编辑，不盲目自动补发 |

“已送达”不是必用词；只有链路能证明其含义时才用。Provider 接收与回合完成必须区分。

### 2.3 恢复过程与错误处理

- 保留 v0.9.3：自动恢复重发最多 **1 次**；30s send 回执窗口；失败回执优先于同步代际守卫的 V093-04b 修复；既有 resume 优先及已冻结的 start 回退规则。
- 恢复状态覆盖 `resume → 必要时 start → send#recovered → 结果核验`，不能在 resume 返回时就清除。阶段从执行路径写入，不根据计时器伪造完成度或倒计时。
- 10s 后增加“耗时较长”说明与已等待时长；这是展示阈值，不触发新命令、不重置既有 2/60 分钟回合预算。回执窗口耗尽但已有可信执行进展时维持“处理中”；无可信结果/进展才进入“结果待确认”，均不等同失败。
- 恢复期间只显示一条当前行动提示；旧错误折叠为“已自动处理的发送异常”，技术详情可展开。恢复最终失败时显示明确原因和一次手动重试入口。
- “取消自动恢复”只取消**尚未提交**的后续自动步骤，使用事务 token 守卫；已在执行的命令不能被虚假标为已取消。已提交 send 需按既有 abort 能力处理中止，没有该能力就说明只能停止等待/核验。
- 已知失败后的手动重试生成新的显式 attempt，与旧 attempt 保持关系并串行；结果未知时必须先核验，不能用新幂等键重复发出。
- `LOCAL_STATE_MISSING` 等恢复分类优先使用结构化错误。已有文本匹配保留兼容回退，不因 UI 文案改写改变恢复判定；配额、认证、版本不兼容等不得被当成可恢复实例缺失。

### 2.4 草稿与发送结果归属

- 原草稿在本地验证通过且消息事务接管内容后清空可编辑区；验证失败（权限、图片能力、slash command）不清空。
- 回执等待不再冻结整块输入框。允许用户编辑下一条草稿；是否可发按真实运行态和 queue/steer 策略决定，不能为解锁输入新增静默队列自动发送。
- 失败内容保留在消息事务中；“编辑后重试”才转回草稿。若已有新草稿，禁止覆盖，提供保留新草稿的明确选择。
- 结果以 `sessionId + attemptToken + draftRevision` 结算。旧响应、切会话、注销、重建不能清掉新草稿或把 A 的恢复状态画到 B。
- 附件与引用同事务快照归属；受理成功仅移除本次附件，不能清掉用户后来选的新附件。沿用既有本地存储安全边界，不新增明文持久化。

### 2.5 发送等待、配置生效与幂等身份

- **发送门控拆分**：提交锁仅保护一次事务的验证/提交接管；回执观察在后台继续，停止拥有独立在途锁。停止仍检查角色、lease、能力和真实可中止状态，但不能仅因send在等终态而禁用。DSH send成功通常意味着回合已结束，不能等待它才允许中断；禁止因解锁输入隐式发送下一条消息。
- **证据有序**：202为受理，started为执行端开始，关联Provider流为正在处理，终态为完成/失败。30s观察窗口结束时，已有执行进展保持执行中并注明结果仍在同步；只有缺少可信结果/进展时显示待确认。迟到失败仍按V093-04b优先处理，不因窗口或切换代际静默丢失。
- **配置确认**：权限、模型、effort各自保存effective、requested、commandId和确认状态。202只显示“切换中”；查询返回null/超时不能触发成功回调。命令成功后刷新权威controls/session投影，值一致才标已生效；投影滞后继续确认，明确失败保留原effective并说明原因。Relay当前model_select在受理时提前更新元数据，本轮须改成确认后的权威投影或显式区分请求值，不能把该乐观元数据当成功证据。
- **未知结果**：保留原值与待确认候选，提供只读核验；不能悄悄改成已生效或用新key补写。同一控制域确认期间串行，后续显式选择需先结束/核验前次事务；切会话、注销和晚回执按session/operation隔离。
- **幂等生命周期**：每次用户新操作生成独立operationId；同一次HTTP响应丢失或重试复用key。已结束操作可归档并释放活动映射，但未知事务不可简单清key重发。权限/模型/effort的A→B→A→B每次真实变更都必须到执行端，不能命中第一次B的旧命令。
- **权限目录**：保留 `available_permission_modes` ID数组，兼容增加可选id/name/description目录。Relay白名单投影、数量/长度限制及客户端DTO/OpenAPI同步；前端按当前Provider/会话目录展示纯文本，旧Relay或缺说明退回原ID及“说明未提供”，不臆测跨Provider权限。风险确认不依赖展示名称，不能用改名绕过完全访问确认。

### 2.6 Web只读同步闭环

`apps/web/src/session.ts` 与 `views/SessionDetailView.vue` 增加在途pending合并与失败后的有界重试/手动核验。收到账号通知不等于本会话snapshot已合并：分别维护收到的账号cursor、完成核验的通知位置和session-local event_seq；重连/重新进入须主动补拉，不能仅靠已推进的SSE游标。增量失败保留最后可信内容、显示同步失败而非清空页面；连接live与同步成功分开。测试连续通知、在途后最后一次通知、请求失败且之后无新事件、断线重连、切会话/卸载旧响应；仍仅GET/只读，不保留或渲染envelope，不扩大Admin改造。

### 3.2 布局验收预算

数值为本版本目标，不是已测结果；按 Flutter 逻辑 dp，系统状态栏、键盘和系统安全区单独记录，禁止拿截图物理像素当 dp。

- 基准 360×800、textScale=1.0、键盘关闭、无 takeover：header（含 tabs）≤124dp；空/单行 composer 含配置摘要≤144dp；恢复槽标准态≤64dp且可随文字放大增长。
- 同基准正常态会话视口≥55%可用安全区高度；恢复态≥45%。三行输入及恢复态要记录前后差异，不能靠缩小正文或点击框达标。
- 输入正文可用宽度≥输入容器内容宽度的90%；左右内边距一致，工具图标不占正文横排。
- 默认可见消息动作区最多一行；附加反馈进入展开区。正常字体下不靠巨大留白分隔消息；交互目标至少48×48dp，图形可小但语义/命中框不能只有32dp。
- 360×800、430×932、1280×800 亮暗主题必测；320dp 极窄宽度和至少一个密集会话 200% 字号补测。大字体和键盘开启时不硬套高度预算，优先不截字、不遮挡、关键动作可达。
- 窄屏横向溢出只允许发生在明确标记的表格/代码内部，不允许整个页面横滚；设置面板正确避让键盘、安全区和横屏低高度。
- 普通文本对比度≥4.5:1，大字/必要图形≥3:1；状态不用颜色单独表达；图标有语义名称，禁用原因可读，动态进度不每帧重复播报。

### 3.3 Markdown 与内容规则

- 保留 GFM、流式不完整 Markdown 降级、原始 HTML/远程图片/外链的既有安全边界，不为美观静默打开链接或拉取图片。
- 表格从 LayoutBuilder 获得实际宽度；列内容可换行，确需超宽时内部横滚并展示滚动提示；2列/多列/长中文/长无空格 token/流式半表格均测试。不默认转键值卡片，避免改表头含义。
- 代码块显示可信语言标签（缺失时“代码”）、复制、长代码展开。复制原始文本并保留换行/缩进；长行内部横滚或显式换行切换，不靠视觉折行改变复制值。
- 普通段落中的命令即便能识别，也不擅自重写为命令块；首先完善正确 Markdown 的阅读与复制。行内代码和整条消息复制必须保留原内容。
- 标题摘要只取已确认属于用户的正文，排除隐藏注入、技术 notice 和附件机密路径；既有 `displayName` 永远优先，不能随每条新消息反复跳动。
- 权限说明按真实 Provider 模式定义，不把 `default/plan/acceptEdits` 笼统解释为跨 Provider 一样的权限；未知 mode 显示原值与“说明未提供”，保持能力禁用/确认门。

## 6. 回归风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 新文案打断靠错误文本匹配的恢复 | 结构化错误优先、旧匹配兼容；分类层与显示文案分离；实例缺失/配额/认证/版本错误分别测试 |
| 消息合并误删两次相同输入或恢复历史 | 只按可靠事务ID合并，不用全历史文本相等；旧无ID不猜；原始事件不删 |
| 解除输入锁后旧结果覆盖新草稿/附件 | 按session/attempt/revision结算；本次附件引用快照单独确认 |
| 取消只隐藏提示但仍偷偷重发 | 自动步骤前检查事务取消token；已发命令标结果待确认，不假称取消 |
| 设置收纳造成高风险权限不可见 | 摘要仍显示“完全访问”警示；确认门保留，未知模式不美化为安全模式 |
| 过度压缩触达与大字体验 | 48dp语义目标；高度预算仅普通字号生效，大字优先可达 |
| Markdown优化放松安全边界 | HTML/图片/链接fail-closed继续回归；复制不执行，普通文本不猜成命令 |
| 改动共享主题影响其他页面 | 优先组件级语义角色，必要token同步规范；全量主题/样式及可见页面回归 |

回滚按 P1 事务/事件关联与 P2/P3 展示的兼容边界拆分提交；先验证新旧事件兼容，再允许客户端回退。禁止回滚数据库、删除历史、降低权限安全门或撤销 v0.9.3 的恢复修复来换取“界面正常”。
