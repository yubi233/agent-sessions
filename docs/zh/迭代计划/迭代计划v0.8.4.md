# Agent Sessions 迭代计划 v0.8.4：细粒度会话状态与 ACP 流式输出

> 状态：`planned`（2026-09-03；安全边界修订：终端所有者对自身终端拥有绝对所有权，raw reasoning 默认直接开启，不做敏感度一刀切禁止）
>
> 前序：[迭代计划 v0.8.3](迭代计划v0.8.3.md)。v0.8.3 已完成 DSH ACP 的 mode、session lifecycle、question/elicitation、plan、goal、skill、subagent 观察投影、usage 和 tool activity 能力收口。本计划只处理新的可观测性缺口：会话/回合状态过粗、DSH ACP 没有真正的增量输出、移动端没有 LLM 打字机式展示，以及 ACP 状态更新没有贯通 Agent Sessions 公共协议。

## 1. 诊断基线

### 1.1 已确认支持

ACP SDK 0.25.1 已定义以下 session update 类型：

- `agent_message_chunk`
- `agent_thought_chunk`
- `tool_call` / `tool_call_update`
- `plan_update` / `plan_removed`
- `available_commands_update`
- `current_mode_update`
- `config_option_update`
- `session_info_update`
- `usage_update`

DSH v0.8.3 bridge 已有以下实现：

- `initialize`、`session/new`、`session/load`、`session/resume`、`session/prompt`、`session/cancel`；
- `session/set_mode`、`current_mode_update`；
- `session/close`、`session/list`、`session/delete`、`session/fork`；
- question/elicitation、plan、goal、skill catalog/invoke、subagent 生命周期投影；
- permission ask、usage 和可选 tool activity。

DSH agent loop 已在 `packages/core/agent-loop/src/agent.ts` 将模型流保存为 `assistant/chunk`，其中包含 `text-delta`、`reasoning-delta`、`tool-call-delta`。因此增量源存在，缺口在 bridge 投影与下游消费。

### 1.2 当前不满足需求的事实

1. `/Users/yubi/code/deepseek-harness/packages/acp/acp/src/index.ts` 的 `session/event` 监听目前主要处理持久化 `assistant/message`；实时输出发送的是完整 assistant content，不是每个 `assistant/chunk`。
2. `internal/adapter/dsh/mapper.go` 把 `agent_message_chunk` 映射为 `EventMessageCompleted`，没有生成 `EventMessageDelta`。
3. Agent Sessions 的 `EventMessageDelta`、Relay `message.delta` 和本地 fixture 累积器已有基础，但 DSH 路径尚未接通。
4. Flutter `MobileSessionStatus` 只有 `idle`、`streaming`、等待交互、停止、错误、离线等粗粒度状态；没有 queued、preparing、thinking、tool-running、finishing、cancelling 等可判断的回合阶段。
5. Flutter 当前显示固定的“模型仍在处理当前轮次” overlay；没有按消息身份累积增量文本的打字机节点。
6. ACP 没有跨 agent 的通用 turn phase 字段。状态阶段必须通过标准 ACP update 加版本化 `dsh/*` extension 协商，不得伪造未注册的 ACP 标准能力。
7. `agent_thought_chunk` 可以承载原始 reasoning/Chain-of-Thought。产品边界是终端所有者本人、主动要求查看，其对自身终端拥有绝对所有权，故不做敏感度一刀切禁止：`agent_thought_chunk` 默认直接开启 `raw` 投影，`hidden`/`summary` 仅作旧客户端或降级场景的兼容模式。raw thought 与 assistant answer 分开建模，不得因为渲染方便而拼进回答正文。

## 2. 目标与完成标准

### 2.1 目标

- G1：为每个 session 建立可回放、可取消、可重连的 turn phase 状态机。
- G2：让 DSH `assistant/chunk` 的 `text-delta` 逐块进入 ACP `agent_message_chunk`，再进入 canonical `EventMessageDelta`、Relay 和 Flutter。
- G3：让客户端能区分排队、启动、思考、文本输出、工具执行、等待权限、等待问题、收尾、取消、成功和失败。
- G4：`agent_thought_chunk` 默认直接开启 raw 投影（reasoning-delta 直达独立 thought 事件）；hidden/summary 作为可选的兼容/降级模式；两种模式可切换、可回放。
- G5：保持已有 message completed、tool、permission、question、plan、goal、usage、lifecycle 语义和 OpenCode/Codex 行为不回归。
- G6：为所有增量和 phase 事件建立顺序、去重、背压、断线恢复和 terminal fence。

### 2.2 完成标准

1. DSH bridge 能为同一 turn 发送有序、可关联的 text chunks；Go adapter 产生 `EventMessageDelta`，而不是把中间 chunk 标为 completed。
2. 一个 turn 只生成一个权威 completed 终态；中断时保留已发送前缀并标记 `interrupted`，不会重复拼接或丢失尾部。
3. `turn.phase` 从 committed 事件和实时通知均可重建，旧客户端忽略未知 phase 仍能正确关闭 `streaming` 状态。
4. Flutter 在固定高度/宽度的聊天节点中实时增长文本，滚动、切换会话、后台恢复和失败重试不会重复或串会话。
5. reasoning delta 默认直接以 `thoughtVisibility=raw` 逐块进入独立 thought 事件和 UI，无需审批或显式开启；未声明 thought capability 或选择降级的客户端才收到 hidden/summary（thinking 状态或摘要）。raw thought 永不混入 assistant answer 事件。
6. 未协商 `dsh/*` 扩展的 ACP client 不会收到不可消费的 phase 通知；不支持流式的 provider 继续返回准确的 capability reason。
7. `task check`、Go/Flutter/Web 定向测试、DSH ACP contract tests、headed Chrome 和可见 Flutter gate 均通过；真实模型测试另以授权 gate 记录。

## 3. 状态模型与协议冻结

### 3.1 Session 与 turn 分层

不再把所有状态塞进 `MobileSessionStatus`。保留其向后兼容的 session 生命周期含义，新增独立的 turn activity projection：

```text
SessionStatus: idle | active | stopped | errored | offline
TurnPhase: queued | preparing | thinking | streaming | tool_running |
           waiting_permission | waiting_question | finishing |
           cancelling | completed | cancelled | failed
```

规则：

- `queued`：输入已接收但尚未进入 agent turn；
- `preparing`：`turn/start`、上下文组装或模型请求准备；
- `thinking`：已有 reasoning activity 或尚未出现第一个安全文本 chunk；
- `streaming`：至少一个 `text-delta` 已投影，仍未收到 completed；
- `tool_running`：tool call 已打开但尚未收到配对结果；
- `waiting_permission` / `waiting_question`：有未解决的结构化交互请求；
- `finishing`：模型输出已结束，正在等待 completed/turn end/usage 收口；
- `cancelling`：收到取消但仍在等待底层资源收敛；
- `completed`、`cancelled`、`failed`：不可继续增长的回合终态。

同一 session 最多一个 active turn；历史 turn phase 只用于回放，不覆盖新的 active turn。所有状态变更必须带 `sessionId`、`turnId`、`step`、单调 `revision` 和安全 `reason`。

### 3.2 ACP 承载方式

| 语义 | ACP 承载 |
| --- | --- |
| 文本增量 | 标准 `agent_message_chunk`，每个 `text-delta` 一帧 |
| 用户消息回放 | 标准 `user_message_chunk`，历史回放仍按完整消息发送 |
| 工具打开/更新 | 标准 `tool_call` / `tool_call_update` |
| 模式、计划、命令、usage | 继续使用 v0.8.3 已接入的标准 update |
| turn phase | 协商后的 `dsh/turn/status` notification |
| thought output | 标准 `agent_thought_chunk`；`thoughtVisibility` 默认 `raw`（直接开启），`hidden|summary` 为兼容/降级选项 |
| completed/terminal | ACP prompt response + canonical `message.completed`/`turn.completed`，不发送伪造的 ACP message-complete 方法 |

`dsh/turn/status` 采用 `protocolVersion`、`sessionId`、`turnId`、`step`、`phase`、`revision`、`reason`、`safeSummary?` 字段。thought 通道另带 `thoughtVisibility`，客户端在 `initialize` 的 namespaced `_meta` 声明版本和支持的可见级别；major 不匹配、revision 回退、跨 session、重复 request 或未知字段均 fail-closed。

### 3.3 增量与重放规则

- 实时路径：`assistant/chunk(text-delta)` → `agent_message_chunk` → `EventMessageDelta` → `message.delta`。
- reasoning delta 必须进入独立 thought 通道，缺省即按 `raw` 逐块发送 `agent_thought_chunk`；`hidden` 只驱动 phase，`summary` 只发送摘要（均为显式选择时的降级行为）。任何模式都不得写入 assistant answer 文本。tool-call 只驱动结构化工具状态。
- completed message 是权威全文，必须携带稳定 `message_id` 或等价 turn/step identity；客户端以 completed 替换同一 identity 的临时文本，而不是再次追加。
- `session/load`、历史回放和断点恢复发送完整已提交消息，不重新播放旧 token 动画；恢复后的新 turn 才启动 typewriter。
- 输出队列必须有界。无法满足客户端背压时，先暂停读取/发送并最终以明确错误或 cancelled 关闭，禁止静默丢 chunk。

## 6. 验证与证据口径

- 默认验证：`fixture_data=true`、`local_test=true`、`real_model=false`、`real_upstream=false`；DSH deterministic overlay 是真实本地进程，但不调用模型。

- 每个 phase、delta 和交互请求都必须有明确终态；timeout、EOF、close、dispose 和 cancel 不能留下无限 pending。
- 历史 V08-12、V083 失败或 partial 证据不可覆盖；修复证据使用新的 V084 ID 和独立报告。
- 通过标准：先契约/单元，再 Go/Relay/Flutter/Web 集成，再 headed/可见 gate，最后才是授权真实模型 smoke；任一层失败保持 `partial` 或 `blocked`。

## 7. 风险、回滚与不做事项

| 风险 | 处理与回滚 |
| --- | --- |
| chunk 与 completed 重复造成消息翻倍 | message identity + per-turn sequence；保留旧 completed 路径作为回滚开关，失败时降级为 completed-only 并标记 capability reason |
| 高频 delta 造成 Flutter 卡顿 | 有界队列、帧级合并、可观测 dropped/backpressure 计数；不能静默丢输出 |
| thought 被误并入正文或破坏兼容 | thought 独立 identity/事件类型；hidden/summary/raw 由 capability 协商；旧客户端只收到 answer 和 phase |
| phase 乱序导致 UI 回退 | revision/turn fence、单调 fold、重复/旧事件丢弃并计数 |
| provider 不支持真正 stream | 按 provider capability 返回 completed-only；不伪造 `native`，UI 保留可解释的降级状态 |
| 断线/恢复重复播放历史 | replay 与 live 分离；历史只发完整消息，新 turn 使用新 identity |
| ACP client 不支持 extension | initialize 协商失败则不发 `dsh/turn/status`，标准消息仍可用 |
| 外部 DSH bridge 尚未发布兼容版本 | Agent Sessions 先保留 `unsupported/partial` gate；不修改本地代码伪造桥能力 |

本期明确不做：把 thought 拼入 assistant answer、ACP 未注册的标准方法伪造、fs/terminal/MCP/NES 接入、`delegate_session` 或跨 provider delegation、无授权的真实模型 full gate，以及把 fixture/录屏结果当作真实模型能力证明。raw thought 属于本期默认能力：默认直接开启 raw 投影，不设敏感内容一刀切禁令；`hidden`/`summary` 仅作旧客户端或降级场景的兼容模式。

## 8. 完成定义

v0.8.4 只有在以下条件同时满足时才能标记 `delivered`：

- DSH text chunks 真实经 ACP、Go adapter、Daemon、Relay 到 Flutter，且 completed/取消/恢复/背压语义一致；
- `TurnPhase` 与 `dsh/turn/status` 已版本化协商，标准 ACP update 与私有 extension 边界清晰；
- Flutter 有可见、稳定、按消息身份更新的打字机展示，并覆盖 thinking、tool、等待交互、收尾和错误状态；
- reasoning/CoT 默认直接进入独立 thought 事件（`thoughtVisibility=raw` 默认开启，不设敏感度禁令）；不得混入 assistant answer；未声明 capability 的客户端自动降级兼容模式；
- OpenCode、Codex、v0.8.3 DSH extension 和既有 V081/V082 回归全绿；
- deterministic bridge、headed Chrome、可见 Flutter gate 和对应 V084 suite 有可审计报告；
- 真实模型 gate 若未获授权或部署缺少所需模型能力，必须明确记为 `blocked/partial`，不能阻止文档如实收口，也不能被写成 `native`。
