# Agent Sessions 迭代计划 v0.8：DSH 本地工作区同步与会话恢复

> 状态：`in_progress`（P2/P3 本地与浏览器验证已完成，真实 DSH live gate 仍待授权/修复；本轮实现记录见 [实施记录 17](../实施记录/17-v0.8-DSH工作区同步与客户端模式.md)）
> 定位：v0.7 之后，把授权根内、可证明属于 DSH 的本地项目目录同步进 Agent Sessions。**核心目标是获取本地已有的 DSH 工作区**，让 Agent Sessions 能识别、登记并管理这些工作区；历史会话列表/恢复建立在工作区同步和非破坏性存量数据迁移之上。
> 关联：ADR-013 修订、`internal/adapter/dsh/*`、`internal/adapter/spi.go`、`internal/daemon/{runner,workspace,relay}.go`、Relay HTTP/API、Flutter/Web 会话列表、`docs/test/16-Adapter-Dsh.json`、`docs/test/测试套件索引.json`、`Taskfile.yml`

## 1. 背景与问题

1. **本地 DSH 与 Agent Sessions 工作区/会话数据隔离。** DSH CLI/Web 在项目根维护自己的工作区与 `.dsh-sessions/**/session.jsonl`，Agent Sessions 又通过自己的 Relay/daemon 维护一套 Workspace/Session；两边互不可见。
2. **关键缺口：本地现有工作区没有同步。** Agent Sessions 目前只登记自己创建/确认过的工作区，本地 DSH 已经存在的项目目录不会自动出现在 Agent Sessions 中。用户需要的首先是“获取本地所有工作区”，而不是先列会话。
3. **基线曾不支持恢复历史会话。** 旧版 `internal/adapter/dsh/adapter.go` 的 `Resume` 恒返回 `WakeUnsupported`，旧 ADR 也记录早期 DSH 桥的 `session/load` / `session/list` 为 `-32601`。当前本地 DSH checkout（调研基线 `1252fc2c36`）的 ACP 已实现 `session/load` 与 `session/resume`，冒烟探测缺少 `sessionId` 时返回 `Invalid params`；`session/list` 仍不存在，因此会话发现必须依赖受控 JSONL 扫描。
4. **基线曾缺少 Daemon 句柄交接。** 旧版 `adapter.Resume` 只返回 `ResumeResult{Result, InstanceID}`，Runner 不会登记或转发新建的 `Handle`，导致 Daemon 重启后无法继续 send。本轮已补齐 typed ready callback、事件转发和回放状态，真实模型闭环仍由 P4 gate 复核。
5. **DSH 子进程持久化根错位且存在误删陷阱。** `internal/adapter/dsh/bridge.go` 的 `minimalEnv` 已固定注入 `DSH_SNAPSHOT_SESSIONS_ROOT=<临时 persistRoot>/sessions`，而 `Close()` 会清理该 `persistRoot`。仅修改 `cordis.yml` 为读取环境变量，会使工作区会话仍写入临时目录并在关闭时被删除。`cmd.Dir` 固定为 DSH checkout 根也不能被误当作会话工作区。
6. **缺少本地工作区发现/同步链路。** Relay 没有把授权根下已存在的 DSH 项目目录同步为 Workspace 的机制；现有 `WorkspaceManager.Create` 还只接受授权根的直接子目录，不能直接用于递归发现的既有项目。即使能扫描到会话，也无法建立安全的 `session -> workspace` 映射。
7. **历史数据位置变更会阻断 G3/G4。** 已有 JSONL 位于旧 DSH checkout/旧桥持久化根时，新的 `<workspaceRoot>/.dsh-sessions` 下找不到它；DSH `resumeExisting` 随即在 `persistence.inspect(sessionId)` 失败。迁移或多根只读查找是恢复和导入的前置条件，不是用户确认后才做的可选清理。
8. **`policy: never` 不是自动批准。** DSH `user-approval` 在 `never` 下会在 waterfall/ACP 桥之前直接返回 `rejected`，正常情况下不会发出 `session/request_permission`。adapter 中硬编码 `cancelled` 是未来 `ask` 或异常桥请求的 fail-closed 后备，不应改造成自动放行。

## 2. 目标与成功标准

### 2.1 目标

- G1（核心）现存 DSH 工作区同步：Daemon 能发现授权根下有 DSH 持久化证据的 Git 项目目录，并同步为 Agent Sessions Workspace。
- G2 统一 DSH 本地工作区：Agent Sessions 新建的 DSH 会话与本地 DSH CLI 会话落在同一个 `.dsh-sessions`。
- G3 DSH 历史会话可恢复：Agent Sessions 能对已迁移或可定位的本地 DSH session 执行 `session.load` / `session.resume`，重建可发送的本机 handle，并继续对话。
- G4（次要）本地会话按需导入：在已同步工作区的基础上，经 owner 明确触发把本地 DSH 会话**元数据**导入 Relay；不追求“列出全部会话”作为关键目标。
- G5（UI）主页提供 DSH 模式/模式切换：主页左上角增加 DSH 模式入口或至少模式切换按钮。
- G6 会话列表按 DSH 工作区区分：在 DSH 模式下，会话列表按已同步的 DSH 工作区（项目目录）分组展示。
- G7 多端可见：Flutter/Web 能看到已同步的工作区和已导入的 DSH 历史会话；恢复/继续严格受其归属 Terminal 约束。
- G8 测试与文档收口：新增结构化用例、Taskfile 聚合入口、更新 ADR-013 与项目文档。

### 2.2 成功标准

1. 授权根下已存在的 DSH 项目目录被扫描并同步为 Relay Workspace；Flutter/Web 能看到这些工作区。
2. 工作区同步幂等：重复扫描不产生重复 Workspace；同名/同路径目录能稳定映射到同一 Workspace。
3. 越权/非法路径不会被同步：只同步授权工作区根内、且符合项目目录条件的 DSH 工作区。
4. Agent Sessions 启动的 DSH 会话文件出现在 `<workspaceRoot>/.dsh-sessions` 下，关闭桥或重启 Daemon 后仍保留；本地 DSH CLI 能读取同一批 session，`Detect` 的临时目录才允许清理。
5. `session.resume` / `session.load` 在真实本地 DSH 会话上通过：恢复成功后返回带可用 handle 的 `WakeResumed`；`session.load` 的用户与助手历史均按顺序、无丢失地进入事件流，随后可以继续 `send`。已移动且 `cwd` 不一致的项目必须返回 `WakeWorkspaceMoved`，不得假装恢复成功。
6. 在已同步工作区基础上，可按需导入本地 DSH 会话元数据；Relay 会话列表出现 DSH 历史会话，字段至少包含 `id/workspace_id/provider=dsh/status`，不含路径、消息摘要或任何正文。
7. 主页左上角出现 DSH 模式/模式切换入口；切换后会话列表按 DSH 工作区进行分组展示。
8. 扫描和导入只能由 owner/write 端对已配对 Terminal 显式触发；Daemon 不持有 owner bearer，也不在启动时静默枚举/上传路径。
9. 新增 `task test:v08:local`（fixture/local）与 `AGENT_SESSIONS_DSH_REAL=1 AGENT_SESSIONS_DSH_PROVIDER=opencode-zen AGENT_SESSIONS_DSH_MODEL=nemotron-3-ultra-free task test:v08:real`（真实 DSH 会话，需用户授权）入口；Zen 测试池为 `nemotron-3-ultra-free`、`nemotron-3.5-lightning-free`、`ling-3.0-flash-fin-free`、`mimo-v2.5-free`，每个模型最多额外重试 5 次；可识别的 `429 FreeUsageLimitError` 按本迭代约定记为通过，并在报告保留“未验证模型回复/恢复”的风险；`task check` 通过。
10. 每个阶段一个 commit，业务逻辑中文注释完整，关键链路回填 `docs/zh/项目文档.md`。

### 2.3 明确不纳入

- 批量把本地 DSH 历史 transcript 或最近消息摘要导入 Relay。显式 `session.load` 的逐条回放是用户发起的 E2EE 事件流，不属于扫描/导入元数据。
- Android 实机 / AVD / Push / 后台恢复。
- 修改 DSH 上游源码。
- 生产多机、分布式部署、新增外部基础设施。
- 改变 E2EE 边界与密钥层级。
- 在本期实现通用 `allow-once` 权限策略、附件回放或未映射的 `tool_call`/`tool_call_update`。这些能力必须保持 truthful，不得继续以 native 名义暴露。
- 没有 Git 根或没有 `.dsh-sessions` 有效 artifact / `session-query.db` 证据的目录。它们只能记录为“未纳入本期”，不得因扫描顺手创建 Git 仓库或猜测其属于 DSH。

## 3. 基线与前置门

### 3.1 当前事实

- DSH 适配器：`internal/adapter/dsh/` 已实现 per-session ACP stdio 子进程、Start/Send/Abort/ForceKill、事件白名单映射、Resume/回放和持久化根所有权；真实模型恢复仍待 P4 gate。
- DSH 本地工作区：旧 DSH checkout/旧桥根和工作区根都可能存在 `.dsh-sessions/**/session.jsonl`；`session-query.db` 可作目录标记或加速索引，但不是会话事实来源，JSONL 才是。
- Relay：`POST /v1/sessions` 创建会话，`POST /v1/sessions/{id}/commands` 下发 `session.start/send/resume/...`；Daemon 本地 `instance:<sessionID>` 保存 Provider InstanceID 与 workspace root。
- Resume：`SessionRunner.resumeSession` 已在 load/resume 前接管新 handle，并在回放事件排空后推进本机状态；无旧 handle 的重启 fixture 已覆盖。
- 权限：仓库根 `cordis.yml` 已把 approval policy 改为 `never`；DSH 侧在交互分发前拒绝此类请求。
- Sandbox：DSH `sandbox-policy` 对正常会话优先使用不可变的 `session.header.cwd`，`DSH_SESSION_CWD` 仅作为无会话/cwd 的回退根；P0 已让回退根与客户端工作区一致，工具 `pwd` 仍需真实 gate 复核，不能仅按桥 `cmd.Dir` 推断。

### 3.2 开工前置门

- `task check`、`task test:relay`、`task test:daemon`、`task test:e2e:relay`、`task test:contract` 通过。
- 本机 DSH checkout 可用，且 `AGENT_SESSIONS_DSH_BIN` / `AGENT_SESSIONS_DSH_CONFIG` 能指向真实 `dsh-acp-demo` 与本地 `cordis.yml`。
- 以显式授权根运行 `node e2e-verify/real/dsh-v08-preflight.mjs`，生成仅本机可见的旧持久化根清单、会话数、压缩格式、header 校验与冲突摘要；迁移只复制/合并，不删除源文件。此步骤完成前不得宣称 G3/G4 可用。
- 用户确认授权范围：允许读取指定授权根下的 `.dsh-sessions` 元数据，并在真实 DSH 会话上执行恢复/继续测试。
- 真实 DSH 测试通道冻结为 `opencode-zen`，默认模型和测试池为 `nemotron-3-ultra-free`、`nemotron-3.5-lightning-free`、`ling-3.0-flash-fin-free`、`mimo-v2.5-free`。每个模型最多额外重试 5 次；随后收到可识别的 `429 FreeUsageLimitError` 时视为 Zen 路由和模型选择的接受证据，测试结果记为 `passed` 且 `pass_reason=zen_quota_accepted`；它不证明回复、回放或恢复后继续发送，报告必须明确这些残余风险。

### 3.3 开工前冻结决策

- **扫描范围。** v0.8 只支持“授权根内、已有 DSH 持久化证据、且自身是 Git 根”的项目。`session-query.db` 仅是证据，JSONL / JSONL.zstd 才是会话事实；非 Git 或空项目在扫描结果中给出脱敏跳过计数，不能隐式纳入 G1。
- **Terminal 归属。** 同一 `account + terminal + canonical workspace root` 才是一个可操作的 DSH Workspace identity；Relay Workspace 与其导入的 Session 都不可变地绑定 `home_terminal_id`。其他 Terminal 只能查看安全投影，不能投递 `resume`、`send`、导入或重新扫描；未在线时返回 `WakeTerminalOffline` / 可观察的 unavailable 状态，不得路由到“同路径”的另一台机器。
- **迁移冲突与并发。** 按 header 的 session id 聚合：相同 artifact digest 可幂等合并；同 id 但不同 digest、同 id 同时存在 `.jsonl` 和 `.jsonl.zstd`、未知压缩或 header 与路径不符均标为冲突并阻断该 session 的迁移/导入/恢复。复制前后重新采样源文件 size、mtime 与 digest；任一变化标 `migration_source_changed`，不写目标，等待 DSH 空闲后重跑。
- **回放状态。** `replay_history` 不进入客户端可控 payload 或公共协议。Daemon 为每个导入 Relay session 维护本机 `pending | loading | complete` 状态；`pending`/崩溃遗留的 `loading` 调 DSH `session/load`，仅 `complete` 调 `session/resume`。导入时创建 `pending`，每条回放事件成功写入本机加密 outbox 后才推进 checkpoint，全部提交后才转为 `complete`。

## 4. 关键设计

### 4.1 统一 DSH 持久化根

- 不再依赖 `process.cwd()` 推导会话存储根。桥的 `cmd.Dir` 继续可为 DSH checkout（供插件/`.env` 解析），但它与 DSH 会话的 `cwd`、持久化根必须分离。
- 将 bridge 的根目录来源建模为显式所有权，而不是一个可随意删除的字符串：
  - `Start`/`Resume` 拿到非空、canonical `WorkspaceRoot` 时，`sessionRoot` 固定为绝对 `<workspaceRoot>/.dsh-sessions`，`cleanup=false`；`minimalEnv` 必须注入这个**精确根**，不得再追加临时 `sessions/` 子目录。
  - `Detect` 无工作区时才创建 bridge 自己拥有的临时根，`cleanup=true`；关闭后只能删除这个已标记为临时且由本次 bridge 创建的目录。
  - `AGENT_SESSIONS_DSH_PERSIST_ROOT` 仅保留给受控测试/取证；不得静默覆盖带 `WorkspaceRoot` 的生产 Start/Resume。若保留显式覆盖，必须另有测试开关并在报告中标注隔离模式。
  - `cleanupPersistRoot` 要按所有权标记和 canonical 路径双重守卫；任何工作区根、其 `.dsh-sessions` 或父目录都不得成为 `os.RemoveAll` 目标。
- 同步修改仓库根 `cordis.yml`（以及 fixture 配置）：
  - `persistenceRoot: !!js "process.env.DSH_SNAPSHOT_SESSIONS_ROOT ?? (process.cwd() + '/.dsh-sessions')"`
- P0 的迁移是 G3/G4 的硬前置，而非“是否合并”的交互选项：
  - 先枚举旧 DSH checkout 根、旧 bridge 根和已发现工作区根；按 JSONL 中的 `cwd` 归属到 canonical workspace，而不是按目录名猜测。
  - 对匹配 workspace 的历史会话按 DSH JSONL backend 的 `projectDir(root,cwd)/sessionDir(root,cwd,id)/session.jsonl[.zstd]` 物理布局复制/合并，并校验首行 header 的 id/cwd 与目标路径一致；保留源文件、记录本机校验摘要和冲突。不能匹配的记录保留在只读 legacy-root 清单中，供后续显式处理。
  - `session-query.db`、WAL/SHM 是派生查询索引，不复制/合并为事实；切根后由 DSH 重建。迁移必须保留当前 `persistenceCompression` 对应的 artifact 后缀，遇到双编码或未知 layout 直接 fail-closed。
  - 迁移前后采样源 artifact 的 size、mtime、SHA-256；源文件在复制期间发生变化时不生成目标文件。相同 session id 仅在 digest 相同才可幂等合并，任一不同 digest / 双编码 / header-path 不一致均保留源、记录冲突并阻断该 session。
  - 迁移完成前，Resume/导入可在受控的 legacy-root 列表中只读查找；不允许扫描任意 DSH checkout。源目录不删除，回滚只需切回清单中的原始根。
- Sandbox 验证不以 `cmd.Dir` 为准：P0 真实桥用 `session/new.cwd=<workspaceRoot>` 执行 `pwd`/受控 `ls`，确认工具会话根与 session cwd 一致。当前 DSH 的 session policy 已优先采用该 cwd；在把 sandbox 收紧为非 `danger-full-access` 前，必须补同一断言。

### 4.2 DSH Resume 支持

- **先补 SPI/Runner 的流式句柄交接，再实现 DSH Resume。** 新增可选 `ResumeStreamingAdapter`（名称可调整，但时序不可调整）：adapter 在 bridge initialize 成功、事件流已建立、但尚未发送 `session/load`/`session/resume` 前，向 Runner 交出 `Handle` 的 ready callback。`ResumeResult` 保持可 JSON 持久化，不能把 runtime `Handle` 塞进 Relay/store。
- `SessionRunner` 在 ready callback 内原子完成：回收同 Relay session 的旧 handle → 登记新 handle → 绑定该 `session.resume` command → 启动 `forwardEvents`；然后 adapter 才能发 load/resume 请求。这样历史帧不会落在“Resume 返回后才订阅”的窗口，也不会因目前 256 条有界 channel 在回放前无人消费而丢失。
- Resume 模式必须显式，不按 UI 时机猜测：不新增客户端字段或重复 command kind；Runner 从本机、可审计的回放状态构造内部 `ResumeRequest.ReplayHistory`。
  - 导入后及崩溃遗留的 `pending` / `loading` 调用 DSH `session/load`；只有持久化 checkpoint 已完整提交的 `complete` 调 `session/resume`。
  - `session.load`/`session.resume` 都传 `sessionId`、canonical `cwd`、`mcpServers: []`、空 `additionalDirectories`；非空 MCP/目录继续 fail-closed。
  - DSH 的 load 响应在 `replaySession` 结束后才返回，因此“收到 load 响应”是本轮回放完成信号，不伪造 `turn_completed`。
- `replay_history` 固定为 Runner → Adapter 的内部 typed 字段及本机状态，不能作为未校验 map 字段透传；v0.8 不修改公共协议。若后续确需客户端可见状态，必须另行升级 `packages/protocol` 类型和契约。
- 回放映射和幂等规则：
  - `user_message_chunk` 映射为 `adapter.EventUserMessage`，`agent_message_chunk` 映射为 `EventMessageCompleted`；两者只接受 text content，保留 DSH 发送顺序。
  - 上游 replay 帧不带稳定 `messageId`，因此 Runner 为同一 Relay session 的回放序号生成 `SHA-256("dsh-replay-v1\\0" + relaySessionID + "\\0" + ordinal)` source key；该 key 只用于本机回放标记并生成稳定 outbox `event_id`，不进入事件正文/导入元数据，也不暴露原始 DSH id。重复 load、断线重试、回放超过 channel 容量均不得重复或丢失历史消息。
  - 回放 checkpoint 只能在对应事件已持久化进本机 outbox 后推进；半途崩溃后允许重放，但必须靠上述 source key 收敛。
- `cwd` 是恢复契约的一部分：若存储记录的 cwd 与当前 canonical workspace 不一致，分类为 `WakeWorkspaceMoved`，不创建/登记 handle、不尝试改写 JSONL。存储不存在、版本不兼容或桥错误仍按明确的 fail-closed 结果/错误上报。
- DSH adapter 成功后返回 `WakeResumed` 与 DSH session id，并复用同一 handle 的 `Send`、`Abort`、`Dispose`。Runner 的 resume 后 send 回归必须覆盖 Daemon 重启且无旧 handle 的情形，而不是只验证存活 handle 未变。
- 更新能力矩阵：仅在上述 ready/转发/继续发送链路完整时把 `resume` 从 `unsupported` 改为 `native`，并同步 ADR-013、`docs/test/16-Adapter-Dsh.json`、`internal/adapter/provider_truth_test.go` 与相关单测/契约。

### 4.3 现存工作区同步与会话按需导入

**本迭代核心：先把授权根内、符合本计划判定规则的本地 DSH 工作区同步进来。**

- **触发与鉴权。** 不在 Daemon 启动时自动全盘同步。Flutter owner/write 端的“刷新 DSH 工作区”显式提交 `workspace.sync_dsh`（名称可调整）到选定在线 Terminal；Relay 复用 v0.7 `workspace.create` 的 owner/write、账号、目标 Terminal、capability、签名和幂等 fence，并新增独立 capability。Web 只读端只能查看已同步结果，不能发起扫描/导入。
- `workspace.sync_dsh` 和会话导入属于 workspace 级控制命令：协议/Daemon store/本机 delivery 校验必须像 `workspace.create` 一样显式允许其没有普通 `session_id`，但仍要求目标 Terminal、专用 capability 和受控 request scope；不得为了接入扫描而放宽通用命令的 session/workspace 校验。
- **结果回传。** 不能让 Daemon 直接拿 owner bearer 调 Relay 的创建接口。新增与 `workspace-result` 同等级的受控、签名 daemon result 链路：Daemon 只在本机确认后上传候选的 canonical root，Relay 在同一事务创建/确认 opaque Workspace 并回传对应 ID；绝对路径不出现在客户端响应、普通 command、日志或报告。会话元数据导入同样走 owner 发起、Terminal 签名的专用结果链路，而不是 Daemon 冒充 owner 创建 Session。
- **Terminal 归属与可用性。** `workspace.sync_dsh` result 必须携带不可变的 source Terminal，Relay 以 `account + terminal + canonical root` 幂等创建/确认 Workspace，并把其 `home_terminal_id` 继承给导入 Session。所有写命令再次校验该归属和 online lease；跨 Terminal 查看只投影“可见但不可在当前 Terminal 恢复”，不泄露 canonical root，也不能借同名路径绕过 fence。
- 新增 Daemon 侧 `DSH Workspace Scanner` 与 `ConfirmExistingDSHWorkspace` 边界：
  - 扫描的唯一根是 canonical `AGENT_SESSIONS_WORKSPACE_ROOT`，已有目录只确认、不 mkdir、不 `git init`、不删除；它不能复用只支持“授权根直接子目录”的 `WorkspaceManager.Create`。
  - 候选必须有 `<project>/.dsh-sessions`，且其中存在有效 DSH JSONL artifact 或 `session-query.db` 标记，并且自身是 Git 根；Git 根绝不能单独使任意 Git 仓库入选。标记但非 Git 的目录不自动修改，记录为跳过原因。
  - 只接受 canonical 后仍位于授权根内的目录；不跟随符号链接；跳过 `.git`、`node_modules`、`.dsh-sessions` 内容和其他隐藏目录。扫描深度上限 4、候选上限 1000，达到上限必须有可见的本机诊断/失败状态，不能悄悄截断。
  - 同一 canonical root 在同一 account + Terminal 内稳定映射一个 Workspace；路径重名不作为 identity。重复 refresh、重放 result 与并发请求不得创建重复 Workspace。
- 工作区同步完成后，再由 owner 明确请求会话按需导入（次要）：
  - 只扫描已确认 workspace 及其已批准 legacy roots 下的 `.dsh-sessions/**/session.jsonl`；`session-query.db` 仅可加速，不能阻碍 JSONL 扫描。
  - 先验证 JSONL session id、记录 cwd 和 canonical workspace 一致；解析失败、cwd 不一致、越权路径或格式漂移都跳过并计数，不以文件名推断归属。
  - Relay 导入白名单仅为 opaque Relay session id、`workspace_id`、`provider=dsh`、状态、创建/更新时间、模型/预设的安全元数据；DSH session id、canonical cwd、文件路径和 storage locator 仅保留在 Daemon 本机映射中。
  - **不提取最近消息摘要、prompt 或回复正文。** 为未导入记录创建 `provider=dsh` 的 Relay Session，在 Daemon 本地写 `instance:<relaySessionID>`（`InstanceID = DSH session id`、`WorkspaceRoot = canonical cwd`）。
  - 幂等 identity 为 account + Terminal + canonical workspace + DSH session id；历史根迁移和重复扫描均不得创建重复 Relay Session。

### 4.4 客户端展示与恢复

- Flutter/Web 工作区列表能显示同步来的 DSH 本地工作区；会话列表能显示已导入的 DSH 历史会话，无需新增公共协议字段。
- 进入历史 DSH 会话详情时：
  - 若 Daemon 本地已有 instance 映射，则按本机 replay state 选择 `session.load` / `session.resume`；无运行中 handle 时也必须由 Resume ready callback 先登记/订阅，再发桥请求。
  - `session.load` 的用户和助手消息作为用户主动恢复产生的既有 E2EE canonical event 进入 Relay；它不同于扫描/导入，不把正文写入 Session 元数据、诊断或报告。
  - 首次回放完成前显示恢复中；load 响应到达后才允许该 UI 状态结束。已经有 checkpoint 的会话改走不回放的 `session.resume`，避免重复时间线。
  - Workspace / Session 的 `home_terminal_id` 不等于当前可操作 Terminal 或该 Terminal 离线时，列表仍可只读显示安全元数据，但恢复、发送、导入与刷新按钮禁用并显示 unavailable；不得尝试跨 Terminal 路由。
- 命令面保持既有 `session.resume`、`session.send`、`session.abort`、`session.kill` 语义，不新增重复命令。

### 4.5 与 `approval.policy: never` 对齐

- `policy: never` 的预期是 DSH `user-approval` 在 ACP request-permission waterfall 前直接决定为 `rejected`；P1 真实/契约测试应断言 Agent Sessions 不收到 `session/request_permission`，并记录这一事实。
- 保留 `handle.go` 对意外 `session/request_permission` 的 `cancelled` 回包及事件，仅作为不可达的 fail-closed 后备；不得在本期新增“never 时 allow-once”配置。`allow-once` 只可能在将来 `ask` 策略和独立授权设计中讨论。

### 4.6 ACP 能力边界与 truthful 状态（基于 `/Users/yubi/code/deepseek-harness`）

当前本地 DSH 的 ACP 桥公开能力与 Agent Sessions SPI 的兼容关系如下：

| DSH ACP 能力 | 当前 Agent Sessions 状态 | v0.8 目标 |
| --- | --- | --- |
| `initialize` / 版本门 | 已兼容（协议版本 1） | 保持 |
| `session/new` | native | 保持 |
| `session/load`（回放历史） | native（假桥/Runner 契约已通过） | 真实桥回放与模型链路由 P4 复核 |
| `session/resume`（不回放） | native（假桥/Runner 契约已通过） | 真实桥恢复后继续 send 由 P4 复核 |
| `session/set_config_option`（model/effort） | `model_select` 名义 native 但尚未真正下发；`effort_select` unsupported | 本期先将未下发能力降为 truthful `unsupported`；真正 `set_config_option` 下发另立迭代 |
| `session/prompt` | native | 保持 |
| `session/cancel` | native | 保持 |
| `session/request_permission` | 仅有 fail-closed 后备 | `policy: never` 下验证不上报；保留 `cancelled` 后备，不自动放行 |
| `session/update` 的 `agent_message_chunk` | native（映射为 message_completed） | 保持 |
| `session/update` 的 `user_message_chunk` | native（映射为 `user_message`） | 保持并纳入 load 回放断言 |
| `session/update` 的 `usage_update` | native | 保持 |
| `session/update` 的 `tool_call` / `tool_call_update`（需 `toolUpdates: true`） | 当前白名单未映射 | 本期保持 unsupported/不投影，另立迭代；不得以 UI 假事件替代 |
| 图片/附件（`promptCapabilities.image`） | 当前 DSH 探测为 false；adapter 标 unsupported | 若 DSH 配置/附件存储可用则补 attachments |
| `session/list` | 不存在 | 不依赖 ACP；用本地 JSONL 扫描替代 |
| `file_read` / `git_read` / `plan` / `goal` / `skill_catalog` / `invoke_skill` / `question` / `fork` / `delegate_*` | DSH ACP 未暴露这些 wire 方法 | 保持 unsupported，不伪造 |

结论：v0.8 的承诺是安全的工作区同步、持久化和 Resume 闭环，不是把 DSH ACP 的全部 UI 能力一次性搬进 Agent Sessions。除 Resume/回放外，尚未实际下发或映射的能力应立即降为 truthful 状态；DSH 内部未由 ACP 暴露的能力一律保持 fail-closed。

### 4.7 主页 DSH 模式与会话按工作区分组

- 主页左上角增加 DSH 模式入口：
  - 优先做一个明确的“DSH 模式”按钮/开关；
  - 至少也要提供一个模式切换按钮，让用户能从普通模式切到 DSH 模式。
- DSH 模式下的会话列表：
  - 按已同步的 DSH 工作区（项目目录）分组；
  - 每个工作区作为分组头，下面展示该工作区下的 DSH 会话；
  - 空工作区也保留分组或提示，避免用户以为丢失。
- 普通模式保持现有“最近会话/全部会话”视图，不被 DSH 分组破坏。
- 优先兼容 DSH 模式：第一版可以把 DSH 模式作为默认/优先视图，先保证 DSH 工作区和会话可用，再完善普通模式。

- 仅 owner/write Flutter 端显示刷新/导入动作与 pending/failed 状态；Web 只读端和无 capability 的 Terminal 不显示可执行入口。
- 列表渲染、切换分组或只读浏览绝不隐式触发扫描、导入、`session.load` 或模型请求。用户打开历史会话并明确恢复时才会产生回放。

## 7. 风险与回滚

| 风险 | 影响 | 对策 |
|---|---|---|
| DSH `session.load` / `session.resume` 行为不稳定 | 恢复链路不可用 | 以真实桥契约测试为准；失败按 `provider_contract_failure` 分类，不伪造 resumed |
| Zen 免费额度耗尽 | 无法拿到模型正文 | 固定 `opencode-zen` 四模型池，每个模型最多额外重试 5 次；可识别的 `429 FreeUsageLimitError` 按本迭代测试约定通过，报告写明仅证明路由/模型选择，回复、回放和恢复后 send 仍待验证 |
| Resume 只返回状态、不交接 handle | 恢复后 send/事件流失效 | 先落地 ready callback/Runner 登记与 forward，再把 resume 标 native；Daemon 重启 fixture 必测 |
| 回放在订阅前发出或超过缓冲 | 历史丢失/重复 | 先注册转发再 load，使用稳定 source key、outbox checkpoint 和重放去重；注入大于缓冲容量的 fixture |
| 本地 `.dsh-sessions` 数据量大/格式变化 | 扫描慢或解析失败 | JSONL 为事实来源；单文件失败跳过并计数，深度/候选上限和忽略目录可观测 |
| 误把无关目录同步为 Workspace | 越权/隐私泄漏 | DSH 标记为必要条件、Git 根仅附加校验；canonical root、非跟随 symlink 和授权根边界三重检查 |
| 未授权触发扫描/导入 | 本机路径和会话元数据被上传 | owner/write、账号、指定 Terminal、capability、签名和幂等 fence 全部复用 v0.7 确认链路；Daemon 不持 owner token |
| 现存工作区映射冲突（同名/移动路径） | Workspace 归属错乱或恢复失败 | 以 canonical root 为准做幂等；cwd 移动返回 `WakeWorkspaceMoved`，不改写历史；由用户确认迁移/重建映射 |
| `policy: never` 被误解为自动批准 | 安全边界被放宽 | 断言批准请求在 DSH 侧直接 rejected、ACP 不上报；adapter 后备恒 cancelled，不实现 allow-once |
| 旧 DSH 版本无 load/resume | 恢复失败 | 版本门继续生效；低版本时 `resume` 保持 unsupported，不回退为伪装成功 |
| 迁移/切根导致历史不可见或丢失 | 用户历史会话无法恢复/导入 | P0 强制生成 legacy-root 清单；按 cwd 复制/合并或只读查找，源文件不删除，回滚可切回原根 |
| 同一 Workspace 在其他 Terminal 被误恢复 | 错误机器执行、错误本机状态或路径混淆 | `home_terminal_id` 不可变绑定、所有写命令重复校验、跨 Terminal 仅只读 unavailable |
| 迁移期间 DSH 继续写 JSONL | 半份 artifact 被导入或覆盖 | 复制前后比对 size/mtime/digest；改变即 fail-closed，不写目标，等待 DSH 空闲重跑 |

## 8. 凭据与安全

- 不读取、不转储 DSH 的 `~/.dsh/.credentials.yaml` 或任何 LLM key；凭据由 DSH 侧配置/环境承载。
- 本地 `.dsh-sessions` 的 JSONL 含明文对话，只在获授权的 Daemon 本机解析；扫描诊断仅记录 artifact 数量、错误类别、压缩计数和不可逆校验摘要（哈希），不记录路径、正文或 DSH session id。

| 数据路径 | 允许进入 Relay 的内容 | 明确禁止/限制 |
| --- | --- | --- |
| 工作区同步 | 专用签名 result 内的 canonical root 仅供 Relay 内部登记 opaque Workspace；客户端只见安全 Workspace 投影 | 路径不得进入普通 command、列表响应、日志、报告或 Web 页面 |
| 会话按需导入 | `workspace_id`、provider、状态、时间、模型/预设等安全元数据 | 不生成或提取最近消息摘要；`cwd`、DSH session id、storage locator、prompt、回复正文均留在 Daemon 本机 |
| 用户显式 `session.load` 回放 | 既有 E2EE canonical event envelope；稳定 source key 仅作为去重标识 | 不得写进导入元数据、明文 Relay 字段、诊断或报告；不因列表浏览自动触发 |
| 存量迁移 | 仅本机复制/合并和校验摘要 | 不删除源文件，不把 JSONL 正文或文件路径上传 |

- 真实 DSH 会话恢复/继续测试前必须向用户说明会读取本地历史并可能触发模型请求；缺少授权时保留 blocked/failed 证据，不标绿。已授权的固定 Zen 通道命中 `429 FreeUsageLimitError` 时，按本计划的测试口径标绿并保留受限证据说明。
