## 1. 目标与明确排除项

**核心目标**：把 Android 唯一写控制端做成“能完成 Happy 移动端同一套编码会话工作”的客户端。v0.1 已交付列表、时间线、permission/question、Plan/Goal/Skill、附件队列、Git DiffView、Delegation 和生命周期恢复；v0.2 补齐会话页里仍缺的完整会话能力，并把真实 OpenCode 会话接到这条控制链路上。

Happy 对照基线只读固定提交，不兼容 Happy wire protocol、Socket.IO 或官方客户端。

**明确排除**：

- 实时语音、Inbox/Friends/社交 feed、付费、远程 shell、Git 写操作
- Happy wire protocol / 官方客户端兼容
- Android AVD / 真机 / UnifiedPush 原生验收（延后，不阻塞 MacBook gate）
- 用 CLI smoke、fixture 或 UI 假能力冒充真实 Provider 已贯通

## 5. 数据、权限、错误和事件边界

- OpenCode session ID 只作为本机加密 ProviderThread，不进 Relay 白名单或 Flutter 卡片正文
- Detect 与 Start/Resume 必须一致：未探测成功或方法不可用时全部 `unsupported` 并给中文原因
- Resume 只允许 `resumed` / `restarted_with_context` / `unsupported`（及已有六态中的失败态），禁止伪装 `resumed`
- 文件浏览只读，走 Workspace 路径校验；不提供 shell 或 Git 写
- usage/context 只展示脱敏计数，不写 prompt/回复
- 选附件仍先本机 MIME/大小校验，再 DEK 密封分块；无 DEK 时按钮保持禁用

## 7. 退出条件、阻塞和残余风险

**退出**：Happy 对照表中标为 v0.2 处理的会话能力均有测试与可见证据；OpenCode Detect/Start/Send/Abort/Resume 与能力矩阵一致；Flutter 会话页能按 capability 展示 resume/文件/模型/usage，并在授权 live 下证明 Adapter 而非仅 CLI；headed Web 能力矩阵可见真实探测结果。

**阻塞**：本机 OpenCode 服务不可发现或凭据缺失时，P1 live 标 `blocked`，契约仍须 fail-closed 通过。

**残余风险**：Claude/Codex/OpenClaw 仍无专属凭据；Android 真机与系统 Push 延后；语音/社交保持排除。
