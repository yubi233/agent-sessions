## 1. 目标与验收标准

### 目标

1. 在阿里云 ECS 上部署可重复恢复的 Relay + SQLite 验收环境，并通过公网 HTTPS 提供 Android/Web/Admin 所需入口。
2. 验证真实网络下的认证、配对、设备撤销、会话快照、REST 命令、账号级 SSE、断线恢复和 SQLite 持久化。
3. 使用一台真实、已授权的 Android 手机完成物理设备 integration gate；结果不得由 AVD、macOS Flutter 窗口或本地 fixture 代替。
4. 在明确授权、额度和停止点后，再单独验证真实 Provider；Provider smoke 不得冒充 Android 全链路通过。
5. 形成可审计的部署、回滚、备份恢复、测试报告和残余风险清单。

### 放行标准

- 云端 `healthz`/`readyz`、TLS、域名、日志脱敏、进程重启和数据卷持久化通过。
- `P0-DEPLOY-01`、`DEPLOY-01`、`DEPLOY-02`、`DEPLOY-03` 与 `SYNC-04` 达到本计划要求；未授权的签名/上传项保持 `blocked`，不能标绿。
- Android 真机报告包含 `real_device=true`、`simulated_device=false`、`headless=false`、设备型号/Android 版本、应用版本、云端 endpoint hash 和完整 case 结果。
- 至少一条真实公网链路完成：Android 登录/配对 → 会话读取 → SSE 更新 → 命令提交 → 结果/终态 → 断线重连；若 Daemon 或 Provider 未授权，明确标记对应缺口。
- 所有失败均按 `product_defect`、`test_harness_defect`、`environment_or_startup_failure`、`credential_or_quota_blocker` 等既有分类归档，并保留脱敏证据。

> **TLS 降级决策（2026-09-14，用户明确接受）**：验收环境无域名，放行标准中的"域名"项以裸 IP + 自签证书执行；证书 SHA-256 指纹记入验收配置与报告，客户端按指纹显式放行，禁止"信任所有证书"的实现进入默认代码路径。明文 HTTP 仍被禁止。该降级必须写入每份报告的 `remaining_risk`。

## 2. 范围、拓扑与明确排除项

### 默认验收拓扑

```text
真实 Android 手机 ──公网 HTTPS──> 阿里云 ECS（TLS 入口 + Relay + SQLite 数据卷）
                                      ▲                         │
                                      │ HTTPS REST/SSE           │
                              测试 PC 上的受控 Daemon ────────────┘
```

- ECS 首阶段承载 Relay；测试 PC 承载有隔离 Workspace 的 Daemon，避免未经确认就把本机代码目录暴露到公网。
- ECS 的 8787 只允许本机或反向代理访问；公网仅开放 SSH（限定来源）和 HTTPS，HTTP 只用于 ACME 或重定向（若采用该方案）。
- 生产域名、生产数据、真实用户账号、签名私钥、Android release key、备份 Bucket 和真实 Provider 均需单独授权。
- 当前仓库 Compose 只有 Relay + SQLite；TLS 反向代理、云端 secret 注入、备份目标和监控需在实施阶段补齐，不能假设已经存在。

### 不在本轮默认范围

- 不执行远程 shell、Git 写入、Web/Admin 写控制或破坏性数据库迁移。
- 不把 `task test:android:device` 现有 fixture 结果称为真实云端闭环；需增加云端 endpoint 配置和真实链路用例。
- 不因 HTTP 200、截图、headless 或 AVD 通过就宣布 full gate 通过。
- 没有 Provider 凭据、额度和用户授权时，不发送真实模型请求。

## 4. 测试方法

### 4.1 本地根因与发布前检查（`local_test=true`）

先运行仓库已存在的真实入口，避免凭空创建命令：

```text
task docs:verify
task check
task test
task test:android
task test:e2e:relay
task test:deploy
```

必要时再运行 `task test:e2e`（headed Chrome）和 `task test:v04:perf`。这些结果证明本地契约、fixture、浏览器或发布脚本行为，不证明公网、真机或真实 Provider。

### 4.2 阿里云部署 smoke（`smoke`）

从部署机和外部客户端分别执行：

1. SSH 只做只读预检：系统架构、Docker/Compose 版本、磁盘、时间同步、监听端口、目录权限和可用磁盘空间。
2. 部署固定 image digest；注入最小环境变量，禁止把 token/密钥放在命令行、日志或报告中。
3. 检查 TLS 证书链、域名、HSTS/安全响应头（按实际代理能力）、`healthz`/`readyz`、容器重启策略和日志脱敏。
4. 以测试账号执行登录/设备 bootstrap/配对；检查设备列表和撤销即时生效。
5. 建立账号级 SSE，验证初始 snapshot、事件到达、`Last-Event-ID`/`after_seq` 恢复和重复连接不丢事件。
6. 重启 Relay 容器，验证 SQLite 中会话、命令、lease、事件和撤销状态仍在；不得把进程内 presence 当作持久化真相。

### 4.3 定向诊断（`targeted_diagnostic`）

每次只针对一个故障假设，保留最小复现：

- 网络：Wi-Fi/4G 切换、短暂断网、DNS/TLS 失败、SSE 重连和 cursor 回放。
- 一致性：重复 `command_id`/`event_id`、旧 lease epoch、设备撤销后的迟到请求、Relay 重启中提交。
- 安全：匿名写请求、Web/Admin 写请求、错误 token、过期 token、错误签名、公开 8787 探测。
- 数据：备份后恢复、迁移前后事件序号/撤销/密文 envelope 校验、磁盘空间告警。

### 4.4 Android 真机测试（`real_device=true`）

真机测试在连接手机的测试 PC 上运行，ECS 只提供后端 endpoint。先执行已有 runner 的纯 Node harness 回归，再新增/配置云端 endpoint 的 integration runner；不把本地 fixture URL 写死。

**设备前置**

- `adb devices` 只有目标真机处于 `device`；排除 `emulator-*`，复核 `ro.kernel.qemu` 为空或 `0`。
- 手机已解锁、允许 USB 调试/安装、时间自动同步，记录型号、Android API、厂商电量/后台策略。
- 测试开始前保存设备网络、系统动画、电池优化和通知权限状态；结束时恢复临时改动。

**P0 用户旅程**

1. 安装候选 APK，打开云端 HTTPS 地址，完成 owner bootstrap/登录和配对。自签证书按指纹放行；放行实现仅存在于 acceptance 配置或构建变体（如内嵌验收 CA/指纹的开关），不得削弱默认构建的证书校验。
2. 查看 terminal/project/workspace/session；建立会话并接收账号 SSE/会话 snapshot。
3. 提交允许的控制命令，验证 pending → ack/result → canonical event → 终态投影；检查重复点击不会重复执行。
4. 锁屏/切后台、断开 Wi-Fi 切到移动网络，再恢复前台；验证 cursor 恢复、草稿和命令状态不重复/不丢失。
5. 在服务端撤销设备，确认手机在一个心跳/请求周期内 fail-closed；重新配对后才恢复。
6. 通过刷新、进程重启和重新登录验证最小缓存只保留密文 envelope/cursor，不出现 token、私钥、会话正文或 diff。

**真机视觉与可用性**

- 至少覆盖窄屏、系统深色、200% 字体、软键盘、横竖屏（若产品允许）、TalkBack 基础焦点和错误/空/加载态。
- 录屏只展示脱敏测试数据和状态，不录制真实 token、恢复码、会话正文、diff 或附件。

### 4.5 真实 Provider（可选授权 gate）

按 `smoke → targeted diagnostic → full gate → recording` 顺序执行。执行前报告 provider/model、预计请求次数、token/费用上限、凭据来源类别和停止点；只通过受限环境变量注入凭据。真实 Provider 失败必须保留 `provider_http_error`、`provider_timeout`、`model_contract_failure` 或 `credential_or_quota_blocker`，不能用重试掩盖。

**已授权范围与关键事实（2026-09-14 用户裁决）**

- Provider 为 **DSH（主）**，走 **openai 渠道**，模型 `gpt-5.6-terra`；不限制用量。
- **DSH 不需要任何 API KEY**：渠道与凭据由 DSH/ACP 自身配置解析。本仓库、验收环境与测试脚本都不得为 DSH 注入、要求或误报凭据缺失；`credential_or_quota_blocker` 分类不适用于 DSH。codex 使用其自身登录态，另行验证。
- 授权验收场景（即停止点）：先经 DSH 全量跑通一个完整的 **Vue hello world**，确认生效后，再**改造为计算器应用**；两个场景都通过即视为 Provider gate 通过。

## 6. 凭据、SSH 与环境输入清单

环境输入统一填写在 `deploy/acceptance.env`（已被 `.gitignore` 忽略，权限 600，禁止提交）；字段模板见 `deploy/acceptance.env.example`。私钥/密码/token 只写值本身或本地路径，不得出现在文档、日志、截图或测试报告中。请在实施前通过安全渠道提供或确认以下信息：

- ECS 公网 IP/域名、区域、架构（x86_64/arm64）、OS、SSH 端口、登录用户、SSH key 的本地路径或 agent 名称、是否具备受限 sudo/Docker 权限。
- 安全组/云防火墙规则：SSH 来源 IP、HTTPS 端口；确认 8787 不直接公网开放。
- DNS/TLS 方案（Caddy/Nginx/ALB 之一）、证书签发方式和续期责任。**已决策（2026-09-14）**：无域名，采用裸 IP 自签证书（`AGENT_SESSIONS_ACC_TLS_MODE=self-signed`），客户端按证书指纹显式放行（`AGENT_SESSIONS_ACC_TLS_BYPASS_CONFIRMED=true`，指纹记录于 `AGENT_SESSIONS_ACC_TLS_FINGERPRINT`）；自签证书无外部续期责任，轮换在验收环境内自行管理。
- Relay/SQLite 数据卷路径、备份目录或 OSS 目标、保留周期、是否允许恢复演练。
- 测试环境密钥的注入方式（受限 `.env`、secret manager 或 CI secret）和测试账号；不使用生产账号。**DSH Provider 例外：不需要任何 API KEY，渠道由 DSH/ACP 自身配置解析，不得为其准备或注入凭据。**
- 是否允许部署测试 Daemon、测试 Workspace、真实 Provider，以及 Provider 名称/模型/额度/停止上限。
- Android 手机型号、Android 版本/API、ADB serial、USB 调试/安装权限；执行 Flutter/ADB 的测试 PC 与网络条件。
- 期望验收域名、是否需要 Web/Admin 公网入口，以及是否允许产生录屏/截图证据。

## 7. 回滚、清理与停止条件

- 部署前保存当前 image digest、Git commit、Compose/env 脱敏快照和 SQLite backup；回滚只切换应用/镜像或 feature flag，不删除事件修复状态。
- 任何迁移先走 additive/N-1 兼容窗口；恢复演练使用隔离目录/实例，不覆盖原库。
- 测试结束只清理本轮创建的容器、测试账号、临时 Workspace、测试 APK 和报告中的敏感临时文件；不停止用户已有服务。
- 出现认证绕过、明文敏感数据、数据丢失/重复执行、越权写入、TLS/SSH 暴露或不可逆迁移风险时立即停止并归类，不继续扩大测试范围。
- 缺少 SSH、DNS/TLS、Android 真机授权、密钥/额度或 Provider 授权时，状态为 `blocked`，完成可安全执行的本地/云端无凭据检查，不伪造结果。
