# Agent Sessions 迭代计划 v0.5.next：完整接入 DeepSeek Harness Provider

> 状态：`planned`
> 定位：插在 v0.5（移动端会话 UI 收口）与 v0.6（Go 后端技术栈优化）之间的第五家 Provider 接入切片。不改变 v0.5 的收口口径，也不依赖 v0.6 的任何技术栈变更。
> 编写参考：`web-iterative-workflow` SKILL.md（验证口径、测试架构、失败分类、断点恢复与交付定义均按该流程落地）。
> 事实来源：本仓库 `internal/adapter/spi.go`、`internal/adapterreg/registry.go`、`internal/adapter/opencode/`；DeepSeek Harness 本机 checkout `/Users/yubi/code/deepseek-harness` 的 `packages/acp/`、`packages/examples/acp-demo/`（固定以实施当日的本地 checkout 为准，DSH 处于 developer preview，协议可能破坏性变更）。
> 联网说明：本计划全部锚点来自两仓本地源码与 README，未访问外部网络。

## 1. 目标

把 DeepSeek Harness（下称 DSH）作为第五类真实 Provider 接入 Adapter SPI，交付：

- 基于 DSH ACP 桥（JSON-RPC over stdio）的真实 transport：Start / Send / Abort / 事件流 / 受控进程终止；
- 诚实的能力矩阵：ACP wire 明确承载的能力标 native，未承载的标 unsupported 并给中文原因；
- Flutter 端 provider 入口与 restart.sh 编排；
- 全链路测试证据：Go 契约测试（假 stdio server）、transport live gate（smoke → targeted → full，真实模型消耗前单独授权）。

非目标见第 8 节。v0.5 的两个外部门禁（物理 Android、OPENCODE_SERVER_PASSWORD）不在本迭代范围内，不得混入口径。

## 2. 背景与依据

### 2.1 为什么是 DSH

- v0.5 会话 UI 的交互基准就是 DSH `ui-conversation` 模块语义，Provider 与 UI 投影词汇同源。
- DSH 提供专为程序化客户端设计的自动化面：`packages/acp/acp/src/index.ts` 基于 `@agentclientprotocol/sdk` 的 `AgentSideConnection` + ndjson stdio，方法面含 `initialize` / `session/new` / `session/prompt` / 取消通知 / `session/event`，承载 prompt 文本+图片、assistant 提交文本+图片、取消、一次性权限决策和 turn 结束原因。
- 相比 OpenCode HTTP 形态，stdio 子进程使 adapter 天然拥有进程树，`ForceKillHandle` 语义完整，与 SESS-05 owned-process 监督机制直接复用——两种进程所有权模式在注册表中形成互补。
- 桥自身无需网络凭据（对比 `OPENCODE_SERVER_PASSWORD` blocker）；LLM 密钥由 DSH 侧配置承载，本仓库不接触（见第 5 节凭据规则）。

### 2.2 已核实的限制（写进契约，不许实施时翻案）

| 限制 | 来源 | 应对 |
| --- | --- | --- |
| ACP demo 入口"只支持新建自动化会话"，恢复属于其他运行入口 | `packages/examples/acp-demo/README.zh.md` 已知限制 | Resume 按 SPI 六态如实返回（预期 `unsupported` 或 `restarted_with_context`），禁止伪装 resumed |
| 工具调用明细是否上 wire 未承诺（桥只声明文本/图片/取消/权限决策） | `packages/acp/acp/src/index.ts` 头注释 | P0 实测定级；`tool_call/tool_result` 映射最坏为 unsupported 带原因 |
| DSH developer preview，会有破坏性变更 | DSH `README.md` | Detect 强制版本门槛（对标 Happy `MINIMUM_CLI_VERSION` 思路），低于门槛整体 unavailable |
| `provider`/`model` 是桥的必填配置 | acp-demo 配置表 | 运行中模型切换大概率 unsupported；StartRequest 的 Model 落到启动配置 |
| stdout 是 ACP wire，诊断只能在 stderr | acp-demo Bin 说明 | 日志采集只读 stderr；禁止向子进程 stdout 写入 |

## 4. 强制契约

- **版本门**：`Detect` 必须先握手 `initialize` 并校验 DSH 版本/`PROTOCOL_VERSION`；低于最低版本或握手失败时 available=false、全部 unsupported、带中文原因，不写 Version。
- **六态唤醒不可伪造**：Resume 结果只能是六种枚举之一；当前桥不支持恢复时如实 `unsupported`，后续若 DSH 提供恢复入口再升级为 `resumed`/`restarted_with_context`，必须有实测证据。
- **ForceKill 所有权**：只有本 adapter 自己 spawn 且能证明进程树所有权的 Handle 才可实现 `ForceKillHandle`；Dispose 必须先 graceful 再强杀，并等待进程组退出确认。共享长驻桥模式下禁止实现 ForceKill。
- **能力三态诚实**：未知能力一律 unsupported；每项带中文 reason；禁止把"配置里存在"当成"wire 上可用"。
- **E2EE 边界不变**：Daemon↔桥之间是本机明文（等同 OpenCode HTTP 形态），进入 Relay 的内容仍走既有 AES-256-GCM 信封；本迭代不改加密层、无 SQLite 迁移。
- **事件脱敏**：canonical event 只携带白名单字段；DSH 私有 payload（persona、系统提示、工具实现细节）不得进入公共协议或日志。
- **失败分类沿用**：统一使用第 11 节分类表；t.Skip、缺 LIVE_SUMMARY 一律不得记 passed（沿用 opencode transport runner 修复后的规则）。

## 5. 验证强度与安全前置门

### 5.1 各阶段验证类型（不混称）

| 阶段 | 类型 | 默认口径 |
| --- | --- | --- |
| P0 smoke | smoke（手动驱动真实桥，最小链路） | `real_upstream=true`（真实 DSH 进程）、`real_model=false`（不触发模型请求的握手/取消路径）、`local_test=true` |
| P1–P2 契约与回归 | 单元/集成（fake stdio server） | `fixture_data=true`、`local_test=true`、`real_model=false`、`real_upstream=false` |
| P3 编排与 UI | restart 回归 + Flutter widget | 同上 |
| P4 transport gate | smoke → targeted diagnostic → full gate（真实模型需授权） | `real_upstream=true`、`real_model` 按授权如实标注、`fixture_data=false` |
| 收尾演示 | recording（核心 gate 通过后才做） | 真实模型演示默认不并入常规回归，避免隐性额度消耗 |

报告字段沿用既有 schema：`report_kind`、`status`、`real_browser/real_model/real_upstream/fixture_data/local_test/headless`、`credential_source`、`command`、`request_ids`、`usage`、`artifacts`、`failure_class`、`remaining_risk`。

### 5.2 凭据与敏感信息

- 桥本身无凭据，报告 `credential_source="none"`；LLM key 由 DSH 侧 `cordis.yml`/其工作目录 gitignored `.env` 承载——本仓库 runner **不读取、不打印、不复制该文件**。
- 子进程环境最小注入：spawn `dsh-acp-demo` 时 scrub 无关变量（尤其其他 Provider 的凭据如 `OPENCODE_SERVER_PASSWORD`），只传 PATH/HOME/`DSH_HOME` 及显式声明的配置项。
- 禁止把 token、Authorization、原始 prompt、原始模型回复写入命令行参数、日志、截图、录屏、报告、fixture 或文档；stderr 日志先脱敏再归档。
- 真实模型 gate 执行前必须向用户说明预计请求次数、模型、token 范围与可停止点；缺少密钥/额度/授权时完成本地安全范围并标记 blocked，不伪造。

### 5.3 长任务生命周期

live gate、recording、全量回归等长命令一律后台可轮询执行：只轮询当前有效 job；等待期定期汇报阶段/耗时/当前 case；必须拿到最终退出码或明确超时分类（stdout 停顿、中间成功日志、部分 artifact 都不算完成）；结束后清理本轮启动的子进程与临时服务，不清用户已有进程。

## 6. 协议映射表（P0 冻结为对照表）

| ACP wire | Adapter SPI | canonical event / 能力 | 初判 |
| --- | --- | --- | --- |
| `initialize` | `Detect` | 版本门 + 能力矩阵基线 | native |
| `session/new`(cwd/provider/model) | `Start(StartRequest)` | `turn_started` 前置绑定；InstanceID 由响应携带则实现 InstanceIDHandle | native |
| `session/prompt`(text/images) | `Send(ctx, text)` | 用户输入入站 | native |
| assistant 文本增量/提交 | mapper | `message_delta` / `message_completed` | native |
| 图片内容 | mapper | attachments 展示位 | native（展示）；发送图片待 P0 实测 |
| 取消通知 | `Abort(ctx)` | turn 终止 | native |
| 权限请求/一次性决策 | mapper | `permission_request` / `permission_decision` | native |
| turn 结束原因（`TurnEndReason`→`StopReason` codec） | mapper | turn 生命周期闭合 | native |
| 工具调用明细 | 待实测 | `tool_call` / `tool_result` | P0 定级，最坏 unsupported |
| question/goal/model_select/skill_catalog 等 seat 类 | 无 wire 面 | 对应能力 | unsupported + 原因 |
| 恢复旧会话 | `Resume` | 六态枚举 | 预期 unsupported（见 2.2） |
| 进程组终止 | `Dispose` / `ForceKillHandle` | kill 能力 | native（仅 per-session 拓扑） |

P0 产出物：把此表补齐"实测列"，落为 `docs/adr/ADR-013-DeepSeek-Harness-Provider接入.md` 的附表；此后映射变更须改 ADR。

**P0 实测结论（2026-08-24，报告 `e2e-verify/reports/ADAPTER-DSH/p0-smoke-2026-08-23T17-48-37-906Z.json`）**：initialize 握手通过（`protocolVersion=1`，冷启动 359ms）；session/new 返回 sessionId；`session/load`、`session/list` 实测 `-32601 Method not found`——Resume=`unsupported` 获得 wire 级证据；空闲 cancel 通知容错；EOF dispose 受控退出（exit 0）。全程未触发模型请求（`real_model=false`），转写无敏感字段。

## 7. 进程拓扑决策门（P1 开工前定案）

- **方案 A（默认推荐）：per-session 子进程**。每次 Start spawn 一个 `dsh-acp-demo`，会话结束 Dispose 回收。优点：所有权清晰、ForceKill 合法、故障隔离、复用 SESS-05；代价：每次启动承担 Node 组合装配开销（秒级），P0 实测记入风险表。
- **方案 B：共享长驻桥**。restart.sh/Daemon 启动一个桥，多会话复用一条 stdio 连接。优点：启动快；代价：kill 一个会话无法证明进程树所有权（ForceKill 禁用），单桥故障影响全部会话。
- 决策门输出：选定方案 + 性能数据 + 写入 ADR-013；切换方案必须重跑 P2 全部回归。

**P0 决策结论**：选定**方案 A（per-session 子进程）**——实测冷启动 359ms 远低于预期，ForceKill 所有权成立；已记入 ADR-013 第 3 节。

## 11. 失败分类、重试与断点恢复

沿用项目十类失败分类，本迭代的典型映射：

| 现象 | 分类 | 处理 |
| --- | --- | --- |
| 桥进程无法启动/EOF/端口或路径缺失 | `environment_or_startup_failure` | 修复环境或启动参数后重跑 |
| DSH 版本低于门槛/协议握手不匹配 | `checkpoint_mismatch` | 锁定版本区间，升级行为须改 ADR 再继续 |
| fake bridge 用例暴露 mapper/adapter 缺陷 | `product_defect` 或 `test_harness_defect` | 按根因层修复并补回归 |
| 真实模型回复违反 oracle | `model_contract_failure` | 保留失败证据，不得自动标绿 |
| 同一契约有限重复内不稳 | `model_flakiness` | 分离统计、重试上限、残余风险入报告 |
| LLM key/额度缺失 | `credential_or_quota_blocker` | 标记 blocked，完成本地安全范围 |
| 桥响应超时 | `provider_timeout` | 限并发、限定重试并记录阶段 |

重试规则：仅 provider timeout、可恢复 5xx、进程启动抖动可在上限内重试并记录次数/间隔/最终结果；契约失败不得靠重试标绿。

断点恢复 checkpoint 必须包含：suite/version、behavior hash、DSH checkout 版本、已完成 case、失败分类、生成时间。DSH checkout 更新（behavior hash 输入变化）后旧 checkpoint 以 `.stale-<时间戳>` 重命名保留，不得复用也不得删除。

## 13. 验收标准

- 设置/创建会话页可见 dsh provider；DSH 未安装或版本过低时整卡 fail-closed 并显示具体原因，不显示可点但必败的入口。
- start → send → abort → dispose 全链路由真实 stdio 子进程驱动；kill 后进程树确证消失，重复 kill 幂等。
- 事件流只含白名单 canonical 字段；权限请求可在移动端完成一次性决策并回到桥。
- Resume 结果与实测一致，绝不伪装 resumed。
- 能力矩阵每一项都有三态之一与中文原因；矩阵与 ADR-013 附表一致。
- live gate 报告字段完整（`credential_source="none"`、`fixture_data=false`、`real_model` 如实），缺 LIVE_SUMMARY 不算通过。
- 全部新增测试登记进测试套件索引，`task check` / `git diff --check` 通过。

## 15. 风险、回滚与决策

- **DSH 协议漂移**：developer preview 破坏性变更可能让本适配器在下游升级后失效；缓解=版本门 + fake bridge 契约测试隔离 + ADR 记录锁定版本区间。
- **启动开销**：per-session 冷启动秒级延迟；P0 实测后若不可接受，重开第 7 节决策门而非静默换拓扑。
- **工具事件缺失**：若 wire 不出 tool_call 明细，移动端 Trajectory 对 dsh 会话将退化为消息级视图；这是上游能力边界，UI 按 unavailable 呈现，不造假行。
- **双仓节奏**：DSH 本地 checkout 非发布件；CI/其他机器复现需固定 DSH 安装方式与版本，写进实施记录。
- **回滚考量**：整体回滚 = registry 移除 `"dsh"` kind + KnownKinds 还原（客户端随即按未知 provider fail-closed 隐藏入口）；本迭代无 SQLite 迁移、无公开 API 破坏性变更，回滚不需要数据动作。
- **范围纪律**：本迭代不承诺 Resume 增强、不承诺 seat 类能力；它们依赖上游 wire 扩展，届时另立切片。

## 16. 完成定义与停止条件

P0–P4 全部退出条件满足、ADPT-DSH-01..12 登记且有长期回归或真实证据、需求级覆盖矩阵完成审计、ADR-013 与四份文档回填一致、且 live gate 有真实报告（passed 或如实 blocked）后，本迭代方可标记 `implemented`。任何"只有 fake bridge 绿"的状态只能记 `partial`。

停止条件（满足其一即停下向用户报告，不称完整迭代）：

- 真实模型 gate 因密钥/额度/授权处于 blocked：交付已完成范围 + 失败分类 + 证据 + 下一步。
- 核心功能变更尚未通过真实模型端到端演示且用户未明确跳过（涉及模型调用的功能默认适用）。
- 关键回归未沉淀到长期测试目录、或权威文档未回填当前事实。
