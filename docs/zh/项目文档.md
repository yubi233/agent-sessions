Flutter 当前已完成 v0.1 P6 的 MacBook 本地验收：P5 的 Delegation 父子会话确认/切入与 P6 的生命周期恢复、cursor 去重、失效 lease、应用内通知降级均有 Dart/Flutter 长期回归、可见 macOS `480x960`窗口 5fps PNG 和专用 5fps MP4 证据。该结论仅覆盖 deterministic fixture 的共享业务链路；Android AVD/真机、Android Keystore/Drift、UnifiedPush distributor 与真实 Provider Adapter transport 仍分别属于后续原生硬化或未实现的 gate。OpenCode CLI 的真实模型 smoke 已通过，但不能延伸为 Flutter 已控制真实 OpenCode 会话。

## 2. 产品定位

Agent Sessions 是一个类 Happy 的远程编码会话平台：

- PC 上的本地服务负责访问工作区、启动本地 Agent、转发事件和执行安全的 Git 读取操作。
- 服务器上的 Relay 负责身份、配对、密文路由、事件持久化、在线状态和命令转发。
- Android 是默认的唯一写控制端，负责完整移动会话控制。
- Web App 提供只读会话查看和 Git diff；管理平台提供只读运维与设备元数据查看，owner Android 管理设备密钥生命周期。

本项目借鉴 Happy 的产品能力和开源实现经验，但不兼容 Happy 的 wire protocol、Socket.IO 事件或客户端。

## 3. 已确认的产品决策

| 领域       | 决策                                                                                                              |
| ---------- | ----------------------------------------------------------------------------------------------------------------- |
| 部署       | 单租户自托管；Docker Compose 单机部署                                                                             |
| 设备关系   | 一个账号绑定多个 PC 和客户端；首个 Android 设备为 owner                                                           |
| PC 平台    | macOS、Windows、Linux                                                                                             |
| 运行时     | Claude、Codex、OpenCode、OpenClaw 四类并行接入                                                                    |
| 运行时接入 | 各类型优先原生深度集成，PTY 只作为显式兼容降级                                                                    |
| OpenCode 验证 | 本机 CLI 已验证`opencode-go/deepseek-v4-flash`真实调用；Adapter 未接入 transport 前全部控制能力必须为 unsupported |
| 唤醒       | 启动/恢复 Agent 会话，不负责唤醒或远程开机 PC                                                                     |
| 控制权     | Android 固定为唯一写控制端；Web/管理台只读                                                                        |
| Git        | 在线只读 status、文件列表和 diff；不做 stage、discard、commit                                                     |
| 加密       | 消息、文件、diff 和工具参数端到端加密；服务器只看白名单元数据                                                     |
| 通道       | REST + SSE + WebSocket                                                                                            |
| 存储       | SQLite 是事件、命令、ControlLease/fencing epoch 的权威；进程内内存只处理可重建的 presence、短租约提示、限流和广播 |
| 推送       | UnifiedPush 优先；无 distributor 时降级为应用内实时通知                                                           |
| 会话留存   | 密文长期保留，用户可以手动删除                                                                                    |
| 附件       | 受大小和 MIME 限制的图片与文本文件                                                                                |
| API        | 仅官方客户端使用的内部版本化 API                                                                                  |
| 更新       | macOS pkg、Windows MSI、Linux deb/rpm/tar，签名后手动升级                                                         |
| 技术选型   | Go + Gin、Vue3 + TypeScript、Flutter + Dart；具体依赖见[技术选型](技术选型.md)                                    |

## 4. 系统拓扑

```text
                         +----------------------+
                         | Android Controller   |
                         | 唯一写控制端         |
                         +----------+-----------+
                                    |
                         REST / SSE / WebSocket
                                    |
+----------------+        +--------v---------+        +----------------+
| Vue Admin      |-------> | Relay Server     | <------| Vue Web App    |
| 运维、只读     |         | Go               |        | 会话、只读     |
+----------------+         +---+----------+---+        +----------------+
                                |          |
                          WebSocket      SQLite
                                 |          |
                          +------v----+  in-memory presence
                          | PC Daemon  |
                         | Go         |
                         +--+--+--+--+
                            |  |  |

```

Relay 不访问 PC 工作区，也不执行 Agent 命令。所有工作区相关能力必须经由已认证的 Daemon 完成。

## 5. 组件职责

### Relay Server

- 账号登录、设备配对、owner 批准和撤销。
- Terminal、Project、Workspace、Session 的元数据索引。
- 密文事件、命令状态和用户游标的持久化。
- WebSocket 终端连接、Android 订阅和 RPC 路由。
- SSE 增量事件读取，支持 `Last-Event-ID` 恢复。
- 控制权租约、幂等键、fencing epoch、限流和 outbox。
- 健康检查、指标、脱敏日志和备份接口。

### PC Daemon

- 系统服务、CLI、进程监督和本地 SQLite 状态。
- 扫描常用目录，用户确认后登记 Git 项目根目录。
- 维护 Terminal 长连接和断线重连。
- 启动、恢复、停止本地 Session Instance。
- 适配四类 Agent，统一为 canonical event stream。
- 在 Workspace 安全边界内执行 Git 只读 RPC。
- 使用系统 Keychain 保存本地密钥和设备凭据。

### Android App

- 登录、二维码配对、设备撤销和恢复码恢复。
- 项目、Workspace、Session 列表与会话详情。
- 新建、唤醒、恢复、停止、终止和删除会话。
- 流式消息、工具调用、权限、问题、plan、goal、skill、跨工具子代理派发和附件。
- 离线缓存、事件游标、断线恢复和通知。
- 项目级 Git diff 只读查看。

#### MacBook 本地 Flutter 验收链路

- `task test:flutter:local`先构建固定的 macOS debug App，再运行`apps/mobile/test/`长期单元与 widget 回归；只有断言通过后才启动可见窗口采集视觉证据。
- debug macOS 可执行文件只在本地 gate 接收`LOCAL_FIXTURE_MODE`和固定场景名，运行时用 deterministic fixture 替换安全存储和 Relay；release、Web、Android 路径仍使用各自的真实存储与传输实现。
- 本地桌面窗口以`480x960`逻辑手机画布渲染。CoreGraphics 仅定位本轮`agent_sessions_mobile`窗口，按 5fps 抓取已登记场景；若系统拒绝 Screen Recording，debug App 仅在自身沙盒临时目录写入同一可见窗口的`RepaintBoundary`渲染帧，由 runner 校验 PNG/尺寸/SHA-256 后复制到证据目录并在 manifest 标记 fallback；抓取完成后仅终止本轮已观测 PID。
- `task test:flutter:record -- --gate-report <passed-report>`只接受已通过的同轮 full-gate 报告，并固定录制`VISUAL-MOBILE-11`、`VISUAL-MOBILE-12`和`VISUAL-MOBILE-14`各 5 帧/5fps 的 MP4；录屏器用 ffprobe 校验帧率、帧数和`480x960`尺寸，不能用 Web `task test:record`替代 Flutter 录屏。
- 这条链路是 macOS 26/Xcode 26 下`flutter run -d macos` open/VM 握手回归的工程化替代，不等价于 Android AVD、Android Keystore/Drift、通知或真机验收。

#### v0.1 P2 会话控制边界

- `SessionController`只管理会话列表、快照、时间线、lease 和 composer 状态；认证/设备身份仍由`AppController`管理，避免登录页面 rebuild 影响已打开的时间线。
- 会话列表只消费 Relay 白名单元数据。快照原始事件保持 opaque `envelope`；未知或未解密事件只显示脱敏占位，不能猜测、日志化或缓存正文。
- 已存在会话的写命令在客户端先校验本地 device 绑定、正数`lease_epoch`和`idempotency_key`，HTTP body 不携带可伪造的`device_id`；Relay 仍必须从 bearer 身份和 fencing epoch 最终裁决。
- `FixtureRelayRepository`只为本地回归生成固定、无敏感的时间线，覆盖用户消息、流式 assistant、工具活动、permission/question、停止和只读状态；它不请求真实 Provider，也不替代真实 Relay wire 验收。
- P2 的可见 macOS gate 固定采集`VISUAL-MOBILE-03`（列表）、`VISUAL-MOBILE-04`（完整会话）和`VISUAL-MOBILE-05`（只读）各 5 帧，作为`MOBILE-02`的视觉证据；行为断言由`apps/mobile/test/`长期回归承担。

#### v0.1 P3 控制面与附件边界

- `CapabilityMatrix`只接受`native`、`emulated`和`unsupported`三态；未知 status、缺失 capability 或不可用 Provider 一律 fail-closed。Plan/Goal 展示来自已解密事件或 deterministic fixture，不能由 Relay 白名单元数据推断。
- 高风险 Skill 先在会话内显示二次确认卡。拒绝只清理本地 pending action，不创建 Provider 或会话命令；确认时复用 Android owner、正数`lease_epoch`和新`idempotency_key`，处理中禁止重复提交。
- 附件 draft 的显示名和原文件只在客户端内存，Relay wire 不含 filename 或正文。客户端只接受 PNG/JPEG/WebP（最多 10 MiB）及 plain/Markdown 文本（最多 1 MiB），上传为按序的密文 chunk；失败从已确认 chunk 继续，并以独立幂等键 complete。
- Relay 仅保存 attachment 的会话/账号归属、MIME/大小/压缩、加密 metadata 和密文 chunk。上传 body 上限为 768 KiB、complete body 上限为 32 KiB，超限返回`413/PAYLOAD_TOO_LARGE`；跨账号既有 attachment ID 返回`403/SCOPE_DENIED`，不会以冲突泄露资源存在性。
- `VISUAL-MOBILE-06..08`已在录制前登记，并在 MacBook 可见窗口以 5fps 验证能力面板、Skill 确认与附件队列。行为回归在`apps/mobile/test/`和`internal/relay/p3_attachment_contract_test.go`，截图只保留 deterministic fixture。

#### v0.1 P5 Delegation 父子会话边界

- `delegation.create`、`delegation.resolve`与`delegation.changed`使用单独的产品层状态机：`proposed -> approved -> running -> completed|failed|cancelled`，也可从`proposed`进入`rejected`。proposal、决策与状态变化均由父 Session 的 Android owner + 当前正数 parent `lease_epoch`保护，child 后续写入必须重新获取 child 自己的 lease。
- Relay 的`delegations`索引只保存账号、parent/child Session 引用、目标 Provider、状态、客户端加密的任务书/摘要 envelope 与 hash、parent lease epoch、幂等键和审计元数据。`GET /v1/sessions/{id}/delegations`及父事件只投影状态、Provider、child 引用和摘要 envelope/hash；任务书、child timeline、文件路径和正文永不出现在 parent REST、事件、日志或 Flutter 卡片中。
- 创建 proposal 只允许同 Workspace 与同 Terminal；跨 Workspace/Terminal、只读 Web/Admin、过期 fencing epoch或`delegate_cross_provider=unsupported`均显式拒绝。deterministic mock Dispatcher 只用于本地 fixture，批准后在同一事务创建独立 child Session 和初始 child lease，不冒充 Claude/Codex/OpenCode/OpenClaw 的真实 Provider 成功。
- Flutter 的`DelegationController`独立于`SessionController`加载 parent 图，避免切页时显示上一会话节点；详情页提供紧凑“父会话 -> 子会话”图、批准/拒绝/取消图标和 child 切入。路由进入 child 时会清空 parent lease，并强制重新获取 child lease；页面只显示摘要 hash，禁止读取 ciphertext或 child 正文。
- `VISUAL-MOBILE-11..13`在 runner 中预登记为 proposed、已批准 parent-child 图和 unsupported 降级三个 deterministic fixture，并已在 MacBook 可见`480x960`逻辑画布完成 P5 full gate：每场景 5fps 连续 5 帧，证据见`e2e-verify/reports/2026-08-14T22-24-46-752Z/MOBILE/mobile-01-macos.json`与同时间戳截图 manifest。Android AVD/实机与真实 Provider live smoke仍是后续硬化或授权 gate。

#### v0.1 P6 生命周期恢复与通知降级边界

- `RuntimeRecoveryBinding`只把 Flutter 前后台状态和`connectivity_plus`链路提示翻译为平台无关的前台/后台、online/offline/unknown 状态；连通性插件不证明 Relay 可达，实际恢复结果只能由只读 snapshot 请求裁决。
- `SessionRecoveryController`只有在后台或离线后才设置恢复待处理标记；首次启动的 online 不显示“恢复完成”。前台且 online 时它仅调用`SessionController.recoverSelectedSessionFromCursor()`，按当前`after_seq`读取增量、按 sequence 去重排序，并在任何后台/离线切换时立即废弃本地 lease。
- 生命周期恢复不调用 create、send、abort、权限/问题确认或附件上传。已生成的`idempotency_key`仅供用户显式重试复用；会话切换 generation 不一致的迟到 snapshot/controls 响应会丢弃，不能污染当前会话或产生错误通知。
- 无 UnifiedPush distributor 时，恢复后仅显示应用内通知队列中的会话 ID、事件数量和时间；不保存事件正文、密文、token 或通知内容。队列同会话只保留最新项，总量保留最新十项。
- `VISUAL-MOBILE-14`使用 deterministic fixture 复现 background -> offline -> 新事件 -> foreground -> online，验证一条新增事件、cursor 边界去重、失效 lease 和应用内通知。`2026-08-14T23-15-43-950Z`的可见 macOS full gate 保存了 15 个场景共 75 张 5fps PNG；随后`2026-08-14T23-17-55-302Z`录制`VISUAL-MOBILE-11/12/14`各 5 帧、5fps、`480x960` MP4。当前 Screen Recording 未授权时，证据明确标记为`flutter-render-boundary-fallback`，不表述为系统截屏或 Android 实机结果。

#### OpenCode 真实模型与移动控制边界

- `task test:real -- --provider opencode --model opencode-go/deepseek-v4-flash --retries 3`先确认本机模型目录，再在新建临时空目录中用`opencode run --pure --format json`执行无工具的最小请求。报告只保留哈希、事件类型、脱敏请求标识和用量，因此这条链路可证明`real_model=true`、`real_upstream=true`，但不是浏览器、Android 或录屏验收。
- 当前`internal/adapter/opencode.Adapter`没有 HTTP/SSE/WS transport：`Start`返回不可用错误，`Resume`返回`unsupported`。即使配置`AGENT_SESSIONS_OPENCODE_URL`，`Detect`也必须把所有控制能力标为`unsupported`并给出原因，避免 Flutter 根据伪 native 状态显示写入口。
- 真实 mobile OpenCode 链路的下一步是 Daemon 内的 version/endpoint 探测、认证边界、create/send/abort、canonical delta/tool/final/error 映射、session handle 加密持久化和 resume 语义；每个步骤要分别补 fixture contract、Adapter 集成和授权 live gate。详细 Happy 对比与证据见[专题实施记录](实施记录/07-HappyMobile功能对比与OpenCode验证.md)。

### Vue Web App

- 查看项目、Workspace、Session、消息、工具事件和父子 Delegation 图。
- 查看在线状态、错误、计划、目标和 Git diff。
- 不发送 prompt、审批、skill、plan、goal 或派发控制命令。

### Vue Admin

- 设备、Terminal、版本、在线状态和连接错误。
- 健康检查、流量和脱敏审计元数据；配对/撤销状态只读展示。
- owner Android 是设备 key-admin，负责批准、撤销与恢复码；Admin 没有这些操作权限，未来扩权必须单独新增 ADR、角色和 API。
- 不显示消息正文、文件内容、diff、工具参数或附件内容。

## 6. 领域模型

```text
Device
  └── Terminal
        └── Project
              └── Workspace
                    └── Session (逻辑持久会话)
                          ├── SessionInstance (一次运行/唤醒)
                          │     └── ProviderThread (原生线程句柄)
                          └── Delegation (产品层子代理任务)
                                └── Child Session (独立会话，可换 Provider)
```

核心实体：

- `Device`：设备身份、公钥、角色、撤销状态和最后在线时间。
- `Terminal`：PC 主机、平台、版本、能力和心跳状态。
- `Project`：仓库指纹、远程身份和加密显示名。
- `Workspace`：Terminal、Project、canonical root、分支或 worktree。
- `Session`：跨运行实例保留的逻辑会话、事件序号和加密元数据。
- `SessionInstance`：一次 Agent 进程运行，拥有 instance id 和 lease epoch。
- `SessionEvent`：有序、可重放的端到端加密事件。
- `Command`：异步控制请求及状态，使用 idempotency key。
- `ControlLease`：当前写控制端和 fencing epoch。
- `Plan`、`Goal`、`SkillDescriptor`：同一会话内的产品层资源，不是跨工具子代理。
- `Delegation`：父 Session 派发的子代理任务；子代理是独立 Child Session，可使用不同 Provider。详见 ADR-007。
- `AttachmentBlob`：分块上传的端到端加密附件。

唤醒结果必须明确区分：

```text
resumed
restarted_with_context
unsupported
local_state_missing
workspace_moved
terminal_offline
```

### SSE

SSE 是账号级的可恢复读取通道。客户端通过 `Last-Event-ID` 或 `after_seq` 请求缺失事件；presence 不写入 SSE 历史。

### WebSocket

WebSocket 分为 authenticated controller 连接和 terminal 连接。首帧完成 challenge/hello、协议版本、设备身份、能力和游标协商。命令和事件均包含：

```json
{
  "protocol_version": 1,
  "message_type": "command|event|presence|ack",
  "message_id": "...",
  "trace_id": "...",
  "scope": { "terminal_id": "...", "workspace_id": "...", "session_id": "..." },
  "issued_by_device": "...",
  "lease_epoch": 0,
  "idempotency_key": "...",
  "payload_version": 1,
  "payload": {}
}
```

服务器从认证连接上下文推导作用域，不信任客户端自行填写的目标前缀。SQLite 事务校验当前 `ControlLease`、epoch、target instance、deadline 和幂等键；内存 lease hint 只能加速提示，不能决定接受命令。

## 8. 统一能力模型

每个 Adapter 在运行时上报能力状态：

```text
native      原生支持并通过契约测试
emulated    由 Daemon 或产品层模拟，语义有限
unsupported 明确不支持，客户端禁用入口并说明原因
```

能力至少包括：

```text
start, resume, abort, permission, question, plan, goal,
skill_catalog, invoke_skill, model_select, effort_select,
attachments, file_read, git_read, usage,
delegate_session, delegate_cross_provider
```

客户端不得根据 Agent 类型硬编码能力，必须消费 capability payload。

## 9. 安全边界

- 邮箱/密码只验证账号，不派生正文解密密钥。
- 每设备使用 Ed25519 身份签名和 X25519 密钥交换。
- 项目或会话生成独立 DEK，并包装给已授权设备。
- AES-256-GCM + HKDF；AAD 绑定实体、事件类型、版本和序号。
- Android 使用 Keystore，PC 使用系统 Keychain，Web 使用最小化浏览器存储。
- 服务器保存密文和明确白名单元数据，不提供正文搜索。
- 项目扫描只登记用户确认的目录；Git 命令必须参数化执行。
- 所有会话写操作要求 Android 控制端身份和当前 lease epoch。
- 旧 instance、旧 epoch 和重复 idempotency key 必须被拒绝或返回原结果。

## 10. Git 读取边界

Git 服务由 Daemon 提供，即使 Session 休眠也可读取 Workspace。Relay 的 Git 路由只是端到端加密 RPC 代理：Daemon 执行 Git、路径检查和 `snapshot_token`，Relay 不解析或缓存 diff。必须支持：

- porcelain v2 或等价结构化 status 解析。
- 文件列表、staged/unstaged、rename、binary、submodule、LFS、untracked。
- 文件级和全量 diff，分页、压缩、最大字节数和大文件提示。
- `snapshot_token`，避免分页期间混用不同工作区状态。
- canonical root、realpath、符号链接和 repo-relative path 校验。

首版明确不提供 stage、unstage、discard、commit、push 或任意 shell。

### v0.1 P4 DiffView 实现边界

- `internal/gitread.Service` 每次读取都重新解析 confirmed workspace 的 canonical Git root；文件级 diff 先用 `ResolveRepoRelative` 校验，再以参数数组传给 Git，拒绝绝对路径、`..`、控制字符和仓库外符号链接。
- Git stdout 在读取时限制为 4 MiB；超限立即停止子进程并返回 `truncated` 结构，二进制、submodule、LFS 和超大 diff 只返回可渲染元数据，不能被当成文本 diff 渲染。
- `snapshot_token` 绑定 canonical root、HEAD、branch、porcelain v2 状态和当前工作区内容 hash。分页、单文件和全量 diff 的前后都会重新校验 token；漂移返回 `SNAPSHOT_STALE` 语义，客户端丢弃旧 hunk 后重新读取。
- Flutter 的 `GitDiffRepository` 与 `RelayRepository` 分离：无 `RELAY_BASE_URL` 的本地测试使用 deterministic Git fixture；配置真实 Relay 但尚未部署加密 Daemon Git RPC 时显示 unavailable，绝不把 fixture 伪装成真实工作区结果。
- 移动端只提供统计、文件树、筛选、搜索、unified/split、hunk 折叠和只读刷新；不提供任何 Git 写按钮或本地 shell 入口。窄屏默认 unified，所有文件树与 hunk 分页共用一个 snapshot。
