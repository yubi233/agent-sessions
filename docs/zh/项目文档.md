# Agent Sessions 项目文档

> 当前事实基线：2026-08-16。本文描述仓库已经存在的运行边界，不把计划、fixture 或历史记录写成已交付功能。
>
> v0.4 状态：P0 治理与契约收口、P1 设计系统基线已完成；P2 已完成受限本地 Relay-Daemon 纵向切片，P3 已新增只读终端状态切片，整体仍为 `partial`。完整范围、阶段与退出条件见[迭代计划 v0.4](迭代计划/迭代计划v0.4.md)；不可逆设计见[ADR](../adr/README.md)。

## 1. 产品范围

Agent Sessions 是一个自托管的远程编码会话平台。目标是让 Android 作为唯一远程写控制端，配合本机 PC Daemon、Relay、只读 Web 和只读 Admin，逐步实现类似 Happy Coder 的安全远程 Agent 核心闭环。

本项目按行为参考 Happy，不复制其品牌、Logo、图片、源码、Socket.IO wire protocol 或服务端内部实现。界面可借鉴 Apple HIG 的内容优先、清晰层级、可访问性与克制动效，但不使用 Apple 商标、专有字体、官网源码或营销素材。

当前明确不做：远程 shell、文件/Git 写入、Web/Admin 写控制、公开会话分享、社交、语音、付费、插件市场和多 Agent 编排。更新、Artifacts、分享、Push 与真实多 Provider 能力分别受 ADR、安全模型和真实 gate 约束，不能以 fixture 代替。

## 3. 运行时边界

| 组件 | 当前实现 | 不能声称已完成的部分 |
| --- | --- | --- |
| Relay | Go + Gin；认证、配对、设备、会话、lease、命令、附件、委派、capabilities、SQLite、账号级 SSE，以及 Terminal 专用 Daemon REST/SSE（hello、heartbeat、delivery、ack/result、event upload）。 | 生产 E2EE key handling、完整多 Terminal/会话控制矩阵、版本/更新接口与真实 Provider/Android 跨层闭环。 |
| PC Daemon | 本地 CLI、本地 SQLite 状态、Workspace 路径校验、Git 只读工具、Adapter/SessionRunner、Relay command/event outbox、delivery cursor、REST/SSE RelayLoop 与本机 Workspace 确认。 | 生产事件加密器、完整 Provider 子进程监督/清理、真实 Provider 与 Android 用户旅程。 |
| Flutter Android | 既定的唯一远程写控制端；已有认证、会话、P1 外观系统，以及基于 `GET /v1/terminals` 的只读终端状态。 | 经 Daemon 的真实远程控制、终端重启/Workspace 关联、Android AVD/物理设备、Push、后台恢复和其余 v0.4 产品面。 |
| Vue Web | 只读首页与 `/capabilities`；使用 Relay 只读接口。 | 会话详情、SSE 恢复、文件/Git 路由、完整状态与无障碍/多视口验收。 |
| Vue Admin | 单页只读健康、登录、设备和会话元数据展示。 | 分区路由、审计分页、终端版本/在线状态、完整错误态与无障碍验收。 |

Relay 不读取工作区或执行 Provider；Daemon 是未来唯一访问已确认工作区和 Provider 进程的组件；Web/Admin 永远不取得写控制权。

### 3.1 当前写入与观察流程

```text
Android 写端 -> Relay REST 命令/lease -> Relay SQLite + Terminal delivery
                                              |                    |
                                              v                    v
                                       账号级 SSE 观察者 <- event/result <- Daemon REST + 专用 SSE
```

P2 的本地 fixture 已证明 `Daemon hello -> 专用 SSE 命令投递 -> ack/result -> canonical event upload` 可闭环，且 Relay 不收到已确认 Workspace 的本机根、文件文本或 diff 明文。默认生产 Daemon 没有 event encoder 时会保留事件而不是上传伪密文；确定性 Adapter/fixture encoder 不能证明真实 E2EE 或 Provider 执行。完整 `start/send/resume/abort/kill`、Android 可见控制与真实 Provider 仍未完成。

## 4. 传输与公开契约

**当前实现的实时传输：REST + 账号级 SSE + Terminal 专用 Daemon SSE；未实现 WebSocket。**

- REST 路由在 `internal/httpapi/handlers.go` 注册；唯一公开 API 事实源为[OpenAPI](../../packages/protocol/schema/openapi.yaml)。
- `GET /v1/events` 是账号级 SSE，支持 `Last-Event-ID` 或 `after_seq` 恢复；它不是 Daemon 的命令流。
- `POST /v1/daemon/hello`、`POST /v1/daemon/heartbeat`、`GET /v1/daemon/commands/stream`、`POST /v1/daemon/commands/{id}/ack`、`POST /v1/daemon/commands/{id}/result` 和 `POST /v1/daemon/events` 仅允许已配对的 Terminal；Daemon stream 使用 terminal-local `delivery_seq`，不能与账号事件 cursor 混用。
- 当前没有 WebSocket 路由、`/v1/version` 或面向 Web/Android 的明文远程 Git RPC。文件/Git 只读操作只作为 Relay 下发的 opaque command，在 Daemon 本机确认 Workspace 后执行。
- 已存在的 `POST /v1/sessions/{id}/commands` 是 Android 写端向 Relay 提交异步命令，不等于 Relay 已投递给或收到 Daemon 的执行结果。

现有 OpenAPI 路径可按下列领域查阅：

| 领域 | 已有路由类型 |
| --- | --- |
| 健康 | `/healthz`、`/readyz` |
| 身份与恢复 | `/v1/auth/*`、`/v1/recovery-codes/*` |
| 设备与配对 | `/v1/devices`、`/v1/pairing/*`、`/v1/terminals` |
| 会话与控制 | `/v1/sessions`、`/v1/sessions/{id}/snapshot`、`/v1/sessions/{id}/commands`、`/v1/commands/{id}`、`/v1/sessions/{id}/lease` |
| 工作区与能力 | `/v1/projects`、`/v1/workspaces`、`/v1/capabilities` |
| 委派与附件 | `/v1/delegations/*`、`/v1/attachments/*` |
| 事件 | `/v1/events`（SSE） |

P2 若新增 Daemon 端点，必须先更新 OpenAPI、生成 Go/TypeScript/Dart DTO，再实现 handler。路径和字段不能只从 ADR 或 UI 推断。

## 5. 存储、加密与授权

- Relay 的权威持久化是 SQLite；Daemon 也有独立的本地 SQLite 状态。项目不依赖 PostgreSQL 或 Redis 运行时。
- presence、限流和广播状态可以是进程内可重建状态，不能保存业务真相。Relay 重启后不应丢失会话、命令、lease、事件或设备记录。
- 数据库迁移采用编号 SQL；新增字段和表遵循 additive、N/N-1、备份/完整性检查和可回滚原则。详情见[ADR-008](../adr/ADR-008-SQLite权威存储.md)。
- 协议/密码学代码和生成物位于 `packages/protocol`、`packages/protocol-ts`、`packages/crypto` 与 `packages/crypto-ts`。Relay 只处理密文 envelope 与白名单元数据；日志、报告、截图和录屏不得记录 token、私钥、会话正文、diff 或附件内容。
- `RequireWrite()` 保护写路由；Android 是唯一预期的写控制角色。隐藏 Web/Admin 按钮不是授权边界，服务端必须拒绝直接写请求。

## 6. Daemon、Provider 与工作区

`apps/daemon/main.go` 当前提供 `status`、`doctor`、`run`、`runner`、`workspace-confirm` 和路径检查等本地 CLI 行为：

- `run` 读取显式 Relay 地址和已配对 Terminal 凭据，建立 REST + 专用 SSE RelayLoop，并持久化 command、cursor 与 event outbox；没有 production event encoder 时不上传事件，避免把明文或假密文发往 Relay。`--fixture-adapter` 仅供本地测试。
- `runner` 保留为从 Daemon 本地 outbox 读取 pending command 的诊断入口；真实 Relay 命令闭环由 `run` 承担。
- `workspace-confirm` 只在本机将 opaque `workspace_id` 绑定到用户确认的 Git 根；Relay 下行不携带 `canonical_root`。
- `workspacesafe` 与 Git 工具限制在本机已确认 Git 根下，并拒绝 `..`、仓外符号链接和非 Git 根。
- Provider 通过 Adapter capability 表示 `native`、`emulated` 或 `unsupported`。未被真实证据证明的操作必须 fail-closed，不能用 UI 入口或 CLI smoke 推断为完整移动端能力。

P2 已完成 ADR-009 的确定性 Adapter 窄闭环与受限 `file.read` 端到端验证。P3/P5 仍需接入 Android 观察、设置、使用量、完整只读客户端与经授权的真实 Provider gate。

## 7. 客户端边界与 UI

### Flutter Android

Flutter 是 Android 技术栈，UI 与业务使用 Dart。P1 已提供 `system/light/dark`、ocean/mint/berry 强调色、语义色 `ThemeExtension` 和公共外观菜单；运行时将非敏感外观偏好按设备写入既有安全存储，fixture/widget 测试则使用内存存储。认证和恢复页面在窄屏/200% 文本下可垂直滚动，Git、文件和会话 UI 已从固定深色状态色迁移到语义 token。

终端状态页已消费账号范围的 Relay 白名单 metadata（hostname、platform、status、Daemon/protocol version、last-seen），并在 online/offline/stale/unsupported/unknown、loading/empty/error 下安全显示。它不展示 terminal ID、工作区路径、日志、Workspace、活跃会话或控制入口；重启仍为 `decision_gated`。

P3-A 已新增设置中心与会话信息只读切片：`/settings` 索引与账户、外观、Agent 能力、用量、连接五个分区只展示可兑现的白名单状态（设备/能力矩阵/终端），token 与恢复码明文不显示；用量分区在 ADR-010 服务端聚合契约落地前明确显示「暂不可用」，不估算统计。`/sessions/:id/info` 只读聚合会话元数据、机器白名单与终止/恢复/分享三态能力，复制仅限会话 ID 与 Provider；分享在独立安全 ADR 前恒为 unavailable。两个切片均覆盖 loading/empty/error/offline 与重试，并登记 `VISUAL-MOBILE-22/23` macOS fixture 场景。

P3-B 已新增只读代码查看器与最近会话切片：文件浏览页点击文本文件进入全屏代码查看器（`CodeViewerScreen`，以 push 打开、路径不进 URL），提供行号、轻量语法高亮（Dart 关键字/字符串/注释/数字，无第三方高亮依赖）、搜索跳行与长行横向滚动；二进制/超大文件显示受限摘要，越界路径（绝对路径、`..`、根外符号链接）fail-closed 并保留重试。`/sessions/recent` 按 updatedAt 稳定降序展示会话白名单，支持下拉刷新与进入详情深链，空/离线/错误状态明确且无写入口；登记 `VISUAL-MOBILE-24/25` macOS fixture 场景。

P3-C 已新增用量、命令面板与单消息深链：Relay 落地 ADR-010 的 `usage_events` 表（`usage_key_hash` 唯一约束去重）与 `POST /v1/daemon/usage/events`（Terminal 专属）`GET /v1/usage/summary?days=1|7|30`（账号只读）契约；`/usage` 页展示 today/7d/30d UTC 日桶聚合与 Provider 分解（本地自绘柱状图，无第三方图表依赖），无数据时明确显示「无可用统计」不估算。`/command-palette` 只索引已注册路由与 capability 门控动作（resume/stop/files/git），unsupported 或无 lease 显示原因且不可执行，订阅会话变化实时刷新。`/sessions/:id/messages/:seq` 深链只定位授权会话中目标消息，复制不附加 token/内部 ID/隐藏正文，无权/不存在统一 empty 不泄漏存在性。登记 `VISUAL-MOBILE-26/27/28` macOS fixture 场景。P1/P3 的 Widget 与 macOS fixture 结果不证明 Android Keystore、系统切换、IME、返回键、通知或真机性能。

对于远程机器、代码和用量等状态，必须同时实现 loading、empty、error、offline、forbidden、unsupported、stale 和 success；在根因链不存在时只显示不可用原因，不伪造 fixture 成功。

### Web 与 Admin

Web 目前有 `/` 和 `/capabilities` 两个 hash 路由；Admin 位于 `apps/admin-web`，当前是单页只读控制台。P1 已为这些既有页面加入浅/深/系统外观、本地-only `localStorage` 偏好、语义 CSS token、可访问的原生选择控件及窄屏布局，仍不增加会话写、设备批准/撤销、密钥恢复或工作区写入入口。

P4 才会补会话、机器、文件/Git、SSE 恢复、Admin 分区与审计等真实只读信息架构。当前 headed Chrome 证据使用隔离 Relay fixture，只能证明 P1 的现有页面和主题契约。

两端的设计遵循同一语义 token、状态组件和可访问性约束，但不以 Apple 官网营销页面作为应用布局模板。Web/Admin 的用户可见验收必须使用 headed Chrome，不能用 headless 或组件测试单独替代。

## 8. 用量、更新与扩展项

- 用量：尚未有真实跨端聚合。P3 按[ADR-010](../adr/ADR-010-用量聚合与隐私边界.md)实现 Daemon 白名单数值上传、UTC 日桶、去重和账户级只读查询；`MOBILE-20` 在此之前为 `decision_gated`。
- 更新：当前没有 `/v1/version` 或签名更新清单；签名者、发布源、回滚和平台链接决策完成前，`MOBILE-21` 只能验证明确标识的 fixture 状态。
- 分享与 Artifacts：当前没有服务端领域模型、访问控制、撤销/过期或保留策略；它们不是 Happy 核心复刻完成的前置承诺，保持 `decision_gated`。
- Push：现有可见本地流程不等于 Android 原生 Push。AVD 和物理设备需要独立长期 gate 与用户授权的外部服务配置。
