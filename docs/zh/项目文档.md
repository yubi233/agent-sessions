## 1. 产品范围

Agent Sessions 是一个自托管的远程编码会话平台。目标是让 Android 作为唯一远程写控制端，配合本机 PC Daemon、Relay、只读 Web 和只读 Admin，逐步实现类似 Happy Coder 的安全远程 Agent 核心闭环。

本项目按行为参考 Happy，不复制其品牌、Logo、图片、源码、Socket.IO wire protocol 或服务端内部实现。界面可借鉴 Apple HIG 的内容优先、清晰层级、可访问性与克制动效，但不使用 Apple 商标、专有字体、官网源码或营销素材。

当前明确不做：远程 shell、文件/Git 写入、Web/Admin 写控制、公开会话分享、社交、语音、付费、插件市场和多 Agent 编排。更新、Artifacts、分享、Push 与真实多 Provider 能力分别受 ADR、安全模型和真实 gate 约束，不能以 fixture 代替。

### 3.1 当前写入与观察流程

```text
Android 写端 -> Relay REST 命令/lease -> Relay SQLite + Terminal delivery
                                              |                    |
                                              v                    v
                                       账号级 SSE 观察者 <- event/result <- Daemon REST + 专用 SSE
```

P2 的本地 fixture 已证明 `Daemon hello -> 专用 SSE 命令投递 -> ack/result -> canonical event upload` 可闭环，且 Relay 不收到已确认 Workspace 的本机根、文件文本或 diff 明文。生产 `daemon run` 在 Daemon 进程同时配置 `AGENT_SESSIONS_EVENT_DEK_B64`（32 字节 DEK 的标准 base64）与 `AGENT_SESSIONS_EVENT_KEY_ID` 后，会将版本化 canonical event 以 AES-256-GCM 密封；AAD 绑定 session、Relay event type、协议版本、canonical 序列与 key ID。两项都缺失时保持事件扣留，不上传伪密文；半配置或非法配置会拒绝启动。`session.kill` 只对 Daemon 明确拥有的本机 Provider 进程树可用：Supervisor 在 Darwin/Linux 使用独立进程组并覆盖正常退出、崩溃、超时、强制终止与子进程清理；当前 OpenCode HTTP Adapter 不拥有 server 进程，必须保持 `kill` unsupported，不能把 HTTP `abort` 伪装为 kill。确定性 Adapter/fixture encoder 不能证明真实 E2EE 密钥生命周期、Android 解密或 Provider 执行。

会话终态由 Provider 适配器和 Relay 对账共同保证：OpenCode idle 事件统一成为 `turn.completed`（正常 `stop_reason=session_idle/status_idle`），`session.error` 先广播 `session_error` 再去重补发 `turn.completed`（`stop_reason=error`）；Flutter 将正常终态显示为 `idle`，异常中断显示为 `stopped`，不新增 `interrupted` 状态。历史 `running` 对账仅处理无 `current_instance_id`、无未终态 command、最后事件为 `message.completed`、无活跃 Terminal 心跳且活动时间超过 2 分钟的会话；对账是幂等的，只更新状态和审计，不 archive 或删除事件。在此之上，Daemon 进程重启后通过 `POST /v1/daemon/sessions/recover` 做一次性启动清扫：新进程声明「上一进程已死亡」（hello 会因网络重连重复发送，不能充当该信号），Relay 据此收口该 Terminal 工作区遗留的 running 会话——带死亡 instance 或回合证据不全的置 `stopped` 并清空 instance，命令全终态且最后事件为 `message.completed` 的置 `idle`；启动清扫不要求心跳失联（活心跳正是历史悬挂行在本地开发形态下永不被确定性对账覆盖的原因），但命令/事件证据仍缺一不可，同样幂等、不 archive。

## 4. 传输与公开契约

**当前实现的实时传输：REST + 账号级 SSE + Terminal 专用 Daemon SSE；未实现 WebSocket。**

- REST 路由在 `internal/httpapi/handlers.go` 注册；唯一公开 API 事实源为[OpenAPI](../../packages/protocol/schema/openapi.yaml)。
- `GET /v1/events` 是账号级 SSE，支持 `Last-Event-ID`（优先）或 `after_seq` 恢复；两者都是 `account_event_log` 的跨会话单调 cursor，绝不能使用 session-local `event_seq`。Hub 丢失通知后从 SQLite 严格回放；它不是 Daemon 的命令流。
- `POST /v1/daemon/hello`、`POST /v1/daemon/heartbeat`、`POST /v1/daemon/sessions/recover`、`GET /v1/daemon/commands/stream`、`POST /v1/daemon/commands/{id}/ack`、`POST /v1/daemon/commands/{id}/result` 和 `POST /v1/daemon/events` 仅允许已配对的 Terminal；Daemon stream 使用 terminal-local `delivery_seq`，不能与账号事件 cursor 混用。`sessions/recover` 是进程启动后的一次性历史收口声明，幂等可重放。
- 当前没有 WebSocket 路由、`/v1/version` 或面向 Web/Android 的明文远程 Git RPC。文件/Git 只读操作只作为 Relay 下发的 opaque command，在 Daemon 本机确认 Workspace 后执行。
- 已存在的 `POST /v1/sessions/{id}/commands` 是 Android 写端向 Relay 提交异步命令，不等于 Relay 已投递给或收到 Daemon 的执行结果。

现有 OpenAPI 路径可按下列领域查阅：

| 领域 | 已有路由类型 |
| --- | --- |
| 健康 | `/healthz`、`/readyz`、owner-only `/v1/diagnostics`（outbox 积压、鉴权失败分类、Daemon SSE 连接计数；只含整数指标，不含正文或会话活动时间） |
| 身份与恢复 | `/v1/auth/device-bootstrap`、兼容 `/v1/auth/*`、`/v1/recovery-codes/*` |
| 设备与配对 | `/v1/devices`、`/v1/pairing/*`、`/v1/terminals`、owner-only `/v1/devices/{id}/identity-keys`（Terminal 签名公钥登记/轮换/撤销，ADR-012） |
| 会话与控制 | `/v1/sessions`、`/v1/sessions/{id}/snapshot`、`/v1/sessions/{id}/commands`、`/v1/commands/{id}`、`/v1/sessions/{id}/lease` |
| 工作区与能力 | `/v1/projects`、`/v1/workspaces`、`/v1/capabilities` |
| 委派与附件 | `/v1/delegations/*`、`/v1/attachments/*` |
| 事件 | `/v1/events`（SSE） |

P2 若新增 Daemon 端点，必须先更新 OpenAPI、生成 Go/TypeScript/Dart DTO，再实现 handler。路径和字段不能只从 ADR 或 UI 推断。

## 5. 存储、加密与授权

- Relay 的权威持久化是 SQLite；Daemon 也有独立的本地 SQLite 状态。项目不依赖 PostgreSQL 或 Redis 运行时。
- presence、限流和广播状态可以是进程内可重建状态，不能保存业务真相。Relay 重启后不应丢失会话、命令、lease、事件或设备记录。
- 数据库迁移采用编号 SQL；新增字段和表遵循 additive、N/N-1、备份/完整性检查和可回滚原则。详情见[ADR-008](../adr/ADR-008-SQLite权威存储.md)。
- 协议/密码学代码和生成物位于 `packages/protocol`、`packages/protocol-ts`、`packages/crypto` 与 `packages/crypto-ts`。Relay 只处理密文 envelope 与白名单元数据；日志、报告、截图和录屏不得记录 token、私钥、会话正文、diff 或附件内容。
- `RequireWrite()` 保护写路由；Android 是唯一预期的写控制角色。隐藏 Web/Admin 按钮不是授权边界，服务端必须拒绝直接写请求。
- 访问令牌寿命按角色区分：交互角色（android_owner/web）15 分钟轮换，Terminal（Daemon）24 小时桥接。鉴权逐请求查库校验令牌与设备状态，设备撤销即时生效，不依赖 TTL。终态是 Terminal 迁移到设备密钥挑战签名认证并移除 TTL 桥接，见 [ADR-012](../adr/ADR-012-Terminal认证的TTL桥接与设备密钥签名终态.md)。
- v0.6 Terminal 签名认证（AUTH-05）已在 optional 兼容窗口内交付最小闭环：`GET /v1/daemon/challenge` 签发绑定设备的一次性 challenge（SQLite 持久化，5 分钟有效、只能消费一次，跨 Relay 重启保持一次性语义）；hello 的签名 nonce 必须是该挑战；heartbeat、ack/result、readonly-response、event upload 与 usage 上传均接受 additive `signature` 字段并完整校验 canonical bytes（`protocol_version|device_id|method|path|timestamp_ms|nonce|sha256(body)|key_id`）。`body_hash` 覆盖删除顶层 `signature` 成员后的紧凑 JSON 原文，两端不得把 signature 纳入哈希（循环依赖）。时间窗口 5 分钟；nonce 在 SQLite 一次性记录中查重。owner 可通过 `/v1/devices/{id}/identity-keys` 登记/查看/撤销 Terminal Ed25519 登记公钥：轮换窗口双读（同设备最多两把 active），新 key 首次成功签名后其余登记 key 自动收口 retired；retired 公钥禁止重新登记。Relay 以 `AGENT_SESSIONS_TERMINAL_SIGNATURE_MODE=optional|required` 控制窗口进度：required 模式下旧 bearer 请求一律返回稳定 `426 UPGRADE_REQUIRED`，hello 响应以 `auth_modes` 字段协商认证方式；签名失败不静默回退 bearer。
- v0.6 P2 命令终态与 outbox 可靠性：命令生命周期固定为 accepted → running → succeeded/failed/cancelled/rejected/expired。`AcquireLease` 换代时在同一事务内把旧 epoch 下仍未终态的命令收敛为 `expired`，迟到的 ack/result 只返回权威终态回执、不能复活命令；旧 instance/epoch、撤销设备和错误幂等键全部 fail-closed。Relay outbox 与 Daemon 本地事件 outbox 均为"失败保留 + 指数退避 + 重试上限 + 显式/自动恢复"状态机：只有 Relay 明确确认后事件才标记 delivered，确定性毒丸立即转 failed 并保留脱敏原因（`RELAY_REJECTED_PERMANENT`），瞬态失败按 30s 起步、封顶 15 分钟、上限 8 次退避重试；hello 成功自动恢复瞬态 failed 行，全量恢复入口可显式复活毒丸。历史行永不删除，重复 event_id 由 Relay 幂等去重兜底。
- v0.6 P3/P4 收口事实：撤销设备会使服务端在一个心跳周期内主动关闭既有 Daemon SSE（查询失败按 fail-closed 关闭）；owner-only `/v1/diagnostics` 仅暴露 outbox 积压、鉴权失败分类与 Daemon SSE 连接数的整数指标。签名模式切换（`AGENT_SESSIONS_TERMINAL_SIGNATURE_MODE` optional↔required）经回滚演练证明只影响认证语义——业务历史表、identity keys、outbox 与命令终态逐行不变。生产出站签名链路由 `internal/daemon.RelayClient.Signer` 承载并有真实 HTTP 回归钉住。生产 Daemon 进程的签名私钥接线已收口（RELEASE-V06-02）：`restart.sh --terminal-signing`（env `AGENT_SESSIONS_DAEMON_SIGNING=true`）在配对时用 `daemon keygen` 生成本机 Ed25519 身份密钥（0600 种子文件 `terminal_signing_seed.b64`，幂等回放同一公钥），把真实公钥写入配对请求的 `identity_public_key`，并通过 `AGENT_SESSIONS_DAEMON_SIGNING_KEY_FILE` 供进程加载；也可内联 `AGENT_SESSIONS_DAEMON_SIGNING_KEY_B64`（与文件互斥）。配置后所有 Terminal POST 自动附加签名，签名类协议错误使 RelayLoop 立即退出而非重试或静默回退 bearer；未配置时行为与 bearer 桥接完全一致（回滚 = 关闭开关/删除密钥文件）。中间件（GORM/Redis/Kafka）依据受限 soak 数据结论为 `deferred`。
- sessions 表新增 additive `last_activity_at_unix_ms` 列，用于 stale-running 对账；`SetSessionStatus`、`SetSessionStatusAt`、`SetSessionLastSeq` 在状态/事件写入时更新时间戳。该列只保存状态机活动元数据，不承载正文，也不通过 diagnostics 暴露。迁移保留旧库数据并兼容缺失列；默认 `ListSessions` 先执行确定性对账，`ListArchivedSessions` 单独读取 archive 元数据。

## 6. Daemon、Provider 与工作区

`apps/daemon/main.go` 当前提供 `status`、`doctor`、`run`、`runner`、`workspace-confirm` 和路径检查等本地 CLI 行为：

- `run` 读取显式 Relay 地址和已配对 Terminal 凭据，建立 REST + 专用 SSE RelayLoop，并持久化 command、cursor 与 event outbox。非 fixture 运行仅从 Daemon 进程环境读取 `AGENT_SESSIONS_EVENT_DEK_B64` 与 `AGENT_SESSIONS_EVENT_KEY_ID`：两项齐全时用 AES-256-GCM 生成随机 nonce 的 canonical event envelope；两项均缺失时扣留事件；半配置、非 base64、非 32 字节 DEK 或非法 key ID 直接拒绝启动。DEK 不写 SQLite、Relay、日志或报告。`--fixture-adapter` 固定使用 deterministic hash encoder，忽略生产 DEK 环境变量。
- `runner` 保留为从 Daemon 本地 outbox 读取 pending command 的诊断入口；真实 Relay 命令闭环由 `run` 承担。
- `workspace-confirm` 只在本机将 opaque `workspace_id` 绑定到用户确认的 Git 根；Relay 下行不携带 `canonical_root`。

投影字段；`SessionContextMeter` 显示上下文窗口压力并可打开 breakdown 对话框；缺字段显示不可用，不填假 0。P7-B 已取得 v0.5 三个 macOS headed 可见窗口证据（`VISUAL-MOBILE-30/31/32`，每场景 100 帧，`headless=false`、`visible_desktop_app=true`），但仍未基于完整 full ### Web 与 Admin

Web 目前有 `/`（总览）、`/sessions`（会话列表）、`/sessions/:id`（详情）、`/sessions/:id/files`、`/sessions/:id/git`、`/terminals`（终端状态）与 `/capabilities`（能力矩阵）hash 路由；全部为只读视图，不注册任何写入口。会话详情先读取嵌套 `/v1/sessions/:id/snapshot` 白名单 DTO，再用带 Authorization 的 fetch SSE 只读取账号 cursor 的 `id` 作为失效通知；收到新 cursor 后以本会话 `last_seq` 增量读取 snapshot，并按 session-local `event_seq` 去重。SSE `data` 与 snapshot 的 envelope 都不会保留、解密或渲染。文件和 Git 通过 `GET /v1/sessions/:id/readonly-transport` 获取会话绑定 Terminal 的已配对 X25519 公钥；当前页面为每个请求生成只驻留内存的临时 X25519 密钥，以 HKDF-SHA256 + AES-256-GCM 密封固定的只读 kind 与 repo-relative 参数，并轮询 `readonly-requests` 的 opaque response envelope。Relay 只保存命令状态和密文；Daemon 重新校验 Session -> Workspace -> Terminal、能力与本机已确认 Git 根后才解封、执行并以同一临时公钥回封结果。刷新或离开页面会丢弃临时私钥和已解密内容，页面必须重新请求；缺失 transport、离线、越权或安全拒绝时明确降级，始终没有编辑、终止或设备管理入口。终端页展示 `/v1/terminals` 白名单投影且无重启入口。Admin 位于 `apps/admin-web`，是单页只读控制台。P1 已为既有页面加入浅/深/系统外观、本地-only `localStorage` 偏好、语义 CSS token、可访问的原生选择控件及窄屏布局，仍不增加会话写、设备批准/撤销、密钥恢复或工作区写入入口。

P4 已完成 Web 只读闭环的会话/终端信息架构、`WEB-02` cursor 恢复和 headed Chrome 多视口验收（`p4-web-readonly`，`real_browser=true`、`fixture_data=true`、`headless=false`）：断网后浏览器以 `Last-Event-ID` 重连，fixture delegation 使时间线增量更新，opaque task envelope 未进入 DOM。`WEB-07` 再以真实本机 Daemon、已配对 X25519 密钥和临时 Git 根运行 headed Chrome，完成文件树、代码读取、Git 状态/变更/diff、刷新清理与 Relay SQLite 无明文断言，证据为 [P4-D headed report](../../e2e-verify/reports/2026-08-17T10-21-03-269Z/WEB/p4-web-read-transport.json)。Relay 侧 `TestCTRL01WebCannotWrite` 反向测试保证 Web token 直接构造写请求被 403 拒绝。上述证据均为隔离本地 fixture，不证明真实 Provider、生产部署、Android 或浏览器 PWA/cache。

Admin 已升级为四分区只读控制台（`/` 概览、`/terminals` 终端、`/sessions` 会话、`/audit` 审计），基于 vue-router 分区导航。概览展示健康与脱敏设备/会话元数据；终端分区展示 `/v1/terminals` 白名单投影（hostname/平台/状态/版本）且无重启入口；会话分区只展示 status/provider/last_seq；审计分区消费新增的 `GET /v1/audit?limit=&offset=` 分页契约（limit≤100、offset≥0，只返回 action/metadata 白名单）。所有分区不展示消息正文、文件内容、diff、工具参数、token、恢复码或会话密文，不注册配对/撤销/写入口；headed Chrome 验收覆盖四分区旅程与 375px 窄屏无横向溢出。

两端的设计遵循同一语义 token、状态组件和可访问性约束，但不以 Apple 官网营销页面作为应用布局模板。Web/Admin 的用户可见验收必须使用 headed Chrome，不能用 headless 或组件测试单独替代。

## 9. 测试架构与命令

稳定测试 ID 由[测试套件索引](../test/测试套件索引.json)唯一管理；结构化可执行用例位于 `docs/test/`；代码回归位于各语言现有测试目录；浏览器、AVD、报告和录屏入口位于 `e2e-verify/`。根目录[Taskfile](../../Taskfile.yml)是唯一长期命令入口。

本地开发服务由根目录 `restart.sh` 编排。默认 `./restart.sh start` 启动 Relay、Daemon 和 Flutter macOS 客户端；Web/Admin 通过 `--with-web`、`--with-admin` 显式开启。Relay 继续由 `tools/relayctl.sh` 持有 `.task/relay.pid`，各组件的 PID 和日志由 `restart.sh` 持有在 `.task/restart/`。Daemon 默认要求 `AGENT_SESSIONS_DAEMON_TOKEN`，缺少时在任何组件启动前 fail-closed；`--no-daemon` 可用于分段调试。Flutter 使用 `flutter run -d macos --no-pub`，或 `--flutter-mode device` 通过 `tools/flutter_device.sh` 选择唯一 online 物理 Android；device 模式必须配置 host 可达的 `AGENT_SESSIONS_FLUTTER_RELAY_BASE`，不启动 AVD。`./restart.sh restart` 会先停止已拥有进程，再清理所选服务端口上遗留的监听进程；普通 `start` 不接管外部端口，需显式传 `--clean-ports`。`./restart.sh stop` 只停止本脚本记录且命令签名匹配的进程。`testbox/` 仍只表示真实 Agent 会话绑定的工作区，不是日志、测试或录屏目录。
