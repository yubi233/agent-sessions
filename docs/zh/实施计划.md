## 1. 目标、范围与当前状态

### 1.1 本轮目标

建立一套 Go + Gin、Vue3 + TypeScript、Flutter + Dart 的类 Happy 远程编码平台，最终形成以下链路：

```text
Android 唯一写控制端
        |
        | REST / SSE / WebSocket
        v
Go + Gin Relay ---- SQLite（权威）/ 进程内可重建状态
        |
        | Terminal WebSocket
        v
Go PC Daemon ---- Claude / Codex / OpenCode / OpenClaw
```

服务器只保存和转发密文及白名单运维元数据；工作区、Agent 进程和 Git 读取始终在 PC Daemon 所在机器完成。

### 1.2 当前事实

- 已落地 P0 工程骨架：根 Go/Node/Flutter workspace、SQLite 迁移、OpenAPI/JSON Schema 生成、Go/TypeScript/Dart crypto vectors、Relay health endpoint、Vue 状态页、headed Chrome 回归与录屏入口。
- P1 及之后的身份、配对、会话同步、Daemon、Provider 与完整客户端功能仍未交付；所有未完成 suite 保持 `planned`。
- 已有权威文档：[项目文档](项目文档.md)、[技术选型](技术选型.md)、[自动化测试文档](自动化测试文档.md)、[基础验收用例](../test/基础验收用例.json) 和 `docs/adr/`。
- 当前 P0 命令、测试目录和端口已可运行；每次执行结果必须写入 `e2e-verify/reports/`，不得以文档存在替代实际 gate。

### 1.3 明确排除项

首版不做：

- Happy wire protocol、官方客户端或 Socket.IO 兼容。
- 远程开机、唤醒睡眠 PC、任意远程 shell。
- Git stage、unstage、discard、commit、push 等写操作。
- 服务器端正文搜索、管理员临时解密、服务器 Git diff 历史缓存。
- 语音、社交、好友、分享、付费和第三方公开 API。
- 将 PTY 作为默认运行时接入方式；PTY 只能在适配器明确标记为兼容降级时启用。

## 2. 实施原则与验收口径

### 2.1 实施原则

1. 先建立协议、密钥和测试夹具，再实现 Relay、Daemon 和客户端。
2. 先实现一条 mock adapter 纵向链路，再扩展四个真实 Provider。
3. 共享契约只有一个事实源：REST 使用 OpenAPI 3.1，事件和命令使用 JSON Schema Draft 2020-12。
4. Gin 只属于 transport/handler 层；`*gin.Context` 不进入 domain/application，handler 不写 SQL、不编排长生命周期任务。
5. 能力统一返回 `native | emulated | unsupported`，客户端根据 capability payload 渲染入口，不根据 Agent 类型猜测能力。
6. 任何写命令必须经过 Android 身份、当前 lease epoch 和 idempotency key 校验。
7. 每个 P0/P1 行为至少有根因层测试和一条跨层回归；测试失败不得通过放宽断言、静默错误或伪造 Provider 响应解决。
8. 每完成一个切片就运行聚焦检查，并把测试、项目文档和 ADR 同步回填。

### 2.2 验收口径

所有测试报告使用以下布尔字段，不得混用：

| 字段 | 含义 |
| --- | --- |
| `local_test` | 本地进程、测试数据库、mock 或离线 fixture |
| `fixture_data` | 种子数据、录制响应或协议样本 |
| `real_browser` | headed 的真实浏览器窗口用户流程 |
| `headless` | 无界面浏览器，仅用于 CI/快速回归 |
| `real_upstream` | 连接真实 Agent、Gateway 或外部服务 |
| `real_model` | 实际消耗模型 token；需要用户授权和凭据 |

每个阶段区分四种验证：

- `smoke`：证明最小链路、配置和认证可用。
- `targeted diagnostic`：针对一个失败行为或契约做定向复现。
- `full gate`：按结构化用例覆盖该阶段全部必须行为。
- `recording`：在 gate 通过后生成可审计的 headed 流程演示；不涉及真实模型的阶段使用等价浏览器演示。

真实 Provider、真实模型、付费服务或生产端点必须在执行前明确凭据来源、预计请求次数、token/额度风险和停止点。缺少授权时只能运行本地 fixture，并标记 `blocked` 或 `incomplete`。

## 4. P0：工程与协议基线

### P0.0 工具链和仓库规范

1. 建立 `apps/relay`、`apps/daemon`、`apps/mobile`、`apps/web`、`apps/admin-web`、`packages/protocol`、`packages/crypto`、`deploy`、`tests` 和 `e2e-verify` 的所有权说明。
2. 锁定 Go、Node、pnpm、Flutter/Dart、JDK、Docker 和 Taskfile 的精确版本；提交 Go module、`pnpm-lock.yaml`、`pubspec.lock` 和生成器版本。
3. 建立根目录 `Taskfile.yml`，统一提供 `task check`、`task test`、`task generate`、`task compose:up`、`task compose:down`、`task test:e2e`、`task test:android` 和 `task test:real` 入口。
4. 建立 `.env.example`、typed config、日志脱敏规则和本地测试数据说明；不得提交真实 token、私钥或账号。
5. 配置 GitHub Actions：Go、Node/Vue、Flutter、schema/生成文件和容器检查分开执行。

**P0.0 验收：** 新机器按 README 完成工具链检查；`task check` 能发现格式、类型、schema 和生成物漂移；敏感环境变量不会进入普通构建日志。

### P0.1 协议事实源

1. 定义统一 envelope：`protocol_version`、`message_id`、`trace_id`、scope、device identity、lease epoch、idempotency key、deadline、payload version。
2. 定义命令状态：`accepted`、`running`、`succeeded`、`failed`、`cancelled`、`rejected`、`expired`。
3. 定义事件类型：会话生命周期、消息增量、工具调用、权限、问题、Plan、Goal、Skill、Usage、FileChange、Git snapshot。
4. 定义错误码：认证、设备撤销、scope 越界、lease 冲突、旧实例、能力不支持、工作区移动、Terminal 离线、大小限制和超时。
5. 定义六种唤醒结果：`resumed`、`restarted_with_context`、`unsupported`、`local_state_missing`、`workspace_moved`、`terminal_offline`。
6. OpenAPI 3.1 定义 REST；JSON Schema 定义 WebSocket/SSE frame 和 payload；文档中注明生成文件禁止手改。
7. 使用 `oapi-codegen` Gin server 模式生成 Go REST 边界，使用 `openapi-typescript`/`openapi-fetch` 生成 TypeScript 客户端，使用 OpenAPI Generator 生成 Dart DTO/API 边界。

**P0.1 验收：** 三端可分别解析同一组 envelope、错误和事件 golden fixtures；未知 `payload_version`、未知事件和协议版本不匹配都有明确错误行为。

### P0.2 端到端加密和设备身份

1. Go、TypeScript、Dart 分别实现 Ed25519 身份签名、X25519 密钥交换、AES-256-GCM 和 HKDF-SHA256 封装。
2. 每设备生成身份签名密钥和加密密钥；Android 使用 Keystore，PC 使用 Keychain，Web 只保存受限密钥包装和短期缓存。
3. 实现项目/会话 DEK、设备授权包装、撤销后的新包装停止和恢复码流程。
4. AAD 绑定实体、事件类型、协议版本、序号和 key id；envelope 包含算法版本、96-bit nonce、ciphertext、AAD hash 和 payload version。
5. 建立跨语言 golden vectors：正常解密、篡改失败、错误 AAD、错误 key id、重复 nonce 防护和密钥轮换。

**P0.2 验收：** 三语言 vectors 互相解密；Relay 测试数据库、日志和错误报告中没有会话正文、工具参数、文件内容或密钥。

### P0.3 本地部署和观测骨架

1. 建立 Relay + SQLite 的本地隔离启动入口；`task compose:up/down` 仅管理本轮 PID 与临时/本地数据库，不依赖 PostgreSQL 或 Redis。
2. 建立编号 SQL（Goose 兼容）迁移入口、schema lint 和迁移命名规则。
3. 统一 `slog` JSON 字段白名单、request id、trace id、脱敏错误分类和 Prometheus/OTel 初始化。
4. 明确数据库备份、恢复演练和 Caddy TLS 配置的占位文档；P0 不触碰生产数据。

**P0.3 验收：** `task compose:up` 能启动 Relay + SQLite；`/healthz` 与 `/readyz` 可区分进程存活和 SQLite 就绪；`task compose:down` 只停止 PID 文件记录的本轮进程。

### P0 退出条件与产物

- 产物：目录骨架、版本锁定文件、OpenAPI、JSON Schema、生成代码、crypto vectors、SQLite 迁移/本地启动入口、配置示例、ADR-006/ADR-008 和 CI workflow。
- 必测：`P0-TOOL-01`、`P0-SCHEMA-01`、`P0-CRYPTO-01`、`P0-DEPLOY-01`。
- 退出：`task check`、`task test:protocol`、`task test:crypto`、`task test:relay`、`task test:android`、`task test:e2e`、`task compose:up/down` 全部通过；P0 headed E2E 与 recording 必须明确 `real_browser=true`、`headless=false`，不得将 fixture 或 API JSON 当作完整产品验证。
- 回滚：P0 只新增文件和可重建本地卷；协议字段采用向后兼容新增，生成器或版本选择不稳定时保留旧配置并停止进入 P1。

## 5. P1：Relay Server 纵向链路

### P1.0 数据模型和迁移

1. 创建账号、设备、设备密钥包装、配对请求、Terminal、Project、Workspace、Session、SessionInstance、ProviderThread、SessionEvent、Command、ControlLease、Plan、Goal、SkillDescriptor、AttachmentBlob、OutboxEvent 表。
2. 所有会话正文、diff、工具参数和附件内容只以密文 envelope 存储；服务器字段只保留白名单元数据、状态和哈希。
3. 为事件建立每会话单调 `event_seq`，为命令建立 `(scope, idempotency_key)` 唯一约束，为租约建立 fencing epoch。
4. 使用 sqlc 查询和显式事务；outbox 与业务写入同事务提交，worker 使用 `FOR UPDATE SKIP LOCKED`。
5. 迁移必须先做 additive change；删除或重命名列需要双写、回填、观测和至少一个可回滚版本。

**测试：** `RELAY-DB-01` 迁移从空库和上一版本库成功；并发写事件不会出现重复 seq；重复命令返回原结果。

### P1.1 账号、Token 和设备配对

1. 使用 Argon2id 验证邮箱/密码；access token 使用短期 opaque token，refresh token 随机生成、服务端只存哈希并轮换。
2. 实现首个 Android bootstrap：设备密钥生成、二维码/短码、owner 标记和恢复码备份确认。
3. 实现 PC/Web 配对请求、Android 批准、设备 key wrap 分发、设备列表和撤销。
4. 撤销设备立即停止新 token、WebSocket、SSE 和新 DEK 包装；旧连接进入关闭流程。
5. 所有配对和撤销操作写脱敏审计元数据，不写正文或二维码秘密。

**测试：** `PAIR-01` 至 `PAIR-03`、`SEC-02`；覆盖重复批准、过期二维码、撤销竞态和恢复码错误次数限制。

### P1.2 Gin REST、SSE 和 WebSocket

1. Gin 路由分为公共健康检查、认证、配对、只读快照、异步命令、Git 代理和账号级事件读取。
2. handler 只做绑定、鉴权、调用 application service 和错误映射；将 scope 从认证上下文推导，不信任客户端目标前缀。
3. SSE 支持 `Last-Event-ID`/`after_seq`、心跳、客户端取消、最大 backlog、慢客户端断开和重连退避。
4. WebSocket 使用 `coder/websocket`，首帧完成 challenge/hello、协议版本、设备身份、能力和游标协商。
5. Android/controller 与 PC/terminal 连接使用相同 envelope，但权限、scope 和可用命令不同。

**测试：** `HTTP-01`、`SSE-01`、`WS-01`；覆盖 malformed JSON、未知字段、协议版本、断线、心跳、慢客户端和认证失败。

### P1.3 事件、outbox、presence 和租约

1. 命令提交先返回 `accepted`，业务处理完成后写 `command.updated` 和标准 SessionEvent。
2. outbox worker 重试、去重和死信记录；Redis 只保存 presence、短租约、限流计数和可重建广播状态。
3. ControlLease 只允许 Android 写端持有；旧 instance、旧 epoch、撤销设备和非 owner 写命令必须返回稳定错误。
4. Relay 重启后从 PostgreSQL 恢复事件和命令状态，Redis 丢失时重新建立 presence，不丢历史真相。

**测试：** `TERM-01`、`SESS-01`、`SESS-02`、`CTRL-01`、`CTRL-02`、`SYNC-01`、`SYNC-02`、`SEC-01`。

### P1 纵向切片和退出条件

先只接入一个 mock Terminal：登录 -> 配对 -> Terminal 注册 -> 创建 mock Session -> 收到加密事件 -> Android/controller 发送 abort -> command.updated -> SSE/WS 断线恢复。该切片必须在接入真实 Provider 前跑通。

**退出条件：**

- 一台 mock Daemon 可稳定注册、重连和上报心跳。
- 两个只读订阅端可按 cursor 读取同一会话的有序事件。
- 相同 idempotency key 不产生第二次 Provider 动作。
- 非 Android、旧 lease epoch、旧 instance 和撤销设备的写命令均被拒绝。
- PostgreSQL/Redis 重启后，事件可恢复，presence 可重建。

**回滚：** REST/WS/SSE 只增加版本化 endpoint 或字段；迁移保持旧字段可读；outbox 新 worker 可暂停并由数据库状态重放；Redis 只可清理可重建 key，不得删除 PostgreSQL 事件。

## 6. P2：PC Daemon、Workspace 与 mock runtime

### P2.0 Daemon 进程和本地状态

1. 建立 Go Daemon 单一二进制和 Cobra CLI：`login`、`pair`、`status`、`project`、`session`、`doctor`、`service install/start/stop`。
2. 使用 `kardianos/service` 适配 macOS、Windows、Linux 后台服务；进程退出通过 context/errgroup 统一回收子进程。
3. 使用 `modernc.org/sqlite` 保存本机 Terminal、Workspace、ProviderThread 映射、命令 outbox、游标和诊断状态。
4. 使用 `zalando/go-keyring` 保存设备密钥包装、refresh token 和 Relay 地址；密钥不写 TOML。
5. 使用 `backoff/v5` 实现有上限 jitter 的 Terminal WS 重连和命令 outbox 重放。

**测试：** `DAEMON-BOOT-01`、`SYNC-03`；覆盖重复启动、优雅退出、子进程泄漏、SQLite 损坏提示和离线重连。

### P2.1 项目扫描与 Workspace 安全边界

1. 扫描用户配置的常用目录，只发现候选 Git 根目录，不自动暴露给手机。
2. 在 PC 端展示候选目录并要求用户确认；登记后生成项目指纹、加密显示名和 canonical root。
3. 所有请求执行 canonical path、realpath、repo-relative path、符号链接和目录越界检查。
4. 拒绝 `..`、绝对路径越界、仓库外符号链接、非 Git 根、移动/删除 Workspace 和不在 allowlist 的 MIME。
5. fsnotify 只用于刷新提示，任何实际读取仍重新做安全检查。

**测试：** `GIT-03`、`WORKSPACE-01`；覆盖特殊文件名、跨盘路径、符号链接、目录移动和 shell 注入字符串。

### P2.2 Git 只读 RPC

1. 通过 `os/exec` 参数数组调用系统 Git，不经过 shell；设置工作目录、环境白名单、超时和输出上限。
2. 解析 porcelain v2 `-z` status，提供 `status`、`listChanges`、`diffFile`、`diffAll`。
3. 支持 staged/unstaged、rename、binary、submodule、LFS、untracked、分页、压缩、最大字节数和大文件提示。
4. 每次读取生成 `snapshot_token`；分页或文件 diff 使用 token 校验工作区未漂移，漂移时返回可重试错误。
5. Relay 只转发加密响应，不缓存 diff 明文；Android/Web 在客户端解密和渲染。

**测试：** `GIT-01`、`GIT-02`、`GIT-04`、`GIT-05`、`GIT-06`；每个临时 Git 仓库测试结束清理，不依赖开发者目录。

### P2.3 Adapter SPI 和 mock runtime

1. 定义 `Detect`、`Capabilities`、`Start`、`Resume`、`Send`、`Abort`、`RespondPermission`、`SetMode`、`PlanAction`、`GoalAction`、`SkillCatalog`、`InvokeSkill`、`Dispose`。
2. 定义 `TurnStarted`、`MessageDelta`、`MessageCompleted`、`ToolCall`、`ToolResult`、`PermissionRequest`、`PermissionDecision`、`UserQuestion`、`PlanChanged`、`GoalChanged`、`SkillCatalogChanged`、`Usage`、`FileChange`、`DelegationChanged`。
3. mock adapter 能模拟流式 delta、工具、权限、问题、Plan、Goal、Skill、跨工具 Delegation、abort、失败和六种唤醒结果。
4. 将 raw provider event 作为受控 fixture，不让 provider-specific payload 进入客户端公共协议。

**P2 纵向退出：** 使用 mock adapter 完成 Relay -> Daemon -> SessionEvent -> Android 最小控制壳的 start/send/stream/abort；同时能读取 idle Session 的实时 Git diff。

## 7. P3：四类 Provider Adapter

### P3.0 共同执行顺序

每个适配器必须按以下顺序独立交付，不得先做 UI 特例：

1. `Detect`：安装状态、版本、启动方式和权限要求。
2. `Capabilities`：逐项返回 native/emulated/unsupported 和原因。
3. `Start`/`Resume`：保存原生线程句柄，明确 `resumed`、`restarted_with_context` 等结果。
4. `Send`/stream：把原生事件归一化为 canonical event，并保持 event_seq 和 backpressure。
5. `Abort`、权限请求、用户问题和重连。
6. `SetMode`、Plan、Goal、Skill catalog/invoke；不支持时返回稳定 unsupported。
7. fixture/golden trace、版本矩阵、崩溃和超时测试。
8. 有授权时运行 live smoke；没有凭据时标记 real_upstream blocked，不伪造通过。

### P3.1 Claude

- 优先 SDK 或 stream-json；验证启动、resume handle、permission mode、plan/goal 状态、skills、tool/use、usage 和 abort。
- 记录 Claude CLI/SDK 版本和最低支持版本；未知版本只提供安全能力子集。
- 测试：`ADPT-CLAUDE-01` 至 `ADPT-CLAUDE-04`。

### P3.2 Codex

- 使用 app-server JSON-RPC/stdio；验证 thread resume、审批、模型/推理级别、skills、abort 和错误映射。
- 不把未被 fixture 或 live gate 证明的能力写成 guaranteed；能力矩阵必须允许 unsupported。
- 测试：`ADPT-CODEX-01` 至 `ADPT-CODEX-04`。

### P3.3 OpenCode

- 使用本地 server API、WebSocket/SSE 和 session API；映射会话、工具、abort、文件/Git 读取和恢复。
- 如果原生线程无法恢复，明确返回 `restarted_with_context` 或 `unsupported`，不伪造 `resumed`。
- 测试：`ADPT-OPENCODE-01` 至 `ADPT-OPENCODE-04`。

### P3.4 OpenClaw

- 使用 Gateway WebSocket challenge、device auth 和 scoped RPC；映射 chat delta、thinking、tool、final、error、abort 和 skills。
- challenge、设备授权和权限风险必须在 Daemon 内部完成，客户端只看到统一状态和确认卡。
- 测试：`ADPT-OPENCLAW-01` 至 `ADPT-OPENCLAW-04`。

### P3 退出条件

- 四类适配器均能返回版本和能力矩阵。
- 每类均有 fixture contract tests；未知版本、安装缺失、provider timeout 和协议错误均有稳定分类。
- 至少一类真实 Provider 通过 live smoke 后，才允许在客户端展示其非 mock 能力；其余能力按证据标记 `incomplete` 或 `blocked`。
- 适配器失败不影响其他类型会话；每个 adapter 可独立回滚到 mock/unsupported。

## 10. 每个切片的固定执行模板

每个实现切片都按以下顺序执行，切片名称和测试 ID 写入提交说明或迭代记录：

1. **契约**：更新 OpenAPI/JSON Schema、错误、权限和状态；生成三端 DTO。
2. **根因层测试**：先写 domain、协议、存储或 adapter contract 测试。
3. **实现**：完成 use-case、transport、持久化/fixture 和客户端状态。
4. **聚焦检查**：运行对应 `task test:*`、格式、类型、lint 和迁移检查。
5. **跨层验证**：mock/fixture 通过后，再运行集成或 headed E2E；真实 Provider 另开 gate。
6. **失败处理**：从第一个因果失败开始分类为 `product_defect`、`test_harness_defect`、`provider_http_error`、`provider_timeout`、`credential_or_quota_blocker`、`environment_or_startup_failure` 等，不静音失败。
7. **文档回填**：同步项目文档、自动化测试文档、结构化用例和 ADR；记录未完成项、证据路径和残余风险。
8. **清理**：停止本轮启动的服务、浏览器、容器、端口和临时目录，不清理用户既有进程或数据。

## 13. Definition of Done

阶段或切片只有同时满足以下条件才算完成：

1. 代码、协议、测试、配置和文档描述的是同一版本事实。
2. 成功、加载、空状态、权限、网络失败、超时、重连和取消路径都有覆盖。
3. P0/P1 行为有稳定测试 ID 或清晰的长期测试名；测试放在 `tests/`、客户端测试目录或 `e2e-verify/`，不是一次性命令输出。
4. 关键跨层流程至少在 mock/fixture 环境真实运行一次；用户可见 Web/Admin 流程使用 headed 浏览器。
5. 真实 Provider、真实模型、Android 真机和生产部署缺口明确标注 `blocked`/`incomplete`，不伪造为 passed。
6. 失败有分类、脱敏证据、可重复步骤和回归测试；没有通过静默、跳过或放宽 oracle 获得绿色结果。
7. 项目文档、自动化测试文档、结构化用例和 ADR 已回填，覆盖审计列出剩余风险。

## 14. 主要风险与决策点

| 风险/决策 | 处理方式 | 进入阶段 |
| --- | --- | --- |
| Provider 协议漂移 | 版本探测、fixture、golden trace、最低版本矩阵 | P3 |
| 某 Provider 不支持原生 resume/goal/skill | 返回六种唤醒结果和 `unsupported`/`emulated`，不伪造 | P3/P4 |
| E2EE 三端实现差异 | 固定 vectors、跨语言互解和篡改测试 | P0 |
| Android 后台被系统挂起 | cursor/outbox、推送只作唤醒、恢复后重放 | P4/P5 |
| 多 Terminal/多实例竞态 | Android 固定写端、lease epoch、旧实例 fencing | P1/P5 |
| Git 路径和命令注入 | 参数数组、allowlist、realpath、OS 集成测试 | P2/P5 |
| 大输出阻塞连接 | chunk、压缩、大小限制、背压、超时 | P1/P2/P5 |
| Redis 故障 | Redis 只存可重建状态，PostgreSQL 保持事件真相 | P1/P5 |
| Gin 与长连接边界 | Gin 只做 REST/handler；SSE 显式 flush，WS 使用 `coder/websocket` | P1 |
| schema/生成器漂移 | `task generate` + CI diff 检查，生成物禁止手改 | P0 |
| 数据库回滚风险 | additive migration、双写/回填、兼容窗口、隔离恢复演练 | P1/P5 |
