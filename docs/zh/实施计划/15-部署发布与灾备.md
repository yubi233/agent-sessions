# 部署发布与灾备实施计划

## 计划元数据

| 字段 | 内容 |
| --- | --- |
| plan_id | `RELIABILITY-RELEASE` |
| owner | Deployment / Release |
| status | `planned` |
| target | M6 / P5 |
| protocol_revision | 发布 manifest 锁定版本 |
| adr | ADR-001、ADR-002、ADR-006 |

## 1. 目标与明确排除项

交付可重复的单租户 Docker Compose 部署、迁移、备份恢复、Web 静态产物、Daemon 跨平台安装包、签名/SBOM、升级与回滚流程。Relay/数据库实际部署必须保持密文边界。

不在未经授权时触碰生产域名、生产数据、签名私钥或真实 Provider；不把发布脚本当作功能测试的替代。

## 2. 进入条件、输入和依赖

- 输入：Relay migrations/health、Web/Admin builds、Daemon binaries、版本矩阵、测试报告。
- 依赖：Docker Compose、Caddy、PostgreSQL、Redis、GoReleaser/nfpm、签名机制、备份目标和 CI。
- 生产 deployment、证书、Android release key、软件签名证书与备份 bucket 必须单独授权。

## 4. 数据、权限、错误和事件边界

- PostgreSQL data volume 是权威；Redis 可以清空并重建。备份和日志不得泄露解密正文、密钥或 token。
- 发布顺序为兼容代码 -> additive migration -> backfill -> feature flag -> contract，回滚只回退应用/feature，不能用删除事件修复状态。
- Caddy TLS 和 `/v1` proxy 可运维，但不增加管理员正文解密或任意 shell 通道。

## 5. 命令、smoke、targeted diagnostic、full gate 和 recording

目标命令 `task compose:up`、`task compose:down`、`task deploy:backup`、`task deploy:restore`、`task release:build`、`task release:verify`。只有真实环境获授权后才执行真实签名/上传；否则使用隔离本地构建并标 `blocked`。

## 6. 退出条件、阻塞和残余风险

退出：隔离 Compose 可重建；备份可恢复并验证密文/事件序号/撤销；升级失败能回退；发布包可校验；RPO/RTO 来自真实演练报告；性能/安全缺口可追溯。

阻塞：没有签名证书、备份目标、生产授权、Android 发布密钥或兼容迁移方案。残余风险：真实 Provider 版本仍由专属 adapter gate 管理。

## 7. 文档回填清单

回填 Compose 版本、环境变量、迁移清单、备份频率、RPO/RTO、artifact digest、最低版本和回滚操作。
