## 1. 责任边界

总控计划由项目负责人维护，负责跨项目依赖、版本节奏、变更审批和阶段门禁；不直接替代 Relay、Daemon、客户端或测试子计划。

权威产品边界是 [项目文档](../项目文档.md)。本文件是里程碑与依赖的唯一总览；执行级工作包在本目录各子计划。两者冲突时先更新本文件，再更新子计划。

## 6. M0 / P0.0 工程基线工作包

在 `PROTO-CRYPTO` W1 之前必须完成。本工作包由总控批准，`RELIABILITY-RELEASE` 接收 Compose 产物，`TEST-RELEASE` 接收命令入口。

| 工作包 | 实现步骤 | 交接输出 | 测试 ID | 最低层级 | 证据 | 回滚 |
| --- | --- | --- | --- | --- | --- | --- |
| W0.1 工具与仓库 | 锁定 Go 1.26.x、Node/pnpm、Flutter/Dart 3.x、JDK 21、Docker、Task；建立根 `go.mod`、pnpm workspace、`apps/mobile/pubspec.yaml` | 版本清单、lockfile、目录 README/所有权 | `P0-TOOL-01` | 静态 | `e2e-verify/reports/<ts>/PROGRAM/toolchain.json` | 保留旧版本选择，不进入 P1 |
| W0.2 任务与配置 | 根 `Taskfile.yml`：`check`、`generate`、`test`、`test:protocol`、`test:crypto`、`compose:up/down`、`docs:verify`；`.env.example`；日志脱敏 | 可复制命令，无真实密钥 | `P0-TOOL-01` | 静态 | Taskfile 与 env 扫描 | 删除新增脚本，不改用户数据 |
| W0.3 协议空仓 | `packages/protocol` 放入可生成的 OpenAPI/JSON Schema 骨架；`packages/crypto` 放入向量目录 | 生成器配置，生成物禁止手改 | `P0-SCHEMA-01` | 静态 + contract | generate diff | 只增字段 |
| W0.4 Compose/CI | Relay/SQLite/Caddy 骨架、编号迁移入口、GitHub Actions 分层检查 | `deploy/docker-compose.yml`、workflow | `P0-DEPLOY-01` | 本地集成 | Compose health | `compose:down` 不删未授权卷 |

**W0 退出：** 新机器按 README 完成工具链检查；`task check` 能发现格式、类型、schema 和生成物漂移；敏感变量不进普通日志。未达到退出条件前，P1 及之后计划保持 `blocked_by: P0`。

## 7. 工作流

每个工作包按“契约 -> 根因层测试 -> 实现 -> 聚焦检查 -> 跨层验证 -> 证据归档 -> 文档回填”执行。总控只接受带证据链接的完成状态。

跨项目顺序固定为：

```text
协议/密码学 -> Relay 认证/事件 -> Daemon/mock -> Android mock/Web mock
                                  \-> Provider adapters -> 完整客户端 -> 发布
```

Web/Admin 可以在 M2 后使用 fixture 并行开发；Android 可以在 M3 后先完成 mock 会话控制；真实能力入口只能在对应 adapter contract 证据存在后启用。

## 8. 依赖和变更控制

- 协议字段、错误码、能力状态、事件序号和密钥格式变更必须先更新 [01-协议与密码学](01-协议与密码学.md)，再由各消费方迁移。
- 数据库迁移由 [Relay 身份、设备与持久化](02-Relay身份设备与持久化.md) 与 [部署发布与灾备](15-部署发布与灾备.md) 联合审查；lease、幂等和 outbox 由 [Relay 实时会话与同步](03-Relay实时会话与同步.md) 负责。
- Adapter 能力不得由客户端自行添加；由 [Adapter 平台](06-Adapter平台与Mock运行时.md) 和对应 Provider 计划提供版本证据。
- 新增测试 ID 只能追加，不能复用或重编号；唯一注册表是 `docs/test/测试套件索引.json`，覆盖矩阵由 [测试验证与质量门禁](14-测试验证与质量门禁.md) 维护。
- 修改公开协议、权限、数据迁移、启动命令或验收 ID 时，必须同步更新本文件、[项目文档](../项目文档.md)、[自动化测试文档](../自动化测试文档.md) 和 ADR。

## 9. 总控完成标准

- 每个子项目都有唯一 owner、当前状态、下一工作包和阻塞条件。
- 每个 P0/P1 用户旅程至少有根因层测试和跨层证据。
- 任何 `blocked`、`incomplete` 或 `failed` 都有分类、命令、残余风险和下一步，不得写成“基本通过”。
- 发布前总控报告能从需求映射到测试 ID、报告路径、版本和回滚方案。
- 在 M0 退出前，不得把空目录、计划命令或 suite JSON 描述为已交付运行时。
