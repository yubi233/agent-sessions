# 测试验证与质量门禁实施计划

## 计划元数据

| 字段 | 内容 |
| --- | --- |
| plan_id | `TEST-RELEASE` |
| owner | Test / Release |
| status | `planned` |
| next_work_package | W1 注册校验与 `task docs:verify` |
| blocked_by | 命令入口与 CI validator 尚未落地；领域 suite 现已登记但仍全部 `planned` |
| target | M0-M6 / P0-P5 |
| protocol_revision | 消费各阶段锁定版本 |
| adr | ADR-001、ADR-006 |

## 1. 目标与明确排除项

建立从协议单元、Relay/Daemon 集成、Provider contract、Flutter integration、headed Vue E2E、真实上游 gate 到发布报告的长期质量体系。唯一测试 ID 事实源为 [测试套件索引](../../test/测试套件索引.json)，当前测试地图为[自动化测试文档](../自动化测试文档.md)。

`TEST-RELEASE` 不拥有 `P0-*`、`DEPLOY-*`、`PERF-*` 或业务旅程 ID。部署与发布产物测试归 [15-部署发布与灾备](15-部署发布与灾备.md) 的 `RELIABILITY-RELEASE`。跨项目入口 [基础验收用例](../../test/基础验收用例.json) 的注册身份是 `FOUNDATION-ACCEPTANCE`，只消费领域 ID。

不拥有业务实现、部署脚本或 Provider 凭据；本计划定义断言、报告和 gate，具体项目交付其代码/fixture。

## 2. 进入条件、输入和依赖

输入是计划目录所有 owner 的接口、fixtures、功能状态和变更说明。P0 首先建立 `Taskfile.yml`/CI 的真实命令；在它们不存在前，文档只能记录 `planned`，不能伪造命令通过。

## 3. 工作包

| 工作包 | 前置输出 | 实现步骤 | 交接输出 | 测试 ID | 最低层级 | 证据 | 回滚/开关 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| W1 注册与契约 | 项目计划、schema | 维护索引、ID 唯一校验、suite schema、requirements-to-ID matrix | `docs/test/*.json`、CI validator | 全部登记 ID | 静态 | registry audit | 禁止未登记 ID 进入 gate |
| W2 根因层回归 | 各项目实现 | 协议/crypto/Relay/Daemon/Git/adapter/widget/component tests，要求 P0/P1 有根因层 | 长期测试文件与 fixtures | 各 owner ID | 单元/集成/contract | test reports | 不用 E2E 取代根因测试 |
| W3 跨层和可见验收 | 可运行系统 | mock E2E、Android integration、headed Web/Admin、恢复/权限/空状态/失败/重试 | e2e runners | `E2E-*`、客户端 ID | integration + headed E2E | traces/screenshots | failure classified, not skipped |
| W4 真实上游和发布 gate | Provider/发布授权 | provider live smoke、性能、灾备、签名/升级；按权限/额度执行 | gated report/manifest | `ADPT-*-04`、`PERF-*`、`DEPLOY-*` | authorized upstream/release | scrubbed reports | marked blocked when unauthorized |

## 4. 验证规则

每份报告必须有 `local_test`、`fixture_data`、`real_browser`、`headless`、`real_upstream`、`real_model`、命令、版本、fixture revision、失败分类和残余风险。headed 浏览器不得由 headless 替代；fixture 不得冒充真实 Provider/模型。报告、fixture、trace、录屏不得包含 token、正文、diff 或解密附件。

## 5. 命令、smoke、targeted diagnostic、full gate 和 recording

目标命令是 `task check`、`task generate`、`task test:protocol`、`task test:crypto`、`task test:relay`、`task test:daemon`、`task test:contract`、`task test:android`、`task test:e2e`、`task test:real`、`task docs:verify`。实际命令建立前不运行/不声称成功。

## 6. 退出条件、阻塞和残余风险

退出：需求可追溯到 ID、测试文件、实际结果、报告和回滚；所有 P0/P1 同时有根因层和跨层证据；无授权 gate 明确 blocked。阻塞：ID 重复、fixture 无版本、报告丢失验证口径、或真实 gate 未授权。残余风险是测试覆盖不能替代生产运维演练。

## 7. 文档回填清单

同步测试注册表、自动化测试地图、项目文档覆盖矩阵、CI 命令、报告路径和每次变更的残余风险。
